How Webpack Emits Files Using webpack-sources

This article explores how Webpack manages asset generation and file emission through its internal compilation pipeline and the webpack-sources library. It covers the life cycle of code representation, the mechanics of webpack-sources classes, how assets are staged in memory, and the final step where Webpack converts these abstract source objects into physical files on disk.

The Role of webpack-sources

In Webpack, chunks and individual assets are rarely stored as plain strings during the build process. Instead, Webpack uses the webpack-sources utility library. A Source object is an abstraction that represents source code along with its associated source map, size, and hash information.

By representing output as structured Source objects rather than static strings or buffers, Webpack achieves several key benefits:

  • Deferred Computation: String concatenations, replacements, and source map generations are delayed until the last possible moment, reducing unnecessary memory allocation.
  • Automatic Source Map Composition: Transforming code (e.g., minifying or prefixing) while maintaining accurate source maps is handled internally through classes like SourceMapSource and ReplaceSource.
  • Caching: Classes such as CachedSource wrap other sources to memoize results for methods like .source(), .buffer(), .size(), and .map().

Common implementations provided by webpack-sources include:

  • RawSource: Represents raw text or a buffer with no source map handling.
  • ConcatSource: Links multiple Source objects together sequentially without immediately evaluating them into a single string.
  • ReplaceSource: Allows slicing and replacing segments of a wrapped Source while keeping source map mappings aligned.
  • PrefixSource: Adds a prefix to every line in the wrapped source.

Staging Assets in the Compilation Phase

During the compilation life cycle, modules are parsed, sealed, and grouped into chunks. Once chunks are constructed, Webpack invokes renderers (such as JavascriptModulesPlugin) to produce the final executable bundle strings.

Instead of writing directly to the filesystem, the rendering plugins construct a webpack-sources instance and assign it to the compilation.assets dictionary:

compilation.emitAsset(
  'bundle.js',
  new ConcatSource(headerSource, moduleSource, footerSource)
);

Using compilation.emitAsset() registers the target filename as a key and the Source instance as the value. Plugins can inspect, mutate, replace, or wrap any asset currently registered in compilation.assets before physical file emission occurs.

The Emission Phase

Once all compilation hooks and optimizations (such as minification via Terser or dynamic banner injection) complete, the Compiler initiates the emission step through compiler.emitAssets().

The emission pipeline proceeds through the following sequence:

  1. Triggering the emit Hook: Webpack executes the emit hook, which is the final opportunity for plugins to modify compilation.assets or add new Source objects.
  2. Resolving Paths and Directories: Webpack resolves the absolute file path for each asset by combining output.path with the asset key. It ensures all required target directories exist on the output filesystem using outputFileSystem.mkdirp (or native recursive directory creation).
  3. Evaluating the Source: For each entry in compilation.assets, Webpack extracts the binary or text payload from the webpack-sources instance by calling .buffer() or .source(). If the source object is a CachedSource, it retrieves the cached buffer directly; otherwise, the underlying tree of ConcatSource or ReplaceSource instances computes the final output.
  4. Writing via outputFileSystem: Webpack writes the resulting buffer to destination paths using the configured compiler.outputFileSystem. In standard production builds, this is Node’s native fs module. In development using webpack-dev-server, this is often a memory filesystem (such as memfs), allowing assets to be served directly from RAM without touching the hard drive.
  5. Triggering the afterEmit Hook: After all buffers are written, Webpack cleans up emitted assets from memory, flags the build as successful, and executes the afterEmit and done hooks with final performance metrics.
