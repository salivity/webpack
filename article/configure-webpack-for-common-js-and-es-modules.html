Configure Webpack for CommonJS and ES Modules

Publishing a modern JavaScript library requires supporting both CommonJS (CJS) for legacy Node.js environments and ES Modules (ESM) for modern bundlers and browsers. This guide demonstrates how to configure Webpack 5 using a multi-compiler setup to build both formats simultaneously and how to properly configure your package.json to route consumers to the appropriate bundle.

Webpack Multi-Compiler Configuration

Webpack cannot output both CJS and ESM from a single configuration block. Instead, export an array containing two configurations: one targeting CommonJS and another targeting ES Modules via Webpack 5's module experiment.

Create or update your webpack.config.js:

const path = require('path');

const sharedConfig = {
  entry: './src/index.js',
  resolve: {
    extensions: ['.js', '.ts'],
  },
  module: {
    rules: [
      {
        test: /\.[jt]s$/,
        exclude: /node_modules/,
        use: 'babel-loader',
      },
    ],
  },
};

// CommonJS Configuration
const cjsConfig = {
  ...sharedConfig,
  target: 'node',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'index.cjs.js',
    library: {
      type: 'commonjs2',
    },
  },
};

// ES Module Configuration
const esmConfig = {
  ...sharedConfig,
  experiments: {
    outputModule: true,
  },
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'index.esm.js',
    library: {
      type: 'module',
    },
  },
};

module.exports = [cjsConfig, esmConfig];

Key Configuration Points

  • experiments.outputModule: Enables Webpack's experimental support for generating ES Module output.
  • library.type: 'module': Tells Webpack to generate standard export statements rather than wrapping code in a UMD or CommonJS wrapper.
  • library.type: 'commonjs2': Assigns exports to module.exports, ensuring clean compatibility when imported via require() in Node.js.

Configuring package.json

To enable consumers to automatically resolve the correct bundle depending on their module environment, configure the exports map alongside traditional fallback fields in your package.json:

{
  "name": "your-library-name",
  "version": "1.0.0",
  "main": "./dist/index.cjs.js",
  "module": "./dist/index.esm.js",
  "exports": {
    ".": {
      "import": "./dist/index.esm.js",
      "require": "./dist/index.cjs.js"
    }
  },
  "files": [
    "dist"
  ]
}
  • exports.import: Directs modern bundlers (such as Vite, Rollup, or Webpack) and Node.js using import statements to the ESM build.
  • exports.require: Directs Node.js using require() to the CommonJS build.
  • main and module: Serve as fallbacks for older build tools that do not recognize the exports field.
