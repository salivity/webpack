Detect Circular Dependencies in Webpack

Circular dependencies occur when two or more modules depend on each other directly or indirectly, often leading to unexpected runtime errors, undefined imports, and unoptimized bundles. This article outlines the primary Webpack plugins and complementary static analysis tools used to detect, visualize, and eliminate circular references within a Webpack dependency graph.

1. circular-dependency-plugin

The most direct solution for Webpack users is circular-dependency-plugin. It hooks directly into the Webpack compilation pipeline, scanning files during the build process and logging cycles to the console.

Installation:

npm install --save-dev circular-dependency-plugin

Webpack Configuration:

const CircularDependencyPlugin = require('circular-dependency-plugin');

module.exports = {
  entry: './src/index.js',
  plugins: [
    new CircularDependencyPlugin({
      // Exclude detection in node_modules
      exclude: /node_modules/,
      // Include specific files if needed
      include: /src/,
      // Add a visual check to the output in the console
      failOnError: true,
      // Allow import cycles that include an asyncronous import
      allowAsyncCycles: false,
      // Set the current working directory for displaying module paths
      cwd: process.cwd(),
    })
  ]
};

When Webpack builds, any loop (such as A.js -> B.js -> A.js) will immediately trigger a warning or fail the build depending on the failOnError setting.

2. Madge

Madge is a developer favorite for analyzing module dependencies outside or alongside the Webpack build step. It works with CommonJS, AMD, and ES modules, and can generate both visual graphs and text-based cycle reports.

Installation:

npm install -g madge

Detecting Cycles via CLI:

# Check for circular dependencies in a project directory
madge --circular ./src/index.js

Madge can be integrated into your CI/CD pipeline or package.json scripts to prevent pull requests with circular dependencies from being merged.

3. DPDM

DPDM is a high-performance static analysis tool designed specifically for JavaScript and TypeScript projects. It detects circular dependencies and missing modules significantly faster than many older alternatives.

Installation:

npm install -g dpdm

Detecting Cycles via CLI:

dpdm --detect-cycle ./src/index.ts

DPDM directly parses TypeScript and TSX files without requiring separate compilation steps, making it ideal for modern TypeScript-heavy Webpack setups.

4. eslint-plugin-import (import/no-cycle)

While not a Webpack plugin, catching circular dependencies at authoring time prevents them from ever reaching your build tool. The import/no-cycle rule from eslint-plugin-import detects cyclical imports across modules during code linting.

Configuration (.eslintrc.json):

{
  "plugins": ["import"],
  "rules": {
    "import/no-cycle": ["error", { "maxDepth": Infinity }]
  }
}

Note: Enabling this rule on very large codebases with maxDepth: Infinity can increase ESLint execution time, so it is often set to a limited depth or run only during CI checks.

5. Statoscope

Statoscope is a suite of tools for analyzing Webpack bundles. It allows you to inspect module dependencies, analyze bundle sizes, and uncover dependency issues.

By passing Webpack stats generated with webpack --json > stats.json into Statoscope, you can visually trace the dependency tree and identify complex indirect cycles that span across multiple packages or lazy-loaded chunks.
