Restrict Dynamic Require Context in Webpack

Dynamic expressions in require() or import() calls can inadvertently bloat your JavaScript bundles because Webpack defaults to capturing every file in a directory tree that could potentially match the pattern. This article explains how dynamic require contexts work and outlines the most effective methods to restrict their scope—including native dynamic imports with magic comments, require.context(), and Webpack plugins—ensuring only essential files are bundled.

The Problem with Dynamic Requires

When Webpack encounters a completely or partially dynamic require statement, such as:

const module = require(`./locales/${lang}.json`);

It cannot determine at build time which exact file will be loaded. To ensure the runtime execution does not fail, Webpack creates a "context module." By default, it walks the target directory recursively and bundles every file matching the surrounding pattern. If the base directory contains tests, documentation, or unsupported languages, those are packaged into the final bundle as well. A completely dynamic statement like require(variable) is even worse, as it defaults to searching the entire project directory.

1. Narrow the Base Path

Avoid passing raw variables directly to dynamic imports. Always provide as specific a static path prefix and file extension suffix as possible.

  • Inefficient: require(path) or import(path) (scans everything from the root)
  • Better: require(./components/${name}.js) (limits search to ./components)

Providing explicit directory prefixes and extensions limits the initial search surface before applying regex filters.

2. Control Scope with require.context()

Webpack provides require.context() to give you explicit, programmatic control over how a directory is crawled. It accepts four arguments:

  1. directory: The target directory to search (string).
  2. useSubdirectories: Whether to traverse nested folders (boolean).
  3. regExp: A regular expression matching only the intended files (RegExp).
  4. mode: Loading behavior ('sync', 'lazy', 'lazy-once', etc.).
// Bundle only .json files in the root of the 'locales' folder, ignoring subdirectories
const context = require.context('./locales', false, /^[a-z]{2}\.json$/);

function loadLocale(lang) {
  return context(`./${lang}.json`);
}

By setting the second parameter to false, you eliminate nested folders, and the regex ensures non-locale files (such as .md or .spec.js) are omitted.

3. Use Webpack Magic Comments with Dynamic import()

If you use ES module dynamic imports (import()), you can restrict the context scope using inline "magic comments" without restructuring your logic:

function loadTemplate(templateName) {
  return import(
    /* webpackInclude: /\.vue$/ */
    /* webpackExclude: /\.spec\.vue$/ */
    /* webpackChunkName: "templates" */
    /* webpackMode: "lazy" */
    `./templates/${templateName}`
  );
}
  • webpackInclude: A regular expression that must match for a file to be included in the bundle.
  • webpackExclude: A regular expression to explicitly exclude matching files, such as test files or backup configurations.

4. Override Third-Party Contexts with ContextReplacementPlugin

Some third-party dependencies (notably libraries like Moment.js) contain dynamic require calls that package unwanted locales into your build. Because you cannot modify the library's source code directly, you can adjust Webpack’s context resolution rules in webpack.config.js via the ContextReplacementPlugin.

// webpack.config.js
const webpack = require('webpack');

module.exports = {
  plugins: [
    // Limit Moment.js to only bundle English, German, and French locales
    new webpack.ContextReplacementPlugin(
      /moment[/\\]locale$/,
      /de|fr/
    )
  ]
};

This configuration intercepts any dynamic context generated within moment/locale and restricts the matched files strictly to the provided regular expression.

5. Strip Unwanted Contexts Entirely with IgnorePlugin

If a library dynamically requires an entire set of assets that your application never uses, you can prevent context generation completely using the IgnorePlugin:

// webpack.config.js
const webpack = require('webpack');

module.exports = {
  plugins: [
    new webpack.IgnorePlugin({
      resourceRegExp: /^\.\/locale$/,
      contextRegExp: /moment$/,
    })
  ]
};

This prevents Webpack from generating a context module for the matched import, requiring you to manually import only the specific modules your application requires.
