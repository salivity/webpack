Webpack Multiple Entry Points for Multi-Page Apps

This article provides a practical guide on configuring Webpack to handle multi-page applications (MPAs) through multiple entry points. You will learn how to define entry objects, configure dynamic output filenames, generate separate HTML files for each page using html-webpack-plugin, and optimize shared assets across pages with code splitting.

1. Defining the Entry Points

In a single-page application, Webpack uses a single string for its entry point. For a multi-page application, you pass an object to the entry property where each key represents a page name (chunk) and the value is the path to that page's main JavaScript file.

// webpack.config.js
const path = require('path');

module.exports = {
  entry: {
    home: './src/pages/home/index.js',
    about: './src/pages/about/index.js',
    contact: './src/pages/contact/index.js',
  },
  // ...
};

2. Configuring Dynamic Output Filenames

When using multiple entries, you cannot use a static output filename like bundle.js, as each entry would overwrite the other. Instead, use Webpack substitutions such as [name] to dynamically generate unique bundle files based on the entry keys.

module.exports = {
  // ...
  output: {
    filename: 'js/[name].[contenthash].js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
};

3. Generating HTML Files per Entry

To serve each page, you need an HTML file that includes its specific JavaScript bundle. Install and configure html-webpack-plugin by declaring an instance for each page. Use the chunks option to restrict which bundles are injected into which HTML document.

npm install --save-dev html-webpack-plugin
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  // ...
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/pages/home/index.html',
      filename: 'index.html',
      chunks: ['home'],
    }),
    new HtmlWebpackPlugin({
      template: './src/pages/about/index.html',
      filename: 'about.html',
      chunks: ['about'],
    }),
    new HtmlWebpackPlugin({
      template: './src/pages/contact/index.html',
      filename: 'contact.html',
      chunks: ['contact'],
    }),
  ],
};

4. Preventing Code Duplication with SplitChunks

Multi-page applications often share common libraries (like React, Lodash, or shared utilities). Without optimization, Webpack duplicates these modules in every entry bundle. Use optimization.splitChunks to extract shared code into vendor or common chunks.

module.exports = {
  // ...
  optimization: {
    splitChunks: {
      chunks: 'all',
      name: 'common',
    },
  },
};

When you define shared chunks, html-webpack-plugin automatically includes the common vendor bundles alongside the entry-specific chunk specified in the chunks array.

Complete Configuration Example

Here is a full webpack.config.js incorporating all the steps above:

const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  mode: 'production',
  entry: {
    home: './src/pages/home/index.js',
    about: './src/pages/about/index.js',
  },
  output: {
    filename: 'js/[name].[contenthash].js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
  optimization: {
    splitChunks: {
      chunks: 'all',
    },
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/pages/home/index.html',
      filename: 'index.html',
      chunks: ['home'],
    }),
    new HtmlWebpackPlugin({
      template: './src/pages/about/index.html',
      filename: 'about.html',
      chunks: ['about'],
    }),
  ],
};
