How to Inspect Webpack's Internal Acorn AST

Webpack parses JavaScript source files into an Abstract Syntax Tree (AST) using an internal version of the Acorn parser to discover dependencies, imports, and exports. You can inspect this internal AST directly during the compilation phase by writing a custom Webpack plugin that taps into the compiler's NormalModuleFactory and hooks into Webpack’s JavascriptParser. This guide walks through the exact compilation hooks required to intercept and inspect the AST for individual modules.

Accessing the AST via a Custom Plugin

The most effective way to inspect the internal Acorn AST is through a lightweight, inline Webpack plugin. Webpack creates module parsers via NormalModuleFactory. By targeting the parser hook on this factory, you can access the parser instance and tap into its program lifecycle event, which receives the parsed Acorn AST and code comments.

Add the following plugin implementation directly to your webpack.config.js:

class InspectAstPlugin {
  constructor(options = {}) {
    // Optional filter to avoid dumping ASTs for every module/library
    this.targetResource = options.targetResource || null;
  }

  apply(compiler) {
    compiler.hooks.normalModuleFactory.tap('InspectAstPlugin', (factory) => {
      const inspectParser = (parser) => {
        parser.hooks.program.tap('InspectAstPlugin', (ast, comments) => {
          const resourcePath = parser.state.current?.resource || parser.state.module?.resource;

          // Apply path filtering if configured
          if (this.targetResource && resourcePath && !resourcePath.includes(this.targetResource)) {
            return;
          }

          console.log(`\n--- AST for: ${resourcePath} ---`);
          console.dir(ast, { depth: null, colors: true });
        });
      };

      // Tap into common JavaScript parser types
      factory.hooks.parser.for('javascript/auto').tap('InspectAstPlugin', inspectParser);
      factory.hooks.parser.for('javascript/esm').tap('InspectAstPlugin', inspectParser);
      factory.hooks.parser.for('javascript/dynamic').tap('InspectAstPlugin', inspectParser);
    });
  }
}

module.exports = {
  // ... other configuration options
  plugins: [
    new InspectAstPlugin({ targetResource: 'src/index.js' }),
  ],
};

Understanding the Key Hooks

  1. compiler.hooks.normalModuleFactory: Taps into the creation of the module factory, which manages the creation of module parsers.
  2. factory.hooks.parser.for(...): Webpack categorizes JavaScript parsing into types (javascript/auto, javascript/esm, and javascript/dynamic). Registering your callback across these types guarantees you capture the parser regardless of how the file is imported.
  3. parser.hooks.program: This hook is triggered immediately after Acorn generates the top-level Program AST node for the current file. The hook passes two arguments: ast (the Acorn-compliant tree) and comments (an array of extracted comments).

Filtering Output and Traversing Nodes

Because Webpack processes dozens or hundreds of files during a single build (including packages inside node_modules), printing the raw AST to standard output without filtering will flood your terminal.

Use the parser.state.current.resource property to locate the absolute file system path of the module being parsed. If you need to inspect fine-grained nodes rather than the full program tree, the parser.hooks object exposes granular hooks for specific Acorn node types, such as:

  • parser.hooks.statement: Fires for every statement node encountered.
  • parser.hooks.call.for('identifier'): Fires on function calls matching a specific name.
  • parser.hooks.import: Fires when an ES module import statement is parsed.

Using these specific parser hooks allows you to inspect isolated components of the AST without serializing the entire syntax tree.
