Webpack Plugins for GitHub Pages and Netlify

Deploying a modern web application directly from your build pipeline saves time and reduces deployment errors. This article outlines the primary Webpack plugins and configuration strategies used to automate builds and deployments to GitHub Pages and Netlify, detailing how they work and how to implement them in your project.

Deploying to GitHub Pages with ghpages-webpack-plugin

For GitHub Pages, the most direct solution inside a Webpack configuration is the ghpages-webpack-plugin (built on top of the popular gh-pages utility). This plugin automatically pushes the generated build output from your compilation directory (such as dist or build) directly to your repository's gh-pages branch upon a successful build.

Installation

npm install --save-dev ghpages-webpack-plugin

Configuration

Add the plugin to your webpack.config.js:

const path = require('path');
const GhPagesWebpackPlugin = require('ghpages-webpack-plugin');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'bundle.js',
    publicPath: '/<repository-name>/', // Required for GitHub Pages asset routing
  },
  plugins: [
    new GhPagesWebpackPlugin({
      path: 'dist',
      options: {
        message: 'Auto-generated commit via Webpack build',
        branch: 'gh-pages',
      },
    }),
  ],
};

Automating Deployments to Netlify

Netlify is primarily designed around a Git-triggered continuous deployment workflow where Netlify itself runs npm run build on your repository. However, if you need Webpack to initiate and push deployments to Netlify independently, you can automate this using webpack-shell-plugin-next in conjunction with the official Netlify CLI.

Installation

npm install --save-dev netlify-cli webpack-shell-plugin-next

Configuration

Configure Webpack to trigger a production deploy to Netlify as an onBuildEnd event:

const path = require('path');
const WebpackShellPluginNext = require('webpack-shell-plugin-next');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'bundle.js',
  },
  plugins: [
    new WebpackShellPluginNext({
      onBuildEnd: {
        scripts: ['npx netlify deploy --dir=dist --prod'],
        blocking: false,
        parallel: true,
      },
    }),
  ],
};

To make this execution seamless in CI environments or local terminal setups, ensure your NETLIFY_AUTH_TOKEN and NETLIFY_SITE_ID environment variables are configured.

Summary of Differences

  • GitHub Pages: Best automated directly using ghpages-webpack-plugin, which manages the Git commit and branch switching for your static assets.
  • Netlify: Best served natively by Netlify's automatic Git integration, but can be automated from Webpack directly by executing Netlify CLI deployment commands using webpack-shell-plugin-next.
