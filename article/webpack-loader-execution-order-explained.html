Webpack Loader Execution Order Explained

This article explains the standard execution order for multiple loaders defined within a single Webpack rule array. You will learn the exact direction in which Webpack evaluates these loaders, the underlying functional composition principle behind this design, and how to properly configure your loader pipelines to prevent build errors.

The Standard Execution Order: Right to Left

In Webpack, when multiple loaders are chained together in a single rule's use array, they execute in reverse order: from right to left (or bottom to top if written on multiple lines).

The result of the first-executed loader (the last one in the array) is passed as input to the next loader, continuing down the line until the first loader in the array returns the final JavaScript output.

Code Example

Consider the following common configuration for compiling Sass files:

module.exports = {
  module: {
    rules: [
      {
        test: /\.s[ac]ss$/i,
        use: [
          'style-loader', // Evaluated 3rd (last)
          'css-loader',   // Evaluated 2nd
          'sass-loader',  // Evaluated 1st
        ],
      },
    ],
  },
};

In this setup, the execution sequence occurs in the following order:

  1. sass-loader executes first, compiling Sass/SCSS code into standard CSS.
  2. css-loader executes second, parsing the compiled CSS and resolving @import and url() statements.
  3. style-loader executes last, taking the exported CSS module and injecting it into the DOM inside <style> tags.

Reversing this array will cause the build to fail because style-loader cannot parse raw Sass, nor can sass-loader process the output of style-loader.

Why Webpack Uses Right-to-Left Ordering

Webpack follows the functional programming concept of function composition, similar to mathematical composition where (f ∘ g)(x) equals f(g(x)).

When written conceptually:

styleLoader(cssLoader(sassLoader(sourceFile)))

The innermost function (sassLoader) must evaluate before the outer functions can receive its output.

The Two-Phase Lifecycle: Pitching and Normal

While standard loader transformations run right-to-left, Webpack actually executes loaders in two distinct phases:

  1. The Pitching Phase (Left to Right): Webpack calls the pitch method on each loader, starting from the first loader in the array to the last. If a loader's pitch method returns a result, Webpack skips the remaining loaders and immediately reverses direction to the normal phase.
  2. The Normal Phase (Right to Left): If no pitch method returns a value, Webpack executes the standard loader functions in right-to-left order to perform the actual file transformations.

Understanding this execution pipeline ensures your asset pipelines are structured correctly and transform your source files in the intended sequence.
