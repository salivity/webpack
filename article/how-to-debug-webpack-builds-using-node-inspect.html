How to Debug Webpack Builds Using Node Inspect

This article explains how the Node.js --inspect flag integrates with Google Chrome DevTools to debug a Webpack build process. By exposing Node's underlying V8 inspector protocol over a WebSocket connection, developers can set breakpoints, step through compilation hooks, analyze memory usage, and troubleshoot custom plugins or loaders directly inside a familiar visual interface.

The Mechanism Behind node --inspect

Webpack is a JavaScript application executed by the Node.js runtime. When you run Webpack normally, Node executes the build scripts from start to finish without exposing internal execution state.

Passing the --inspect flag to Node tells the V8 JavaScript engine to activate its internal inspector agent. Upon activation, the runtime binds an HTTP and WebSocket server to a local network interface—by default, 127.0.0.1:9229. This server listens for incoming commands formatted according to the Chrome DevTools Protocol (CDP), a bidirectional JSON-RPC protocol designed for inspecting and debugging web browsers and JavaScript environments.

Establishing the Connection with Chrome DevTools

Because Google Chrome natively communicates using the Chrome DevTools Protocol, it can interface seamlessly with the V8 engine running your Webpack build.

  1. Discovery: When you navigate to chrome://inspect in Google Chrome, the browser queries local network interfaces on specified ports (including 9229) via HTTP to find active targets.
  2. WebSocket Upgrade: Once Chrome detects the running Node process, clicking "inspect" upgrades the HTTP connection to a full-duplex WebSocket connection.
  3. Execution Control: DevTools sends protocol messages to control execution (such as Debugger.enable or Runtime.evaluate), while Node pushes runtime events (such as Debugger.paused when a breakpoint is hit).

Running Webpack in Inspect Mode

To debug a build from the very beginning, you should use the --inspect-brk flag instead of --inspect. Because Webpack builds often execute quickly, --inspect-brk pauses code execution on the first line of the Webpack entry script, allowing you time to attach DevTools before the compilation lifecycle begins.

Execute Webpack through Node directly:

node --inspect-brk ./node_modules/webpack/bin/webpack.js --config webpack.config.js

Once executed, the terminal outputs a message indicating that the debugger is listening on ws://127.0.0.1:9229/ along with a unique target UUID.

Debugging Capabilities

Once attached, DevTools maps the loaded files in its Sources panel. From here, you have full visibility into the build environment:

  • Config and Plugin Breakpoints: You can place breakpoints directly inside webpack.config.js, custom loaders, or plugin hooks (such as compiler.hooks.emit.tapAsync).
  • Variable Inspection: Pause execution to inspect the compilation state, dependency graph, asset modules, and configuration options in the Scope pane.
  • Console Evaluation: Execute commands in the DevTools console in the context of the paused build step.
  • CPU and Memory Profiling: Use the Profiler and Memory panels to identify build bottlenecks, slow plugins, or memory leaks during large bundling tasks.
