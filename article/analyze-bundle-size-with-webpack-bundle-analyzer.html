Analyze Bundle Size with Webpack Bundle Analyzer

This article explains how to inspect and optimize your web application's build output using webpack-bundle-analyzer. You will learn how to install and configure the plugin in your Webpack build pipeline, generate an interactive zoomable treemap of your output files, understand key bundle size metrics (stat, parsed, and gzipped sizes), and identify bloat or duplicate dependencies to keep your application fast and lean.

1. Install the Plugin

To get started, install webpack-bundle-analyzer as a development dependency using your preferred package manager:

npm install --save-dev webpack-bundle-analyzer
# or
yarn add -D webpack-bundle-analyzer

2. Configure Webpack

Import the plugin and add it to the plugins array within your webpack.config.js file.

const path = require('path');
const BundleAnalyzerPlugin = require('webpack-bundle-analyzer').BundleAnalyzerPlugin;

module.exports = {
  entry: './src/index.js',
  output: {
    filename: '[name].[contenthash].js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
  plugins: [
    new BundleAnalyzerPlugin({
      analyzerMode: 'server', // Starts an HTTP server to view the report
      analyzerPort: 8888,
      openAnalyzer: true,     // Automatically opens the browser
      generateStatsFile: false, // Set to true if you want to export a stats.json
    }),
  ],
};

Optional: Conditional Activation

To prevent the analyzer server from launching on every standard build, bind it to an environment variable in webpack.config.js:

const BundleAnalyzerPlugin = require('webpack-bundle-analyzer').BundleAnalyzerPlugin;

module.exports = (env, argv) => {
  const isAnalyze = process.env.ANALYZE === 'true';

  return {
    // ... base webpack config
    plugins: [
      ...(isAnalyze ? [new BundleAnalyzerPlugin()] : []),
    ],
  };
};

You can then add a script to your package.json:

"scripts": {
  "build": "webpack --mode production",
  "analyze": "cross-env ANALYZE=true webpack --mode production"
}

3. Run the Analyzer

Execute your build or analysis command:

npm run analyze

Webpack will compile your assets, and webpack-bundle-analyzer will automatically launch an interactive treemap in your default web browser at http://127.0.0.1:8888.

4. Understanding Size Metrics

The control panel in the top-left corner allows you to toggle between three key size measurements:

  • Stat Size: The "input" size of your modules before Webpack applies transformations, minification, or tree shaking. This represents raw source code size.
  • Parsed Size: The actual size of the JavaScript files emitted to disk after bundling and minification. This represents what the browser's JavaScript engine must parse and compile.
  • Gzip Size: The size of the files after compression (Gzip or Brotli). This reflects the actual data transferred over the network.

5. Identifying Optimization Targets

Navigate the visual interface to discover common performance issues:

  • Accidental Monoliths: Large blocks indicate heavy libraries. Look for libraries like moment.js or lodash where lighter alternatives (date-fns, dayjs, or lodash-es) or targeted imports can drastically reduce bundle size.
  • Duplicate Packages: Search for common dependencies across different chunks. If two versions of the same package appear, reconcile your dependency tree to eliminate redundancy.
  • Missing Tree Shaking: If an entire library is present when you only use one function, ensure you are using ES module imports (e.g., import { map } from 'lodash-es') rather than CommonJS imports.
  • Chunk Splitting Opportunities: If vendor code and application code are bundled together, adjust your optimization.splitChunks configuration to separate third-party vendor code from application logic for better long-term browser caching.
