Webpack Subresource Integrity with SHA-256 and SHA-512

This article explains how Webpack implements Subresource Integrity (SRI) to secure web applications against unauthorized script modifications. You will learn the mechanics of how Webpack processes output assets, generates cryptographic digests using algorithms like SHA-256, SHA-384, and SHA-512, and injects integrity attributes into both static HTML templates and dynamic runtime chunk loaders.

Understanding Subresource Integrity (SRI)

Subresource Integrity is a security specification defined by the W3C that allows web browsers to verify that resources they fetch (such as JavaScript or CSS files from CDNs) have not been unexpectedly manipulated. When a browser detects an integrity attribute on a <script> or <link> element, it hashes the fetched content using the specified algorithm and compares the result to the provided hash string. If the hashes match, the resource executes; if they differ, the browser blocks execution to prevent cross-site scripting (XSS) and code injection.

An integrity attribute consists of the algorithm prefix followed by a base64-encoded cryptographic digest, formatted as sha256-[hash], sha384-[hash], or sha512-[hash].

The Role of Webpack in Asset Integrity

Webpack natively generates internal hashes (like contenthash, chunkhash, and fullhash) primarily for cache-busting, but these internal identifiers do not conform to the base64-encoded digest formats mandated by the SRI specification. To manage asset integrity in the browser, Webpack integrates with specialized plugins—most notably webpack-subresource-integrity—which interface with Webpack’s compilation lifecycle.

The Compilation and Hashing Lifecycle

Webpack manages cryptographic integrity through a multi-step pipeline during compilation:

  1. Asset Finalization: Webpack compiles code, performs tree-shaking, bundles modules, and emits raw asset buffers into the compilation pipeline.

  2. Hooking Compilation Assets: The integrity plugin taps into the Compilation.hooks.processAssets lifecycle hook. This ensures all minification and optimization steps are completed so the final file content is locked.

  3. Cryptographic Hashing: Using Node.js's native crypto module, the plugin reads the emitted binary buffer of each file. It applies the designated hashing algorithm (such as sha256, sha384, or sha512):

    const crypto = require('crypto');
const hash = crypto.createHash('sha384').update(assetSource).digest('base64');
const integrity = `sha384-${hash}`;

  4. Metadata Storage: The resulting digests are stored in the compilation metadata mapped to their corresponding chunk and asset filenames.

Injecting Integrity Attributes into Static HTML

When paired with html-webpack-plugin, the integrity plugin taps into HTML generation hooks (such as alterAssetTags). During this phase:

  • Webpack locates <script> and <link> elements destined for the entry point HTML.
  • It matches the asset URL to the generated digests in memory.
  • It attaches the computed integrity string and sets crossorigin="anonymous" to ensure proper CORS validation, which is required by browsers for SRI checks on external assets.

Handling Dynamic Chunks and Lazy Loading

A significant challenge in modern applications is maintaining integrity across dynamically imported files (e.g., import('./module')). Webpack solves this at the runtime level:

  1. Runtime Modification: The integrity plugin modifies Webpack's dynamic chunk-loading runtime code (traditionally jsonpScript or the chunk-loading template).
  2. Manifest Generation: Webpack builds an in-memory map of chunk IDs to their cryptographic hashes.
  3. Dynamic Script Creation: When a dynamic import triggers at runtime, Webpack’s internal require.ensure or import() function creates a new <script> tag. The runtime intercepts this creation, looks up the target chunk ID in the embedded manifest, and applies the integrity and crossorigin properties directly to the DOM element before appending it to the document head.

Configuration and Algorithm Selection

Developers configure algorithm preferences in their Webpack configuration via the plugin options:

const { SubresourceIntegrityPlugin } = require('webpack-subresource-integrity');
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  output: {
    crossOriginLoading: 'anonymous',
  },
  plugins: [
    new HtmlWebpackPlugin(),
    new SubresourceIntegrityPlugin({
      hashFuncNames: ['sha384', 'sha512'],
      enabled: process.env.NODE_ENV === 'production',
    }),
  ],
};

Choosing stronger algorithms like SHA-384 or SHA-512 increases collision resistance with negligible performance overhead during build time. By pairing compilation hooks with runtime script overrides, Webpack ensures that both static entry files and lazy-loaded asynchronous bundles remain cryptographically verified from deployment through execution.
