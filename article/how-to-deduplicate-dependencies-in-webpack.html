How to Deduplicate Dependencies in Webpack

Managing duplicate dependencies across different packages is critical for optimizing bundle size and runtime performance in modern web applications. Webpack solves this problem primarily through the SplitChunksPlugin, a built-in optimization strategy configured under the optimization.splitChunks configuration block. This article explains how the SplitChunksPlugin works to extract identical code into shared chunks, the specific configuration parameters required to enable it, and complementary dependency resolution techniques to ensure redundant packages are completely eliminated.

The Primary Strategy: SplitChunksPlugin

The standard approach to extract duplicated dependencies in Webpack is configuring optimization.splitChunks. Introduced in Webpack 4 and expanded in Webpack 5, the SplitChunksPlugin analyzes dependency graphs to find modules shared across multiple entry points or asynchronous chunks, extracting them into a common chunk.

To enable dependency extraction across the entire application, the minimum configuration requires setting chunks to 'all':

// webpack.config.js
module.exports = {
  // ...
  optimization: {
    splitChunks: {
      chunks: 'all',
    },
  },
};

By default, Webpack only extracts dynamic (asynchronously imported) chunks. Setting chunks: 'all' informs Webpack to apply optimization to both synchronous and asynchronous imports.

Fine-Tuning with Cache Groups

To specifically target and consolidate third-party vendor libraries from node_modules, Webpack uses cacheGroups. This controls how modules are assigned to separate output files.

// webpack.config.js
module.exports = {
  optimization: {
    splitChunks: {
      chunks: 'all',
      minSize: 20000,
      cacheGroups: {
        defaultVendors: {
          test: /[\\/]node_modules[\\/]/,
          priority: -10,
          reuseExistingChunk: true,
          name: 'vendors',
        },
        default: {
          minChunks: 2,
          priority: -20,
          reuseExistingChunk: true,
        },
      },
    },
  },
};

Key configuration options include:

  • chunks: 'all': Inspects all modules regardless of whether they are statically or dynamically imported.
  • minChunks: Sets the minimum number of chunks that must share a module before it is extracted into a common file (default is 1 for vendors or 2 for common code).
  • reuseExistingChunk: true: Tells Webpack to reuse an existing chunk containing the module instead of generating a new one if the module has already been split.
  • priority: Determines which cache group takes precedence when a module matches multiple rules.

Addressing Version-Mismatched Duplicates

SplitChunksPlugin can only extract modules if Webpack resolves them to the exact same physical file path on disk. If different packages in your project depend on slightly different semantic versions of the same library (e.g., Package A requires lodash@^4.17.0 and Package B requires lodash@^4.16.0), package managers often install multiple copies inside nested node_modules folders.

Because their file paths differ, Webpack treats them as distinct modules and bundles both. To enforce deduplication when versions differ:

  1. Package Manager Deduplication: Run npm dedupe or yarn dedupe to flatten the dependency tree and point packages to a single shared version where compatible.
  2. Webpack Aliasing: Force all references to a library to resolve to a single installation using the resolve.alias setting:
// webpack.config.js
const path = require('path');

module.exports = {
  resolve: {
    alias: {
      lodash: path.resolve(__dirname, 'node_modules/lodash'),
    },
  },
};

This ensures that every package requiring lodash resolves to the identical root path, allowing SplitChunksPlugin to extract it into a single shared vendor chunk.
