Webpack publicPath and Dynamic Chunk 404 Errors

When using dynamic imports in Webpack for code-splitting, the output.publicPath configuration setting informs the Webpack runtime where to fetch your generated split chunks in the browser. Misconfiguring this setting causes the browser to build an incorrect URL for dynamic scripts—frequently resolving them relative to the current browser route instead of the asset root—which results in HTTP 404 Not Found errors when users navigate to nested application pages.

How Dynamic Chunk Loading Works

When you use dynamic imports (such as import('./module')), Webpack separates that module into an isolated chunk file (e.g., 1.bundle.js). Unlike initial bundles loaded directly via the main HTML file, dynamic chunks are fetched on demand at runtime.

When a dynamic import is triggered, Webpack’s runtime dynamically injects a <script> tag into the DOM. To determine the src attribute of this script, Webpack combines the output.publicPath setting with the asset filename:

Request URL = publicPath + chunkFilename

Why Misconfiguring publicPath Causes 404 Errors

The most common cause of 404 errors for dynamic chunks is using a relative publicPath (such as "", "./", or leaving it undefined) in a Single Page Application (SPA) with nested client-side routing.

If publicPath is relative, the browser evaluates the request relative to the current window location:

  1. Root URL (/): If a user is at https://example.com/ and triggers a chunk named admin.js, a relative path causes the browser to request https://example.com/admin.js. If your files are stored at the root, the file loads successfully.
  2. Nested URL (/users/settings): If a user navigates or refreshes directly to https://example.com/users/settings and triggers the same chunk, a relative path causes the browser to request https://example.com/users/settings/admin.js.

Because your asset files are not hosted inside the /users/settings/ directory on the server, the server responds with a 404 Not Found error (or returns the fallback index.html file, which leads to a "Uncaught SyntaxError: Unexpected token '<'" failure when the browser tries to parse HTML as JavaScript).

How to Fix the Error

To ensure dynamic chunks resolve correctly regardless of the browser's current route depth, configure publicPath as an absolute path or configure Webpack to infer it automatically.

1. Use an Absolute Path

Set publicPath to the root directory / or to the absolute subfolder where your build assets are served:

// webpack.config.js
module.exports = {
  output: {
    filename: '[name].bundle.js',
    chunkFilename: '[name].chunk.js',
    publicPath: '/', // Resolves assets relative to the domain root
  },
};

If your application is hosted under a subdirectory (for example, https://example.com/app/), ensure publicPath reflects that path:

publicPath: '/app/',

2. Use Automatic Public Path

In Webpack 5, you can set publicPath to 'auto'. This instructs Webpack to determine the correct path automatically by inspecting the current script's location (document.currentScript or import meta):

// webpack.config.js
module.exports = {
  output: {
    publicPath: 'auto',
  },
};

3. CDN Configurations

If assets are hosted on an external CDN, provide the full origin URL:

publicPath: 'https://cdn.example.com/assets/',

By ensuring that publicPath resolves to an absolute path, chunk requests will consistently point to the true location of your static assets regardless of how deeply nested the user's current URL is.
