How Webpack Dev Server Serves Static Files

Webpack Dev Server serves both dynamically compiled application bundles and physical static assets during local development. While compiled bundles reside in system memory for fast access, assets like static HTML pages, favicons, or standalone images are read directly from the filesystem. Depending on your version of webpack-dev-server, this behavior is controlled by either the modern static option (version 4 and above) or the legacy contentBase option (version 3 and earlier).

How Static Asset Resolution Works

When a request arrives at Webpack Dev Server, it follows an internal lookup sequence:

  1. In-Memory Assets: Webpack writes compiled bundles to virtual memory using an in-memory filesystem (such as memfs). The server first evaluates whether the incoming request path matches any compiled bundle located at the defined output.publicPath.
  2. Static Fallback: If the requested file is not in memory, the internal Express server forwards the request to underlying static file middleware (similar to express.static). The middleware searches the directory designated by static (or contentBase).
  3. Response or 404: If a physical file matching the path exists in that directory, it is served to the client. If not, the server either falls back via historyApiFallback (if enabled for single-page applications) or returns a 404 Not Found response.

Modern Configuration: The static Option (v4+)

Starting in webpack-dev-server v4, the contentBase option was deprecated and replaced with the static configuration block. The static option allows developers to specify where static files should be served from and how the server monitors them for changes.

Basic String Usage

To tell the server to serve files from a single physical directory:

const path = require('path');

module.exports = {
  // ...
  devServer: {
    static: path.join(__dirname, 'public'),
  },
};

Advanced Object Configuration

The static property accepts an object to fine-tune asset delivery:

const path = require('path');

module.exports = {
  // ...
  devServer: {
    static: {
      directory: path.join(__dirname, 'public'),
      publicPath: '/static-assets',
      serveIndex: true,
      watch: true,
    },
  },
};
  • directory: The absolute path to the directory containing static assets.
  • publicPath: The mount path or URL prefix from which static assets are served. In the example above, a file at public/logo.png would be accessed at http://localhost:8080/static-assets/logo.png.
  • serveIndex: Instructs the server to generate a directory listing if a requested path maps to a directory without an index.html.
  • watch: Tells the server to monitor the static directory for file modifications and trigger a browser reload when changes occur.

Multiple Directories

You can serve static files from multiple sources by supplying an array of strings or configuration objects:

devServer: {
  static: [
    path.join(__dirname, 'public'),
    path.join(__dirname, 'assets'),
  ],
}

To completely disable serving static files from disk, set the property to false:

devServer: {
  static: false,
}

Legacy Configuration: The contentBase Option (v3 and earlier)

In version 3 and earlier of webpack-dev-server, static file resolution was governed by contentBase. Although superseded by static, it handled requests in the same general manner.

Syntax

const path = require('path');

module.exports = {
  // ...
  devServer: {
    contentBase: path.join(__dirname, 'public'),
    contentBasePublicPath: '/serve-path',
    watchContentBase: true,
  },
};
  • contentBase: Accepted a path string, an array of paths, or a boolean (false disabled static serving).
  • contentBasePublicPath: Dictated the URL path where contentBase assets were mounted.
  • watchContentBase: When set to true, enabled file watching on the static directory to reload the page on updates.

Key Differences

Feature Legacy (contentBase) Modern (static)
Server Version webpack-dev-server ≤ v3 webpack-dev-server ≥ v4
Directory Watch Setting watchContentBase: true static: { watch: true }
URL Prefix Setting contentBasePublicPath: '/path' static: { publicPath: '/path' }
Structure Scattered root-level properties Consolidated configuration object
