Webpack 5 Asset Inlining with parser.dataUrlCondition

Webpack 5 introduced Asset Modules to replace legacy loaders like url-loader and file-loader, streamlining how static files are handled. By using the generic type: 'asset' module type, Webpack automatically toggles between inlining files as Base64 data URLs and emitting them as separate files. The parser.dataUrlCondition option is the specific configuration property used to override the default 8 KB threshold, giving developers precise control over the conditions under which an asset is embedded into the bundle or served as an external resource.

The Default Behavior of type: 'asset'

When a rule is configured with type: 'asset', Webpack applies a hybrid approach between asset/inline and asset/resource. By default, it applies a simple size check:

  • Files smaller than 8 KB (8192 bytes) are converted into Base64-encoded Data URLs and embedded directly into the generated JavaScript bundles.
  • Files equal to or larger than 8 KB are copied to the build output directory, and their resolved URLs are emitted instead.

Customizing the Threshold with maxSize

To alter the standard 8 KB cutoff, assign an object containing a maxSize property to parser.dataUrlCondition. The value represents the maximum file size in bytes for an asset to still be inlined.

module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|gif|svg)$/i,
        type: 'asset',
        parser: {
          dataUrlCondition: {
            maxSize: 4 * 1024 // 4 KB threshold
          }
        }
      }
    ]
  }
};

In this configuration, any matched image smaller than 4 KB will be converted into a data URI. Any image that is 4 KB or larger will be treated as an external file.

Advanced Decision-Making with a Custom Function

parser.dataUrlCondition also accepts a function instead of an object. This allows you to apply conditional logic that goes beyond a strict byte-size evaluation, taking into account file names, paths, or module metadata.

The function receives two arguments: the asset's binary source and a context object containing { filename, module }. It must return a boolean—true to inline the asset, or false to emit it as a separate resource.

module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|svg)$/i,
        type: 'asset',
        parser: {
          dataUrlCondition: (source, { filename }) => {
            // Always inline SVGs regardless of size, but apply an 8 KB limit to PNGs
            if (filename.endsWith('.svg')) {
              return true;
            }
            return source.length < 8 * 1024;
          }
        }
      }
    ]
  }
};

Performance Impact

Adjusting this condition allows you to balance HTTP request overhead against JavaScript bundle size. Inlining tiny assets reduces initial network round trips, which benefits latency-sensitive environments. Conversely, raising the threshold too high increases bundle parse and download times, while also preventing independent browser caching of static media.
