Webpack NormalModuleFactory and Module Creation Hooks

Webpack's NormalModuleFactory is the core engine component responsible for turning raw dependency requests into fully realized module instances. This article covers the role of NormalModuleFactory within the Webpack compilation lifecycle, breaks down its key execution stages, and demonstrates how custom plugins can tap into its Tapable hooks to intercept, modify, or halt module generation.

What is NormalModuleFactory?

In Webpack, every import or require statement represents a dependency. The compiler does not handle the translation of these file paths into module objects directly; instead, it delegates this task to module factories. For standard application code—such as JavaScript, TypeScript, CSS, and asset files—Webpack uses NormalModuleFactory.

The primary responsibility of NormalModuleFactory is to:

  1. Accept raw dependency data (path, context, import type).
  2. Resolve the request against file system rules and configured aliases.
  3. Determine and apply applicable loaders.
  4. Instantiate a NormalModule object that contains the resolved resource path, associated loaders, and parser configurations.

The Module Creation Lifecycle

The module creation process in NormalModuleFactory follows a sequential pipeline governed by Tapable hooks:

  1. factorize: The starting point of module creation. It receives the dependency request parameters and initiates the resolution chain.
  2. resolve: Webpack looks up the module using the enhanced resolver. It determines the absolute file path and identifies any loaders that must run against the file.
  3. afterResolve: Triggered immediately after the file path and loaders are established, but before the module is constructed. This hook contains the final module creation data.
  4. createModule: The factory creates the actual NormalModule instance using the resolved data.
  5. module: The module object is created and ready to be processed by Webpack's parser and dependency graph builder.

Accessing NormalModuleFactory in Plugins

To interact with NormalModuleFactory, a plugin must first intercept the Webpack Compiler or Compilation object. Webpack provides a dedicated compiler hook named normalModuleFactory:

class ModuleModifierPlugin {
  apply(compiler) {
    compiler.hooks.normalModuleFactory.tap(
      'ModuleModifierPlugin',
      (normalModuleFactory) => {
        // Tap into NormalModuleFactory hooks here
      }
    );
  }
}

module.exports = ModuleModifierPlugin;

Key Hooks for Intercepting Module Creation

1. beforeResolve

Runs before the resolver starts searching the filesystem. Plugins use this hook to rewrite request strings, modify query parameters, or ignore certain paths.

normalModuleFactory.hooks.beforeResolve.tap(
  'ModuleModifierPlugin',
  (resolveData) => {
    // Redirect an import to a different path
    if (resolveData.request === './legacy-code') {
      resolveData.request = './modern-code';
    }
  }
);

2. afterResolve

Fires after Webpack identifies the exact file location and matches all loaders from module.rules. It is ideal for inspecting matched loaders or injecting custom loaders dynamically.

normalModuleFactory.hooks.afterResolve.tap(
  'ModuleModifierPlugin',
  (resolveData) => {
    const resource = resolveData.createData.resource;

    // Dynamically inject a loader for specific files
    if (resource.endsWith('.special.js')) {
      resolveData.createData.loaders.push({
        loader: require.resolve('special-loader'),
        options: {},
      });
    }
  }
);

3. createModule

Executes when Webpack is about to instantiate the NormalModule. Tapping here allows developers to substitute the default module constructor with a custom module subclass.

normalModuleFactory.hooks.createModule.tap(
  'ModuleModifierPlugin',
  (createData, resolveData) => {
    // Modify createData attributes directly before instantiation
    createData.userRequest = createData.userRequest + '?customFlag=true';
  }
);

4. module

Invoked immediately after the NormalModule instance is created. This allows direct modification of the module instance properties, such as setting build metadata or adjusting build criteria.

normalModuleFactory.hooks.module.tap(
  'ModuleModifierPlugin',
  (module, createData, resolveData) => {
    // Access and manipulate the created NormalModule instance
    module.buildInfo.customProperty = 'injected-value';
  }
);

Summary

NormalModuleFactory translates module requests into compiled AST-ready modules. By tapping into compiler.hooks.normalModuleFactory, plugins gain fine-grained control over resolution behavior, loader matching, and the instantiation of NormalModule instances within the build pipeline.
