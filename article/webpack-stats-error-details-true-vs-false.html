Webpack stats errorDetails: True vs False

When troubleshooting compilation failures in Webpack, the stats.errorDetails configuration controls the verbosity of error diagnostics emitted in the terminal or build logs. Setting this option to true exposes exhaustive stack traces and the step-by-step module resolution process, while setting it to false suppresses this extra output to keep build logs concise. Understanding the operational difference between these two settings is critical for pinpointing elusive bundling errors without overwhelming your terminal during standard development.

What is stats.errorDetails?

In Webpack, the stats object governs which build statistics are displayed after a compilation run. The errorDetails property specifically targets error output, deciding whether to append detailed diagnostic information to high-level error summaries.

stats.errorDetails: false

Setting stats.errorDetails: false restricts Webpack to displaying only high-level summary messages when a build fails.

  • Output Style: Short, single-sentence or single-paragraph messages (e.g., Module not found: Error: Can't resolve './missing-file' in '/path/to/project').
  • Hidden Information: Suppresses internal Webpack stack traces, detailed plugin error context, and the filesystem steps traversed by Webpack's resolver engine.
  • Best Used For: Standard local development and clean CI/CD production pipelines where standard error messages provide sufficient context to fix simple syntax or missing file errors.

stats.errorDetails: true

Setting stats.errorDetails: true instructs Webpack to log every piece of contextual data available for any encountered error.

  • Output Style: Highly verbose output containing internal module resolution steps, file-system lookups, and complete call stacks.
  • Key Diagnostic Information Provided:
    • Module Resolution Tracing: When a Module not found error occurs, Webpack displays every directory, file extension, and package.json entry point it inspected while attempting to locate the file.
    • Loader Context: Pinpoints precisely which loader failed and the exact arguments passed to it.
    • Inner Error Stacks: Surfaces nested exceptions originating from third-party plugins or custom loaders.
  • Best Used For: Debugging complex dependency resolution issues, diagnosing symlink or monorepo import failures, and troubleshooting custom loader or plugin integrations.

Key Differences at a Glance

Feature stats.errorDetails: false stats.errorDetails: true
Log Volume Minimal, human-readable Extensive, highly technical
Resolver Paths Hidden Fully printed (shows every failed lookup)
Stack Traces Webpack runtime traces hidden Full internal stack traces exposed
Primary Use Case Daily development workflow Deep diagnostic troubleshooting

Configuration Example

To enable or disable this feature, modify the stats object in your webpack.config.js:

module.exports = {
  // ... other configuration options
  stats: {
    errorDetails: true // Set to false to reduce output verbosity
  }
};

Alternatively, Webpack 5 supports 'auto', which acts as true when errors are present in standard configurations, but setting the value explicitly to true or false gives you deterministic control over your debugging logs.
