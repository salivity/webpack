Webpack 5 Asset/Resource: Replacing file-loader

Webpack 5 introduced Asset Modules, a built-in mechanism that allows developers to process assets such as images, fonts, and icons without installing additional loaders. This article explains what the asset/resource type is, why it was introduced to replace the legacy file-loader, and how to update your build configuration to take advantage of this modern feature.

What is asset/resource in Webpack 5?

In Webpack 4 and earlier, handling static assets like .png, .svg, or .woff files required installing external packages, primarily file-loader and url-loader.

Webpack 5 replaces these external dependencies with native Asset Modules. The asset/resource type emits a separate file into the output directory and exports its public URL. This behavior is functionally identical to what file-loader previously provided, but it is built directly into Webpack's core runtime.

Why asset/resource Replaces file-loader

  1. Zero External Dependencies: You no longer need to install file-loader via npm or maintain it in your package.json.
  2. Improved Performance: Because asset processing is handled internally by Webpack's compiler rather than through the loader pipeline, build performance is faster and consumes less memory.
  3. Deprecation of Legacy Loaders: As of Webpack 5, file-loader, raw-loader, and url-loader are officially deprecated. Using them in modern setups can lead to duplicate asset emissions unless explicitly configured with esModule: false and type: 'javascript/auto'.

Configuration Comparison

Migrating from file-loader to asset/resource requires only a small update in your webpack.config.js.

The Legacy Approach (Webpack 4 / file-loader)

module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|gif|svg|woff2?)$/i,
        use: [
          {
            loader: 'file-loader',
            options: {
              name: '[name].[contenthash][ext]',
              outputPath: 'assets/',
            },
          },
        ],
      },
    ],
  },
};

The Modern Approach (Webpack 5 / asset/resource)

Replace the use array with the type property set to 'asset/resource':

module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|gif|svg|woff2?)$/i,
        type: 'asset/resource',
      },
    ],
  },
};

Customizing Output Paths and Filenames

With file-loader, output paths and filename templates were configured via loader options. With asset/resource, you have two straightforward alternatives:

1. Globally via output.assetModuleFilename

To apply a default naming pattern for all asset modules, configure it in the output block:

const path = require('path');

module.exports = {
  output: {
    path: path.resolve(__dirname, 'dist'),
    assetModuleFilename: 'assets/[name].[contenthash][ext]',
    clean: true,
  },
};

2. Per-Rule via the generator Property

If you need different paths for different asset types (e.g., images vs. fonts), define a generator directly in the rule:

module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|gif|svg)$/i,
        type: 'asset/resource',
        generator: {
          filename: 'images/[name].[contenthash][ext]',
        },
      },
      {
        test: /\.(woff|woff2|eot|ttf|otf)$/i,
        type: 'asset/resource',
        generator: {
          filename: 'fonts/[name].[contenthash][ext]',
        },
      },
    ],
  },
};

Note that Webpack 5 automatically includes the dot before the extension in the [ext] template variable (e.g., .png), eliminating the need to write .[ext].
