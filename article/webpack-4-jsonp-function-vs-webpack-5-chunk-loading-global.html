Webpack 4 jsonpFunction vs Webpack 5 chunkLoadingGlobal

When running multiple Webpack applications on the same webpage, configuring unique chunk-loading namespaces prevents global runtime collisions. Webpack 4 relied on output.jsonpFunction to define the global array used for asynchronous chunk loading, whereas Webpack 5 replaced this setting with output.chunkLoadingGlobal to support diverse transport protocols beyond JSONP. This guide explains how both options work, how to configure them, and the architectural differences between Webpack 4 and 5.

Webpack 4: Using output.jsonpFunction

In Webpack 4, asynchronous bundle loading defaults to JSONP via a global function attached to the window object named webpackJsonp. When multiple independently built Webpack applications or micro-frontends share the same browser environment, using the default name causes collision issues where chunks from one application are intercepted by another.

To prevent this collision, define a custom string for output.jsonpFunction in your webpack.config.js:

// webpack.config.js (Webpack 4)
const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].bundle.js',
    chunkFilename: '[name].chunk.js',
    jsonpFunction: 'webpackJsonp_myUniqueApp'
  }
};

Setting jsonpFunction renames the global variable from window.webpackJsonp to window.webpackJsonp_myUniqueApp.

Webpack 5: Using output.chunkLoadingGlobal

Webpack 5 supports various chunk-loading methods, including ES modules, Fetch, Node.js require, and Web Worker importScripts, making the "JSONP" terminology obsolete. As a result, output.jsonpFunction was deprecated and renamed to output.chunkLoadingGlobal.

To configure this in Webpack 5, update your webpack.config.js:

// webpack.config.js (Webpack 5)
const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].bundle.js',
    chunkFilename: '[name].chunk.js',
    chunkLoadingGlobal: 'webpackChunk_myUniqueApp'
  }
};

This assigns chunk registration to window.webpackChunk_myUniqueApp instead of the default window.webpackChunk.

Migration and output.uniqueName

In Webpack 5, manually setting output.chunkLoadingGlobal is often unnecessary due to the introduction of output.uniqueName.

Webpack 5 uses output.uniqueName to compute a unique namespace for chunkLoadingGlobal automatically. By default, it derives this value from your project's package.json name field:

// webpack.config.js (Webpack 5 recommended approach)
module.exports = {
  output: {
    uniqueName: 'myUniqueApp'
  }
};

Setting output.uniqueName automatically namespaces both chunkLoadingGlobal and other runtime globals such as script containers and Module Federation remotes, eliminating the need to set chunkLoadingGlobal explicitly in most micro-frontend setups.
