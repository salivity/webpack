How to Bundle Audio and Video with Webpack

Webpack handles audio and video formats like MP3, OGG, and MP4 by managing asset paths, emitting files to the distribution directory, and providing valid URLs directly inside your JavaScript code. Rather than compiling or transcoding binary media files, Webpack integrates them into the dependency graph so they can be imported and consumed by HTML elements like <audio> and <video>. This guide covers how Webpack processes these formats using modern Webpack 5 Asset Modules, how the underlying build process works, and best practices for media assets.

Using Webpack 5 Asset Modules

Prior to Webpack 5, bundling binary assets required third-party loaders such as file-loader or url-loader. Webpack 5 introduced native Asset Modules, eliminating the need for extra dependencies.

To bundle media files, use the asset/resource module type. This emits the media file into your output folder and exports the asset's URL into your JavaScript bundle.

Webpack Configuration Example

Add a rule to your webpack.config.js inside the module.rules array:

const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
  module: {
    rules: [
      {
        test: /\.(mp4|webm|ogg|mp3|wav|flac|aac)$/i,
        type: 'asset/resource',
        generator: {
          filename: 'media/[name].[contenthash][ext]',
        },
      },
    ],
  },
};
  • test: A regular expression identifying audio and video file extensions.
  • type: 'asset/resource': Directs Webpack to emit separate physical files and return their final paths.
  • generator.filename: Specifies the output directory (dist/media/) and attaches a content hash to the filename for effective cache-busting.

How the Bundling Process Works

When Webpack builds your application, it processes media files through three main steps:

  1. Resolution: When Webpack encounters an import or require statement for a media file (for example, import sampleAudio from './sounds/sound.mp3'), it matches the file against your configured test regex.
  2. File Emission: Webpack copies the raw binary file directly to the build destination directory (dist/media/) without modifying the internal audio/video data.
  3. URL Export: Webpack generates a module that exports the public URL string representing where the file will reside on the server.

Usage in Application Code

Because the import yields a path string, you can assign it directly to media elements in JavaScript:

import oceanWaves from './media/waves.mp3';
import introVideo from './media/intro.mp4';

// Using Audio in JavaScript
const audio = new Audio(oceanWaves);
audio.play();

// Attaching to a Video element in the DOM
const videoElement = document.createElement('video');
videoElement.src = introVideo;
videoElement.controls = true;
document.body.appendChild(videoElement);

Legacy Approach: Webpack 4 and file-loader

In Webpack 4 and older setups, file-loader performs the same task:

module.exports = {
  module: {
    rules: [
      {
        test: /\.(mp4|ogg|mp3)$/i,
        use: [
          {
            loader: 'file-loader',
            options: {
              name: '[name].[hash].[ext]',
              outputPath: 'media/',
            },
          },
        ],
      },
    ],
  },
};

Important Considerations for Media Bundling

  • File Size and Inlining: Avoid using asset/inline (base64 strings) for video and high-resolution audio. Inlining increases file size by roughly 33%, inflates JavaScript parsing time, and prevents browsers from leveraging byte-range requests for streaming.
  • No Transcoding: Webpack does not transcode, compress, or convert media formats (e.g., converting WAV to MP3). Optimize and compress all media files before placing them in your source directory.
  • Streaming Media: For long-form video or adaptive bitrate streaming (HLS or MPEG-DASH), host segmented files (.m3u8, .ts, .mpd) on a dedicated Content Delivery Network (CDN) or media server rather than bundling them through Webpack.
