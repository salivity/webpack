Webpack ES5 Target: Fix Arrow Functions and Const

Webpack 5 generates modern ECMAScript 6+ syntax, such as arrow functions and const declarations, inside its runtime boilerplate by default. Even when loaders like Babel transpile your application code, this runtime wrapper code can break legacy environments like Internet Explorer 11. Configuring target: ['web', 'es5'] resolves this issue by instructing Webpack's internal template generators to fall back to ES5-compliant primitives, replacing arrow functions with regular function expressions and const declarations with var.

The Cause: Transpilers vs. Webpack Runtime

Loaders such as babel-loader or ts-loader only transpile the modules defined in your application's source code. They do not process the runtime glue code that Webpack injects to manage module loading, chunk resolution, and scoping.

In Webpack 5, the build engine assumes modern browser environments by default to produce smaller and faster runtime bundles. Consequently, the runtime templates use:

  • Arrow functions: () => { ... }
  • Block-scoped variable declarations: const and let
  • Shorthand object notation and destructuring

When targeting older browsers, these constructs result in immediate SyntaxError exceptions before any application code executes.

How target: ['web', 'es5'] Fixes the Output

Setting target: ['web', 'es5'] provides Webpack with explicit instructions about both the platform (web) and the ECMAScript specification limit (es5).

Webpack uses this target array to configure its internal output.environment options automatically. The output.environment object contains a set of boolean flags that dictate what features the runtime generator is allowed to emit:

  • arrowFunction: Controls whether arrow functions can be generated.
  • const: Controls whether const and let can be generated.
  • destructuring: Controls destructuring assignment generation.
  • forOf: Controls for...of loop generation.
  • dynamicImport: Controls modern dynamic import() emission.

When es5 is passed in the target array, Webpack sets these environment flags to false.

The Resulting Runtime Transformation

With the es5 target active, Webpack swaps its modern code generation templates for legacy-compatible alternatives:

  1. Arrow Functions to Standard Functions: Webpack replaces (() => { ... })() wrappers and helper callbacks with standard (function() { ... })().
  2. const and let to var: Runtime variable assignments that store module caches, chunk manifests, and export definitions are declared strictly using var.

Configuration

To apply this behavior, update your webpack.config.js:

module.exports = {
  target: ['web', 'es5'],
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: __dirname + '/dist',
  },
  // Loaders and plugins follow...
};

Alternatively, you can manually define output.environment if you only need to restrict specific syntax features while keeping a single string target:

module.exports = {
  target: 'web',
  output: {
    environment: {
      arrowFunction: false,
      const: false,
    },
  },
};

Using target: ['web', 'es5'] is the recommended shorthand, as it ensures all runtime output flags simultaneously adhere to the ES5 standard.
