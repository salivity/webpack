How to Bundle WebAssembly with Webpack

This article explains how to bundle native WebAssembly (Wasm) modules using Webpack. Starting with Webpack 5, native WebAssembly support is integrated directly into the core bundler via experimental flags. Below, you will learn how to configure Webpack to recognize and process .wasm files, import them into your JavaScript code, and execute them efficiently in a web environment.

Enabling WebAssembly in Webpack 5

Webpack 5 supports WebAssembly natively, but the feature is disabled by default. To enable it, you must configure the experiments option in your webpack.config.js file:

// webpack.config.js
module.exports = {
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: __dirname + '/dist',
  },
  experiments: {
    asyncWebAssembly: true,
  },
  mode: 'development',
};

The asyncWebAssembly flag allows you to import WebAssembly modules asynchronously, which is aligned with the WebAssembly Web API specifications. An older flag, syncWebAssembly, exists for legacy Webpack 4 behavior, but it is deprecated and not recommended for modern implementations.

Importing Wasm Modules in JavaScript

With asyncWebAssembly enabled, Webpack treats .wasm files as standard ECMAScript modules. You can load and use them directly in your JavaScript files using standard import syntax.

Using Dynamic Imports (Recommended)

Dynamic imports ensure that the WebAssembly binary is fetched and instantiated asynchronously without blocking the initial execution of your JavaScript bundle:

// src/index.js
async function run() {
  const { add } = await import('./math.wasm');
  console.log(`2 + 3 = ${add(2, 3)}`);
}

run();

Using Static Imports

You can also use top-level static imports, provided your target environment supports Top-Level Await or Webpack is configured to handle it via experiments.topLevelAwait:

// src/index.js
import { add } from './math.wasm';

console.log(add(5, 7));

Loading Native Modules from Rust or C/C++

When compiling native languages like Rust or C/C++ into WebAssembly, your toolchain (such as wasm-pack or Emscripten) typically generates two artifacts: a .wasm binary and a JavaScript "glue" file.

  1. Rust (wasm-pack): Use the --target bundler option when building with wasm-pack. This generates an ES module wrapper and imports the .wasm file directly, allowing Webpack to handle both files automatically.
  2. C/C++ (Emscripten): Compile with -s MODULARIZE=1 -s EXPORT_ES6=1. Import the generated JavaScript wrapper inside your application rather than the .wasm binary directly, as the wrapper manages memory initialization and native imports.

Web Server Configuration for Production

When Webpack bundles your application for production, it emits the .wasm binary as an asset in the output directory. To ensure the browser compiles the module via WebAssembly.instantiateStreaming, your production web server must serve .wasm files with the correct MIME type:

Content-Type: application/wasm

Without this header, browsers will fall back to slower array-buffer decoding instead of streaming compilation.
