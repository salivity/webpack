How to Set Minimum Chunk Size in Webpack

Code splitting is an essential performance optimization in modern web development, but overly aggressive splitting can lead to micro-chunk proliferation—a scenario where dozens of tiny JavaScript files create unnecessary HTTP request overhead and reduce compression efficiency. This guide explains how to prevent this issue by leveraging Webpack’s built-in SplitChunksPlugin configuration. You will learn how to enforce minimum size thresholds globally, configure cache groups, and balance file count against byte size to achieve optimal application delivery.

Understanding the Problem of Micro-Chunks

When dynamic imports (import()) or automatic vendor splitting are implemented without constraints, Webpack often generates chunks that are only a few hundred bytes or a couple of kilobytes in size. While HTTP/2 and HTTP/3 handle concurrent streams better than HTTP/1.1, managing dozens of tiny requests still introduces browser latency, TLS overhead, and diminished gzip or Brotli compression ratios.

To solve this, Webpack allows you to set a lower bound for chunk creation. If an extracted module does not meet the specified size threshold, Webpack merges it back into the parent chunk or bundles it with other modules.

Configuring minSize Globally

The primary mechanism for restricting chunk creation is the minSize property under optimization.splitChunks. This setting specifies the minimum size, in bytes, that a chunk must reach before it is generated.

Add the following configuration to your webpack.config.js:

module.exports = {
  // ... other webpack settings
  optimization: {
    splitChunks: {
      // Apply size thresholds to both initial and async chunks
      chunks: 'all',
      // Minimum chunk size in bytes (e.g., 20 KB)
      minSize: 20000,
    },
  },
};

In this setup:

  • chunks: 'all' ensures that the size enforcement applies to both statically imported shared dependencies and dynamically imported asynchronous bundles.
  • minSize: 20000 tells Webpack to avoid creating any separate chunk smaller than 20 KB. Any dependency that fails this check will remain inside its requesting entry point or parent chunk.

Setting Minimum Sizes per Cache Group

You can define granular thresholds depending on the type of code being bundled. For instance, you might accept smaller sizes for third-party vendor code to improve long-term browser caching, while requiring larger chunks for internal application code.

module.exports = {
  optimization: {
    splitChunks: {
      chunks: 'all',
      minSize: 20000, // Default for internal modules
      cacheGroups: {
        defaultVendors: {
          test: /[\\/]node_modules[\\/]/,
          priority: -10,
          reuseExistingChunk: true,
          // Stricter minimum size specifically for third-party libraries
          minSize: 30000, 
        },
        default: {
          minChunks: 2,
          priority: -20,
          reuseExistingChunk: true,
          // Common internal code threshold
          minSize: 15000,
        },
      },
    },
  },
};

Preventing Inefficient Splits with minSizeReduction

Webpack 5 introduced minSizeReduction, which provides an additional safeguard against unproductive code splitting. This property specifies the minimum byte reduction that must be achieved in the main bundle to justify creating a new chunk.

module.exports = {
  optimization: {
    splitChunks: {
      minSize: 20000,
      minSizeReduction: 10000, // Must reduce parent bundle size by at least 10 KB
    },
  },
};

Even if a module exceeds minSize, Webpack will skip splitting if the overhead of extracting it does not result in a significant size decrease for the remaining code.

Limiting Total Requests

Setting a minimum chunk size works best when paired with concurrency constraints. If you combine minSize with request limit properties, you ensure that the browser is never flooded with requests regardless of bundle size:

  • maxAsyncRequests: Limits the maximum number of parallel requests when loading chunks on demand (default is 30 in Webpack 5).
  • maxInitialRequests: Limits the maximum number of parallel requests for entry points (default is 30 in Webpack 5).
module.exports = {
  optimization: {
    splitChunks: {
      chunks: 'all',
      minSize: 20000,
      maxAsyncRequests: 10,
      maxInitialRequests: 6,
    },
  },
};

If generating a chunk would exceed these limits, Webpack ignores the split condition and folds the code into larger bundles, preventing request thrashing on resource-constrained devices.
