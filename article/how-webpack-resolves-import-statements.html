How Webpack Resolves Import Statements

When Webpack encounters an import statement in source code, it initiates a module resolution process powered by its internal resolver library, enhanced-resolve. This mechanism converts abstract path specifiers into concrete, absolute file paths on the file system, taking into account path types, file extensions, directory package manifests, and custom configuration rules.

1. Determining the Path Type

Webpack first identifies the format of the import string. Import paths fall into three distinct categories:

  • Absolute Paths: Paths starting with / (e.g., import util from '/src/util'). Webpack treats these as already pointing to an exact system location and skips relative path computations.
  • Relative Paths: Paths starting with ./ or ../ (e.g., import helper from './helper'). The resolver calculates the absolute path by appending this specifier to the directory of the file containing the import statement.
  • Module Paths: Non-relative identifiers (e.g., import React from 'react'). Webpack searches for these modules inside directories specified by the resolve.modules configuration option, which defaults to ['node_modules']. It starts in the current directory and walks up the directory tree until it locates a matching folder or reaches the file system root.

2. Resolving Aliases

Before checking the disk, Webpack checks the path against the resolve.alias configuration. If a module path begins with an alias key (such as @components), Webpack substitutes that alias with its mapped absolute path before continuing the resolution pipeline.

3. File Resolution

Once a target path is established, Webpack checks whether the target points directly to a file:

  • Exact Match: If the path includes an extension and points to an existing file, resolution succeeds.
  • Missing Extensions: If no extension is specified, Webpack systematically appends extensions from the resolve.extensions array (defaulting to ['.js', '.json', '.wasm']) in order until an existing file is found.

4. Directory Resolution

If the resolved path points to a directory rather than a file, Webpack resolves it through the following steps:

  1. Check package.json: If the directory contains a package.json, Webpack reads the field matching the resolve.mainFields configuration (commonly browser, module, or main depending on the build target) or uses modern package.json exports maps.
  2. Fallback to Index Files: If no package.json exists or the specified entry file is missing, Webpack checks for filenames defined in resolve.mainFiles (defaulting to ['index']), trying each extension in resolve.extensions (such as index.js).

5. Final Processing and Bundling

Once the absolute file path is determined, Webpack checks its module.rules to match the file path against configured loaders (such as babel-loader or ts-loader). The file is then read, parsed into an Abstract Syntax Tree (AST) to discover downstream dependencies, and added to the dependency graph.
