webpackPrefetch vs webpackPreload Execution Differences

Webpack provides two resource hints via magic comments—webpackPrefetch and webpackPreload—to optimize how dynamic imports are loaded by the browser. While both mechanisms instruct the browser to fetch JavaScript chunks in advance, they differ significantly in their execution timing, loading priority, and intended use cases. Understanding these differences ensures your application prioritizes critical resources without congesting network bandwidth.

How webpackPrefetch Works

When you declare /* webpackPrefetch: true */, Webpack injects a <link rel="prefetch" as="script" href="chunk.js"> tag into the document head.

  • Timing: The browser requests the chunk during idle time, after the initial page has finished loading its critical assets.
  • Priority: Lowest network priority. The browser intentionally delays fetching until bandwidth becomes available.
  • Use Case: Resources that might be needed in future navigations or subsequent user actions (e.g., a modal that opens on a button click, or the next route in a multi-step form).
// Prefetched in the background during idle time
button.addEventListener('click', () => {
  import(/* webpackPrefetch: true */ './HeavyModalComponent.js')
    .then(({ default: HeavyModal }) => {
      // Render modal
    });
});

How webpackPreload Works

When you declare /* webpackPreload: true */, Webpack injects a <link rel="preload" as="script" href="chunk.js"> tag into the document head.

  • Timing: The chunk begins downloading immediately in parallel with the parent chunk, without waiting for the browser to become idle.
  • Priority: Medium-to-high network priority, similar to critical resources needed for the current view.
  • Use Case: Code split from the main bundle that is required for the current navigation or immediately after the parent chunk executes.
// Preloaded immediately alongside the current chunk
import(/* webpackPreload: true */ './CriticalChartRenderer.js')
  .then(({ default: ChartRenderer }) => {
    // Render chart immediately
  });

Key Differences in Execution

Feature webpackPrefetch webpackPreload
HTML Tag <link rel="prefetch"> <link rel="preload">
Loading Phase Browser idle time (future navigation) In parallel with parent (current navigation)
Network Priority Lowest / Idle Medium / High
Parent Chunk Lifecycle Independent of parent loading Starts execution alongside parent loading
Browser Warning None if left unused Emits console warning if not used within a few seconds

Choosing Between the Two

Use webpackPreload sparingly. Because it contends for bandwidth with other critical resources on the initial load, overuse can degrade your page's Time to Interactive (TTI) and First Contentful Paint (FCP). It should be reserved for chunks that are split out for caching purposes but are strictly necessary for rendering the current view.

Use webpackPrefetch for speculative loading. It is safe for performance because it yields entirely to critical network traffic, making it the ideal choice for secondary UI states, conditional components, and adjacent routes.
