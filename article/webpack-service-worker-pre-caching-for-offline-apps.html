Webpack Service Worker Pre-Caching for Offline Apps

Building an offline-first web application requires intercepting network requests and serving cached assets when connectivity is lost. This article demonstrates how to configure Webpack with Google’s Workbox plugin to automatically pre-cache static assets during the build process. By following this guide, you will learn how to install the required plugins, update your Webpack configuration, and register the service worker within your client-side application code.

1. Install the Workbox Webpack Plugin

The recommended tool for integrating service worker pre-caching into Webpack is workbox-webpack-plugin. Install it as a development dependency using npm:

npm install workbox-webpack-plugin --save-dev

2. Configure Webpack

The plugin provides two primary modes: GenerateSW and InjectManifest. For standard pre-caching without custom service worker code, GenerateSW is the simplest and most effective option. It automatically creates a service worker file and generates a pre-cache manifest containing your Webpack build outputs.

Open your webpack.config.js and add the plugin:

const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');
const WorkboxPlugin = require('workbox-webpack-plugin');

module.exports = {
  entry: './src/index.js',
  output: {
    filename: '[name].[contenthash].js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/index.html',
    }),
    new WorkboxPlugin.GenerateSW({
      // Forces waiting service workers to become active immediately
      clientsClaim: true,
      skipWaiting: true,
      // Name of the output service worker file
      swDest: 'service-worker.js',
    }),
  ],
};

When Webpack runs in production mode, GenerateSW analyzes all compiled bundles (JavaScript, CSS, images) and embeds their URLs along with content hashes into service-worker.js.

3. Register the Service Worker in Your Application

A generated service worker will not run until it is explicitly registered by the client. Add registration logic to your application's entry point (such as src/index.js):

if ('serviceWorker' in navigator && process.env.NODE_ENV === 'production') {
  window.addEventListener('load', () => {
    navigator.serviceWorker
      .register('/service-worker.js')
      .then((registration) => {
        console.log('Service Worker registered: ', registration);
      })
      .catch((registrationError) => {
        console.error('Service Worker registration failed: ', registrationError);
      });
  });
}

Registering on the window load event prevents the service worker registration process from contending with the initial page rendering performance.

4. Customizing Pre-Caching Limits and Exclusions

By default, Workbox ignores files larger than 2 MB. You can adjust limits or filter specific file formats using configuration flags in GenerateSW:

new WorkboxPlugin.GenerateSW({
  clientsClaim: true,
  skipWaiting: true,
  swDest: 'service-worker.js',
  // Exclude map files or specific vendor files
  exclude: [/\.map$/, /manifest\.json$/],
  // Increase file size limit to 4MB if needed
  maximumFileSizeToCacheInBytes: 4 * 1024 * 1024,
})

5. Testing the Offline Functionality

  1. Build your project using npx webpack --mode production.
  2. Serve the generated dist directory using a local web server (e.g., npx serve dist). Note that service workers require HTTPS or localhost.
  3. Open your browser's Developer Tools and navigate to the Application tab.
  4. Under Service Workers, verify that service-worker.js is installed and running.
  5. Check the Cache Storage tab to confirm that your compiled assets appear in the pre-cache list.
  6. Check the Offline checkbox in Developer Tools and reload the page; the application should load successfully without an active network connection.
