Understanding Webpack External Types: Var, Window, Script

Webpack's externals configuration provides a way of excluding specific dependencies from the output bundle, delegating their resolution to the host environment at runtime. By configuring external types, developers can specify precisely how the application accesses these external resources—whether from the global scope, the browser's window object, or via dynamically injected script tags. This guide explores the core Webpack external types—var, window, and script—highlighting their behavior, configuration syntax, and optimal use cases.

What Are Webpack External Types?

When you declare a module as external, Webpack must generate code to access that module at runtime. The externalsType property (or setting the type directly in the externals mapping) determines the JavaScript syntax Webpack uses to retrieve the dependency.

By default, Webpack defaults to the var type in standard web targets, but different deployment environments and loading strategies often require explicit control over how globals are referenced.

1. The var External Type

The var type treats the external dependency as a globally scoped variable accessible directly by name.

How It Works

When a module is imported, Webpack emits code that reads the specified variable name directly from the execution scope:

// Webpack output equivalent
const externalLibrary = GlobalLibraryName;

Configuration Example

module.exports = {
  // Global externalsType setting
  externalsType: 'var',
  externals: {
    lodash: '_',
    jquery: 'jQuery',
  },
};

You can also specify it on a per-dependency basis:

module.exports = {
  externals: {
    lodash: 'var _',
  },
};

When to Use

  • Standard web setups where third-party scripts (like jQuery or Lodash) are preloaded via static <script> tags in index.html.
  • Node.js or agnostic environments where global variables exist without a browser-specific window object.

2. The window External Type

The window external type explicitly accesses dependencies as properties of the global browser window object (window['variableName']).

How It Works

Instead of referencing a variable directly, Webpack attaches the lookup directly to window:

// Webpack output equivalent
const externalLibrary = window['GlobalLibraryName'];

Configuration Example

module.exports = {
  externalsType: 'window',
  externals: {
    react: 'React',
    'react-dom': 'ReactDOM',
  },
};

Or scoped individually:

module.exports = {
  externals: {
    react: 'window React',
  },
};

When to Use

  • Browser-only applications that strictly define shared vendor libraries on the global window object.
  • Scenarios with strict scoping rules or linters that flag undeclared variable names, ensuring all external lookups explicitly target window.

3. The script External Type

Introduced in Webpack 5, the script external type goes beyond static variable resolution by dynamically loading the dependency at runtime before your code executes.

How It Works

Instead of assuming the external library is already available, Webpack creates and injects a <script src="..."> tag into the DOM when the dependent chunk is requested. It waits for the script to download, resolves the resulting global variable, and hands it over to your module.

Configuration Example

The value of a script external must specify both the script URL and the global variable it creates:

module.exports = {
  externals: {
    lodash: 'script https://cdn.jsdelivr.net/npm/lodash@4.17.21/lodash.min.js _',
  },
};

Alternatively, you can define it using an object with script as the external type:

module.exports = {
  externalsType: 'script',
  externals: {
    lodash: ['https://cdn.jsdelivr.net/npm/lodash@4.17.21/lodash.min.js', '_'],
  },
};

When to Use

  • Dynamically loading CDN resources only when the chunk requiring them is loaded.
  • Micro-frontends and Module Federation architectures that load remote entry points on demand.
  • Reducing initial HTML payload size by avoiding long lists of preloaded <script> tags.

Summary Comparison

External Type Mechanism Execution Requirement Target Environment
var References variable directly (foo) Library must be loaded before runtime Universal (Browser/Node)
window References window['foo'] Library must be attached to window Browser only
script Injects <script> and reads global Dynamically loaded on demand Browser only (Webpack 5+)
