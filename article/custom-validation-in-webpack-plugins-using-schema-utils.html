Custom Validation in Webpack Plugins Using schema-utils

Configuring Webpack plugins correctly requires robust validation to catch user errors before the build process begins. This article demonstrates how to define a JSON Schema and apply it within a custom Webpack plugin using the official schema-utils package, ensuring your plugin provides clear, informative error messages whenever invalid options are passed.

1. Install schema-utils

To get started, install schema-utils as a dependency in your project or plugin repository:

npm install schema-utils

2. Define the JSON Schema

Webpack relies on JSON Schema (Draft-07) to validate options. Create a schema definition that outlines your plugin's accepted options, expected data types, and whether unexpected properties are allowed.

Save this as schema.json:

{
  "type": "object",
  "properties": {
    "name": {
      "type": "string",
      "description": "The name used in output artifacts."
    },
    "enabled": {
      "type": "boolean",
      "description": "Toggles plugin execution."
    },
    "targets": {
      "type": "array",
      "items": {
        "type": "string"
      },
      "description": "List of build targets."
    }
  },
  "additionalProperties": false
}

Setting additionalProperties: false ensures users receive an error if they pass unrecognized options.

3. Integrate Validation into Your Plugin

Import the validate function from schema-utils and invoke it directly in the plugin's constructor.

The validate function takes three arguments:

  1. Schema: The JSON Schema object.
  2. Options: The user-provided configuration object.
  3. Configuration Object: Metadata such as name (the plugin name displayed in error outputs) and baseDataPath (the root name shown in the error path, usually set to 'options').
const { validate } = require("schema-utils");
const schema = require("./schema.json");

class MyCustomPlugin {
  constructor(options = {}) {
    validate(schema, options, {
      name: "MyCustomPlugin",
      baseDataPath: "options",
    });

    this.options = options;
  }

  apply(compiler) {
    compiler.hooks.emit.tap("MyCustomPlugin", (compilation) => {
      // Plugin logic goes here
    });
  }
}

module.exports = MyCustomPlugin;

4. Provide Custom Error Messages

You can enrich error output by adding the errorMessage property directly to your JSON schema. This allows you to give users precise hints on how to correct their input:

{
  "type": "object",
  "properties": {
    "name": {
      "type": "string",
      "errorMessage": "The 'name' option must be a valid non-empty string."
    }
  },
  "additionalProperties": {
    "errorMessage": "Unknown option detected. Please check plugin documentation for valid properties."
  }
}

5. Expected Output on Failure

If a user provides invalid input in their webpack.config.js:

new MyCustomPlugin({
  name: 12345,
  unknownProp: true
});

Webpack will halt the execution immediately with a formatted error message detailing the exact location and nature of the issue:

ValidationError: Invalid options object. MyCustomPlugin has been initialized using an options object that does not match the API schema.
 - options.name should be a string.
 - options has an unknown property 'unknownProp'. These properties are valid:
   object { name?, enabled?, targets? }
