Webpack contenthash vs chunkhash for CSS Extraction

When extracting CSS into separate files in Webpack, using [contenthash] instead of [chunkhash] is critical for effective long-term browser caching. While [chunkhash] couples the generated hash to the entire entry chunk—causing CSS files to bust cache even when only JavaScript code changes—[contenthash] derives its value solely from the extracted CSS file's internal content. This ensures client browsers only re-download stylesheets when actual style definitions are modified.

The Limitation of [chunkhash]

In Webpack, a "chunk" represents a group of modules compiled together, often starting from a single entry point. When an entry file imports a stylesheet, both the JavaScript logic and the CSS belong to the same chunk.

If you use [chunkhash] to name extracted CSS files (for example, via MiniCssExtractPlugin), Webpack assigns the hash of the parent chunk to the extracted CSS asset. Because the hash is shared:

  • Modifying a single line of JavaScript changes the chunk's overall hash.
  • The extracted CSS filename receives the new hash, even if not a single line of CSS was modified.
  • Browsers are forced to invalidate their cached version of the CSS file and re-download it unnecessarily.

This behavior defeats the primary purpose of long-term caching, which is to allow static assets to remain cached indefinitely until they actually change.

How [contenthash] Solves the Problem

The [contenthash] placeholder generates a unique hash calculated exclusively from the final content of the individual asset being emitted.

When applied to CSS extraction:

  1. Independent Invalidation: If you modify JavaScript files without touching CSS, the JavaScript bundle's hash updates, while the CSS file's hash remains unchanged.
  2. Selective Updating: If you update only CSS rules, only the CSS file's hash changes, leaving the JavaScript bundle intact in the user's browser cache.
  3. Reduced Bandwidth and Faster Loads: Returning users only download the assets that were genuinely modified between deployments, significantly improving load performance.

Because of this decoupled cache invalidation, modern Webpack configurations and extraction plugins standardize on [contenthash] for both production CSS files and split code bundles.
