Configure Webpack Output for AMD and RequireJS

This article provides a concise guide on configuring Webpack to bundle code that integrates smoothly with Asynchronous Module Definition (AMD) environments, such as RequireJS. It covers the essential output.library configurations, handling external dependencies via externals, and managing anonymous versus named module definitions to prevent path resolution conflicts.

Configure the Output Target

To make a Webpack bundle consumable by an AMD loader, you must set the library target type to amd within your webpack.config.js.

In Webpack 5, configure the output.library object:

const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'my-library.js',
    library: {
      type: 'amd',
    },
  },
};

This configuration wraps the compiled output in an AMD wrapper function:

define([], function() {
  return /******/ (function() {
    // Compiled code...
  })();
});

Anonymous vs. Named AMD Modules

By default, omitting a module name creates an anonymous AMD module, which is the recommended practice for RequireJS. Anonymous modules allow the consumer to define their own path and alias in their RequireJS configuration without naming collisions.

If your architecture strictly requires a named module, specify the name in the configuration:

output: {
  library: {
    name: 'my-library',
    type: 'amd',
  },
}

This generates define('my-library', [], function() { ... }). Be cautious with named modules, as RequireJS will only execute them if the request path matches the hardcoded module name or if an explicit shim/path configuration is established.

Mapping External Dependencies

If your Webpack bundle relies on libraries that should be provided by the host RequireJS application (such as jQuery or Lodash), configure them in the externals section:

module.exports = {
  // ...
  externals: {
    jquery: 'jquery',
    lodash: 'lodash',
  },
};

When Webpack compiles the bundle, it automatically lists these dependencies in the generated define call:

define(['jquery', 'lodash'], function(__WEBPACK_EXTERNAL_MODULE_jquery__, __WEBPACK_EXTERNAL_MODULE_lodash__) {
  // Module implementation
});

RequireJS will resolve and load these dependencies prior to executing your Webpack bundle.

Consuming the Bundle in RequireJS

Once compiled, load the output file inside your RequireJS configuration just like any other AMD module:

require.config({
  paths: {
    'my-library': 'path/to/dist/my-library',
    jquery: 'path/to/jquery.min',
  },
});

require(['my-library', 'jquery'], function(myLibrary, $) {
  myLibrary.init();
});
