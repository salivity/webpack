Webpack 5 Asset Modules: Native Asset Management

Webpack 5 introduces Asset Modules, a native system designed to handle static assets such as images, fonts, and text files without requiring additional loaders like file-loader, url-loader, or raw-loader. By integrating this functionality directly into the Webpack core, developers can process, emit, and inline assets with simpler configurations, reduced dependency overhead, and improved build performance. This guide covers how these native modules work, the four core asset types available, and how to configure them in your projects.

The Shift from Legacy Loaders

In Webpack 4 and earlier versions, managing assets required installing and configuring separate npm packages:

  • file-loader emitted files into the output directory and returned their public URLs.
  • url-loader converted files into Base64-encoded Data URIs, falling back to file-loader if a size limit was exceeded.
  • raw-loader imported file contents as plain text strings.

Webpack 5 replaces all of these loaders with Asset Modules, configuring asset processing directly through the type property in module.rules.

The Four Core Asset Module Types

Webpack 5 provides four distinct module types to handle different asset requirements:

1. asset/resource

This type emits a separate file into the output directory and exports its public URL. It acts as a direct replacement for file-loader.

module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|svg|jpg|jpeg|gif)$/i,
        type: 'asset/resource',
      },
    ],
  },
};

When an image matching the regular expression is imported in JavaScript or referenced in CSS, Webpack copies the asset to the output folder and provides the relative or absolute path to the file.

2. asset/inline

This type exports the asset as a Base64-encoded Data URI, embedding the content directly into the bundle. It acts as a direct replacement for url-loader when used without file-size fallback limits.

module.exports = {
  module: {
    rules: [
      {
        test: /\.svg$/i,
        type: 'asset/inline',
      },
    ],
  },
};

This is ideal for small vector graphics or icons where minimizing HTTP requests is preferred over file size overhead.

3. asset/source

This type exports the raw, uncompiled source code of the asset as a string. It acts as a direct replacement for raw-loader.

module.exports = {
  module: {
    rules: [
      {
        test: /\.txt$/i,
        type: 'asset/source',
      },
    ],
  },
};

It is commonly used for loading plain text files, raw GLSL shader code, or unparsed HTML templates.

4. asset

This hybrid type automatically decides whether to emit a separate file (asset/resource) or inline the asset as a Data URI (asset/inline). By default, Webpack uses an 8 KB size threshold: assets smaller than 8 KB are inlined, while larger assets are emitted to the output directory.

module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpg|jpeg)$/i,
        type: 'asset',
      },
    ],
  },
};

Customizing Asset Handling

Webpack 5 provides options to modify the default behavior of Asset Modules.

Customizing Output Filenames

You can set a global output pattern for all asset modules using output.assetModuleFilename:

module.exports = {
  output: {
    assetModuleFilename: 'assets/[hash][ext][query]',
  },
};

Alternatively, you can define filenames on a per-rule basis using the generator property:

{
  test: /\.(woff|woff2|eot|ttf|otf)$/i,
  type: 'asset/resource',
  generator: {
    filename: 'fonts/[name].[contenthash][ext]',
  },
}

Changing the Inlining Size Limit

For the general asset type, you can override the default 8 KB threshold using the parser.dataUrlCondition.maxSize property:

{
  test: /\.(png|jpg)$/i,
  type: 'asset',
  parser: {
    dataUrlCondition: {
      maxSize: 4 * 1024, // 4 KB limit
    },
  },
}

Through these native module types, Webpack 5 simplifies static asset bundling, eliminates the need for legacy third-party loaders, and provides fine-grained control over how files are emitted or embedded.
