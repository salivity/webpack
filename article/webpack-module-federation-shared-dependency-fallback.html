Webpack Module Federation Shared Dependency Fallback

Webpack Module Federation enables micro-frontends to share runtime dependencies to reduce bundle sizes and avoid redundant library execution. When independent builds require varying versions of a shared library, configuring fallback versions ensures an application continues to function by loading its own local copy if the host does not supply a compatible version. This article explains how to define and configure fallback versions for shared dependencies using the ModuleFederationPlugin.

Understanding the Fallback Mechanism

By default, Webpack's ModuleFederationPlugin includes each declared shared dependency in the build output as a potential fallback. At runtime, the application checks the global shared scope. If another container (such as the host shell) provides a version matching the consumer's semantic versioning constraints, that instance is used. If no acceptable version is available in the shared scope, the application falls back to loading its own bundled version.

Configuring the Plugin

To configure fallback behavior, define the dependency inside the shared configuration object in webpack.config.js. Specify the version requirements using requiredVersion alongside fallback control options like strictVersion and singleton.

const { ModuleFederationPlugin } = require('webpack').container;
const deps = require('./package.json').dependencies;

module.exports = {
  plugins: [
    new ModuleFederationPlugin({
      name: 'remoteApp',
      filename: 'remoteEntry.js',
      remotes: {},
      exposes: {
        './Widget': './src/Widget',
      },
      shared: {
        react: {
          singleton: true,
          requiredVersion: deps.react,
          strictVersion: false,
        },
        'lodash/': {
          singleton: false,
          requiredVersion: '^4.17.0',
          strictVersion: false,
        },
      },
    }),
  ],
};

Key Configuration Options

  • requiredVersion: Specifies the accepted semantic version (SemVer) range. Webpack checks the shared scope against this range. If the host provides a version outside this range, the fallback is triggered.
  • strictVersion: Set this to false (default) to allow the module to fall back to its locally bundled version when the shared scope version does not satisfy requiredVersion. If set to true, Webpack throws a runtime error instead of falling back when a version mismatch occurs in a singleton.
  • singleton: Ensures only one instance of the dependency is loaded across all federated modules. When using libraries with internal state (like React), set singleton: true. If a version mismatch occurs with strictVersion: false, Webpack prints a console warning and uses the highest available version in the scope instead of loading multiple versions.
  • import: Defines the fallback module path. By default, it resolves to the package name specified in the key. Setting import: false disables the fallback entirely, forcing the container to rely solely on the host or throw an error if the dependency is missing.

Disabling Automatic Fallbacks

In scenarios where bundle size must be strictly minimized and remotes should never bundle their own duplicate copies, disable the fallback mechanism by setting import: false:

shared: {
  react: {
    singleton: true,
    requiredVersion: deps.react,
    import: false, // Prevents bundling a local fallback
  },
}

When import: false is configured, the application assumes the host will always provide the dependency. If the host fails to provide it, the application encounters a runtime failure rather than loading a local fallback.
