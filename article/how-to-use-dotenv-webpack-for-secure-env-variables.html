How to Use dotenv-webpack for Secure Env Variables

Managing configuration data across different environments is a critical aspect of modern web development. This article explains how to set up and use dotenv-webpack to inject variables from a .env file into a Webpack bundle, while detailing the security practices necessary to avoid exposing sensitive credentials in client-side code.

The Security Reality of Client-Side Bundles

Before writing any configuration, you must understand how Webpack handles environment variables. Webpack compiles code to run in a browser. Any variable injected into the bundle via dotenv-webpack will be converted into plain text in the final JavaScript output.

Therefore, you must never expose sensitive backend secrets—such as database passwords, private encryption keys, or privileged API secrets—using dotenv-webpack. Use this tool exclusively for public configuration data, such as public API endpoints, analytics IDs, or feature flags.

1. Installation

Install the package as a development dependency:

npm install dotenv-webpack --save-dev

or with Yarn:

yarn add dotenv-webpack --dev

2. Basic Configuration

To use the plugin, import it into your webpack.config.js file and add it to the plugins array.

const Dotenv = require('dotenv-webpack');

module.exports = {
  // ... rest of your Webpack configuration
  plugins: [
    new Dotenv()
  ]
};

By default, this looks for a .env file in the root directory and replaces references to process.env.VARIABLE_NAME in your source code with the actual values defined in that file.

3. Securing and Validating Variables with Options

To maintain a secure and reliable setup, use the configuration options provided by dotenv-webpack:

const Dotenv = require('dotenv-webpack');

module.exports = {
  plugins: [
    new Dotenv({
      path: './.env', // Path to your .env file
      safe: true,     // Loads .env.example to verify .env has all required keys
      systemvars: false, // Set to true only if you need to load system environment variables
      silent: false,  // Suppress warnings
      defaults: false // Load .env.defaults if it exists
    })
  ]
};

Key Security Options:

  • safe: true: When enabled, the plugin checks your .env against a .env.example file. If any required variables are missing, the build fails immediately. This prevents broken production deployments caused by missing configuration.
  • systemvars: false: Setting this to false prevents the plugin from accidentally exposing local system environment variables (such as OS credentials or global machine tokens) to your bundle. Keep this false unless your CI/CD pipeline injects variables directly as system environment variables.

4. Setting Up Environment Files

Create a .env file for your local values:

API_BASE_URL=https://api.example.com
PUBLIC_ANALYTICS_ID=UA-12345678-1

Create a .env.example file to commit to your version control system:

API_BASE_URL=
PUBLIC_ANALYTICS_ID=

Add your actual .env file to your .gitignore to prevent leaking local settings or developer-specific tokens:

.env
.env.local

5. Accessing Variables in Your Source Code

In your application files, reference the variables directly off process.env:

const apiEndpoint = process.env.API_BASE_URL;

function fetchData() {
  return fetch(`${apiEndpoint}/items`)
    .then(response => response.json());
}

During the build process, dotenv-webpack locates exact string occurrences like process.env.API_BASE_URL and replaces them directly with the string literal (e.g., 'https://api.example.com'). Variables defined in .env that are not explicitly referenced in your code will be omitted, keeping unused keys out of the final bundle.
