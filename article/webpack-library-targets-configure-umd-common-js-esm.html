Webpack Library Targets: Configure UMD, CommonJS, ESM

This guide explains how to configure Webpack 5 to compile your JavaScript or TypeScript library into various distribution formats, specifically Universal Module Definition (UMD), CommonJS (CJS), and ECMAScript Modules (ESM). By leveraging the output.library configuration options and Webpack 5's experimental module output, you can deliver reusable packages optimized for Node.js environments, script tags, and modern bundlers.

Understanding output.library

In Webpack, defining an entry point as a library is handled via the output.library configuration object. The primary properties involved are:

  • type: Specifies the module format (e.g., 'umd', 'commonjs', 'module').
  • name: Defines the variable name exposed in global scopes (required for UMD or browser globals).
  • export: Optional; specifies which export from your entry point should be exposed as the library.

Configuring UMD (Universal Module Definition)

UMD packages run in multiple environments: as an AMD module (RequireJS), as a CommonJS module, or directly in the browser via a <script> tag as a global variable.

// webpack.config.js
const path = require('path');

module.exports = {
  mode: 'production',
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'my-library.umd.js',
    library: {
      name: 'MyLibrary',
      type: 'umd',
      export: 'default', // Optional: expose default export directly
    },
    globalObject: 'this', // Ensures compatibility across browser and Node environments
    clean: true,
  },
};

Setting globalObject: 'this' prevents errors when referencing window in non-browser runtimes like Node.js.

Configuring CommonJS (CJS)

If your library targets Node.js exclusively, outputting to CommonJS avoids the overhead of UMD wrappers.

// webpack.config.js
const path = require('path');

module.exports = {
  mode: 'production',
  entry: './src/index.js',
  target: 'node',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'my-library.cjs.js',
    library: {
      type: 'commonjs2', // 'commonjs2' assigns exports to module.exports
    },
    clean: true,
  },
};

type: 'commonjs' assigns outputs to exports, whereas type: 'commonjs2' sets them on module.exports, which is generally preferred for Node-compatible packages.

Configuring ECMAScript Modules (ESM)

Webpack 5 supports native ESM generation. Because this feature is experimental, you must explicitly enable experiments.outputModule.

// webpack.config.js
const path = require('path');

module.exports = {
  mode: 'production',
  entry: './src/index.js',
  experiments: {
    outputModule: true,
  },
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'my-library.esm.js',
    library: {
      type: 'module',
    },
    clean: true,
  },
};

This configuration outputs modern import and export statements, allowing consumers to benefit from tree-shaking.

Outputting Multiple Targets Simultaneously

To build UMD, CommonJS, and ESM bundles in a single build command, export an array of configuration objects:

// webpack.config.js
const path = require('path');

const baseConfig = {
  mode: 'production',
  entry: './src/index.js',
  // Shared loaders, plugins, and resolve settings go here
};

module.exports = [
  // UMD Build
  {
    ...baseConfig,
    output: {
      path: path.resolve(__dirname, 'dist'),
      filename: 'index.umd.js',
      library: {
        name: 'MyLibrary',
        type: 'umd',
      },
      globalObject: 'this',
    },
  },
  // CommonJS Build
  {
    ...baseConfig,
    target: 'node',
    output: {
      path: path.resolve(__dirname, 'dist'),
      filename: 'index.cjs.js',
      library: {
        type: 'commonjs2',
      },
    },
  },
  // ESM Build
  {
    ...baseConfig,
    experiments: {
      outputModule: true,
    },
    output: {
      path: path.resolve(__dirname, 'dist'),
      filename: 'index.esm.js',
      library: {
        type: 'module',
      },
    },
  },
];

Pair this with a properly configured package.json utilizing main, module, and exports fields to ensure consumers automatically resolve the correct bundle for their environment.
