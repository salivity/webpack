Webpack: Prefer Browser Over Node Implementations

Many npm packages provide dual implementations designed to run in both Node.js and browser environments. This article covers how to configure Webpack to prioritize client-side implementations over Node.js builds using the resolve.mainFields, resolve.conditionNames, and target configuration options.

Set the Target to Web

Webpack includes built-in defaults based on your deployment target. Setting the target property to 'web' automatically configures Webpack to favor browser-specific fields:

module.exports = {
  target: 'web',
};

While this is the default setting for Webpack, declaring it explicitly ensures default module resolution behaviors align with client-side requirements.

Configure resolve.mainFields for Legacy Packages

Older npm packages rely on the browser field in package.json rather than the modern exports map. By default, when target is set to 'web', Webpack looks for ['browser', 'module', 'main'].

If your setup overrides defaults or needs explicit enforcement, define resolve.mainFields in your webpack.config.js:

module.exports = {
  resolve: {
    mainFields: ['browser', 'module', 'main'],
  },
};

Webpack evaluates this array from left to right. When it inspects a dependency's package.json, it will look for the browser property first, using the browser bundle instead of the Node-oriented main file.

Configure resolve.conditionNames for Modern Packages

Modern packages utilize the exports field in package.json with conditional mappings (such as "node", "browser", "import", and "require"). To ensure Webpack matches the browser condition instead of a Node runtime condition, configure resolve.conditionNames:

module.exports = {
  resolve: {
    conditionNames: ['browser', 'import', 'require'],
  },
};

Listing 'browser' first guarantees that if an entry point exports a conditional path for the browser, Webpack will select it over the Node equivalent.

Handle Node Built-in Fallbacks

When forcing browser implementations, some packages may still attempt to reference Node.js core modules (such as path, crypto, or buffer). Webpack 5 no longer includes polyfills by default. To disable or redirect these imports, use resolve.fallback:

module.exports = {
  resolve: {
    fallback: {
      fs: false,
      path: false,
      crypto: false,
    },
  },
};

Setting an unused Node.js module to false instructs Webpack to ignore the import and prevent build errors when resolving dependencies that retain superficial Node references.
