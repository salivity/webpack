Workbox Webpack: GenerateSW vs InjectManifest

When building Progressive Web Apps (PWAs) using the workbox-webpack-plugin, developers must choose between two primary modes: GenerateSW and InjectManifest. While both modes handle precaching build assets effectively, they serve different project requirements. GenerateSW automates the entire service worker creation process through Webpack configuration, making it ideal for simple use cases. Conversely, InjectManifest takes an existing custom service worker file and injects the precache manifest into it, granting full control over service worker logic.

What is GenerateSW?

The GenerateSW mode creates a complete, ready-to-use service worker file during the Webpack build process. It derives all functionality strictly from the configuration options provided in webpack.config.js.

Key Characteristics:

  • Fully Automated: You do not write a separate service worker file; Workbox generates the entire script automatically.
  • Precache and Runtime Caching: Handles precaching of Webpack assets and allows configuration of runtime caching strategies (e.g., CacheFirst, NetworkFirst) using regular expressions.
  • Zero Boilerplate: Quickest setup for standard caching strategies.

Limitations:

  • You cannot write custom service worker code.
  • It cannot be combined with custom APIs like Web Push notifications, Background Sync, or complex message handling (postMessage).
  • If you need logic that falls outside Workbox’s configuration parameters, GenerateSW will not work.

What is InjectManifest?

The InjectManifest mode is designed for applications requiring custom service worker behaviors. In this mode, you write your own source service worker file (e.g., src/sw.js), and Workbox injects an array of assets to be precached into a specific placeholder variable: self.__WB_MANIFEST.

Key Characteristics:

  • Full Control: You have direct access to standard service worker events (install, activate, fetch, push, sync).
  • Workbox Library Access: You can import modules from the workbox-* packages (like workbox-routing or workbox-strategies) inside your custom file while retaining native control.
  • Custom Code Integration: Essential for implementing push notifications, custom offline fallbacks, and advanced message passing between the client and worker.

Limitations:

  • Requires managing and compiling a separate source file.
  • Requires manual setup of routing and strategies within the worker code itself rather than declarative Webpack options.

Key Differences at a Glance

Feature GenerateSW InjectManifest
Service Worker Source Generated entirely by Workbox Written by developer (src/sw.js)
Configuration Location Webpack config file Webpack config + custom JS/TS file
Custom Code Support No Yes
Web Push / Sync Support No Yes
Ease of Setup High (few lines of config) Moderate (requires source file setup)
Precache Handling Automatic Injected via self.__WB_MANIFEST

Which One Should You Choose?

Choose GenerateSW if:

  • You only need straightforward offline capabilities.
  • Your caching needs consist entirely of precaching build assets and basic runtime caching rules for external fonts or API calls.
  • You do not need Web Push notifications or custom lifecycle events.

Choose InjectManifest if:

  • You need to support Web Push notifications.
  • You plan to use Background Sync or periodic sync APIs.
  • You require custom cache validation, complex client communication, or logic that cannot be expressed through Webpack configuration options alone.
