Webpack resolve.roots: Prioritize Module Resolution

This article explains how to configure Webpack's resolve.roots option to prioritize module resolution from specific folders. You will learn the purpose of resolve.roots, how it affects root-relative imports (paths starting with /), step-by-step configuration examples, and how Webpack processes directory precedence.

What Is resolve.roots?

Introduced in Webpack 5, resolve.roots defines a list of base directories used to resolve server-relative URLs—imports that begin with a forward slash (/).

By default, Webpack treats imports starting with / as absolute paths on your operating system's filesystem. Setting resolve.roots redirects these requests to one or more project directories, allowing you to establish root directories for project-level module resolution.

Basic Configuration

To configure resolve.roots, define an array of absolute paths inside the resolve object of your webpack.config.js.

const path = require('path');

module.exports = {
  // ... other webpack configuration
  resolve: {
    roots: [
      path.resolve(__dirname, 'src'),
      path.resolve(__dirname, 'shared'),
    ],
  },
};

How Folder Prioritization Works

Webpack resolves modules by evaluating the directories in the resolve.roots array in sequential order:

  1. Top-to-bottom lookup: Webpack inspects the first path in the array. If the requested file is found, resolution stops immediately.
  2. Fallback: If the file does not exist in the first directory, Webpack checks the second directory, and so on.
  3. Error handling: If none of the folders contain the requested module, Webpack throws a Module not found error.

Example Scenario

Consider a project with the following directory structure:

my-project/
├── src/
│   └── components/
│       └── Header.js
├── shared/
│   └── components/
│       ├── Header.js
│       └── Footer.js
└── webpack.config.js

Given the configuration:

resolve: {
  roots: [
    path.resolve(__dirname, 'src'),
    path.resolve(__dirname, 'shared'),
  ],
}

When importing modules using root-relative paths:

  • import Header from '/components/Header'; resolves to src/components/Header.js because src is listed first.
  • import Footer from '/components/Footer'; checks src/components/Footer first, fails, and falls back to shared/components/Footer.js.

resolve.roots vs. resolve.modules vs. resolve.alias

  • resolve.roots: Resolves paths starting with a leading slash (/path/to/file). It does not affect bare module specifiers.
  • resolve.modules: Resolves bare specifiers (like import 'lodash' or import 'components/Button'). It tells Webpack which directories to search for non-relative, non-absolute imports.
  • resolve.alias: Maps exact path prefixes or aliases (such as @components) to specific file or directory targets.

Best Practices

  • Always provide absolute paths: Use Node's built-in path.resolve(__dirname, 'folder') to avoid platform-specific path discrepancies.
  • Combine with TypeScript or ESLint: If using TypeScript or ESLint, synchronize your tsconfig.json (paths or baseUrl) or ESLint import resolvers so your editor correctly understands / imports.
