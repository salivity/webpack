Webpack Alias for Scoped NPM Packages

Configuring aliases for scoped npm packages in Webpack allows developers to redirect, mock, or locally link dependencies under namespaced scopes such as @scope/package. This guide covers how to set up Webpack's resolve.alias configuration to target scoped packages accurately, avoid syntax conflicts with root-level @ path aliases, and properly handle subpath imports.

Basic Scoped Package Alias

To alias a scoped npm package, define the full package name including the @ prefix and the forward slash within the resolve.alias object in your webpack.config.js.

const path = require('path');

module.exports = {
  // ...
  resolve: {
    alias: {
      '@scope/package': path.resolve(__dirname, 'src/local-packages/package'),
    },
  },
};

This configuration ensures that any import statement calling import module from '@scope/package' will resolve to your specified local directory instead of node_modules/@scope/package.

Preventing Conflicts with Root @ Aliases

A common pitfall occurs when a project uses @ as an alias for the src directory (e.g., @/components/Button). Without proper configuration, Webpack may attempt to parse @scope/package as a path inside the src directory.

To prevent this collision, apply these strategies:

  1. Order Matters: Define more specific aliases before general ones. Place @scope/package above the generic @ alias.
  2. Use the $ Exact Match Anchor: Add a trailing $ to the generic @ alias if you only intend to match that exact string, or ensure your specific package aliases take precedence.
const path = require('path');

module.exports = {
  resolve: {
    alias: {
      // 1. Scoped packages defined first
      '@scope/package': path.resolve(__dirname, 'src/overrides/package'),
      
      // 2. Generic application aliases defined after
      '@': path.resolve(__dirname, 'src'),
    },
  },
};

Handling Exact Matches and Subpaths

By default, an alias definition like '@scope/package': '/path/to/pkg' matches subpaths as well. An import for @scope/package/utils will resolve to /path/to/pkg/utils.

If you only want to alias the root entry point while leaving internal module imports unchanged, append a $ to the end of the package key:

module.exports = {
  resolve: {
    alias: {
      // Only matches "import from '@scope/package'"
      '@scope/package$': path.resolve(__dirname, 'src/overrides/package/index.js'),
    },
  },
};

Conversely, if you need to alias a specific submodule inside a scoped package while keeping the rest untouched:

module.exports = {
  resolve: {
    alias: {
      '@scope/package/feature': path.resolve(__dirname, 'src/mocks/feature.js'),
    },
  },
};

Aliasing an Entire Scope

If you are developing a monorepo or private registry packages and want to redirect all packages under a single organization scope to a local folder, you can alias the scope prefix:

module.exports = {
  resolve: {
    alias: {
      '@scope': path.resolve(__dirname, 'packages'),
    },
  },
};

With this rule in place, import from '@scope/button' automatically resolves to packages/button.
