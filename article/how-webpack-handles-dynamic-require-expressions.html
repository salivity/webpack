How Webpack Handles Dynamic Require Expressions

When Webpack encounters a require statement containing an expression instead of a static string literal, it cannot resolve the exact module path at compile time. To handle this, Webpack extracts whatever static directory and file pattern it can from the expression, generates a "context module," and bundles every single file that matches that pattern. This article explains how Webpack's AST analysis detects these expressions, how context modules bundle matching files, the performance implications of this behavior, and how developers can control the process.

The Static Analysis Limitation

Webpack builds its dependency graph at compile time using static analysis. Under normal circumstances, a static call like require('./locales/en.json') maps directly to a single file.

When you use an expression such as:

const locale = 'en';
const data = require('./locales/' + locale + '.json');

Webpack cannot execute the runtime JavaScript to determine what locale evaluates to. Because it cannot predict the exact value at build time, it must prepare for any valid runtime outcome.

Context Modules and Regular Expression Matching

To resolve dynamic calls, Webpack's parser inspects the string concatenation or template literal via the Abstract Syntax Tree (AST) to identify two components:

  1. A base directory: The static prefix of the path (in this case, ./locales/).
  2. A regular expression: Derived from the remaining dynamic parts and extensions (in this case, /^.*\.json$/).

With these two elements, Webpack creates a context module. The build process navigates to the ./locales/ directory on your file system, checks every file against the regular expression, and includes all matching files in the final bundle.

Internally, Webpack generates a lookup map for that context module:

var map = {
  "./en.json": 1234,
  "./es.json": 1235,
  "./fr.json": 1236
};

At runtime, the expression is evaluated to a string, matched against the internal map, and the corresponding module ID is loaded. If the evaluated string does not exist in the map, Webpack throws a runtime Cannot find module error.

Completely Dynamic Expressions

If you write a completely dynamic require statement with no static prefix:

require(someVariable);

Webpack lacks a base directory to anchor its search. In response, it treats the current directory of that file as the base directory and matches everything recursively.

This causes significant performance problems:

  • Webpack will attempt to bundle every file in the folder and its subdirectories.
  • The build output increases dramatically in size.
  • Webpack issues a compiler warning: Critical dependency: the request of a dependency is an expression.

Performance and Security Implications

Because dynamic expressions bundle all matching files, they can introduce unintended consequences:

  • Bundle Bloat: If a directory contains 50 translation files, all 50 will be bundled into the application, even if the user only ever requires one.
  • Sensitive File Exposure: Any file matching the pattern—such as internal documentation, tests, or config files inside that directory—will be bundled and exposed in the client-side JavaScript.

Best Practices and Control Mechanisms

To prevent bloated bundles when using dynamic expressions, apply the following strategies:

1. Be as Specific as Possible

Always include as much static path information as possible, including file extensions and specific subdirectories:

// Bad: Bundles entire components folder recursively
require('./components/' + name);

// Better: Limits bundling only to .js files inside a dedicated folder
require('./components/buttons/' + name + '.js');

2. Use require.context for Explicit Control

Webpack provides the require.context() utility, allowing you to explicitly define the directory, whether to search subdirectories, and the exact regular expression:

const context = require.context('./locales', false, /^(en|es)\.json$/);
const data = context('./' + locale + '.json');

This prevents unwanted files from matching arbitrary dynamic expressions.

3. Migrate to Dynamic import() with Magic Comments

For modern applications, dynamic import() allows asynchronous code-splitting. Webpack supports "magic comments" to restrict which files are included in the context:

import(
  /* webpackInclude: /(en|es)\.json$/ */
  /* webpackChunkName: "locale" */
  `./locales/${locale}.json`
);

This approach generates separate on-demand chunks rather than forcing every matching file into the main bundle.
