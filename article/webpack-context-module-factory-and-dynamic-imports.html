Webpack ContextModuleFactory and Dynamic Imports

This article explains the purpose of Webpack's ContextModuleFactory and details its internal process for handling dynamic directory imports. It breaks down how dynamic imports containing variable expressions are identified, how the compilation environment scans the file system, and how Webpack produces a ContextModule map that enables dynamic runtime dependency resolution without knowing the exact file path at build time.

What is ContextModuleFactory?

ContextModuleFactory is an internal Webpack class responsible for generating ContextModule instances. In a typical build, Webpack resolves static module paths (such as import './utils.js') directly via the standard NormalModuleFactory. However, when an import statement includes a dynamic expression—such as import(./locales/${lang}.json)—Webpack cannot determine the exact target file during compilation.

Instead of failing, Webpack delegates the request to the ContextModuleFactory. This factory evaluates the static parts of the path, inspects the local file system, and bundles all potentially matching files into a single context module.

How Dynamic Directory Imports Are Processed

The conversion of a dynamic import expression into a bundle-ready ContextModule follows a multi-step pipeline inside Webpack:

1. Parsing and Context Dependency Creation

During the Abstract Syntax Tree (AST) parsing phase, Webpack’s JavascriptParser encounters an import statement containing dynamic expressions (e.g., require('./assets/' + name + '.png') or import(./pages/${route})).

Because the argument is not a single string literal, the parser cannot generate a standard NormalModuleFactory dependency. Instead, it extracts:

  • The prefix (base directory): The static leading part of the path (e.g., ./pages/).
  • The dynamic segment: The variable part of the expression.
  • The postfix (extension/suffix): The static trailing part of the path, if present (e.g., .vue or .json).

The parser packages this data into a ContextDependency (such as ImportContextDependency or RequireContextDependency) and attaches it to the module graph.

2. Factory Delegation and Context Resolution

The compilation engine passes the ContextDependency to ContextModuleFactory. The factory performs resolution on the base directory using Webpack's enhanced resolver:

  • It verifies that the specified base directory exists on disk.
  • It applies Webpack configuration rules, such as path aliases or custom module directories.
  • It determines the dynamic import mode (lazy, lazy-once, eager, or sync).

3. Regular Expression Generation

ContextModuleFactory constructs a regular expression based on the dynamic segment and the postfix. For an import such as ./components/${name}.jsx, it generates a regular expression that resembles:

^\.\/.*\.jsx$

This pattern matches any file within the resolved directory that meets the structural constraints of the original import expression.

4. Directory Traversal and File Matching

Once the directory path and regular expression are established, ContextModuleFactory reads the target directory using the file system interface (fs.readdir or Webpack's cached input file system).

It recursively traverses subdirectories (unless recursive behavior is explicitly disabled in a require.context call) and tests each encountered file path against the generated regular expression. Every matching file is converted into an entry in an internal mapping table, linking the relative request string to the absolute file path.

5. ContextModule Creation

Using the collected map of matching files, ContextModuleFactory instantiates a ContextModule. The ContextModule encapsulates:

  • The base directory path.
  • The matching regular expression.
  • The import mode (e.g., lazy for asynchronous chunk generation per file, or sync to bundle them in the current chunk).
  • The resolved map of all eligible dependencies.

Each resolved file in this map is then queued for compilation through the standard module pipeline, ensuring loaders and standard transformations are applied to all potential matches.

Runtime Execution

At runtime, the generated ContextModule acts as an internal module registry. It exports a function that accepts the resolved dynamic string (such as the value of ${lang}.json) and searches its internal map for the corresponding module ID:

  • If the key exists in the map, Webpack executes the corresponding module and returns the exports (or returns a Promise resolving to the module, depending on the import mode).
  • If the dynamic value does not match any file discovered during the build-time directory scan, Webpack throws a runtime error indicating that the module could not be found.
