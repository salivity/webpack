How to Downgrade Webpack 5 Runtime to ES5

This article explains how to configure Webpack 5 to force its internal runtime boilerplate code to downgrade to ES5 syntax. By default, Webpack 5 generates modern ES6 runtime code—such as arrow functions and const declarations—regardless of whether loaders like Babel compile your application code down to ES5. Setting the correct target property prevents parsing and runtime syntax errors in legacy environments like Internet Explorer 11.

The Target Setting for ES5 Runtime

To force Webpack 5 to emit ES5-compliant runtime code, set the target configuration to an array containing both the platform and the ECMAScript version:

// webpack.config.js
module.exports = {
  target: ['web', 'es5'],
  // ... other configurations
};

Passing 'es5' as an item in the target array instructs Webpack to avoid any modern JavaScript features when generating runtime wrappers and bundle bootstrapping code.

Why This Setting Is Required

In Webpack 4, runtime code was written in ES5 by default. Webpack 5 assumes an ES2015 (ES6) environment out of the box to reduce bundle sizes and improve execution efficiency.

Even if tools like @babel/preset-env transpile your source code down to ES5, Babel does not touch the internal runtime wrapper injected by Webpack. Without the ['web', 'es5'] target, Webpack injects arrow functions (e.g., () => { ... }) into the bundle, causing older browsers to fail immediately during script parsing.

Alternative Approaches

1. Using Browserslist

If your project utilizes a .browserslistrc file or a browserslist field in package.json, set the target to:

module.exports = {
  target: 'browserslist',
};

Webpack will automatically parse your Browserslist query. If the query includes browsers that do not support ES6 (such as ie 11), Webpack will automatically downgrade its runtime code to ES5.

2. Manual Environment Control

The target: ['web', 'es5'] shorthand works by setting all fields in output.environment to false. You can achieve the same result explicitly:

module.exports = {
  target: 'web',
  output: {
    environment: {
      arrowFunction: false,
      bigIntLiteral: false,
      const: false,
      destructuring: false,
      dynamicImport: false,
      forOf: false,
      module: false,
      optionalChaining: false,
      templateLiteral: false,
    },
  },
};

Setting target: ['web', 'es5'] remains the simplest and most maintainable way to ensure complete ES5 compatibility for Webpack 5 runtime output.
