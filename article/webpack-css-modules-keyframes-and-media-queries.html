Webpack CSS Modules: Keyframes and Media Queries

Webpack processes CSS Modules primarily through the css-loader, transforming locally scoped styles into uniquely hashed identifiers to avoid global namespace collisions. When dealing with keyframe animations and media queries, Webpack applies distinct strategies: it automatically scopes @keyframes names alongside selector classes while leaving @media query conditions intact, scoping only the CSS rules declared inside them.

Handling CSS Keyframe Animations

When CSS Modules are enabled in Webpack via css-loader, animation names defined in @keyframes rules are treated as local identifiers by default.

  1. Identifier Hashing: Webpack identifies @keyframes [name] declarations and renames them to a unique hash based on the configured localIdentName pattern (for example, styles_fade__3a8b2).
  2. Property Rewriting: Any usage of the identifier inside properties like animation, animation-name, or shorthand declarations within the same module is automatically updated to reference the hashed name.
  3. JavaScript Export: The generated keyframe name is exported into the JavaScript module object alongside your class names, allowing you to reference the animation directly in component logic if needed.
/* Input: style.module.css */
@keyframes slideIn {
  from { transform: translateX(-100%); }
  to { transform: translateX(0); }
}

.banner {
  animation: slideIn 0.3s ease-in-out;
}
/* Output generated by Webpack */
@keyframes _style__slideIn_a8f9d {
  from { transform: translateX(-100%); }
  to { transform: translateX(0); }
}

._style__banner_k3j9c {
  animation: _style__slideIn_a8f9d 0.3s ease-in-out;
}

If an animation must be shared globally across components, the :global modifier can be used to prevent Webpack from hashing it:

:global(@keyframes globalSpinner) {
  to { transform: rotate(360deg); }
}

Handling Media Queries

Media queries (@media) are conditional at-rules rather than selectors, so Webpack does not alter or hash the @media declaration itself. The queries retain their standard CSS syntax and behavior in the final bundle.

  1. Scoped Inner Selectors: While the media condition (e.g., screen and (max-width: 768px)) remains unhashed, any class selectors declared inside the block are scoped locally like any other CSS module selector.
  2. Selector Mapping: The exported JavaScript class mapping remains identical whether styles for that class exist inside or outside a media query. Multiple declarations for the same class name—base styles and media-query overrides—resolve to the same hashed identifier.
/* Input: style.module.css */
.container {
  width: 100%;
}

@media (min-width: 1024px) {
  .container {
    width: 960px;
  }
}
/* Output generated by Webpack */
._style__container_x9q1z {
  width: 100%;
}

@media (min-width: 1024px) {
  ._style__container_x9q1z {
    width: 960px;
  }
}

Configuration Requirements

Webpack relies on css-loader to execute these transformations. Ensure your webpack.config.js enables modules:

module.exports = {
  module: {
    rules: [
      {
        test: /\.module\.css$/,
        use: [
          'style-loader',
          {
            loader: 'css-loader',
            options: {
              modules: {
                localIdentName: '[name]__[local]--[hash:base64:5]',
              },
            },
          },
        ],
      },
    ],
  },
};

When using preprocessors like Sass or Less, ensure the preprocessor loader runs before css-loader. Webpack resolves nesting inside media queries and keyframes during the compilation pipeline before the scoping logic is applied.
