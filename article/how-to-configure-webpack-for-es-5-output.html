How to Configure Webpack for ES5 Output

This guide explains how to configure modern Webpack to compile and emit JavaScript bundles fully compatible with the ECMAScript 5 (ES5) standard. Ensuring ES5 compliance requires two essential steps: configuring Webpack's internal runtime code to avoid modern syntax, and integrating Babel to transpile your application code and polyfill missing APIs.

1. Configure Webpack's Target and Output Runtime

Webpack 5 defaults to emitting ES6+ features (such as arrow functions and const/let declarations) in its generated runtime wrappers. To force Webpack's runtime code to adhere to ES5, set the target property and configure the output.environment settings in webpack.config.js:

module.exports = {
  target: ['web', 'es5'],
  output: {
    environment: {
      arrowFunction: false,
      bigIntLiteral: false,
      const: false,
      destructuring: false,
      dynamicImport: false,
      forOf: false,
      module: false,
    },
  },
};
  • target: ['web', 'es5'] instructs Webpack to generate runtime code compatible with ES5 environments.
  • output.environment explicitly disables modern ECMAScript features in the Webpack runtime wrapper.

2. Install Babel and Polyfill Dependencies

Webpack alone does not transpile modern JavaScript within your source files; it only bundles modules. To convert modern application syntax and APIs to ES5, install Babel along with core-js for polyfills:

npm install --save-dev babel-loader @babel/core @babel/preset-env
npm install core-js@3

3. Add Babel Loader to Webpack Configuration

Add a rule in webpack.config.js to process JavaScript files using babel-loader. Configure @babel/preset-env with useBuiltIns: 'usage' to inject ES5 polyfills on demand.

Here is the complete webpack.config.js file:

const path = require('path');

module.exports = {
  mode: 'production',
  entry: './src/index.js',
  target: ['web', 'es5'],
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'bundle.js',
    environment: {
      arrowFunction: false,
      bigIntLiteral: false,
      const: false,
      destructuring: false,
      dynamicImport: false,
      forOf: false,
      module: false,
    },
  },
  module: {
    rules: [
      {
        test: /\.m?js$/,
        exclude: /node_modules/,
        use: {
          loader: 'babel-loader',
          options: {
            presets: [
              [
                '@babel/preset-env',
                {
                  targets: {
                    browsers: ['ie 11', 'es 5'],
                  },
                  useBuiltIns: 'usage',
                  corejs: 3,
                },
              ],
            ],
          },
        },
      },
    ],
  },
};

4. Handling Third-Party Dependencies

Many third-party libraries published to npm distribute ES6+ syntax. If your build needs to support legacy environments like Internet Explorer 11, modify the exclude pattern in the Babel rule to include packages that need transpilation:

exclude: /node_modules\/(?!(untranspiled-dependency-name)\/).*/,

With both the Webpack runtime environment and Babel properly configured, your final bundle will be fully conforming to ECMAScript 5.
