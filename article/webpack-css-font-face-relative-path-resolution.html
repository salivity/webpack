Webpack CSS @font-face Relative Path Resolution

Webpack processes CSS @font-face rules by treating local url() references as module dependencies through css-loader. When a relative path points to a font located in a subdirectory, Webpack resolves that path relative to the specific stylesheet where the rule is declared, extracts the file using asset modules, and automatically updates the output URL to match the final build directory structure.

The Role of css-loader

When Webpack compiles stylesheets, css-loader parses the CSS AST (Abstract Syntax Tree) and scans for url() declarations. Upon encountering an @font-face rule with a relative path such as:

@font-face {
  font-family: 'CustomFont';
  src: url('./fonts/subfolder/custom-font.woff2') format('woff2');
}

css-loader translates url('./fonts/subfolder/custom-font.woff2') into a module request equivalent to require('./fonts/subfolder/custom-font.woff2').

Path Resolution Context

Webpack strictly resolves relative paths in CSS relative to the file where the rule is written, not relative to:

  • The root JavaScript entry point.
  • The root directory of the application.
  • The output HTML document.

If your stylesheet is located at src/styles/typography.css and the font is at src/styles/fonts/subfolder/custom-font.woff2, the path ./fonts/subfolder/custom-font.woff2 correctly maps to the physical file system. If the path cannot be resolved from that specific file location, Webpack immediately halts compilation with a Module not found error.

Asset Module Handling in Webpack 5

Once css-loader resolves the dependency, Webpack delegates the asset to its module pipeline. In modern Webpack (version 5+), font files are processed using native Asset Modules instead of legacy loaders like file-loader or url-loader.

A standard configuration designates font formats as asset/resource:

module.exports = {
  module: {
    rules: [
      {
        test: /\.css$/i,
        use: ['style-loader', 'css-loader'],
      },
      {
        test: /\.(woff|woff2|eot|ttf|otf)$/i,
        type: 'asset/resource',
        generator: {
          filename: 'assets/fonts/[name].[hash][ext]',
        },
      },
    ],
  },
};

When configured as asset/resource, Webpack:

  1. Emits the font file into the specified output directory (e.g., dist/assets/fonts/custom-font.a1b2c3.woff2).
  2. Calculates the final public URL based on output.publicPath.
  3. Rewrites the original url(...) string in the compiled CSS output to reference the emitted file's new destination.

Public Path and Deployment Considerations

The rewritten URL inside the generated @font-face declaration relies directly on your output.publicPath setting.

  • Absolute paths (publicPath: '/'): Webpack rewrites the font URL to /assets/fonts/custom-font.hash.woff2. The browser requests the font from the server root, which works reliably across multi-level routes.
  • Relative paths (publicPath: 'auto' or ''): Webpack calculates the path relative to the generated CSS file. If the extracted CSS is located in a css/ directory and fonts are placed in assets/fonts/, Webpack automatically inserts necessary relative traversal segments (e.g., ../assets/fonts/custom-font.hash.woff2).

If fonts fail to load with a 404 status at runtime despite a successful build, the issue typically stems from a mismatched output.publicPath relative to how the production server routes static assets.
