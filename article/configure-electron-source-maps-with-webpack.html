Configure Electron Source Maps with Webpack

Configuring source maps in an Electron application bundled with Webpack allows developers to debug original source code directly within both the Chromium-based renderer DevTools and the Node.js main process. Because Electron uses two distinct runtime environments, proper source map generation requires configuring specific Webpack devtool settings for each process and implementing runtime support for the Node.js main environment.

1. Install Required Dependencies

While the renderer process can parse source maps natively via Chromium, the main process runs in Node.js and requires the source-map-support package to translate error stack traces back to the original source files.

Install the package via your terminal:

npm install source-map-support --save
npm install --save-dev source-map-loader

2. Configure the Main Process

The main process runs in a Node.js context (target: 'electron-main'). The ideal devtool option for this process in development is 'source-map' or 'inline-source-map'.

In your webpack.main.config.js:

const path = require('path');

module.exports = {
  mode: 'development',
  target: 'electron-main',
  entry: './src/main/index.js',
  devtool: 'source-map',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'main.js'
  },
  node: {
    __dirname: false,
    __filename: false
  }
};

To enable Node.js to read these maps at runtime, initialize source-map-support at the very top of your main entry file (src/main/index.js):

import 'source-map-support/register';
// Alternatively, in CommonJS:
// require('source-map-support').install();

import { app, BrowserWindow } from 'electron';
// Remaining application code...

3. Configure the Renderer Process

The renderer process runs inside Chromium (target: 'electron-renderer' or target: 'web'). When configuring source maps here, you must account for your Content Security Policy (CSP).

Fast development options like 'eval-source-map' require 'unsafe-eval' in your HTML CSP header. If your CSP forbids unsafe-eval, use standard 'source-map'.

In your webpack.renderer.config.js:

const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  mode: 'development',
  target: 'web', // Use 'electron-renderer' if nodeIntegration is true
  entry: './src/renderer/index.js',
  devtool: 'source-map', // Safest for strict CSP policies
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'renderer.js'
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/renderer/index.html'
    })
  ]
};

4. Configure Content Security Policy (CSP)

If you use 'source-map', Chromium loads .map files via standard requests, requiring no special CSP allowances.

If you use 'eval-source-map' or 'eval-cheap-module-source-map' for faster rebuilds during development, ensure your HTML template contains a meta tag permitting unsafe-eval:

<meta 
  http-equiv="Content-Security-Policy" 
  content="default-src 'self'; script-src 'self' 'unsafe-eval'; style-src 'self' 'unsafe-inline';"
/>

Note: Remove 'unsafe-eval' in production builds by switching devtool to false or 'source-map'.

5. Debugging Setup

Once both configurations are in place:

  • Renderer Debugging: Launch the Electron app and open the DevTools (mainWindow.webContents.openDevTools()). The original files will appear under the webpack:// scheme in the Sources tab.
  • Main Process Debugging: Start Electron with the inspect flag (electron --inspect=5858 .). Attach your code editor (such as VS Code) to port 5858, and breakpoints placed in your original source files will be hit accurately.
