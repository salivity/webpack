Inline Critical CSS in HTML Head with Webpack

Inlining critical CSS directly into the <head> of an HTML document is an effective performance technique to eliminate render-blocking stylesheets and drastically improve First Contentful Paint (FCP). This guide explains how to configure Webpack to automatically extract above-the-fold CSS and inject it directly into the generated HTML markup using modern, automated plugins.

The Recommended Solution: Critters

The cleanest, most efficient way to inline critical CSS with Webpack is using Critters (via critters-webpack-plugin). Developed by the Google Chrome team, Critters parses your compiled HTML and CSS, identifies the styles required for the initial render, inlines them into a <style> block in the <head>, and lazy-loads the remaining CSS asynchronously without needing a headless browser like Puppeteer.

Step 1: Install the Dependencies

Install critters-webpack-plugin alongside standard Webpack HTML and CSS processing plugins:

npm install --save-dev critters-webpack-plugin html-webpack-plugin mini-css-extract-plugin css-loader

Step 2: Configure Webpack

Add Critters to the plugins array in your webpack.config.js. It must run after both MiniCssExtractPlugin and HtmlWebpackPlugin.

const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');
const MiniCssExtractPlugin = require('mini-css-extract-plugin');
const Critters = require('critters-webpack-plugin');

module.exports = {
  mode: 'production',
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].[contenthash].js',
    clean: true,
  },
  module: {
    rules: [
      {
        test: /\.css$/i,
        use: [MiniCssExtractPlugin.loader, 'css-loader'],
      },
    ],
  },
  plugins: [
    new MiniCssExtractPlugin({
      filename: '[name].[contenthash].css',
    }),
    new HtmlWebpackPlugin({
      template: './src/index.html',
    }),
    new Critters({
      // Inlines critical CSS directly into <style> tags in the head
      preload: 'swap',
      // Removes inlined styles from external stylesheets to avoid duplication
      pruneSource: true,
    }),
  ],
};

Key Configuration Options for Critters

You can fine-tune how CSS is handled using Critters' built-in options:

  • preload: Defines the loading strategy for the non-critical stylesheet.
    • 'swap': Converts external <link rel="stylesheet"> tags to load asynchronously using media="print" and switches to media="all" once loaded.
    • 'js': Uses an inline script to load the external stylesheet asynchronously.
    • false: Leaves the external stylesheet unchanged (not recommended, as it remains render-blocking).
  • pruneSource: When set to true, Critters removes the inlined CSS rules from the external .css file to save bandwidth.
  • reduceInlineStyles: When set to true, merges multiple inline <style> tags into a single block inside the <head>.
  • inlineFonts: If set to true, inlines critical @font-face rules into the generated critical CSS.

Alternative: Using HTML-Critical-Webpack-Plugin

If your application relies heavily on viewport dimensions to determine above-the-fold content, you can use html-critical-webpack-plugin, which uses Chromium (via Penthouse) to render pages at specified viewport resolutions.

Configuration Example

const HtmlCriticalWebpackPlugin = require('html-critical-webpack-plugin');
const path = require('path');

module.exports = {
  // ... other webpack settings
  plugins: [
    // Must run after HtmlWebpackPlugin and MiniCssExtractPlugin
    new HtmlCriticalWebpackPlugin({
      base: path.resolve(__dirname, 'dist'),
      src: 'index.html',
      dest: 'index.html',
      inline: true,
      minify: true,
      extract: true,
      width: 1300,
      height: 900,
      penthouse: {
        blockJSRequests: false,
      },
    }),
  ],
};

Note: While html-critical-webpack-plugin provides strict viewport-based extraction, it significantly increases build times because it spins up a headless browser instance during compilation.

Verifying the Output

Once configured, run your build script:

npx webpack

Inspect the generated dist/index.html. You should observe:

  1. A <style> tag directly inside the <head> containing only the CSS rules required for elements present in the static HTML.
  2. The remaining CSS loaded via a non-blocking <link rel="preload"> or an asynchronous media="print" pattern.
