Webpack GraphQL Loading with graphql-tag/loader

This article explains how Webpack processes .graphql and .gql files using graphql-tag/loader. It details how the loader intercepts file imports, pre-compiles query strings into Abstract Syntax Trees (ASTs) at build time, resolves external fragments, and optimizes client-side performance by eliminating runtime parsing overhead.

The Role of graphql-tag/loader

In standard JavaScript applications utilizing GraphQL, queries are typically written inside template literals tagged with the gql function from the graphql-tag library. At runtime, this function parses the query string into a GraphQL DocumentNode (AST).

graphql-tag/loader moves this parsing process from runtime to the Webpack build step. It enables developers to write queries, mutations, and fragments in separate .graphql or .gql files and import them directly into JavaScript or TypeScript modules as compiled AST objects.

Webpack Configuration

To enable Webpack to process GraphQL files, graphql-tag/loader is added to the module.rules array within webpack.config.js:

module.exports = {
  module: {
    rules: [
      {
        test: /\.(graphql|gql)$/,
        exclude: /node_modules/,
        loader: 'graphql-tag/loader'
      }
    ]
  }
};

The Step-by-Step Processing Pipeline

  1. Resolution: When Webpack encounters an import statement such as import myQuery from './myQuery.graphql', the regex match in the loader configuration directs the file contents to graphql-tag/loader.

  2. Fragment Inclusion: The loader inspects the file for GraphQL fragment imports defined via comment syntax, such as #import "./userFragment.graphql". It recursively loads and resolves these dependencies, appending them to the document definitions.

  3. AST Pre-compilation: The loader passes the raw query text through the core graphql/language/parser. It converts the schema definition or operation into a JSON-serializable AST.

  4. Code Generation: Instead of exporting plain text, the loader generates a JavaScript module that exports the parsed AST object:

    var doc = { "kind": "Document", "definitions": [ /* ... */ ] };
module.exports = doc;

  5. Bundling: Webpack includes the generated JavaScript code directly in the final application bundle.

Advantages of This Approach

  • Performance Optimization: Offloading query parsing to the build step eliminates the CPU cost of parsing query strings in the user's browser, leading to faster startup and execution times.
  • Bundle Size Reduction: Because the operations are pre-compiled into ASTs, client bundles do not always need to include the full GraphQL parser utility.
  • Modular Codebase: Developers can organize operations and fragments into dedicated files rather than embedding large strings inside component files, improving maintainability, editor syntax highlighting, and static validation.
