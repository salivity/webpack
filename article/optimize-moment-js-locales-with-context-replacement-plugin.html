Optimize Moment.js Locales with ContextReplacementPlugin

Moment.js is notorious for significantly bloating JavaScript production bundles, largely because Webpack packages all of its internationalization locale files by default. This article explains why Webpack includes every locale file during compilation and demonstrates how to configure the ContextReplacementPlugin to strip out unnecessary languages. By applying this optimization, you can keep only the specific locales your application requires and drastically reduce your overall bundle size.

The Moment.js Bundle Bloat Problem

When you import Moment.js into a project (import moment from 'moment'), the library dynamically imports its locale files using the following pattern:

function loadLocale(name) {
    // ...
    return require('./locale/' + name);
}

Because Webpack cannot determine at build time which dynamic string values name will take, its default behavior is to use a regular expression to match and bundle every single file in the moment/locale directory. This results in dozens of unused language files being bundled, adding over 200 KB (uncompressed) of unnecessary code to your client-side application.

How ContextReplacementPlugin Solves the Issue

Webpack’s built-in ContextReplacementPlugin modifies how dynamic dependencies (contexts) are resolved. It allows you to intercept the dynamic require call and supply a custom regular expression that restricts which files Webpack is allowed to resolve within a given directory.

Instead of bundling every locale found inside moment/locale, the plugin instructs Webpack to bundle only the locales matching your specified pattern.

Configuring Webpack ContextReplacementPlugin

To restrict the included locales, update your webpack.config.js by adding an instance of webpack.ContextReplacementPlugin inside the plugins array.

const webpack = require('webpack');
const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: path.resolve(__dirname, 'dist'),
  },
  plugins: [
    // Whitelist only the required locales (e.g., French, German, and Spanish)
    new webpack.ContextReplacementPlugin(
      /moment[/\\]locale$/,
      /fr|de|es/
    ),
  ],
};

Understanding the Parameters

  1. Context Directory Regex (/moment[/\\]locale$/): The first parameter matches the directory path where the dynamic require is triggered. The [/\\] syntax ensures compatibility across both POSIX and Windows file systems.
  2. File Match Regex (/fr|de|es/): The second parameter specifies which files inside that directory should be resolved and included. Any locale file not matching this expression is omitted from the final compilation.

If your application only needs English (which is built into the Moment.js core), you can pass a regular expression that matches nothing:

new webpack.ContextReplacementPlugin(
  /moment[/\\]locale$/,
  /$^/
)

ContextReplacementPlugin vs. IgnorePlugin

An alternative approach is using Webpack's IgnorePlugin:

new webpack.IgnorePlugin({
  resourceRegExp: /^\.\/locale$/,
  contextRegExp: /moment$/,
});

While IgnorePlugin completely strips all locales, it requires you to manually load individual locale files explicitly in your application code (e.g., import 'moment/locale/fr').

ContextReplacementPlugin is generally preferred when you support a known subset of languages, as it keeps Moment's internal locale-switching mechanism functional for those languages without requiring manual import declarations across your application.

Bundle Size Impact

Eliminating unused locales typically removes around 160 KB to 200 KB of unminified JavaScript from the final output. After minification and gzip compression, this results in an immediate reduction of roughly 50 KB to 60 KB, decreasing parse and execution time in the browser and improving Core Web Vitals.
