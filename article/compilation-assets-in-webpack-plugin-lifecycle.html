Compilation Assets in Webpack Plugin Lifecycle

In Webpack, compilation.assets serves as the in-memory staging ground for all output files generated during the build process before they are written to disk. This article explains the technical role of compilation.assets across the plugin lifecycle, illustrating how plugins use this object to inspect, modify, generate, and delete build artifacts.

What is Compilation.assets?

The compilation.assets property is a plain JavaScript object where keys represent target file paths (relative to the configured output directory) and values represent asset objects. These asset objects adhere to the webpack-sources interface, providing methods such as:

  • source(): Returns the content of the asset as a string or a Buffer.
  • size(): Returns the size of the asset in bytes.
  • map(): Returns source maps, if available.

This structure allows Webpack to manipulate files entirely in memory, avoiding redundant file system reads and writes until the final phase of compilation.

Position in the Plugin Lifecycle

The compilation.assets dictionary is populated and finalized across distinct compilation hooks before the output is physically written to the disk by the compiler.

  1. Asset Creation: Loaders and internal plugins parse modules, resolve dependencies, and generate initial chunks. The compilation.assets object is populated with the generated bundles, source maps, and extracted files.
  2. Asset Processing: Plugins intercept the assets using hooks on the compilation object. In modern Webpack (v5+), this is handled primarily via compilation.hooks.processAssets.
  3. Emission: Once all asset hooks complete, the main compiler invokes the emit hook, where compilation.assets is finalized. Finally, Webpack iterates over the keys of compilation.assets and writes each item to the output directory specified in output.path.

Primary Roles in Plugin Development

Plugins interact with compilation.assets to accomplish four main tasks:

1. Generating New Assets

Plugins can emit additional files that do not originate from individual JavaScript modules, such as dynamic HTML files, build manifests, or license files. In Webpack 5, the recommended approach is using compilation.emitAsset(name, source):

compilation.hooks.processAssets.tap(
  {
    name: 'MyPlugin',
    stage: Compilation.PROCESS_ASSETS_STAGE_ADDITIONAL,
  },
  () => {
    const content = JSON.stringify({ buildTime: Date.now() });
    compilation.emitAsset('build-meta.json', new sources.RawSource(content));
  }
);

2. Modifying Existing Assets

Plugins such as banner injectors, obfuscators, and custom minifiers read the existing source code of an asset and wrap or transform it. Using compilation.updateAsset() ensures that downstream plugins receive the updated source and accurate size metrics:

compilation.hooks.processAssets.tap(
  {
    name: 'MyPlugin',
    stage: Compilation.PROCESS_ASSETS_STAGE_OPTIMIZE,
  },
  (assets) => {
    Object.keys(assets).forEach((assetName) => {
      if (assetName.endsWith('.js')) {
        compilation.updateAsset(
          assetName,
          (oldSource) => new sources.ConcatSource('// License Header\n', oldSource)
        );
      }
    });
  }
);

3. Inspecting Asset Metadata

Analysis tools, bundle visualizers, and deployment plugins inspect compilation.assets to read file sizes, verify hash names, or gather stats. These plugins read from compilation.assets during stages such as PROCESS_ASSETS_STAGE_REPORT or the compiler-level emit hook without altering the contents.

4. Removing Assets

Plugins can prune assets from the final build—for example, removing temporary source maps or extraneous files generated during intermediate steps—by using compilation.deleteAsset(name).

Modern Webpack 5 Stages

In earlier Webpack versions, plugins manipulated compilation.assets directly inside the compiler.hooks.emit hook. Webpack 5 introduced the processAssets hook, categorizing operations into standardized stages to prevent race conditions:

  • STAGE_ADDITIONAL: Add extra assets to the compilation.
  • STAGE_PRE_PROCESS: Basic transformations before major optimizations.
  • STAGE_OPTIMIZE: Optimizing existing assets (e.g., minification).
  • STAGE_OPTIMIZE_COUNT: Combining or inlining assets to reduce output count.
  • STAGE_OPTIMIZE_COMPATIBILITY: Modifying assets for browser compatibility.
  • STAGE_SUMMARIZE: Aggregating assets (e.g., generating manifest.json).
  • STAGE_REPORT: Inspecting assets for reporting or logging purposes.

Through compilation.assets and its associated methods, Webpack ensures that any plugin can safely read, transform, or append to the final build output in a predictable, high-performance in-memory pipeline.
