How React Refresh Preserves Component State in HMR

React Refresh enables stateful React components to maintain their state during Webpack Hot Module Replacement (HMR) by decoupling component execution from the underlying component state tree. By combining a compiler transform to track component identities and hook signatures with a specialized runtime module integrated into Webpack's update lifecycle, React Refresh safely patches rendered components in place without re-mounting them or wiping their in-memory Fiber nodes.

The Problem with Traditional HMR

In standard Webpack HMR, updating a module typically invalidates the file and re-evaluates the code from scratch. When a React component is redefined this way, React treats it as an entirely new component type. This triggers a full unmount and remount cycle, destroying DOM nodes, discarding existing state, and resetting any active effects.

The Architecture of React Refresh

React Refresh overcomes this by operating at three distinct levels:

  1. The Compiler Transform (react-refresh/babel): Injects code registration calls around React components and hooks during the build step.
  2. The Runtime (react-refresh/runtime): Manages the global registry of components and handles reconciliation logic for hot updates.
  3. The Webpack Integration (@pmmmwh/react-refresh-webpack-plugin): Intercepts Webpack’s native HMR events to feed updated modules into the React Refresh runtime instead of triggering a full page reload.

Step-by-Step State Preservation Process

1. Component Registration and Hook Signatures

During compilation, the Babel transform analyzes files for React component exports and hook usage. It registers every component using a generated ID via $RefreshReg$ and creates a unique signature for its hooks via $RefreshSig$.

// Conceptual output of the transform
var _s = $RefreshSig$();

function Counter() {
  _s();
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}

_s(Counter, "useState{[count, setCount](0)}");
$RefreshReg$(Counter, "Counter");

The hook signature captures the sequence, types, and primary keys of hooks inside the component. This metadata allows the runtime to verify whether the internal state structure remains compatible across changes.

2. Hot Update Interception

When you edit a component, Webpack identifies the changed module and generates a hot update chunk. Instead of bubbling the update up the dependency tree, the Webpack plugin automatically injects module.hot.accept() boundaries around files that only export React components. Webpack loads the new module code and executes it, invoking the new $RefreshReg$ calls.

3. Component Identity Mapping

The React Refresh runtime intercepts the new component definition and maps it back to the existing registration ID. Because the component's identity is retained through the runtime's internal registry, React understands that the incoming function is an update to an existing component rather than an entirely new entity.

4. Hook Signature Validation

Before applying the update, the runtime inspects the component's hook signature:

  • Signature matches: If the order, type, and count of hooks remain unchanged (e.g., editing JSX or non-hook helper logic), React Refresh considers the state structure safe.
  • Signature changes: If a hook is added, removed, or reordered, state persistence could lead to runtime errors or memory corruption. The runtime deliberately marks the component as invalidated, resetting its state while keeping the rest of the component tree intact.

5. Fiber Tree Patching

React renders components using an internal tree of nodes called Fibers. Each Fiber holds the component's current DOM reference, props, and a linked list of hook states.

Once the runtime validates that the update is safe, it patches the component's type reference directly in the existing Fiber tree. It then signals the React reconciler to perform a shallow re-render of only the affected components. Because the Fiber nodes remain untouched, the linked list of hook states persists, resulting in an updated UI that retains its current state.

Conditions That Trigger a State Reset

State cannot always be preserved. React Refresh resets component state to prevent inconsistent behavior when:

  • Hook types, counts, or execution orders are modified.
  • A file exports both React components and regular JavaScript values or utilities (which breaks HMR boundary detection).
  • Class components are edited, as React Refresh is primarily designed around functional components and hooks.
