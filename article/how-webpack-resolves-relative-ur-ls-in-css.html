How Webpack Resolves Relative URLs in CSS

When bundling stylesheets, Webpack handles relative paths within CSS url() functions by treating them as module import requests rather than simple static paths. Driven primarily by css-loader, Webpack intercepts each url() statement, resolves the target asset relative to the stylesheet containing the declaration, processes the referenced file as a dependency, and finally updates the URL to point to the compiled asset's public destination.

The Role of css-loader

Webpack does not natively understand CSS syntax. When processing a stylesheet, css-loader scans the CSS Abstract Syntax Tree (AST) for url() declarations. It converts standard expressions like url('./image.png') into standard module requests, effectively translating them into JavaScript require('./image.png') or ES module import statements behind the scenes.

Resolving the Path

Webpack resolves relative paths using its built-in resolver system (enhanced-resolve) under the following rules:

  • Relative Paths (./ or ../): Resolved relative to the directory of the CSS file where the url() is written, not the entry HTML file or the output directory.
  • Module Paths (e.g., ~package/image.png or bare package names): In older versions, a tilde prefix (~) told Webpack to look inside node_modules. Modern versions of css-loader resolve bare specifiers directly against node_modules without requiring the tilde.
  • Root-Relative Paths (/assets/image.png): By default, paths beginning with a slash are treated as server-absolute paths and are left untransformed unless explicitly configured otherwise.

Asset Processing and Output Rewriting

Once Webpack resolves the referenced file, the asset is passed to the Webpack module pipeline. In modern Webpack 5, this is typically handled by Asset Modules:

  1. Asset Emission or Inlining: Depending on configuration, the asset is either emitted to the build directory (via asset/resource) with a generated cache-busting filename, or inlined as a Base64 Data URI (via asset/inline).
  2. Path Rewriting: Webpack generates the final output string for the CSS file by prefixing the asset's emitted filename with your configured output.publicPath. The original relative path inside url(...) is replaced with this final generated URL.

Disabling URL Resolution

If you need url() paths left untouched—such as when pointing to external static files already served from a specific public folder—you can disable automatic resolution by setting { url: false } inside your css-loader configuration.
