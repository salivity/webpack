Why Webpack DefinePlugin Requires JSON.stringify

Webpack’s DefinePlugin performs direct, compile-time text replacement in your source code rather than assigning runtime variables. Because it injects the raw value directly into the code as JavaScript tokens, string values must be wrapped in JSON.stringify()—or explicit double-quotes—to ensure they are treated as string literals rather than variable identifiers or invalid syntax.

Direct Code Replacement Mechanism

The DefinePlugin operates as a direct text find-and-replace mechanism. When Webpack bundles your code, it looks for occurrences of the keys defined in the plugin and replaces them with the exact characters provided as their values.

If you pass a string without extra quotes:

new webpack.DefinePlugin({
  API_URL: 'https://api.example.com',
  ENVIRONMENT: 'production',
});

Webpack replaces every instance of ENVIRONMENT in your code with the raw token production:

// Before compilation:
if (process.env.NODE_ENV === ENVIRONMENT) { ... }

// After compilation:
if (process.env.NODE_ENV === production) { ... }

In the compiled output, the browser or Node.js runtime attempts to find an in-scope variable named production. Because no such variable exists, it throws a runtime error: Uncaught ReferenceError: production is not defined.

For complex values like URLs (e.g., https://api.example.com), the syntax breaks entirely because the parser encounters an unquoted colon and slashes, interpreting https: as a label followed by a comment.

How JSON.stringify() Fixes the Issue

To ensure that the replaced code evaluates to a string literal, the injected replacement itself must contain literal quotation marks.

Applying JSON.stringify() adds these quotes around the string:

new webpack.DefinePlugin({
  ENVIRONMENT: JSON.stringify('production'),
});

JSON.stringify('production') produces the string '"production"'. When Webpack substitutes this into your file, it outputs valid JavaScript with the quotes intact:

// After compilation:
if (process.env.NODE_ENV === "production") { ... }

Alternative Syntax

While JSON.stringify(value) is the industry standard—especially when passing dynamic environment variables such as JSON.stringify(process.env.API_KEY)—the same effect can be achieved using nested quotes:

new webpack.DefinePlugin({
  ENVIRONMENT: '"production"',
  API_URL: "'https://api.example.com'",
});

Using JSON.stringify() is preferred because it safely handles special characters, escaped characters, and undefined environment variables without manual string escaping.
