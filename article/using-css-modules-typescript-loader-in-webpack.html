Using css-modules-typescript-loader in Webpack

This article covers css-modules-typescript-loader, a specialized Webpack loader that automatically generates TypeScript declaration files (.d.ts) for CSS Modules. It breaks down the role the tool plays in bringing type safety to styling in TypeScript applications, outlines how it interacts with other standard style loaders, and demonstrates how to correctly place it within the Webpack build pipeline.

What is css-modules-typescript-loader?

When using CSS Modules in a TypeScript project, importing styles directly into a component typically causes a compilation error because TypeScript does not natively understand CSS files. A common workaround is declaring a global wildcard definition, such as:

declare module '*.module.css' {
  const classes: { [key: string]: string };
  export default classes;
}

While this eliminates compilation errors, it provides no genuine type safety. Developers can misspell class names or access removed styles without triggering any build-time warnings.

css-modules-typescript-loader solves this problem. During the build process, it inspects the class names defined in each CSS Module and automatically creates a corresponding .d.ts file directly on disk alongside the source style file (for example, generating Button.module.css.d.ts next to Button.module.css). These generated typings explicitly export every class name present in the stylesheet, giving developers code completion, IntelliSense, and compile-time type verification.

How It Fits into the Webpack Pipeline

Webpack evaluates loaders in reverse order: from right to left (or bottom to top in an array configuration). Understanding this execution flow is critical when positioning css-modules-typescript-loader.

In a standard setup, a stylesheet flows through several transformation stages:

  1. A preprocessor loader (such as sass-loader or postcss-loader) compiles the source code into standard CSS.
  2. css-loader interprets @import and url() statements, processes CSS Modules, and maps class names into an exported JavaScript object.
  3. style-loader (or MiniCssExtractPlugin.loader) takes that CSS and injects it into the DOM or extracts it into standalone bundles.

css-modules-typescript-loader needs access to the class-mapping tokens that css-loader creates, and it must run before the styles are extracted or injected. Therefore, it must be positioned directly before css-loader in execution order, which means placing it above or to the left of css-loader in the Webpack configuration array.

Webpack Configuration Example

Below is a typical Webpack rule showing how the loader integrates into the pipeline:

module.exports = {
  module: {
    rules: [
      {
        test: /\.module\.css$/,
        use: [
          // 4. Injects CSS into the DOM (or MiniCssExtractPlugin.loader in production)
          'style-loader',

          // 3. Generates the .d.ts files based on the exports from css-loader
          'css-modules-typescript-loader',

          // 2. Resolves imports and processes CSS Modules
          {
            loader: 'css-loader',
            options: {
              modules: {
                localIdentName: '[name]__[local]--[hash:base64:5]',
              },
            },
          },

          // 1. (Optional) Compiles Sass/SCSS or processes PostCSS
          'postcss-loader',
        ],
      },
    ],
  },
};

Execution Flow in the Pipeline

When Webpack encounters an import styles from './Button.module.css' statement:

  1. postcss-loader runs first, transforming modern or preprocessed CSS into standard CSS syntax.
  2. css-loader processes the transformed CSS, scopes the class selectors according to the module configuration, and creates an internal map of original names to scoped names.
  3. css-modules-typescript-loader receives this output, extracts the exported keys, and writes or updates Button.module.css.d.ts.
  4. style-loader takes the resulting CSS and prepares it for browser injection.

By placing css-modules-typescript-loader between style-loader and css-loader, your build pipeline maintains standard CSS processing behavior while keeping TypeScript interfaces strictly synchronized with your style declarations.
