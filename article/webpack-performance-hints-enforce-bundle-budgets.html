Webpack performance.hints: Enforce Bundle Budgets

This article explains the performance.hints configuration in Webpack and demonstrates how to use it to enforce performance budgets. You will learn the available configuration values, how it pairs with size threshold metrics, and how integrating it into your continuous integration workflow prevents oversized bundles from reaching production.

What is performance.hints?

In Webpack, performance.hints is a configuration option located within the performance object of webpack.config.js. It controls how Webpack responds when generated assets or entry points exceed defined file size limits. By alerting developers to bloated bundles during the build phase, it helps maintain web performance benchmarks and fast load times.

Available Options for performance.hints

The performance.hints property accepts three values:

  • false: Completely disables performance notifications. No warnings or errors will be displayed, regardless of asset sizes.
  • "warning": Emits a compilation warning in the terminal if an asset or entry point exceeds the specified threshold. The build succeeds and exits cleanly. This is Webpack's default behavior in production mode.
  • "error": Emits a compilation error if limits are breached. This causes the build process to fail with a non-zero exit code.

Defining Bundle Budget Thresholds

performance.hints works in tandem with two other properties in the performance object that establish your budget limits, measured in bytes:

  • maxAssetSize: The maximum allowable size for any individual emitted file (such as a single JavaScript chunk or CSS file).
  • maxEntrypointSize: The maximum allowable total size of all assets combined that are required during the initial load of a specific entry point.

Example Configuration

module.exports = {
  mode: 'production',
  // ... other configuration settings
  performance: {
    hints: 'error',
    maxAssetSize: 250000, // 250 KB
    maxEntrypointSize: 400000 // 400 KB
  }
};

In this setup, if any generated chunk exceeds 250 KB, or if the entry point exceeds 400 KB, Webpack will immediately fail the compilation.

Enforcing Budgets in CI/CD Pipelines

Setting performance.hints: "error" is the primary mechanism for hard budget enforcement. While "warning" informs developers during local compilation, warnings can easily be overlooked.

When set to "error", automated CI/CD pipelines will fail the build if a pull request introduces dependencies or code that pushes bundle sizes beyond the agreed-upon limits. This guarantees that code exceeding the performance budget cannot be merged or deployed, forcing teams to optimize imports, implement code splitting, or use dynamic imports before deployment.
