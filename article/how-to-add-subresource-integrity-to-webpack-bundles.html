How to Add Subresource Integrity to Webpack Bundles

Subresource Integrity (SRI) is a web security feature that enables browsers to verify that resources fetched from CDNs or third-party servers have not been manipulated or tampered with. This article explains how to automate the generation and injection of cryptographic integrity hashes into your Webpack bundle output using standard plugins, ensuring that your application only executes authentic code.

1. Install the Required Packages

To automatically calculate hashes and inject integrity attributes into your HTML script and style tags, you need webpack-subresource-integrity alongside html-webpack-plugin.

Run the following command in your project directory:

npm install --save-dev webpack-subresource-integrity html-webpack-plugin

2. Configure Webpack

Open your webpack.config.js file and import SubresourceIntegrityPlugin. You must also set the output.crossOriginLoading property to 'anonymous' (or 'use-credentials'). Webpack requires this setting to load dynamic chunk scripts with CORS-enabled integrity checks.

const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');
const { SubresourceIntegrityPlugin } = require('webpack-subresource-integrity');

module.exports = {
  entry: './src/index.js',
  output: {
    filename: '[name].[contenthash].js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
    // Required: Enables cross-origin loading for asynchronous chunks
    crossOriginLoading: 'anonymous',
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/index.html',
    }),
    new SubresourceIntegrityPlugin({
      hashFuncNames: ['sha384'],
      enabled: 'auto', // Defaults to true in production mode
    }),
  ],
};

3. Configuration Options

  • hashFuncNames: An array of cryptographic hash functions used to generate the hash digests. Valid options include 'sha256', 'sha384', and 'sha512'. Using 'sha384' is generally recommended for optimal balance between performance and collision resistance.
  • enabled: Defines whether the plugin should run. When set to 'auto', the plugin is enabled in production mode and disabled in development mode to speed up builds.

4. Verify the Build Output

Run your build command:

npx webpack --mode production

Inspect the generated dist/index.html file. The injected <script> and <link> tags will now contain integrity and crossorigin attributes:

<script 
  src="main.a1b2c3d4.js" 
  integrity="sha384-abc123def456..." 
  crossorigin="anonymous">
</script>

5. Ensure Proper CORS Headers on the Server

If your assets are served from an external domain or a Content Delivery Network (CDN), the hosting server must deliver those assets with the Access-Control-Allow-Origin header:

Access-Control-Allow-Origin: *

Without this header, the browser will block the script from executing due to cross-origin security restrictions, even if the SRI hash matches.
