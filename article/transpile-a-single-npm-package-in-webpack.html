Transpile a Single npm Package in Webpack

Modern npm packages increasingly publish untranspiled ES6+ syntax directly to the registry. By default, Webpack configurations ignore the entire node_modules directory to speed up build times, which causes build errors or runtime crashes in older environments when an uncompiled package is imported. This guide explains how to selectively target and transpile a single npm package using Webpack and Babel without degrading build performance for your other dependencies.

Why Webpack Ignores node_modules

In a standard webpack.config.js, you typically configure babel-loader with an exclude pattern like this:

module: {
  rules: [
    {
      test: /\.m?js$/,
      exclude: /node_modules/,
      use: {
        loader: 'babel-loader',
      },
    },
  ],
}

This tells Webpack to skip processing any file inside node_modules. To transpile an individual dependency, you must modify this behavior so that your specific package is passed to babel-loader.

Solution 1: Use an include Array (Recommended)

The cleanest and most cross-platform approach is to replace the broad exclude rule with an explicit include list. By specifying only the directories you want processed, Webpack will process your project source files and the designated third-party package while ignoring everything else.

const path = require('path');

module.exports = {
  module: {
    rules: [
      {
        test: /\.m?js$/,
        include: [
          path.resolve(__dirname, 'src'),
          path.resolve(__dirname, 'node_modules/uncompiled-package-name'),
        ],
        use: {
          loader: 'babel-loader',
          options: {
            presets: ['@babel/preset-env'],
          },
        },
      },
    ],
  },
};

Replace uncompiled-package-name with the exact folder name of the package located in your node_modules.

Solution 2: Exclude Using a Negative Lookahead Regex

If you prefer to keep your general exclude pattern, you can use a regular expression negative lookahead. This pattern matches every path inside node_modules except paths containing the package you specify.

module.exports = {
  module: {
    rules: [
      {
        test: /\.m?js$/,
        exclude: /node_modules\/(?!(uncompiled-package-name)\/).*/,
        use: {
          loader: 'babel-loader',
          options: {
            presets: ['@babel/preset-env'],
          },
        },
      },
    ],
  },
};

To include multiple packages, separate them with a pipe: (?!(package-one|package-two)\/).

Solution 3: Custom Exclude Function

For complex setups or cross-platform environments where operating system path separators (like Windows backslashes \) might cause regular expressions to fail, use a function for the exclude property:

module.exports = {
  module: {
    rules: [
      {
        test: /\.m?js$/,
        exclude: function (modulePath) {
          // Transpile our target package
          if (/node_modules[\\/]uncompiled-package-name/.test(modulePath)) {
            return false; // Do not exclude
          }
          // Exclude all other node_modules
          return /node_modules/.test(modulePath);
        },
        use: {
          loader: 'babel-loader',
        },
      },
    ],
  },
};

Returning false tells Webpack not to exclude the file, allowing babel-loader to process it.

Important: Ensure Babel Processes node_modules

If you are using a .babelrc file, Babel will not apply configurations to files outside of your project root by default. To ensure your configuration applies to the untranspiled dependency inside node_modules, ensure you:

  1. Use a project-wide babel.config.json or babel.config.js file instead of .babelrc.
  2. Alternatively, specify your Babel options directly inside the webpack.config.js under the babel-loader rule options object.
