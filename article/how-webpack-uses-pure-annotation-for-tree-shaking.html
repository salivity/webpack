How Webpack Uses PURE Annotation for Tree Shaking

The /*#__PURE__*/ annotation serves as a compiler directive that informs bundlers like Webpack and minifiers like Terser that a specific function call is free of side effects. While JavaScript bundlers can easily eliminate unused variable declarations, top-level function calls present a challenge because they might modify global state, mutate objects, or execute unpredictable logic. By prepending a function execution with the /*#__PURE__*/ comment, developers and transpilers explicitly guarantee that if the returned value of the call is not consumed elsewhere in the application, the entire call can be safely stripped during the minification and tree-shaking stages.

The Challenge of Function Calls in JavaScript

JavaScript is a highly dynamic language. When a bundler evaluates code during the build process, it statically analyzes imports and exports to identify dead code. However, static analysis struggles with function calls:

const Button = createComponent('button');

Even if Button is never imported or used by another module, Webpack cannot know whether createComponent logs data, alters the window object, or modifies external variables. Erring on the side of caution, the bundler must retain the function call to preserve any potential runtime side effects, resulting in bloated bundle sizes.

How the /*#__PURE__*/ Annotation Solves the Problem

The /*#__PURE__*/ annotation acts as an explicit override to static analysis limitations. When placed immediately before an invocation, it marks the call as "pure," meaning its only purpose is producing a return value with zero external side effects:

const Button = /*#__PURE__*/ createComponent('button');

If the Button identifier is determined to be unused by Webpack’s dependency graph:

  1. Webpack identifies that the export is dead.
  2. Webpack passes the code along with its annotations to the configured minifier (such as Terser or SWC).
  3. The minifier recognizes the /*#__PURE__*/ marker and drops both the variable declaration and the function invocation entirely from the final production bundle.

If the returned value is used, the annotation is ignored, and the function executes normally at runtime.

Webpack and Transpiler Integration

Developers rarely need to write /*#__PURE__*/ comments manually. Transpilers like Babel, the TypeScript compiler, and frameworks like React automatically inject these annotations into generated code.

For example, when transpiling ES6 classes or higher-order components down to ES5, compilers frequently generate Immediately Invoked Function Expressions (IIFEs):

var MyComponent = /*#__PURE__*/ (function () {
  function MyComponent() {}
  return MyComponent;
})();

Without the /*#__PURE__*/ annotation, Webpack would be forced to bundle this IIFE regardless of whether MyComponent is used, because the self-executing function could theoretically execute arbitrary code. The inserted comment ensures that modular libraries remain fully tree-shakeable.
