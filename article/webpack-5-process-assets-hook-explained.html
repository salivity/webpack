Webpack 5 processAssets Hook Explained

Webpack 5 introduced Compilation.hooks.processAssets as the standardized hook for creating, modifying, optimizing, and deleting output assets during the build lifecycle. This article explains the core purpose of processAssets, why it replaces legacy asset modification hooks, how its execution stages provide deterministic build ordering, and how to use it in custom plugins.

The Purpose of processAssets

In previous versions of Webpack, plugins altered assets across a fragmented collection of hooks, including optimizeAssets, optimizeChunkAssets, and the final emit hook. This approach often caused race conditions where one plugin overwrote changes made by another because execution order was determined solely by plugin declaration order.

Compilation.hooks.processAssets solves this problem by providing a single, unified pipeline for all asset modifications. It ensures that every asset transformation—from initial generation to minification and final reporting—happens predictably through explicit lifecycle stages.

Key Benefits

  • Deterministic Execution: By using predefined stages, plugins can declare precisely when their logic should execute relative to other transformations, regardless of the order in which plugins are loaded.
  • Persistent Caching Compatibility: Webpack 5 relies heavily on persistent caching. The processAssets hook integrates with the internal caching mechanism and asset information tracking, ensuring that modified assets do not break cache invalidation.
  • Native Asset Representation: The hook interacts with the sources abstraction (webpack-sources), allowing Webpack to track source maps and asset sizes efficiently without unnecessary buffer conversions.

Lifecycle Stages

When tapping into processAssets, developers specify a stage using webpack.Compilation.PROCESS_ASSETS_STAGE_*. These stages execute in a strict sequential order:

  1. PROCESS_ASSETS_STAGE_ADDITIONAL: Used to generate new assets from scratch that do not depend on existing assets.
  2. PROCESS_ASSETS_STAGE_PRE_PROCESS: For early alterations to existing assets before optimization begins.
  3. PROCESS_ASSETS_STAGE_DERIVED: Used to derive new assets from existing assets (e.g., generating compressed .gz or .br versions).
  4. PROCESS_ASSETS_STAGE_OPTIMIZE: The stage where asset content is optimized or minified.
  5. PROCESS_ASSETS_STAGE_OPTIMIZE_COUNT: Used for reducing the total number of assets, such as combining smaller files.
  6. PROCESS_ASSETS_STAGE_OPTIMIZE_INLINE: Handles inlining small assets directly into other assets (like HTML or CSS).
  7. PROCESS_ASSETS_STAGE_DEV_TOOLING: Dedicated to adding developer tools, such as source map generation and appending.
  8. PROCESS_ASSETS_STAGE_REPORT: Read-only operations intended for logging, auditing, and generating bundle analysis reports.

Basic Implementation

To use processAssets, a plugin taps into the hook during the compilation lifecycle event:

const { Compilation, sources } = require('webpack');

class BannerPlugin {
  apply(compiler) {
    compiler.hooks.thisCompilation.tap('BannerPlugin', (compilation) => {
      compilation.hooks.processAssets.tap(
        {
          name: 'BannerPlugin',
          stage: Compilation.PROCESS_ASSETS_STAGE_OPTIMIZE,
        },
        (assets) => {
          for (const [filename, source] of Object.entries(assets)) {
            if (filename.endsWith('.js')) {
              const content = `/* Custom Banner */\n${source.source()}`;
              compilation.updateAsset(
                filename,
                new sources.RawSource(content)
              );
            }
          }
        }
      );
    });
  }
}

Through methods like compilation.emitAsset, compilation.updateAsset, and compilation.deleteAsset, processAssets establishes a safe, structured interface for asset management throughout the Webpack 5 compilation lifecycle.
