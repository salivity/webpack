Load Local Loaders with Webpack resolveLoader

This guide demonstrates how to configure Webpack's resolveLoader option to load custom, unreleased loaders directly from a local repository. By adjusting the loader resolution paths, you can reference your in-house loaders by name within your Webpack configuration without publishing them to npm or setting up local symlinks via npm link.

Understanding resolveLoader

By default, Webpack resolves loaders exclusively from the node_modules directory. When authoring an unreleased loader inside your repository, typing out absolute file paths inside every rule definition can quickly become verbose and difficult to maintain.

The resolveLoader configuration option mimics standard module resolution, but applies exclusively to Webpack loaders. It provides two primary ways to reference local loaders: expanding loader lookup directories via modules, or mapping specific names via alias.

Method 1: Using resolveLoader.modules

The most flexible approach is adding your local loader directory to resolveLoader.modules. This instructs Webpack to search your local folder alongside node_modules.

Assume the project structure looks like this:

my-project/
├── loaders/
│   └── custom-text-loader.js
├── src/
│   └── index.js
├── webpack.config.js
└── package.json

In your webpack.config.js, configure resolveLoader.modules:

const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: path.resolve(__dirname, 'dist'),
  },
  resolveLoader: {
    modules: [
      'node_modules',
      path.resolve(__dirname, 'loaders'),
    ],
  },
  module: {
    rules: [
      {
        test: /\.txt$/,
        use: 'custom-text-loader',
      },
    ],
  },
};

Webpack will first check node_modules for custom-text-loader. If it is not found, it checks the local loaders/ directory and resolves custom-text-loader.js.

Method 2: Using resolveLoader.alias

If you have a single loader file or want to explicitly map a specific loader name to a file path, use resolveLoader.alias:

const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: path.resolve(__dirname, 'dist'),
  },
  resolveLoader: {
    alias: {
      'custom-text-loader': path.resolve(__dirname, 'loaders/custom-text-loader.js'),
    },
  },
  module: {
    rules: [
      {
        test: /\.txt$/,
        use: 'custom-text-loader',
      },
    ],
  },
};

This method is ideal for one-off loaders where directory-wide searching is unnecessary.

Creating the Local Loader

The local loader file itself follows the standard Webpack loader API. For example, loaders/custom-text-loader.js:

module.exports = function (source) {
  // Simple transformation example
  const transformed = source.replace(/foo/g, 'bar');
  return `module.exports = ${JSON.stringify(transformed)};`;
};

With either the modules or alias configuration in place, running webpack will seamlessly resolve, execute, and bundle assets processed by your local loader.
