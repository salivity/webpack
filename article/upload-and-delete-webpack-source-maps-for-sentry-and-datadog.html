Upload and Delete Webpack Source Maps for Sentry and Datadog

Uploading source maps to monitoring platforms like Sentry and Datadog is essential for debugging production errors without exposing your unminified source code to end users. By properly configuring your Webpack build pipeline, you can generate comprehensive source maps, automatically send them to your monitoring vendor during the build, and immediately purge the .map files from your final build output so they are never deployed to your public static asset server.

Step 1: Configure Webpack Source Map Generation

To avoid exposing your source map references to users, configure Webpack using the hidden-source-map option instead of source-map. This generates the .map files on disk but omits the //# sourceMappingURL=... reference comment at the end of output JavaScript files, preventing browsers from attempting to download them.

// webpack.config.js
module.exports = {
  mode: 'production',
  devtool: 'hidden-source-map',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].[contenthash].js',
  },
  // plugins configured below...
};

Step 2: Configure Sentry Webpack Plugin

The official @sentry/webpack-plugin provides built-in functionality to upload source maps and delete them from the file system prior to packaging or deployment.

Installation

npm install @sentry/webpack-plugin --save-dev

Configuration

In your webpack.config.js, require the plugin and configure the sourcemaps property with filesToDeleteAfterUpload:

const path = require('path');
const { sentryWebpackPlugin } = require('@sentry/webpack-plugin');

module.exports = {
  mode: 'production',
  devtool: 'hidden-source-map',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].[contenthash].js',
  },
  plugins: [
    sentryWebpackPlugin({
      org: process.env.SENTRY_ORG,
      project: process.env.SENTRY_PROJECT,
      authToken: process.env.SENTRY_AUTH_TOKEN,
      release: {
        name: process.env.RELEASE_VERSION,
      },
      sourcemaps: {
        assets: './dist/**',
        // Automatically delete the .map files once the upload completes
        filesToDeleteAfterUpload: ['./dist/**/*.map'],
      },
    }),
  ],
};

Step 3: Configure Datadog Source Map Upload and Deletion

Datadog handles source map uploads primarily through its CLI tool @datadog/datadog-ci. To execute this process within Webpack and delete the files immediately after upload, use a custom Webpack compiler hook or a post-build script.

Installation

npm install @datadog/datadog-ci rimraf --save-dev

Webpack Hook Implementation

You can execute the upload and cleanup directly within your Webpack configuration using the compiler.hooks.done lifecycle event:

const { execSync } = require('child_process');
const path = require('path');
const rimraf = require('rimraf');

class DatadogSourceMapPlugin {
  constructor(options) {
    this.options = options;
  }

  apply(compiler) {
    // Run only on production builds
    if (compiler.options.mode !== 'production') return;

    compiler.hooks.done.tapPromise('DatadogSourceMapPlugin', async () => {
      const { service, version, minifiedPathPrefix } = this.options;
      const distPath = path.resolve(__dirname, 'dist');

      try {
        console.log('Uploading source maps to Datadog...');
        execSync(
          `npx datadog-ci sourcemaps upload ${distPath} ` +
          `--service=${service} ` +
          `--release-version=${version} ` +
          `--minified-path-prefix=${minifiedPathPrefix}`,
          { stdio: 'inherit' }
        );

        console.log('Upload complete. Deleting local .map files...');
        // Remove .map files from the build output
        await rimraf(`${distPath}/**/*.map`);
        console.log('Source maps successfully deleted from dist.');
      } catch (error) {
        console.error('Failed to process source maps for Datadog:', error);
        throw error;
      }
    });
  }
}

module.exports = {
  mode: 'production',
  devtool: 'hidden-source-map',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].[contenthash].js',
  },
  plugins: [
    new DatadogSourceMapPlugin({
      service: process.env.DD_SERVICE_NAME,
      version: process.env.RELEASE_VERSION,
      minifiedPathPrefix: 'https://example.com/static/',
    }),
  ],
};

Verification

After running your production build (webpack --mode production):

  1. Check your monitoring dashboard (Sentry Releases or Datadog Source Maps) to confirm your release assets and maps were registered.
  2. Inspect your local or generated build directory (e.g., /dist). Ensure that only the minified .js bundles remain and that all .map files have been purged.
