How to Use webpackChunkName in Webpack

Webpack automatically splits code into separate bundles using dynamic imports, but these generated chunks are assigned arbitrary numeric IDs by default. By utilizing the webpackChunkName magic comment, developers can assign human-readable names to these split chunks, making network requests easier to inspect, debugging straightforward, and asset caching more predictable. This article explains how Webpack reads webpackChunkName, how to configure your output settings to support it, and how to group multiple modules into a single named chunk.

The Magic Comment Syntax

Webpack supports chunk naming through inline comments known as "magic comments" inside dynamic import() statements. When Webpack's parser encounters an import expression, it inspects the Abstract Syntax Tree (AST) for comment nodes preceding the module path.

To name a chunk, insert the /* webpackChunkName: "custom-name" */ comment inside the dynamic import call:

// Dynamic import with webpackChunkName
import(/* webpackChunkName: "dashboard" */ './components/Dashboard')
  .then((module) => {
    const Dashboard = module.default;
    Dashboard.render();
  });

Configuring Webpack Output

For the custom name to reflect in your build artifacts, you must configure the output.chunkFilename property in your webpack.config.js to utilize the [name] placeholder. The [name] placeholder dynamically resolves to the string provided in the magic comment.

// webpack.config.js
const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].bundle.js',
    chunkFilename: '[name].chunk.js', // [name] is replaced by webpackChunkName
    clean: true,
  },
};

With this configuration, the imported module from the previous example will output as dashboard.chunk.js instead of an auto-generated identifier like 1.chunk.js.

Grouping Multiple Modules into a Single Chunk

You can combine multiple dynamically imported modules into a single chunk by giving them the exact same webpackChunkName. Webpack merges all imports sharing the same chunk name into one file, reducing HTTP requests when related components are required together.

// File: src/routes.js
const loadSettings = () => import(/* webpackChunkName: "user-admin" */ './settings');
const loadProfile = () => import(/* webpackChunkName: "user-admin" */ './profile');

When either import is executed, Webpack creates and fetches a single bundle named user-admin.chunk.js containing both the settings and profile modules.

Dynamic Chunk Names with Placeholders

Webpack also allows variable interpolation within webpackChunkName when importing files dynamically using path variables. You can use the [request] placeholder, which substitutes the resolved file name or path of the imported module.

function loadLocale(language) {
  return import(
    /* webpackChunkName: "locale-[request]" */
    `./locales/${language}.json`
  );
}

If language resolves to es, Webpack generates a file named locale-es.chunk.js. This prevents you from manually declaring chunk names for every variation of dynamic, parameterized imports.
