Swap Components by Brand Using Webpack resolve.alias

This article explains how to leverage Webpack's resolve.alias configuration to dynamically swap component directories at compile time based on brand-specific parameters. By passing an environment variable during the build process, you can maintain a single codebase for white-label or multi-brand applications while seamlessly replacing UI components, styling, or assets for each specific brand target.

The Multi-Brand Architecture

In multi-brand architectures, applications often share core business logic while requiring distinct UI components or themes for different clients. Instead of using runtime conditional checks (like if (brand === 'A')), swapping directories at build time eliminates dead code and keeps bundle sizes minimal.

Consider the following directory structure:

project-root/
├── src/
│   ├── brands/
│   │   ├── brandA/
│   │   │   └── Button.jsx
│   │   ├── brandB/
│   │   │   └── Button.jsx
│   │   └── default/
│   │       └── Button.jsx
│   ├── app/
│   │   └── App.jsx
│   └── index.js
├── webpack.config.js
└── package.json

Configuring Webpack

To direct module imports to the appropriate brand folder, configure resolve.alias in webpack.config.js to read an environment variable such as BRAND.

const path = require('path');

module.exports = (env, argv) => {
  const currentBrand = process.env.BRAND || 'default';
  const brandPath = path.resolve(__dirname, `src/brands/${currentBrand}`);
  const fallbackPath = path.resolve(__dirname, 'src/brands/default');

  return {
    entry: './src/index.js',
    output: {
      path: path.resolve(__dirname, 'dist'),
      filename: 'bundle.js',
    },
    resolve: {
      extensions: ['.js', '.jsx', '.json'],
      alias: {
        // Point the generic alias to the targeted brand directory
        '@brand-components': brandPath,
      },
      // Optional: Allows Webpack to fall back to default components 
      // if an imported file does not exist in the brand directory
      modules: [brandPath, fallbackPath, 'node_modules'],
    },
    module: {
      rules: [
        {
          test: /\.jsx?$/,
          exclude: /node_modules/,
          use: 'babel-loader',
        },
      ],
    },
  };
};

Consuming Aliased Components

In your application code, import components using the defined alias rather than relative paths.

// src/app/App.jsx
import React from 'react';
import Button from '@brand-components/Button';

export const App = () => {
  return (
    <div>
      <h1>Multi-Brand Application</h1>
      <Button label="Click Me" />
    </div>
  );
};

During compilation, Webpack resolves @brand-components/Button directly to src/brands/[BRAND]/Button.jsx.

Configuring Build Scripts

Define separate npm scripts in package.json that inject the target brand name using cross-env:

{
  "scripts": {
    "build:brandA": "cross-env BRAND=brandA webpack --mode production",
    "build:brandB": "cross-env BRAND=brandB webpack --mode production",
    "build:default": "cross-env BRAND=default webpack --mode production"
  },
  "devDependencies": {
    "cross-env": "^7.0.3",
    "webpack": "^5.0.0",
    "webpack-cli": "^5.0.0"
  }
}

Implementing Fallback Resolution

If a brand only customizes a subset of components, you can configure Webpack to fall back to a base directory when a component is missing. By setting resolve.modules with the brand directory prioritized before the default directory, you can import without an alias:

// webpack.config.js
resolve: {
  modules: [
    path.resolve(__dirname, `src/brands/${currentBrand}`),
    path.resolve(__dirname, 'src/brands/default'),
    'node_modules',
  ],
}

With this approach, an import statement such as import Button from 'Button' will resolve src/brands/brandA/Button.jsx if it exists; otherwise, it will resolve src/brands/default/Button.jsx.
