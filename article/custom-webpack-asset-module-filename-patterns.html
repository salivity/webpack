Custom Webpack Asset Module Filename Patterns

Webpack 5 introduced Asset Modules to replace legacy loaders like file-loader, raw-loader, and url-loader for handling static assets such as images, fonts, and media. By default, Webpack emits these files using an internal hashing format, but you can fully customize their output directory and file-naming structures. This article demonstrates how to define custom filename patterns for Asset Modules globally using output.assetModuleFilename, selectively on specific asset rules using generator.filename, and dynamically through custom callback functions.

Global Configuration via output.assetModuleFilename

To apply a default naming pattern to all emitted asset modules across your project, define the assetModuleFilename property within the output configuration object.

// webpack.config.js
const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    filename: 'main.js',
    path: path.resolve(__dirname, 'dist'),
    assetModuleFilename: 'assets/[name].[contenthash][ext][query]',
  },
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|gif|svg)$/i,
        type: 'asset/resource',
      },
    ],
  },
};

In this setup, every asset processed with type: 'asset/resource' or type: 'asset' will be written to the dist/assets/ folder matching the original file name, its content hash, and its extension.

Granular Configuration via Rule generator.filename

When different asset types require different directory destinations (for example, keeping fonts separate from images), you can override the global configuration by defining generator.filename within individual module rules.

// webpack.config.js
module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|gif|webp)$/i,
        type: 'asset/resource',
        generator: {
          filename: 'images/[name].[hash:8][ext]',
        },
      },
      {
        test: /\.(woff|woff2|eot|ttf|otf)$/i,
        type: 'asset/resource',
        generator: {
          filename: 'fonts/[name][ext]',
        },
      },
    ],
  },
};

Any pattern defined inside generator.filename takes precedence over the global output.assetModuleFilename for matching modules.

Available Template Placeholders

Webpack provides template strings to construct filename patterns:

  • [name]: The base filename of the resource without the extension.
  • [ext]: The file extension prefixed with a period (e.g., .png).
  • [contenthash]: An MD4 hash of the file's contents. You can specify length, such as [contenthash:8].
  • [hash]: The compilation build hash (or asset content hash, depending on context).
  • [query]: The query string from the import path, if present.

Dynamic Filename Patterns via Functions

For advanced requirements—such as preserving subdirectory structures from your source folder—assign a function to generator.filename instead of a static template string. The function accepts a pathData object and returns the path string.

// webpack.config.js
const path = require('path');

module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|svg|jpg)$/i,
        type: 'asset/resource',
        generator: {
          filename: (pathData) => {
            const relativePath = path.relative(
              path.resolve(__dirname, 'src'),
              path.dirname(pathData.filename)
            );
            return `${relativePath}/[name].[contenthash:8][ext]`;
          },
        },
      },
    ],
  },
};

This method provides full control over the output paths by programmatically evaluating metadata for each asset during compilation.
