Required Headers for Webpack SharedArrayBuffer

To utilize SharedArrayBuffer in modern web applications, browsers require a cross-origin isolated environment to guard against side-channel vulnerabilities like Spectre. This article details the specific HTTP response headers your server must send to allow Webpack-bundled modules to execute SharedArrayBuffer, explains why these headers are necessary, and demonstrates how to configure them across development and production environments.

The Mandatory Security Headers

Browsers gate the SharedArrayBuffer API behind cross-origin isolation. To place your document into this isolated state, your web server must deliver two specific HTTP response headers on the top-level document:

  1. Cross-Origin-Opener-Policy (COOP)

    Cross-Origin-Opener-Policy: same-origin

    This isolates your browsing context exclusively to same-origin documents. Cross-origin windows opened via your page cannot directly interact with it.

  2. Cross-Origin-Embedder-Policy (COEP)

    Cross-Origin-Embedder-Policy: require-corp

    This prevents the document from loading any cross-origin resources (such as scripts, stylesheets, or images) that have not explicitly granted permission via Cross-Origin Resource Sharing (CORS) or the Cross-Origin-Resource-Policy (CORP) header. Alternatively, you can use credentialless to load cross-origin resources without credentials:

    Cross-Origin-Embedder-Policy: credentialless

Both headers must be present simultaneously. If either is missing or misconfigured, window.crossOriginIsolated will evaluate to false, and calling new SharedArrayBuffer() will throw a ReferenceError or fail silently depending on the browser.

Configuring Webpack Dev Server

During development, you can inject these headers directly through your webpack.config.js file using the devServer.headers configuration option:

module.exports = {
  // ... other webpack config
  devServer: {
    headers: {
      "Cross-Origin-Opener-Policy": "same-origin",
      "Cross-Origin-Embedder-Policy": "require-corp",
    },
    // Required if loading Web Workers or Wasm assets locally
    client: {
      overlay: true,
    },
  },
};

Restart your Webpack development server after applying these settings for the changes to take effect.

Configuring Production Servers

In a production environment, your reverse proxy, CDN, or static file server must supply these headers alongside your bundled Webpack output.

Nginx

Add the headers inside your server or location block:

server {
    listen 80;
    server_name example.com;

    location / {
        root /path/to/dist;
        try_files $uri $uri/ /index.html;

        add_header Cross-Origin-Opener-Policy "same-origin" always;
        add_header Cross-Origin-Embedder-Policy "require-corp" always;
    }
}

Node.js (Express)

If using an Express server to serve your Webpack build directory, use custom middleware or configure the helmet package:

const express = require('express');
const app = express();

app.use((req, res, next) => {
  res.setHeader("Cross-Origin-Opener-Policy", "same-origin");
  res.setHeader("Cross-Origin-Embedder-Policy", "require-corp");
  next();
});

app.use(express.static('dist'));
app.listen(3000);

Apache

Add the following directives to your .htaccess file or VirtualHost configuration:

<IfModule mod_headers.c>
    Header always set Cross-Origin-Opener-Policy "same-origin"
    Header always set Cross-Origin-Embedder-Policy "require-corp"
</IfModule>

Verifying Cross-Origin Isolation

After deploying the headers, verify that the environment is set up correctly:

  1. Open your application in the browser.
  2. Open Developer Tools and switch to the Console tab.
  3. Type self.crossOriginIsolated and press Enter.

If the returned value is true, your Webpack bundles can safely instantiate and use SharedArrayBuffer threads, WebAssembly multi-threading, and related parallel execution features.
