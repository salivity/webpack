Why Webpack 5 Builds Fail on Older Browsers

Early Webpack 5 builds frequently failed on older browsers like Internet Explorer 11 even when developers properly configured Babel to transpile their source code to ES5. This breakdown occurred because Webpack 5 defaulted to generating modern ECMAScript (ES6+) syntax within its own internal runtime code, which is injected after Babel finishes transpiling application files. This article explains why the loader pipeline created this issue and how to configure Webpack 5 to properly support legacy environments.

The Separation of Application Code and Runtime Code

Babel operates as a loader via babel-loader. Loaders in Webpack only process user-authored source code and designated dependencies during the initial module compilation phase. Once Babel converts modern JavaScript into ES5, it passes the transformed strings back to Webpack.

After processing all modules, Webpack wraps them inside its own runtime boilerplate code. This runtime handles module resolution, asynchronous chunk loading, and export binding. In Webpack 4, this runtime was generated using ES5 syntax by default.

In Webpack 5, the default output target was upgraded to modern standards (ES2015/ES6+). Consequently, Webpack injected features such as arrow functions, const, and let into the final bundle's runtime wrappers. Because this injection happens at the end of the bundling phase—long after babel-loader has completed its work—Babel never has the opportunity to transpile the runtime code.

Why Older Browsers Crashed

When older browsers without ES6 support encountered the bundle, they crashed immediately with syntax errors, most commonly SyntaxError: Expected ':' or unhandled arrow function tokens (=>). Even if 100% of the application code was successfully converted to ES5, the surrounding bundle infrastructure remained unparseable by legacy JavaScript engines.

The Solution: Configuring the Runtime Target

To resolve this issue, developers must explicitly instruct Webpack itself—not just Babel—to downgrade its generated runtime code.

1. Set the Target Array

Webpack 5 introduced support for an array syntax in the target configuration field to define both the platform and the ECMAScript version:

module.exports = {
  target: ['web', 'es5'],
  // ...
};

This tells Webpack to avoid any modern JavaScript constructs in its runtime wrappers.

2. Configure output.environment

For granular control, developers can specify individual features via the output.environment object. This defines which modern features Webpack is permitted to generate:

module.exports = {
  output: {
    environment: {
      arrowFunction: false,
      const: false,
      destructuring: false,
      forOf: false,
      module: false,
    },
  },
};

Setting these flags to false forces Webpack to fall back to ES5-compliant wrappers, resolving runtime syntax errors on legacy browsers.
