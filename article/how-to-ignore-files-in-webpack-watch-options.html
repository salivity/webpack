How to Ignore Files in Webpack watchOptions

When running Webpack in watch mode or using webpack-dev-server, actively tracking every file in a project can drastically slow down build times and consume excessive CPU and memory. By configuring the watchOptions.ignored property in your Webpack configuration, you can explicitly tell Webpack to skip non-essential directories—such as node_modules, build outputs, temporary files, and version control directories—ensuring faster recompilations and a smoother development workflow.

Configuring watchOptions.ignored

To ignore specific files or directories, add the watchOptions object to your webpack.config.js root configuration and define the ignored property. The ignored setting accepts an anyhow pattern, a regular expression, a string glob, or an array containing combinations of these types.

Here is a standard configuration example:

const path = require('path');

module.exports = {
  // Entry, output, and other standard configurations...
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: path.resolve(__dirname, 'dist'),
  },

  // Watch mode configuration
  watch: true,
  watchOptions: {
    // Files or directories to ignore
    ignored: [
      '**/node_modules/**',
      '**/dist/**',
      '**/.git/**',
      '**/*.test.js',
    ],
    aggregateTimeout: 300,
    poll: false,
  },
};

Pattern Matching Options

Webpack offers several ways to define what files to exclude:

1. Glob Patterns

Glob patterns are the most readable way to target directories across your project. Wrapping patterns with double asterisks ensures matches regardless of project depth:

watchOptions: {
  ignored: '**/node_modules/**',
}

2. Regular Expressions

Regular expressions provide granular control when pattern matching file names or file extensions:

watchOptions: {
  ignored: /node_modules|dist/,
}

3. Absolute Paths

You can provide an absolute path using Node's path module, which is useful when targeting specific folders outside the main source root:

watchOptions: {
  ignored: path.resolve(__dirname, 'node_modules'),
}

4. Multiple Exclusions with Arrays

For most real-world applications, an array provides the cleanest structure to combine multiple ignored patterns:

watchOptions: {
  ignored: [
    path.resolve(__dirname, 'node_modules'),
    path.resolve(__dirname, 'build'),
    path.resolve(__dirname, 'coverage'),
    '**/.cache/**',
  ],
}

Common Files to Ignore

To maximize performance, consider ignoring:

  • Dependencies: node_modules should almost always be ignored unless you are actively developing and linking a local package.
  • Build Outputs: Folders like dist, build, or out that change during the compilation process, avoiding recursive watch loops.
  • Metadata and Cache: Directories like .git, .cache, .nyc_output, or temporary IDE folders like .vscode and .idea.
  • Testing and Documentation: Test suites (**/*.spec.js, **/*.test.js) and markdown docs (**/*.md) if they do not affect the client-side bundle.
