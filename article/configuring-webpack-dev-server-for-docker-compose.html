Configuring Webpack Dev Server for Docker Compose

Running Webpack Dev Server inside a Docker Compose environment often leads to common pitfalls, such as unreachable local addresses, failing Hot Module Replacement (HMR), and missed file changes. This article details the exact configuration needed in both webpack.config.js and docker-compose.yml to ensure seamless containerized development, live reloading, and reliable network communication between the host browser and the container.

1. Webpack Dev Server Configuration

By default, Webpack Dev Server binds to localhost (127.0.0.1) and relies on native file system events. Inside a container, binding to localhost makes the server unreachable from the host machine, and file events across container volume boundaries often fail to trigger.

Update your webpack.config.js with the following devServer settings:

module.exports = {
  // ... other webpack settings
  devServer: {
    host: '0.0.0.0', // Exposes the server outside the container
    port: 8080,
    allowedHosts: 'all', // Allows requests from the host machine
    watchFiles: {
      paths: ['src/**/*'],
      options: {
        usePolling: true, // Required for Docker volume file-change detection
        interval: 1000,   // Polling frequency in milliseconds
      },
    },
    client: {
      webSocketURL: 'ws://localhost:8080/ws', // Ensures browser connects to the host's forwarded port
    },
  },
};
  • host: '0.0.0.0': Listens on all network interfaces inside the container, allowing traffic forwarded from the host.
  • usePolling: true: Replaces OS-level file notifications (like inotify) with active polling, which is necessary when editing files on the host that are mounted into a Docker container (particularly on macOS and Windows).
  • client.webSocketURL: Directs the browser to maintain the HMR WebSocket connection via the host machine's port rather than attempting to connect to the internal container IP.

2. Docker Compose Configuration

The docker-compose.yml file must map the required ports, preserve container-installed dependencies, and set up the bind mount for source code.

version: '3.8'

services:
  app:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "8080:8080" # Maps host port to container port
    volumes:
      - .:/app               # Mounts local source code into the container
      - /app/node_modules    # Anonymous volume to prevent local override of container dependencies
    environment:
      - NODE_ENV=development
      - WATCHPACK_POLLING=true # Fallback polling flag for Webpack 5 watchpack
    stdin_open: true # Equivalent to -i, keeps the process running smoothly
    tty: true        # Equivalent to -t
  • Port Mapping (8080:8080): Exposes Webpack Dev Server to http://localhost:8080 on your host machine.
  • Anonymous Volume (/app/node_modules): Prevents the host directory's node_modules (or lack thereof) from overwriting the dependencies installed inside the container during build.
  • WATCHPACK_POLLING=true: Ensures underlying file-watching utilities recognize changes even if underlying configuration values are overridden.

Summary Checklist

To verify your setup:

  1. Ensure the server binds to 0.0.0.0, not 127.0.0.1.
  2. Enable file polling in Webpack to capture changes across the Docker bind mount.
  3. Explicitly define webSocketURL so the browser connects HMR to localhost rather than internal container network addresses.
  4. Expose and map the exact application port in docker-compose.yml.
