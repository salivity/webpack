Why Webpack Loaders Execute Right-to-Left

In Webpack, chained loaders are executed from right-to-left (or bottom-to-top in multiline arrays) rather than left-to-right. This article explores why Webpack adopted this convention, demonstrating how functional programming concepts like function composition dictate this behavior, how the transformation pipeline processes files, and how the underlying loader execution phases work.

The Principle of Function Composition

The primary reason Webpack executes loaders from right-to-left is functional programming composition. In mathematics and functional programming languages, composing two functions \(f\) and \(g\) is denoted as \((f \circ g)(x)\), which evaluates to:

f(g(x))

In this composition, the innermost function g must execute first to produce a result, which is then passed as an argument to the outer function f.

When you configure loaders in webpack.config.js:

module.exports = {
  module: {
    rules: [
      {
        test: /\.css$/,
        use: ['style-loader', 'css-loader', 'sass-loader'],
      },
    ],
  },
};

Webpack conceptually interprets this array as composed functions:

styleLoader(cssLoader(sassLoader(sourceCode)))

Because sass-loader is the innermost function, it must run first, followed by css-loader, and finally style-loader.

The Transformation Pipeline

Loaders are designed to transform source code from one format to another in a step-by-step pipeline. For a Sass file to end up as styles applied on a web page, the transformation must happen in a specific order:

  1. sass-loader: Takes raw SCSS/Sass and compiles it into standard CSS.
  2. css-loader: Takes that standard CSS, resolves @import and url() statements, and translates it into a JavaScript module.
  3. style-loader: Takes the exported CSS string module and creates a <style> tag to inject the CSS into the DOM.

If Webpack executed left-to-right, style-loader would attempt to inject uncompiled Sass directly into the DOM, breaking the build. Reading from right-to-left (or bottom-to-top when formatted vertically) ensures that each loader receives the transformed output of the loader that ran immediately before it.

Pitching vs. Normal Phases

While loader transformations run from right-to-left, Webpack's loader runtime actually operates in two distinct phases: the pitching phase and the normal phase.

|- style-loader `pitch`
  |- css-loader `pitch`
    |- sass-loader `pitch`
       [File is read from disk]
    |- sass-loader (normal execution)
  |- css-loader (normal execution)
|- style-loader (normal execution)
  1. Pitching Phase (Left-to-Right): Webpack iterates through the array from left to right (0 to \(n\)), checking if each loader defines a pitch method. If a loader's pitch method returns a value, Webpack skips the remaining loaders, bypasses reading the source file, and immediately reverses execution to the normal phase of the preceding loaders.
  2. Normal Phase (Right-to-Left): If no pitch method returns a result, Webpack reads the target file from the filesystem and executes each loader's normal export function from right to left (\(n\) to 0), passing the transformed source down the line until the final module is generated.

Webpack uses the right-to-left order for its normal phase to align directly with function composition, allowing developers to pipe data cleanly from one transform to the next.
