Bundle Electron Main and Renderer with Webpack

This article provides a concise guide on configuring Webpack to compile and bundle an Electron application. Because Electron operates across two distinct runtime environments—Node.js for the main process and Chromium for the renderer process—Webpack must be configured to produce separate bundles tailored to the security and architectural needs of each environment.

Understanding the Process Separation

An Electron application consists of at least two primary components:

  1. The Main Process: Runs in a full Node.js environment, controls the application lifecycle, creates native GUI elements, and manages native operating system interactions.
  2. The Renderer Process: Displays web pages and runs inside a Chromium browser window. For modern security practices, this environment should be sandboxed without direct Node.js access.
  3. The Preload Script: Acts as a secure bridge between the main and renderer processes, exposing selective Node.js APIs to the renderer via contextBridge.

Because these environments require different polyfills, globals, and compilation targets, Webpack must handle them via separate configuration objects.

Webpack Configuration Architecture

The cleanest way to bundle an Electron application is by exporting an array of configurations from a single webpack.config.js file. Webpack's multi-compiler mode executes each configuration concurrently.

Project Directory Structure

my-electron-app/

The Multi-Target webpack.config.js

Below is the complete configuration addressing the main process, preload script, and renderer process:

const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

const isProduction = process.env.NODE_ENV === 'production';

// 1. Main Process Configuration
const mainConfig = {
  mode: isProduction ? 'production' : 'development',
  entry: './src/main/main.js',
  target: 'electron-main',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'main.js',
    clean: true,
  },
  node: {
    __dirname: false,
    __filename: false,
  },
};

// 2. Preload Script Configuration
const preloadConfig = {
  mode: isProduction ? 'production' : 'development',
  entry: './src/preload/preload.js',
  target: 'electron-preload',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'preload.js',
  },
};

// 3. Renderer Process Configuration
const rendererConfig = {
  mode: isProduction ? 'production' : 'development',
  entry: './src/renderer/index.js',
  target: 'web', // Use 'web' to enforce contextIsolation and sandbox security
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'renderer.js',
  },
  module: {
    rules: [
      {
        test: /\.css$/,
        use: ['style-loader', 'css-loader'],
      },
      {
        test: /\.(png|svg|jpg|jpeg|gif)$/i,
        type: 'asset/resource',
      },
    ],
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/renderer/index.html',
    }),
  ],
};

module.exports = [mainConfig, preloadConfig, rendererConfig];

Key Configuration Directives

target: 'electron-main'

This tells Webpack to bundle for a Node.js runtime while keeping built-in Electron APIs (such as app, BrowserWindow, and ipcMain) external rather than attempting to bundle them.

target: 'electron-preload'

Preload scripts require access to certain Node.js primitives and the Electron renderer module to set up contextBridge. Using electron-preload ensures compatibility while keeping runtime dependencies isolated.

target: 'web'

Modern Electron security best practices dictate that contextIsolation should be set to true and nodeIntegration set to false. Therefore, the renderer should be compiled with target: 'web' rather than target: 'electron-renderer'. This prevents Webpack from including Node.js polyfills or modules that will fail in a sandboxed browser context.

Preserving __dirname

In the main process configuration, setting __dirname: false inside the node object prevents Webpack from overwriting the Node.js __dirname global with a virtual root path (/). This ensures path resolution to the preload.js and index.html files works properly at runtime.

Linking the Bundled Files in main.js

Within your src/main/main.js entry file, reference the output files generated in the dist directory:

const { app, BrowserWindow } = require('electron');
const path = require('path');

function createWindow() {
  const mainWindow = new BrowserWindow({
    width: 1024,
    height: 768,
    webPreferences: {
      preload: path.join(__dirname, 'preload.js'),
      contextIsolation: true,
      nodeIntegration: false,
      sandbox: true,
    },
  });

  mainWindow.loadFile(path.join(__dirname, 'index.html'));
}

app.whenReady().then(createWindow);

app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') {
    app.quit();
  }
});

Build Integration

Add the standard build scripts to your package.json to handle development and production builds:

{
  "main": "dist/main.js",
  "scripts": {
    "build": "webpack --mode production",
    "watch": "webpack --watch --mode development",
    "start": "electron ."
  },
  "devDependencies": {
    "css-loader": "^7.1.2",
    "electron": "^30.0.0",
    "html-webpack-plugin": "^5.6.0",
    "style-loader": "^4.0.0",
    "webpack": "^5.91.0",
    "webpack-cli": "^5.1.4"
  }
}

Running npm run build will trigger all three Webpack configurations concurrently and output main.js, preload.js, renderer.js, and index.html directly into the dist/ directory, ready to be executed by Electron.
