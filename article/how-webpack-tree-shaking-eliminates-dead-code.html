How Webpack Tree Shaking Eliminates Dead Code

Tree shaking is a dead-code elimination technique that removes unused JavaScript exports from final production bundles to reduce file size and improve loading performance. In Webpack, this optimization relies on the static structure of ES modules, abstract syntax tree (AST) analysis to mark unused exports, module-level side-effect detection, and a minifier like Terser to permanently strip the dead code. This article explains the exact step-by-step mechanism Webpack uses to identify, mark, and eliminate this unused code during the build process.

Reliance on Static ES Module Syntax

Tree shaking requires static module structure, which is provided by ES6 modules using import and export statements. Unlike CommonJS (require() and module.exports), which allows dynamic imports inside conditionals or functions at runtime, ES module imports and exports are completely static. Webpack reads this syntax at compile time without executing the code, determining the exact dependency tree beforehand. If a project or third-party package compiles down to CommonJS before Webpack processes it, tree shaking cannot determine unused exports and fails to eliminate dead code.

Dependency Graph Analysis and Marking

When Webpack compiles an application, it parses the code into an Abstract Syntax Tree (AST) and constructs an internal module graph. During this phase:

  1. Import/Export Mapping: Webpack tracks all defined exports in every module and maps them against the imports requested by dependent modules.
  2. Export Tagging: Through its internal FlagDependencyExportsPlugin and SideEffectsFlagPlugin, Webpack tags unused exports. In the output code prior to minification, Webpack annotates unused items with comments such as /* unused harmony export [name] */.
  3. Reference Rewriting: Webpack rewrites the module code to sever direct references to those unused exports, transforming them into dangling variables or unused statements.

The sideEffects Property

A major challenge in dead-code elimination is code that performs an action upon import, such as modifying global prototypes, polyfilling, or importing global CSS. If an entire file is imported but none of its exports are used, Webpack cannot safely delete the file unless it knows the file has no side effects.

Developers declare this behavior in package.json using the sideEffects property:

  • "sideEffects": false: Informs Webpack that none of the files in the package produce runtime side effects. If an import from this package has no used exports, Webpack skips including the file entirely.
  • "sideEffects": ["*.css", "./src/polyfills.js"]: Informs Webpack to retain specific files that perform side effects while safely shaking the rest.

Dead Code Elimination via Minification

Webpack itself does not directly delete dead code statements; it analyzes, marks, and isolates them. The actual elimination is handed off to a minifier, typically Terser (via terser-webpack-plugin) or SWC/ESBuild minifiers.

Because Webpack has already decoupled the unused exports and marked them as unreferenced variables, the minifier performs Dead Code Elimination (DCE). The minifier traverses the code, detects that the isolated functions, objects, or variables have zero references, and strips them entirely from the output bundle.

Production Configuration Requirements

Webpack enables the full tree shaking pipeline automatically when the configuration mode is set to production:

module.exports = {
  mode: 'production',
  optimization: {
    usedExports: true,
    sideEffects: true,
    minimize: true,
  },
};
  • usedExports: true instructs Webpack to determine and tag unused exports for each module.
  • sideEffects: true instructs Webpack to recognize the sideEffects flag in package.json to drop whole unused files.
  • minimize: true executes the minifier to delete the marked, unreferenced code.
