Webpack 5 clean Option vs CleanWebpackPlugin

Webpack 5 introduced the built-in output.clean configuration option, providing a native mechanism to clean your build directory prior to emitting new bundles. This article explains how the native output.clean option works, how it directly compares to the traditionally used clean-webpack-plugin (often referenced as CleanWebpackPlugin), and why migrating to the native solution simplifies your build configuration.

Understanding Webpack 5's output.clean

In Webpack 5, the output.clean option handles clearing the output directory (defined by output.path) before generating new files. Previously, Webpack left stale assets in the distribution folder, which could lead to confusion or deployment of unused files when bundle hashes changed.

Enabling it natively requires no extra packages. In its simplest form, it takes a boolean:

module.exports = {
  output: {
    filename: '[name].[contenthash].js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
};

Webpack 5 also supports advanced configurations through an object:

  • keep: A RegExp, function, or string to preserve specific files (e.g., keep: /ignored-dir\//).
  • dry: A boolean (true/false) to log which files would be removed without actually deleting them.

What is CleanWebpackPlugin?

Before Webpack 5, the standard community approach to cleaning output folders was the third-party package clean-webpack-plugin. It hook into the Webpack compilation lifecycle via the plugins array:

const { CleanWebpackPlugin } = require('clean-webpack-plugin');

module.exports = {
  plugins: [
    new CleanWebpackPlugin({
      cleanStaleWebpackAssets: true,
      protectWebpackAssets: false,
    }),
  ],
};

This plugin provided extensive configuration options, such as glob pattern matching, cleaning files outside the Webpack build directory, and granular lifecycle hooks.

Key Differences

1. Zero External Dependencies

The most significant difference is that output.clean is built directly into the Webpack 5 core. Using it removes clean-webpack-plugin from your package.json, reducing dependency bloat, security audit overhead, and compatibility issues across minor Webpack updates.

2. Configuration Simplicity

Configuring the native feature is concise. Instead of importing a plugin class and adding it to the plugins array, setting output.clean: true handles the vast majority of standard use cases.

3. Execution Lifecycle and Performance

Because output.clean is an internal Webpack feature, it integrates seamlessly with Webpack 5's file-system caching and Asset Modules. It only removes files created by previous builds or outdated assets within the designated output.path, minimizing unexpected file deletions. In contrast, clean-webpack-plugin operates as an external lifecycle listener and occasionally required workarounds for development servers or watch mode (e.g., cleanStaleWebpackAssets: false).

4. Advanced Matching and Path Boundaries

While output.clean covers almost all typical workflows, clean-webpack-plugin offers broader flexibility for edge cases:

  • Outside Output Paths: clean-webpack-plugin can delete files located outside of Webpack's output.path (e.g., clearing root-level temp folders), though this requires explicit opt-in via dangerouslyAllowCleanPatternsOutsideProject.
  • Pattern Matching: CleanWebpackPlugin uses full glob syntax for removals. Webpack 5's output.clean relies on regular expressions or predicate functions via the keep property.

Which Should You Use?

For nearly all Webpack 5 projects, the native output.clean is the recommended choice. It eliminates an unnecessary dependency, runs cleanly alongside modern Webpack features, and requires minimal configuration. CleanWebpackPlugin should only be retained if your build pipeline explicitly depends on cleaning directories outside the defined output.path.
