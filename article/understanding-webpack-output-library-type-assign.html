Understanding Webpack output.library.type = 'assign'

This article provides an overview of the output.library.type = 'assign' configuration in Webpack 5, explaining how it formats bundle exports, how it contrasts with standard variable declarations, and the specific use cases where direct assignment is necessary.

What is output.library.type = 'assign'?

In modern Webpack (version 5 and newer), the output.library configuration controls how your compiled JavaScript bundle exposes its entry point's exports to external consumers.

When you set output.library.type = 'assign', Webpack generates code that uses a standard assignment expression (=) to assign your bundle's exports to the identifier defined in output.library.name. Unlike other library targets, it does not prepend a declaration keyword such as var, const, or let.

Configuration Example

To use this configuration, specify both the library name and the 'assign' type in your webpack.config.js:

module.exports = {
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    library: {
      name: 'MyLibrary',
      type: 'assign'
    }
  }
};

When Webpack builds this bundle, the resulting output structure assigns the bundled module directly to MyLibrary:

MyLibrary = (() => {
  // Bundled module code
  return { /* your exports */ };
})();

How It Compares to output.library.type = 'var'

The default target in many classic configurations is var. Understanding the distinction between var and assign clarifies why 'assign' exists:

  • type: 'var': Produces var MyLibrary = .... This declares a new variable in the local or global scope.
  • type: 'assign': Produces MyLibrary = .... This performs an assignment to a target that is presumed to already exist or that will implicitly become global in non-strict environments.

Common Use Cases

1. Attaching to Existing Namespaces or Deep Paths

The primary use case for 'assign' is populating an existing global object or a nested namespace. If output.library.name is configured with an object property or nested path, a var declaration would produce invalid JavaScript syntax (such as var window.MyLibrary = ...). With 'assign', Webpack produces valid code:

module.exports = {
  output: {
    library: {
      name: ['window', 'App', 'Services'],
      type: 'assign'
    }
  }
};

This compiles to window.App.Services = ..., assuming window.App is already initialized.

2. Avoiding Identifier Re-declaration

In applications where bundles are loaded dynamically or multiple times, declaring an existing variable with var, let, or const can cause syntax errors or unintended shadowing. The 'assign' target overwrites the target variable cleanly without altering its declaration scope.

Important Caveats

When using type: 'assign', be mindful of strict mode. In JavaScript strict mode ("use strict";), assigning a value to an undeclared variable throws a ReferenceError. If the variable specified in output.library.name does not exist in the host environment prior to executing the bundle, the assignment will fail. Always ensure the receiving variable or object hierarchy is initialized before the bundle script executes.
