Using postcss-preset-env with Webpack

This article explains what postcss-preset-env is, why it is essential for modern web development, and how to seamlessly integrate it with Webpack using postcss-loader. You will learn how this PostCSS plugin converts modern CSS specifications into browser-compatible styles, how to configure your build tools, and how to manage browser targets effectively.

What is postcss-preset-env?

postcss-preset-env is a PostCSS plugin that allows developers to write future-facing CSS using the latest W3C CSS specifications. Much like Babel compiles modern JavaScript (ES6+) down to backwards-compatible JavaScript, postcss-preset-env polyfills modern CSS features based on your target browser environment.

Key features include:

  • Specification Stages: It groups upcoming CSS features by their CSS Working Group stability stages (Stage 0 to Stage 4). By default, it enables Stage 2 (Draft) features.
  • Built-in Autoprefixer: It automatically applies vendor prefixes, meaning you do not need to install or run autoprefixer as a separate plugin.
  • Browserslist Integration: It queries your project's Browserslist configuration to determine which polyfills and fallbacks are necessary for your supported browsers.

How it Integrates with postcss-loader in Webpack

Webpack processes assets through a chain of loaders. For CSS, Webpack typically uses:

  1. postcss-loader to transform CSS using PostCSS plugins (like postcss-preset-env).
  2. css-loader to resolve @import and url() paths.
  3. style-loader or MiniCssExtractPlugin.loader to inject styles into the DOM or extract them into separate CSS files.

1. Installation

Install the required packages as development dependencies:

npm install --save-dev postcss postcss-loader postcss-preset-env css-loader style-loader

2. Configure PostCSS

The cleanest way to configure PostCSS is via a dedicated configuration file named postcss.config.js in your project root:

module.exports = {
  plugins: [
    [
      'postcss-preset-env',
      {
        stage: 2, // Enable Stage 2 features or specify a custom stage
        features: {
          'nesting-rules': true, // Explicitly enable or disable specific features
        },
      },
    ],
  ],
};

3. Configure Webpack

In your webpack.config.js, configure a rule for handling .css files with postcss-loader:

const path = require('path');

module.exports = {
  module: {
    rules: [
      {
        test: /\.css$/i,
        use: [
          'style-loader', // Injects styles into the DOM
          'css-loader',   // Resolves CSS imports
          'postcss-loader' // Processes CSS with PostCSS
        ],
      },
    ],
  },
};

When Webpack processes a CSS file, postcss-loader automatically detects and uses the postcss.config.js file, passing the code through postcss-preset-env.

4. Define Target Browsers

To ensure postcss-preset-env applies only the polyfills your users need, define your target environments using a .browserslistrc file in your root directory:

> 0.5%
last 2 versions
Firefox ESR
not dead

Alternatively, add a "browserslist" field directly to your package.json:

"browserslist": [
  "> 0.5%",
  "last 2 versions",
  "not dead"
]

With this setup complete, you can write modern CSS features—such as CSS nesting, custom media queries, and newer color functions—and Webpack will automatically compile them into widely supported CSS during your build step.
