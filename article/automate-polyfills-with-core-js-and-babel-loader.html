Automate Polyfills with Core-JS and Babel-Loader

Automating polyfill injection ensures that modern JavaScript features work seamlessly across older browsers without unnecessarily bloating bundle sizes. By integrating core-js with babel-loader and @babel/preset-env inside your Webpack configuration, Babel automatically analyzes your source code against defined browser targets and injects only the polyfills required by those specific environments.

1. Install Required Packages

First, install the necessary dependencies. You need core-js as a production dependency because the polyfills must exist in the final runtime bundle. The Babel and Webpack integration tools should be installed as development dependencies.

Run the following command:

npm install --save core-js@3
npm install --save-dev @babel/core @babel/preset-env babel-loader webpack webpack-cli

2. Define Browser Targets with Browserslist

@babel/preset-env requires a target environment definition to determine which polyfills are actually needed. Add a browserslist entry to your package.json, or create a separate .browserslistrc file at the root of your project:

{
  "browserslist": [
    "> 0.5%",
    "last 2 versions",
    "not dead"
  ]
}

3. Configure Babel

Create a babel.config.json file in your project root. To enable automatic polyfilling, configure @babel/preset-env with the useBuiltIns option set to "usage" and specify the core-js version.

{
  "presets": [
    [
      "@babel/preset-env",
      {
        "useBuiltIns": "usage",
        "corejs": {
          "version": "3.36",
          "proposals": true
        }
      }
    ]
  ]
}
  • useBuiltIns: "usage": Scans your code for ECMAScript features (such as Promise, Array.prototype.flat, or Object.assign) and imports only the required core-js submodules automatically where used.
  • corejs: 3: Tells Babel to target core-js version 3. Specifying a minor version (e.g., "3.36") allows Babel to use newer polyfills available in that version. Setting proposals: true enables polyfills for stage proposals if your code uses experimental features.

4. Configure Webpack

Next, instruct Webpack to process JavaScript files using babel-loader. Update or create your webpack.config.js:

const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
  module: {
    rules: [
      {
        test: /\.m?js$/,
        exclude: /node_modules/,
        use: {
          loader: 'babel-loader',
        },
      },
    ],
  },
};

Ensure the exclude: /node_modules/ rule is present. Polyfilling already-compiled third-party modules can significantly slow down build times and potentially introduce redundant polyfill code.

Verification

When you run Webpack, you no longer need to write import "core-js" anywhere in your application. If your source code contains modern methods, Webpack and Babel will automatically prepend statements like require("core-js/modules/es.array.flat.js") directly into the files where those methods are invoked, provided your target browsers lack native support.
