Webpack Loaders for 3D Assets: GLTF and OBJ

Integrating 3D assets into modern web applications requires handling binary and text-based model files such as GLTF, GLB, and OBJ. This article outlines the essential Webpack mechanisms and loaders used to bundle these files, comparing modern Webpack 5 built-in Asset Modules with specialized loaders designed to parse 3D geometries directly into JavaScript.

Webpack 5 Built-in Solution: Asset Modules

In Webpack 5, dedicated file-handling loaders are largely obsolete. The recommended approach for 3D formats like .gltf, .glb, .obj, .mtl, and .bin is using Asset Modules, specifically asset/resource.

When configured with asset/resource, Webpack emits the 3D file to the output directory and exports the public URL string. This URL is then passed directly to WebGL framework loaders, such as Three.js (GLTFLoader, OBJLoader) or Babylon.js.

// webpack.config.js
module.exports = {
  module: {
    rules: [
      {
        test: /\.(gltf|glb|obj|mtl|bin|fbx)$/i,
        type: 'asset/resource',
        generator: {
          filename: 'assets/models/[name][hash][ext]',
        },
      },
    ],
  },
};

Specialized 3D Loaders

When you need to parse geometry at build time rather than runtime, specialized loaders transform the file data into structured JSON or native objects directly inside your bundle.

1. webpack-obj-loader

The webpack-obj-loader parses .obj and companion .mtl files directly during the Webpack build step. Instead of returning a URL string, importing the file returns an object containing parsed mesh data (vertices, vertex normals, texture coordinates, and faces).

  • Use Case: Best suited for lightweight OBJ models where you want immediate access to geometry data without fetching the file via an HTTP request at runtime.
  • Configuration:
module.exports = {
  module: {
    rules: [
      {
        test: /\.obj$/,
        loader: 'webpack-obj-loader',
      },
    ],
  },
};

2. raw-loader (or asset/source)

Wavefront OBJ and MTL files are plain-text formats. If you prefer to parse them with a custom or framework-specific parser at runtime without making an extra network request, you can import them as raw strings.

  • Webpack 5: Use type: 'asset/source'.
  • Webpack 4: Use raw-loader.
module.exports = {
  module: {
    rules: [
      {
        test: /\.(obj|mtl)$/i,
        type: 'asset/source',
      },
    ],
  },
};

Legacy Loaders (Webpack 4 and Below)

In Webpack 4, native asset handling was not present, requiring external packages:

  • file-loader: Copies the model file to the output directory and returns the generated URL. This was the universal choice for .gltf, .glb, .obj, and accompanying textures.
  • url-loader: Conditionally inlines models as base64 data URIs if they fall below a designated file-size threshold. While functional for tiny OBJ or GLTF files, it is rarely recommended for large 3D models due to increased bundle size and memory overhead.

Managing Dependent Assets in GLTF and OBJ

A common issue with 3D formats is external dependencies. A .gltf file often references .bin buffers and .png/.jpg textures, while an .obj file references .mtl files.

  • Single-file formats: Use .glb (binary GLTF) whenever possible. A .glb embeds all meshes, buffers, and textures into a single self-contained binary file, eliminating path resolution issues in Webpack.
  • Multi-file formats: When using unpacked .gltf or .obj, ensure that your Webpack configuration includes rules for .bin, image files, and .mtl files using matching output paths so the relative references inside the models remain intact at runtime.
