Understanding Webpack maxAsyncRequests in Code Splitting

The maxAsyncRequests configuration in Webpack controls the maximum number of parallel HTTP requests allowed when loading on-demand chunks via dynamic imports. In modern web performance optimization, excessive code splitting can create too many tiny files, leading to request overhead. This article explains what maxAsyncRequests is, how it influences chunk generation in Webpack's SplitChunksPlugin, and how to configure it effectively for your application.

What is maxAsyncRequests?

In Webpack, optimization.splitChunks.maxAsyncRequests acts as an upper limit on how many separate files (chunks) can be requested simultaneously when an asynchronous entry point or dynamic import() is triggered.

When you dynamically import a module using import('./module'), Webpack attempts to split shared dependencies into separate chunks to maximize browser caching. However, every additional chunk generated creates an additional HTTP request. maxAsyncRequests tells Webpack to stop splitting chunks for that specific on-demand import once the specified threshold of parallel network requests is reached.

How It Works in Practice

When Webpack analyzes an asynchronous import:

  1. It counts the primary chunk generated for the dynamic import itself as the first request.
  2. It identifies shared libraries or vendor modules that qualify for splitting based on size and cache group rules.
  3. It incrementally creates separate chunks for these modules, prioritizing larger chunks first.
  4. Once the total count of parallel requests for that import reaches the maxAsyncRequests limit, Webpack halts further splitting. Any remaining modules that would have otherwise been split are bundled directly into the remaining chunks instead.

For example, if a dynamic module imports 10 distinct libraries and your maxAsyncRequests is set to 5:

  • 1 request is used for the module itself.
  • 4 requests are used for the 4 highest-priority shared chunks.
  • Any remaining dependencies are grouped into these existing chunks rather than creating 6 more network requests.

Default Value and Configuration

In Webpack 5, the default value for maxAsyncRequests is 30. In Webpack 4, the default was significantly lower, set to 5.

You can customize this setting in your webpack.config.js:

module.exports = {
  // ...
  optimization: {
    splitChunks: {
      maxAsyncRequests: 10,
    },
  },
};

You can also override this value on a per-cache-group basis if certain packages require different splitting strategies.

When to Adjust maxAsyncRequests

  • Decrease the value if your users frequently operate on high-latency mobile networks or legacy HTTP/1.1 connections where each individual request suffers from connection-handshake bottlenecks and head-of-line blocking.
  • Increase the value if you serve assets strictly over HTTP/2 or HTTP/3, which support multiplexing and handle many concurrent requests efficiently, enabling more granular caching of small utilities across your application.
