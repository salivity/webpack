Webpack Compiler vs Compilation Hooks Explained

Webpack's plugin architecture relies on the Tapable library, exposing two core objects that define its build lifecycle: the Compiler and the Compilation. The primary difference between their hooks is their scope and lifespan: Compiler hooks represent the entire Webpack runtime, managing global configuration and high-level build states, while Compilation hooks represent a single build cycle, managing the dependency graph, modules, and chunk generation. Understanding the distinct roles of these hooks is essential for creating custom plugins and controlling asset processing.

The Compiler and Its Hooks

The Compiler instance is created once when Webpack starts. It maintains all global settings, options, loaders, and plugins across the entire lifecycle of the Webpack process.

Key characteristics of the Compiler:

  • Lifespan: Runs from the moment Webpack boots until it exits. In watch mode, a single Compiler instance persists throughout the process.
  • Scope: Handles operations external to the dependency graph, such as reading configuration, initializing watchers, emitting files to disk, and reporting build completion.
  • Common Hooks:
    • environment / afterEnvironment: Triggered right after the configuration and environment are initialized.
    • run / watchRun: Fired before Webpack begins reading modules or compiling.
    • compile: Fired immediately before a new compilation cycle begins, passing compilationParams.
    • emit: Executed right before Webpack writes compiled assets to the output directory.
    • done: Triggered when the entire build process finishes and stats are ready.

Use Compiler hooks when you need to inspect high-level configuration, interact with the file system before or after a build, or respond to process termination.

The Compilation and Its Hooks

A Compilation instance is created by the Compiler whenever Webpack processes your source files. It contains the state of the dependency tree, individual modules, chunks, and rendered assets for a specific build.

Key characteristics of the Compilation:

  • Lifespan: Transient. A new Compilation object is generated every time code changes during watch mode or hot module replacement (HMR).
  • Scope: Handles the transformation of source code, module resolution, optimization passes, and chunk graph construction.
  • Common Hooks:
    • buildModule: Triggered before an individual module is built.
    • succeedModule: Fired when a module has been successfully parsed and loaded.
    • seal: Fired when the compilation stops receiving new modules and begins organizing them into chunks.
    • optimizeModules / optimizeChunks: Triggered during internal tree-shaking and minification optimization passes.
    • processAssets: The standard hook for modifying, adding, or deleting generated output assets before emission.

Use Compilation hooks when your plugin needs to analyze individual source files, modify the dependency tree, alter chunk composition, or transform output asset contents.

Core Differences at a Glance

Feature Compiler Hooks Compilation Hooks
Instance Count Singleton per Webpack run One per build or re-compile cycle
Watch Mode Persists across file changes Destroyed and recreated on every change
Primary Focus Build orchestration, environment, file I/O Dependency graphs, modules, chunks, assets
Data Handled Global options, file systems, final outputs Source files, ASTs, intermediate representations

Connecting the Two in a Plugin

In standard Webpack plugin development, you access Compilation hooks by tapping into the Compiler first. The Compiler provides a hook called thisCompilation or compilation, which exposes the fresh Compilation instance to your plugin logic:

class ExamplePlugin {
  apply(compiler) {
    // Compiler Hook: Runs at the start of the entire process
    compiler.hooks.run.tap('ExamplePlugin', (compilerInstance) => {
      console.log('Build process starting...');
    });

    // Compiler Hook: Accessing the Compilation instance
    compiler.hooks.compilation.tap('ExamplePlugin', (compilation) => {
      // Compilation Hook: Runs whenever assets are processed
      compilation.hooks.processAssets.tap('ExamplePlugin', (assets) => {
        console.log('Processing assets for this build pass.');
      });
    });
  }
}

module.exports = ExamplePlugin;

As a general rule, use Compiler hooks for macro-level tasks like setting up services or moving files, and use Compilation hooks for micro-level operations like code transformation, dependency analysis, and asset manipulation.
