Webpack Performance: Set Asset and Entrypoint Limits

This guide covers how to monitor and restrict bundle sizes in Webpack using the native performance configuration object. You will learn how to define limits for both individual emitted assets and initial entrypoints, customize the severity of threshold violations between warnings and errors, and exclude specific file types from size calculations.

The Webpack Performance Configuration

Webpack provides a built-in performance option inside webpack.config.js. This feature checks the output file sizes against defined thresholds after each build and alerts developers if the files exceed the specified size.

Here is a standard configuration example:

const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: path.resolve(__dirname, 'dist'),
  },
  performance: {
    hints: 'warning', // 'warning', 'error', or false
    maxAssetSize: 250000, // Size in bytes (approx. 244 KiB)
    maxEntrypointSize: 400000, // Size in bytes (approx. 390 KiB)
    assetFilter: function (assetFilename) {
      // Apply performance checks only to JavaScript and CSS files
      return assetFilename.endsWith('.js') || assetFilename.endsWith('.css');
    },
  },
};

Key Performance Options

1. hints

The hints property determines how Webpack responds when an asset or entrypoint exceeds the configured thresholds:

  • 'warning' (default in production mode): Emits a build warning in the console without failing the build process.
  • 'error': Emits a build error and causes the compilation process to fail with an exit code, which is ideal for CI/CD pipelines to prevent oversized bundles from being deployed.
  • false: Completely disables performance hints and calculations.

2. maxAssetSize

The maxAssetSize property sets the maximum file size limit for any single emitted asset (such as an individual .js, .css, or image file).

  • The value is measured in bytes.
  • The default threshold in Webpack is 250000 bytes (approximately 244 KiB).
  • If an individual emitted file exceeds this value, Webpack triggers the configured hint.

3. maxEntrypointSize

The maxEntrypointSize property sets the threshold for the total size of all assets combined that are required during the initial load of a specific entrypoint.

  • The value is measured in bytes.
  • The default threshold is 250000 bytes.
  • This calculation includes all assets loaded upfront by the entrypoint (e.g., initial JS and CSS bundles combined), but excludes dynamically imported, asynchronously loaded chunks.

4. assetFilter

The assetFilter option is a predicate function that allows you to exclude specific files from being evaluated against the size limits.

  • Webpack passes the emitted file name (assetFilename) as an argument.
  • Return true to apply the size checks to the asset.
  • Return false to ignore the asset, which is useful for bypassing non-critical static assets like images, source maps (.map), or font files.

Environment-Based Configuration

It is best practice to enable strict errors in continuous integration environments while keeping checks relaxed during local development:

module.exports = (env, argv) => {
  const isProduction = argv.mode === 'production';

  return {
    // ...other configuration settings
    performance: {
      hints: isProduction ? 'error' : false,
      maxAssetSize: 300000,
      maxEntrypointSize: 500000,
    },
  };
};

This ensures fast local compilation without disruption, while enforcing strict bundle budgets before code is merged or deployed.
