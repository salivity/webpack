How to Proxy API Requests with Webpack Dev Server

When developing single-page applications, frontend and backend code often run on different local ports, resulting in Cross-Origin Resource Sharing (CORS) errors during API requests. Webpack Dev Server solves this issue through its built-in proxy feature, powered by http-proxy-middleware. This guide covers how to configure the devServer.proxy property in your Webpack configuration to seamlessly forward frontend requests to a local or remote backend server.

Basic Proxy Configuration

To forward API requests, open your webpack.config.js file and locate the devServer configuration object. Define the proxy property to map a request URL pattern to your target server:

// webpack.config.js
module.exports = {
  // ... other webpack settings
  devServer: {
    port: 3000,
    proxy: [
      {
        context: ['/api'],
        target: 'http://localhost:5000',
        changeOrigin: true,
      },
    ],
  },
};

In this setup, any request initiated by the frontend matching /api (for example, /api/users) will be intercepted by Webpack Dev Server and forwarded to http://localhost:5000/api/users.

Common Configuration Options

Depending on your backend architecture, you may need additional settings within the proxy entry:

  • changeOrigin: Set to true if your backend relies on the incoming Host header matching its own domain. This is essential when proxying to name-based virtual hosts or remote cloud environments.
  • pathRewrite: Use this to rewrite the request path before it hits the backend. For instance, if your frontend requests /api/users but your backend endpoint is simply /users, strip the prefix using a regular expression:
proxy: [
  {
    context: ['/api'],
    target: 'http://localhost:5000',
    pathRewrite: { '^/api': '' },
    changeOrigin: true,
  },
]
  • secure: By default, the proxy rejects backend targets using invalid or self-signed SSL certificates. If your backend uses HTTPS locally with a self-signed certificate, set secure: false:
proxy: [
  {
    context: ['/api'],
    target: 'https://localhost:5001',
    secure: false,
    changeOrigin: true,
  },
]

Proxying Multiple Specific Paths

If you need to route multiple distinct paths to the same destination without catching all traffic, pass an array to the context option:

proxy: [
  {
    context: ['/auth', '/api', '/media'],
    target: 'http://localhost:8080',
    changeOrigin: true,
  },
]

Bypassing the Proxy

You can conditionally bypass the proxy based on the incoming request using the bypass function. This is useful for serving mock files or allowing browser navigation to proceed normally:

proxy: [
  {
    context: ['/api'],
    target: 'http://localhost:5000',
    bypass: function (req, res, proxyOptions) {
      if (req.headers.accept.indexOf('html') !== -1) {
        return '/index.html';
      }
    },
  },
]

Once configured, restart your Webpack development server. Requests sent to paths matching your proxy rules will automatically route through the dev server to your specified backend without encountering CORS restrictions.
