Upload Webpack Build Artifacts to Amazon S3

This guide provides a straightforward walkthrough on how to configure Webpack to automatically upload compiled assets to an Amazon S3 bucket during the build process. By leveraging the webpack-s3-plugin, you can bypass manual upload steps and streamline your continuous integration and deployment pipelines by transmitting your bundles, source maps, and static assets directly to cloud storage.

Prerequisites

Before configuring Webpack, ensure you have:

  • An AWS account with an active Amazon S3 bucket.
  • An IAM user with programmatic access containing policies that grant s3:PutObject and s3:PutObjectAcl permissions for your target bucket.
  • The AWS Access Key ID and Secret Access Key stored securely in environment variables.

Step 1: Install Required Dependencies

Webpack requires a dedicated plugin to handle the transfer of emitted assets to Amazon S3. Install webpack-s3-plugin alongside dotenv to securely manage your credentials:

npm install --save-dev webpack-s3-plugin dotenv

Step 2: Configure Environment Variables

Create a .env file in the root of your project to hold your AWS credentials. Do not commit this file to version control.

AWS_ACCESS_KEY_ID=your_access_key_id
AWS_SECRET_ACCESS_KEY=your_secret_access_key
AWS_REGION=us-east-1
S3_BUCKET_NAME=your-target-bucket-name

Step 3: Update webpack.config.js

Import the plugin and add it to the plugins array. Webpack will compile the files into your local output directory and immediately trigger the S3 upload upon the afterEmit compilation hook.

const path = require('path');
const S3Plugin = require('webpack-s3-plugin');
require('dotenv').config();

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].[contenthash].js',
    publicPath: `https://${process.env.S3_BUCKET_NAME}.s3.${process.env.AWS_REGION}.amazonaws.com/`
  },
  plugins: [
    new S3Plugin({
      // Exclude uploading specific files (optional)
      exclude: /.*\.html$/,
      
      // Specify the local directory to upload
      s3Options: {
        accessKeyId: process.env.AWS_ACCESS_KEY_ID,
        secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
        region: process.env.AWS_REGION
      },
      s3UploadOptions: {
        Bucket: process.env.S3_BUCKET_NAME
      },
      // Target folder inside your S3 bucket (optional)
      basePath: 'assets'
    })
  ]
};

Step 4: Fine-Tune Upload Options

You can optimize the upload behavior by adding cache headers or compression support within s3UploadOptions:

  • Cache-Control: Add long-term caching headers for immutable assets:

    s3UploadOptions: {
  Bucket: process.env.S3_BUCKET_NAME,
  CacheControl: 'max-age=31536000, immutable'
}

  • Directory Matching: If your build outputs to nested folders, set directory: path.resolve(__dirname, 'dist') inside the S3Plugin options to maintain the directory structure in S3.

Step 5: Run the Build

Execute your standard Webpack production build:

npx webpack --mode production

During execution, Webpack compiles your bundles into the local output directory and streams them directly to your Amazon S3 bucket under the specified path.
