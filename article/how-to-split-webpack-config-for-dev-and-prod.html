How to Split Webpack Config for Dev and Prod

Splitting your Webpack configuration allows you to maintain clean, optimized setups for both local development and deployment. Instead of writing duplicate code or cluttering a single file with conditional statements, you can use a common base configuration and merge it with environment-specific files: webpack.dev.js and webpack.prod.js. This guide covers the installation of required utilities, structuring the configuration files, and updating npm scripts to run each build.

1. Install webpack-merge

To combine shared configurations with environment-specific settings, install webpack-merge as a development dependency:

npm install --save-dev webpack-merge

2. Create the Base Configuration (webpack.common.js)

The common file contains rules and settings shared between development and production, such as entry points, output paths, and general file loaders.

Create webpack.common.js:

const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  entry: './src/index.js',
  output: {
    filename: '[name].bundle.js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/index.html',
    }),
  ],
  module: {
    rules: [
      {
        test: /\.css$/i,
        use: ['style-loader', 'css-loader'],
      },
      {
        test: /\.(png|svg|jpg|jpeg|gif)$/i,
        type: 'asset/resource',
      },
    ],
  },
};

3. Create the Development Configuration (webpack.dev.js)

Development requires strong source mapping, a local development server, and fast build times.

Create webpack.dev.js:

const { merge } = require('webpack-merge');
const common = require('./webpack.common.js');

module.exports = merge(common, {
  mode: 'development',
  devtool: 'inline-source-map',
  devServer: {
    static: './dist',
    port: 3000,
    open: true,
    hot: true,
  },
});

4. Create the Production Configuration (webpack.prod.js)

Production targets performance, smaller bundle sizes, cache busting, and lightweight external source maps.

Create webpack.prod.js:

const { merge } = require('webpack-merge');
const common = require('./webpack.common.js');

module.exports = merge(common, {
  mode: 'production',
  devtool: 'source-map',
  output: {
    filename: '[name].[contenthash].js',
  },
  optimization: {
    splitChunks: {
      chunks: 'all',
    },
  },
});

5. Update package.json Scripts

Define scripts to execute Webpack using the --config flag to target the corresponding file:

"scripts": {
  "start": "webpack serve --config webpack.dev.js",
  "build": "webpack --config webpack.prod.js"
}

Running npm start now executes your development server using webpack.dev.js, while npm run build bundles your application for production using webpack.prod.js.
