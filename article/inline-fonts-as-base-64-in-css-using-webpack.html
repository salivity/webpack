Inline Fonts as Base64 in CSS Using Webpack

Inlining small font files directly into your compiled CSS as Base64-encoded Data URLs reduces HTTP requests and prevents flashes of unstyled text (FOUT). In modern Webpack, you can automatically inline fonts below a specific byte threshold while outputting larger files as separate assets by configuring Webpack’s built-in Asset Modules.

Webpack 5 Configuration (Asset Modules)

Webpack 5 introduced Asset Modules, replacing legacy loaders like url-loader and file-loader. To conditionally inline fonts based on file size, use the asset type paired with the parser.dataUrlCondition.maxSize option.

Add the following rule to the module.rules array in your webpack.config.js:

const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
  module: {
    rules: [
      {
        test: /\.css$/i,
        use: ['style-loader', 'css-loader'],
      },
      {
        test: /\.(woff|woff2|eot|ttf|otf)$/i,
        type: 'asset',
        parser: {
          dataUrlCondition: {
            maxSize: 8 * 1024, // 8 KB threshold
          },
        },
        generator: {
          filename: 'fonts/[name].[hash][ext]',
        },
      },
    ],
  },
};

How the Configuration Works

  1. test: /\.(woff|woff2|eot|ttf|otf)$/i: Matches common font formats referenced inside your CSS files via @font-face rules and url() declarations.
  2. type: 'asset': Instructs Webpack to automatically choose between emitting a separate file (asset/resource) and inlining the file as a Base64 URI (asset/inline).
  3. parser.dataUrlCondition.maxSize: Specifies the maximum file size in bytes for inlining. In the example above, any font smaller than 8,192 bytes (8 KB) is converted into a Base64 string and directly embedded into the CSS. Any font equal to or larger than 8 KB is emitted to the output directory using the path defined in generator.filename.
  4. css-loader Resolution: When css-loader encounters a @font-face { src: url('./font.woff2'); } rule, it delegates the asset resolution to Webpack's module rules. If the condition is met, the url(...) string in the generated CSS is replaced with data:font/woff2;charset=utf-8;base64,....

Webpack 4 Legacy Configuration

For projects running Webpack 4, the same behavior requires url-loader:

module.exports = {
  module: {
    rules: [
      {
        test: /\.(woff|woff2|eot|ttf|otf)$/,
        use: [
          {
            loader: 'url-loader',
            options: {
              limit: 8192, // 8 KB in bytes
              name: 'fonts/[name].[hash].[ext]',
              fallback: 'file-loader',
            },
          },
        ],
      },
    ],
  },
};

When using url-loader, files smaller than the limit value are transformed into Base64 Data URLs, while files exceeding the limit automatically fall back to file-loader to be emitted as standalone assets.
