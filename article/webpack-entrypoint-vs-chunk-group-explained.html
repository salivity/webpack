Webpack Entrypoint vs Chunk Group Explained

In Webpack, managing how code is bundled and loaded depends heavily on understanding the internal dependency graph. This article explains what an entrypoint is, defines chunk groups, and clarifies the key architectural differences between them to help optimize asset delivery.

What Is a Webpack Entrypoint?

An entrypoint represents the starting module or set of modules that Webpack uses to begin building its internal dependency graph. Defined via the entry property in webpack.config.js, it tells Webpack where to begin resolving imports and building out the application's module tree.

Assets derived directly from an entrypoint represent the initial bundles required to boot your application. In a browser environment, these manifest as the primary <script> and <link> tags inserted into your initial HTML document.

What Is a Chunk Group?

A chunk group is a collection of chunks that are loaded together. Webpack breaks modules down into distinct units called "chunks" (such as a vendor chunk, a main chunk, or a lazy-loaded chunk). A chunk group acts as a logical container that bundles these individual chunks together so they can be requested as a coordinated set.

Chunk groups can be created automatically through various Webpack mechanisms, such as dynamic import() statements (which create child chunk groups for code splitting) or through optimization configurations like optimization.splitChunks.

Key Differences Between an Entrypoint and a Chunk Group

  • Inheritance and Relationship: Under the hood, an Entrypoint in Webpack is actually a specialized subclass of ChunkGroup. Every entrypoint is a chunk group, but not every chunk group is an entrypoint.
  • Creation Source: Entrypoints are explicitly declared by the developer in the build configuration under the entry field. Other chunk groups are typically generated automatically by Webpack when it encounters code-splitting boundaries, such as dynamic import() statements or extracted vendor code.
  • Initial Loading vs. On-Demand Loading: An entrypoint defines the initial assets that must be loaded immediately when the page renders. Non-entry chunk groups usually represent asynchronous or on-demand assets fetched later during user interaction or route transitions.
  • Execution Runtime: Entrypoints are responsible for including the Webpack runtime code required to execute the bundle and resolve dynamic dependencies. Child chunk groups do not initialize the runtime; they rely on the runtime already initialized by an entrypoint.
