How to Prefetch and Preload Assets in Webpack

Modern web applications split code into smaller bundles to improve initial load times, but fetching these chunks on demand can introduce latency during user interactions. Webpack allows developers to implement browser resource hints—specifically prefetch and preload—to download assets strategically before they are strictly needed. This article examines the core patterns used to trigger these hints in Webpack, focusing on dynamic import magic comments, priority weighting, and plugin configurations for non-JavaScript assets.

Understanding Preload vs. Prefetch

Before implementing resource hints, it is important to distinguish between their purposes:

  • Preload (<link rel="preload">): Directs the browser to download a critical chunk with high priority for the current navigation. It executes in parallel with the parent chunk and is intended for resources needed almost immediately after the initial page load.
  • Prefetch (<link rel="prefetch">): Instructs the browser to download a chunk during idle time with low priority for future navigations. It is intended for resources a user might need on subsequent interactions, such as visiting a new route.

Pattern 1: Inline Magic Comments in Dynamic Imports

The primary mechanism for generating resource hints in Webpack is inline magic comments placed inside dynamic import() statements. When Webpack encounters these comments, it automatically injects corresponding <link> tags into the document head during bundle execution.

Implementing Prefetch

Use the /* webpackPrefetch: true */ comment to load non-critical resources during idle browser time:

// Triggered on idle time for future navigation
button.addEventListener('click', () => {
  import(/* webpackPrefetch: true */ './features/analyticsModal.js')
    .then(module => {
      module.openModal();
    });
});

When Webpack builds this module, it outputs an entry in the HTML head similar to:

<link rel="prefetch" as="script" href="analyticsModal.bundle.js">

Implementing Preload

Use the /* webpackPreload: true */ comment for chunks required during the current page lifecycle:

// Triggered with high priority alongside the parent bundle
import(/* webpackPreload: true */ './components/CriticalChart.js')
  .then(module => {
    module.render();
  });

Webpack outputs:

<link rel="preload" as="script" href="CriticalChart.bundle.js">

Note: Overusing preload can harm performance. If a chunk is preloaded but not consumed within a few seconds of page load, modern browsers will log a console warning.

Pattern 2: Priority Ordering with Numeric Values

When an application prefetches multiple chunks across different user flows, you can establish an explicit loading order. Webpack supports passing integer values to webpackPrefetch:

// High-probability next route (loads first)
import(/* webpackPrefetch: 10 */ './pages/Dashboard.js');

// Lower-probability route (loads later)
import(/* webpackPrefetch: 1 */ './pages/Settings.js');

Higher numbers receive higher loading priority during idle browser cycles. The same numeric pattern applies to /* webpackPreload: <number> */, allowing fine-grained control over resource scheduling.

Pattern 3: Plugin-Driven Hints for Non-Chunk Assets

Magic comments only work inside dynamic import() calls for JavaScript chunks. To preload or prefetch external assets like web fonts, global CSS, or images that exist outside the dynamic import tree, Webpack uses HTML-injection plugins.

Libraries such as @vue/preload-webpack-plugin (a maintained fork compatible with Webpack 5) hook into HtmlWebpackPlugin to automatically add resource hints to generated assets.

// webpack.config.js
const HtmlWebpackPlugin = require('html-webpack-plugin');
const PreloadWebpackPlugin = require('@vue/preload-webpack-plugin');

module.exports = {
  plugins: [
    new HtmlWebpackPlugin(),
    new PreloadWebpackPlugin({
      rel: 'preload',
      as(entry) {
        if (/\.css$/.test(entry)) return 'style';
        if (/\.woff2$/.test(entry)) return 'font';
        return 'script';
      },
      include: 'allAssets',
      fileWhitelist: [/\.woff2$/] // Preload only critical web fonts
    })
  ]
};

This configuration ensures critical assets like fonts are requested early in the network waterfall without waiting for JavaScript execution.

Implementation Guidelines

  • Avoid preloading non-critical code: Preload contends with critical CSS and scripts for network bandwidth. Reserve it for above-the-fold dependencies.
  • Prefetch route boundaries: The most effective pattern for single-page applications (SPAs) is prefetching the next logical route based on user location (e.g., prefetching the checkout bundle when a user views the shopping cart).
  • Audit bandwidth usage: Prefetching downloads assets even if the user never navigates to the target page. Avoid excessive prefetching on mobile-first applications or when data-saver headers are active.
