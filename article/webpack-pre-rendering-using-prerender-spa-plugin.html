Webpack Pre-Rendering Using prerender-spa-plugin

This article explains how Webpack utilizes the prerender-spa-plugin to generate static HTML pages for single-page applications (SPAs). You will learn the core mechanism behind build-time pre-rendering, how the plugin integrates into the Webpack compilation pipeline, and the step-by-step process of converting client-side routes into crawlable, high-performance static files.

The Purpose of Pre-Rendering in SPAs

Single-page applications built with frameworks like Vue, React, or Angular typically serve a minimal HTML shell (index.html) alongside bundled JavaScript. The client's browser downloads and executes the JavaScript to populate the DOM. While effective for user interactivity, this approach can delay First Contentful Paint (FCP) and hinder search engine crawlers that do not reliably execute JavaScript.

The prerender-spa-plugin solves this problem at build time. It intercepts Webpack's output, launches a headless browser, renders each specified route, and captures the fully rendered DOM as static HTML files.

How prerender-spa-plugin Operates

The plugin executes after Webpack compiles the project assets. Its internal workflow follows five distinct phases:

  1. Compilation Interception: Webpack emits the production bundles (HTML, CSS, JS) to the output directory.
  2. Local Server Initialization: The plugin spins up an ephemeral, lightweight Express or static web server serving the newly compiled assets.
  3. Headless Browser Launch: It launches an instance of Puppeteer (Headless Chrome) to navigate to the routes defined in the plugin configuration.
  4. DOM Snapshotting: The headless browser executes the client-side JavaScript for each route, waiting for network idle events, specific DOM selectors, or custom events before capturing the final HTML.
  5. Static File Output: The generated DOM tree is written to individual HTML files structured according to the route paths (for example, /about becomes /about/index.html).

Basic Webpack Configuration

To integrate the plugin, import it into webpack.config.js and add it to the plugins array:

const path = require('path');
const PrerenderSPAPlugin = require('prerender-spa-plugin');
const Renderer = PrerenderSPAPlugin.PuppeteerRenderer;

module.exports = {
  // Standard Webpack configuration...
  plugins: [
    new PrerenderSPAPlugin({
      // Path to the compiled assets
      staticDir: path.join(__dirname, 'dist'),

      // List of routes to pre-render
      routes: ['/', '/about', '/pricing', '/contact'],

      // Configuration for the headless browser renderer
      renderer: new Renderer({
        headless: true,
        renderAfterDocumentEvent: 'custom-post-render-event',
        skipThirdPartyRequests: true
      })
    })
  ]
};

Key Configuration Elements

  • staticDir: Specifies the directory where Webpack outputs your assets. The plugin serves files from this directory to Puppeteer.
  • routes: An array of URL paths. Each path will result in a corresponding folder and index.html file in your distribution folder.
  • renderer: Controls the headless browser behavior. Using renderAfterDocumentEvent ensures the snapshot is taken only after asynchronous data fetching completes. In your application code, dispatch this event once the view is fully mounted:
document.dispatchEvent(new Event('custom-post-render-event'));

Client-Side Hydration

When a user visits a pre-rendered route, the web server immediately returns the static HTML, rendering content instantly. Once the client-side JavaScript bundles finish downloading, the SPA framework attaches its event listeners to the existing DOM nodes through a process called hydration. This retains the speed of static websites while maintaining full SPA functionality.
