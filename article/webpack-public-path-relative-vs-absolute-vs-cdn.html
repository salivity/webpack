Webpack publicPath: Relative vs Absolute vs CDN

In Webpack, the output.publicPath configuration determines how the application resolves URLs for bundled assets such as scripts, stylesheets, and images in the browser. This article explores the core differences between using a relative, absolute, and CDN-hosted publicPath, demonstrating how each impacts your asset URLs and deployment strategy.

What is output.publicPath?

While output.path tells Webpack where to physically write the emitted files on your disk, output.publicPath tells loaders and plugins where those files will be located in the browser relative to your server or domain. When HTML files, CSS rules, or dynamic imports request an asset, Webpack prepends the publicPath to the asset's file name.

1. Relative publicPath

A relative publicPath specifies asset locations relative to the URL of the HTML document loading the assets. It typically starts with ./, ../, or no slash at all.

// webpack.config.js
module.exports = {
  output: {
    publicPath: './', // or 'assets/'
  },
};
  • Generated URL Example: <script src="./bundle.js"></script> or <script src="assets/bundle.js"></script>
  • How it works: The browser resolves the resource relative to the current page's URL path. If the current URL is https://example.com/blog/, the asset resolves to https://example.com/blog/bundle.js.
  • Best used for:
    • Applications hosted in arbitrary or unknown subdirectories.
    • Static sites opened directly via the local filesystem (file:// protocol).
    • Desktop applications built with Electron or mobile apps built with Cordova/Capacitor.
  • Limitations: Breaks single-page applications (SPAs) using HTML5 pushState routing. Navigating to a nested route like /users/123 will cause the browser to search for assets under /users/123/bundle.js instead of the root directory.

2. Absolute (Host-Relative) publicPath

An absolute publicPath begins with a forward slash (/). It directs the browser to resolve assets starting from the host's root domain, regardless of the page's current URL path.

// webpack.config.js
module.exports = {
  output: {
    publicPath: '/', // or '/assets/'
  },
};
  • Generated URL Example: <script src="/assets/bundle.js"></script>
  • How it works: Regardless of whether the user visits https://example.com/ or https://example.com/dashboard/settings/, the browser always requests the asset directly from the domain root: https://example.com/assets/bundle.js.
  • Best used for:
    • Single-Page Applications (React, Vue, Angular) relying on client-side routing.
    • Web servers where the root path for static assets is fixed and predictable.
  • Limitations: The application cannot be deployed to a subfolder (e.g., https://example.com/my-app/) without changing the publicPath to match the subpath (e.g., publicPath: '/my-app/').

3. CDN-Hosted (Fully Qualified) publicPath

A CDN-hosted publicPath includes an explicit external protocol and domain (or a protocol-relative URL starting with //). It instructs the browser to fetch assets from an external storage bucket or Content Delivery Network instead of the host web server.

// webpack.config.js
module.exports = {
  output: {
    publicPath: 'https://cdn.example.com/assets/',
  },
};
  • Generated URL Example: <script src="https://cdn.example.com/assets/bundle.js"></script>
  • How it works: The asset requests bypass your main web server entirely and load directly from the CDN endpoint.
  • Best used for:
    • High-traffic production environments offloading static asset delivery to services like AWS CloudFront, Cloudflare, or Akamai.
    • Micro-frontend architectures where shared assets or remote modules are hosted independently from the host page.
  • Limitations: Requires dynamic configuration during development, as local builds will fail if they point to an unavailable remote CDN. This is typically managed via environment variables (e.g., using process.env.NODE_ENV to toggle between / in development and the full CDN URL in production).

Summary of Differences

Type Syntax Example Resolution Context SPA Routing Friendly Primary Use Case
Relative './' or '' Current page URL No Offline apps, Electron, flexible subfolders
Absolute '/' or '/assets/' Domain root Yes Standard SPAs, monolithic web servers
CDN-Hosted 'https://cdn.com/' External origin Yes Production performance, offloading server load
