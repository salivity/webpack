Webpack Service Workers with WorkboxWebpackPlugin

Integrating service workers into a Webpack build allows developers to implement offline capabilities, precaching, and advanced network caching strategies in Progressive Web Apps (PWAs). Google's workbox-webpack-plugin streamlines this process by hooking directly into Webpack's asset pipeline. This article explains how the plugin functions, the differences between its two core strategies—GenerateSW and InjectManifest—and how to configure them directly in your project.

Core Architecture and Functionality

Service workers require a list of static assets to cache during their installation phase. Manually maintaining URLs and file hashes is inefficient and prone to cache invalidation errors.

workbox-webpack-plugin resolves this by inspecting Webpack’s internal compilation manifest at build time. It generates a precache manifest that maps each compiled file name (including content hashes) to its specific revision. When the application loads, Workbox automatically downloads, caches, and updates these assets without manual intervention.

Choosing Between GenerateSW and InjectManifest

The plugin provides two distinct plugins tailored for different use cases:

  1. GenerateSW: Automatically generates a complete service worker file based on your Webpack configuration. It is best suited for straightforward offline precaching and simple runtime routing rules without requiring custom service worker code.
  2. InjectManifest: Takes an existing, hand-written service worker file, compiles it, and injects the precache manifest (self.__WB_MANIFEST) into it. This approach is necessary if you need custom features like push notifications, background sync, or complex foreign fetch events.

Installation

Install the plugin as a development dependency:

npm install workbox-webpack-plugin --save-dev

Configuration: GenerateSW

To have Webpack handle the entire service worker creation process, import GenerateSW into your webpack.config.js:

const path = require('path');
const { GenerateSW } = require('workbox-webpack-plugin');

module.exports = {
  entry: './src/index.js',
  output: {
    filename: '[name].[contenthash].js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
  plugins: [
    new GenerateSW({
      clientsClaim: true,
      skipWaiting: true,
      swDest: 'service-worker.js',
      runtimeCaching: [
        {
          urlPattern: /\.(?:png|jpg|jpeg|svg)$/,
          handler: 'CacheFirst',
          options: {
            cacheName: 'images',
            expiration: {
              maxEntries: 50,
            },
          },
        },
      ],
    }),
  ],
};
  • clientsClaim: true forces newly activated service workers to take control of open clients immediately.
  • skipWaiting: true allows the service worker to bypass the waiting lifecycle state and activate immediately.
  • runtimeCaching defines routing strategies (like CacheFirst, NetworkFirst, or StaleWhileRevalidate) for dynamic or external requests not covered by precaching.

Configuration: InjectManifest

For granular control, use InjectManifest. First, create a source service worker file (e.g., src/sw.js):

import { precacheAndRoute } from 'workbox-precaching';

// Webpack replaces this placeholder with the build-time manifest array:
precacheAndRoute(self.__WB_MANIFEST);

// Custom logic (push notifications, background sync, custom listeners):
self.addEventListener('push', (event) => {
  const data = event.data ? event.data.text() : 'No payload';
  event.waitUntil(
    self.registration.showNotification('PWA Notification', { body: data })
  );
});

Next, configure the plugin in webpack.config.js:

const path = require('path');
const { InjectManifest } = require('workbox-webpack-plugin');

module.exports = {
  entry: './src/index.js',
  output: {
    filename: '[name].[contenthash].js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
  plugins: [
    new InjectManifest({
      swSrc: './src/sw.js',
      swDest: 'service-worker.js',
    }),
  ],
};

Client-Side Registration

Regardless of the strategy selected, the generated service worker must be registered inside your application's client-side entry point (such as src/index.js):

if ('serviceWorker' in navigator && process.env.NODE_ENV === 'production') {
  window.addEventListener('load', () => {
    navigator.serviceWorker
      .register('/service-worker.js')
      .then((registration) => {
        console.log('SW registered: ', registration);
      })
      .catch((registrationError) => {
        console.error('SW registration failed: ', registrationError);
      });
  });
}

Registering only during production builds prevents aggressive caching from interfering with the local development server and hot module replacement.
