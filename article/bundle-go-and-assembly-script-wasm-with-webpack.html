Bundle Go and AssemblyScript Wasm with Webpack

This article explains how to bundle WebAssembly (Wasm) compiled from Go and AssemblyScript using Webpack 5. You will learn the required Webpack configurations, how to directly import standard AssemblyScript binaries, and how to manage the required runtime glue code and asset loading for Go-compiled WebAssembly modules.

Enabling WebAssembly in Webpack 5

Webpack 5 supports WebAssembly natively through experimental flags. In your webpack.config.js, enable the asyncWebAssembly experiment:

module.exports = {
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: __dirname + '/dist',
  },
  experiments: {
    asyncWebAssembly: true,
  },
  module: {
    rules: [
      {
        test: /\.wasm$/,
        type: 'webassembly/async',
      },
    ],
  },
};

Bundling AssemblyScript with Webpack

AssemblyScript compiles a TypeScript-like language directly to standard Wasm without requiring a heavy runtime environment.

1. Compile AssemblyScript

Compile your AssemblyScript source file into a .wasm binary:

asc assembly/index.ts -o build/optimized.wasm --optimize

2. Import into JavaScript

With asyncWebAssembly: true, Webpack allows you to import the .wasm file just like an ECMAScript module:

import * as wasmModule from '../build/optimized.wasm';

async function run() {
  const result = wasmModule.add(1, 2);
  console.log(result);
}

run();

Webpack automatically fetches, compiles, and instantiates the Wasm module asynchronously upon import.

Bundling Go (Golang) WebAssembly with Webpack

Go generates WebAssembly binaries that rely on a specific execution bridge provided by Go's runtime via wasm_exec.js. Because Go requires custom imports and manual lifecycle management, using Webpack's native asset/resource loader is the most reliable approach.

1. Compile Go to WebAssembly

Compile your Go code targeting the js architecture:

GOOS=js GOARCH=wasm go build -o src/main.wasm main.go

Copy the runtime bridge file from your Go installation directory into your project:

cp "$(go env GOROOT)/misc/wasm/wasm_exec.js" src/

2. Update Webpack Configuration for Go Wasm

Treat Go's .wasm file as an asset rather than a native WebAssembly module to prevent instantiation conflicts with the missing Go runtime imports:

module.exports = {
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: __dirname + '/dist',
  },
  module: {
    rules: [
      {
        test: /\.wasm$/,
        type: 'asset/resource',
      },
    ],
  },
};

3. Load and Instantiate the Go Module

Import wasm_exec.js into your entry file, import the .wasm URL, and execute the runtime:

import './wasm_exec.js';
import wasmUrl from './main.wasm';

async function runGoWasm() {
  const go = new window.Go();
  const response = await fetch(wasmUrl);
  const { instance } = await WebAssembly.instantiateStreaming(response, go.importObject);
  
  go.run(instance);
}

runGoWasm();

Summary of Differences

  • AssemblyScript: Can be loaded directly as native modules using Webpack's webassembly/async rule, requiring zero extra runtime code.
  • Go: Emits binaries that depend on Go's runtime bridge. It must be treated as a static asset via asset/resource and manually instantiated alongside wasm_exec.js.
