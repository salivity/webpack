Run Webpack Programmatically Using Node.js API

Running Webpack programmatically allows you to integrate build tasks directly into custom build tools, server workflows, or CI/CD pipelines without relying on the command-line interface. This guide demonstrates how to invoke Webpack through its official Node.js API, execute standalone builds, inspect compilation statistics, handle errors properly, and set up dynamic watch modes.

Basic Compilation

To execute Webpack within a Node.js script, import the webpack function, pass your configuration object, and provide a callback function to execute the build immediately.

const webpack = require('webpack');

const config = {
  mode: 'production',
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: __dirname + '/dist',
  },
};

webpack(config, (err, stats) => {
  if (err) {
    console.error('Fatal configuration or execution error:', err.stack || err);
    if (err.details) {
      console.error('Error details:', err.details);
    }
    return;
  }

  const info = stats.toJson();

  if (stats.hasErrors()) {
    console.error('Compilation errors:');
    info.errors.forEach((error) => console.error(error.message));
  }

  if (stats.hasWarnings()) {
    console.warn('Compilation warnings:');
    info.warnings.forEach((warning) => console.warn(warning.message));
  }

  console.log(
    stats.toString({
      chunks: false,
      colors: true,
    })
  );
});

Manual Compiler Execution

If you omit the callback function when calling webpack(config), it returns a Compiler instance. This allows you to manually control the build lifecycle using compiler.run() and compiler.close().

const webpack = require('webpack');
const config = require('./webpack.config.js');

const compiler = webpack(config);

compiler.run((err, stats) => {
  if (err) {
    console.error(err);
  } else {
    console.log(stats.toString({ colors: true }));
  }

  // In Webpack 5, always call compiler.close to release cache and lock handles
  compiler.close((closeErr) => {
    if (closeErr) {
      console.error('Error closing compiler:', closeErr);
    }
  });
});

Watching for File Changes

To recompile automatically when files change, use the compiler.watch() method instead of compiler.run(). It accepts a watch options object and a callback function that runs after each recompilation.

const webpack = require('webpack');
const config = require('./webpack.config.js');

const compiler = webpack(config);

const watchOptions = {
  aggregateTimeout: 300,
  poll: undefined, // Set a duration in ms if filesystem events are not supported
};

const watching = compiler.watch(watchOptions, (err, stats) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log(
    stats.toString({
      colors: true,
      modules: false,
    })
  );
});

Handling Multi-Compiler Configurations

If you pass an array of configuration objects to the webpack function, it returns a MultiCompiler instance that executes builds in parallel.

const webpack = require('webpack');

const clientConfig = { entry: './src/client.js', output: { filename: 'client.js' } };
const serverConfig = { entry: './src/server.js', output: { filename: 'server.js' }, target: 'node' };

webpack([clientConfig, serverConfig], (err, stats) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log(stats.toString({ colors: true }));
});
