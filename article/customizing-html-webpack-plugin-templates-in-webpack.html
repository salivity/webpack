Customizing HtmlWebpackPlugin Templates in Webpack

Customizing HTML templates in Webpack using HtmlWebpackPlugin allows developers to dynamically inject variables, control asset placement, and define custom document structures for their web applications. This article explains how to specify custom templates, pass dynamic template parameters, utilize templating engines, control script and stylesheet injection, and generate multiple distinct HTML files.

Using a Custom Template File

By default, HtmlWebpackPlugin generates a standard, blank HTML5 file that includes all Webpack bundles. To use your own base structure, provide the path to your HTML file using the template property inside your Webpack configuration.

// webpack.config.js
const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'bundle.js',
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/template.html',
    }),
  ],
};

Passing Custom Variables

HtmlWebpackPlugin uses Lodash templating by default, allowing you to access configuration options and custom parameters directly inside the template file.

In your Webpack configuration, define properties directly on the plugin or use the templateParameters object:

plugins: [
  new HtmlWebpackPlugin({
    template: './src/template.html',
    title: 'My Custom App',
    appMountId: 'root',
    templateParameters: {
      metaDescription: 'A dynamic description passed from Webpack config',
    },
  }),
];

In your template.html, reference these variables using Lodash syntax (<%= ... %>):

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="description" content="<%= metaDescription %>">
  <title><%= htmlWebpackPlugin.options.title %></title>
</head>
<body>
  <div id="<%= htmlWebpackPlugin.options.appMountId %>"></div>
</body>
</html>

Controlling Asset Injection

The inject option determines where and how generated bundles (<script> and <link> tags) are added to the HTML file:

  • true or 'body': All JavaScript files are injected at the bottom of the <body> element.
  • 'head': All JavaScript files are injected inside the <head> element.
  • false: Disables automatic injection entirely.

When inject: false is used, you must manually iterate through the assets inside the template:

<!DOCTYPE html>
<html lang="en">
<head>
  <% for (var css in htmlWebpackPlugin.files.css) { %>
    <link href="<%= htmlWebpackPlugin.files.css[css] %>" rel="stylesheet">
  <% } %>
</head>
<body>
  <div id="root"></div>

  <% for (var js in htmlWebpackPlugin.files.js) { %>
    <script src="<%= htmlWebpackPlugin.files.js[js] %>"></script>
  <% } %>
</body>
</html>

Using Alternative Template Engines

If you prefer template syntaxes such as Pug or Handlebars, configure the appropriate Webpack loader to parse the template file before HtmlWebpackPlugin processes it.

For example, to use Pug:

npm install --save-dev pug pug-loader

Configure the loader and template path in webpack.config.js:

module.exports = {
  module: {
    rules: [
      {
        test: /\.pug$/,
        loader: 'pug-loader',
      },
    ],
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/template.pug',
    }),
  ],
};

Generating Multiple HTML Pages

For multi-page applications, instantiate HtmlWebpackPlugin multiple times and map each instance to its respective template and entry chunks using the chunks array:

plugins: [
  new HtmlWebpackPlugin({
    filename: 'index.html',
    template: './src/pages/index.html',
    chunks: ['main'],
  }),
  new HtmlWebpackPlugin({
    filename: 'about.html',
    template: './src/pages/about.html',
    chunks: ['about'],
  }),
];
