When to Export a Function from Webpack Config

Exporting a function instead of a plain JavaScript object from webpack.config.js allows you to dynamically generate your build configuration based on runtime parameters. While a static object works well for straightforward setups, returning a configuration object from a function is necessary when you need to access environment variables, read command-line interface (CLI) arguments, or perform asynchronous setup tasks before generating your build.

Accessing Environment Variables via CLI

The most common reason to export a function is to capture environment flags passed directly through the command line. Webpack passes an env object as the first parameter to the configuration function when you use the --env flag.

// Run via: npx webpack --env production --env platform=web
module.exports = (env, argv) => {
  return {
    mode: env.production ? 'production' : 'development',
    devtool: env.production ? 'source-map' : 'eval-cheap-module-source-map',
    // ... rest of configuration
  };
};

This approach eliminates the need for separate configuration files for each environment, keeping related configuration logic consolidated in a single place.

Reading Webpack CLI Options

The second argument passed to the exported function is argv, an object containing all options passed to the Webpack CLI (such as --mode or --hot).

Instead of guessing the mode via Node's process.env.NODE_ENV, you can directly read the exact flags Webpack is running with:

module.exports = (env, argv) => {
  const isProduction = argv.mode === 'production';

  return {
    output: {
      filename: isProduction ? '[name].[contenthash].js' : '[name].js',
    },
  };
};

This prevents mismatched states where Webpack's internal optimizations expect one mode, but custom plugins or loaders are configured for another.

Performing Asynchronous Operations

Webpack supports returning a Promise or an async function. Exporting a function is mandatory if your configuration depends on asynchronous data, such as:

  • Fetching remote secrets, credentials, or endpoints from a cloud provider (e.g., AWS Secrets Manager).
  • Dynamically finding free ports using network libraries.
  • Reading file system metadata or asynchronous configuration files.
module.exports = async (env, argv) => {
  const apiEndpoint = await fetchConfigFromRemoteServer();

  return {
    entry: './src/index.js',
    plugins: [
      new webpack.DefinePlugin({
        'process.env.API_URL': JSON.stringify(apiEndpoint),
      }),
    ],
  };
};

Summary of Use Cases

Export a function from webpack.config.js when:

  1. You pass custom properties to the build using the --env CLI flag.
  2. You need to inspect CLI arguments such as argv.mode inside the configuration.
  3. You must execute asynchronous logic or API calls before finalizing Webpack's settings.
