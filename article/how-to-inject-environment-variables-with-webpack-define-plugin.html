How to Inject Environment Variables with Webpack DefinePlugin

Webpack's DefinePlugin allows you to inject compile-time constants directly into your application code, serving as the standard mechanism for passing environment variables from your build system into your client-side JavaScript bundles. This guide explains how the plugin functions, demonstrates the proper configuration syntax, highlights the necessity of value stringification, and covers essential security practices.

Understanding How DefinePlugin Works

The DefinePlugin performs a direct text replacement in your source code during the compilation step. It does not create true runtime variables in the browser. Instead, whenever Webpack encounters a key defined in the plugin configuration (such as process.env.API_URL), it replaces that token directly with the value you provided before generating the final output bundle.

Basic Webpack Configuration

To use DefinePlugin, import Webpack into your webpack.config.js file and instantiate the plugin within the plugins array.

const webpack = require('webpack');

module.exports = {
  // ... other webpack configuration options
  plugins: [
    new webpack.DefinePlugin({
      'process.env.NODE_ENV': JSON.stringify(process.env.NODE_ENV || 'development'),
      'process.env.API_URL': JSON.stringify('https://api.example.com'),
      'process.env.FEATURE_FLAG_NEW_UI': JSON.stringify(true),
    }),
  ],
};

The Importance of JSON.stringify()

A common pitfall with DefinePlugin is omitting JSON.stringify(). Because the plugin performs a direct code replacement:

  • If you pass 'https://api.example.com', Webpack writes process.env.API_URL = https://api.example.com;, which causes a syntax error at runtime because the value is interpreted as JavaScript code rather than a string literal.
  • Passing JSON.stringify('https://api.example.com') produces '"https://api.example.com"', which ensures the output code properly contains a wrapped string literal.

Primitives such as booleans and numbers can be passed without JSON.stringify(), but using it consistently for all values prevents accidental syntax errors.

Consuming the Variables in Application Code

Inside your source files, reference the variables using standard property access.

function fetchUserData() {
  const endpoint = `${process.env.API_URL}/users`;

  if (process.env.NODE_ENV === 'development') {
    console.log(`Fetching from: ${endpoint}`);
  }

  return fetch(endpoint).then((res) => res.json());
}

During the build process, if process.env.NODE_ENV is defined as 'production', Webpack replaces if (process.env.NODE_ENV === 'development') with if ('production' === 'development'). Modern minifiers like Terser recognize this as dead code and automatically remove the entire block from the production bundle.

Safely Exposing .env Files

To load variables dynamically from a .env file using the dotenv package, explicitly map only the variables your client application requires:

const webpack = require('webpack');
const dotenv = require('dotenv');

// Load environment variables from .env file
const env = dotenv.config().parsed || {};

// Format variables for DefinePlugin
const envKeys = Object.keys(env).reduce((prev, next) => {
  prev[`process.env.${next}`] = JSON.stringify(env[next]);
  return prev;
}, {});

module.exports = {
  plugins: [
    new webpack.DefinePlugin(envKeys),
  ],
};

Security Considerations

Any value injected using DefinePlugin is permanently baked into the client-side JavaScript files and can be read by anyone inspecting the bundle in a browser. Never inject sensitive data such as database passwords, private encryption keys, or restricted API secrets using this method. Only expose public configurations intended for client-side execution.
