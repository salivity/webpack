Webpack Chunk vs Bundle: Key Differences Explained

In Webpack, understanding the distinction between a "chunk" and a "bundle" is essential for optimizing build performance and asset delivery. While developers often use these terms interchangeably, they represent two distinct stages in Webpack's build pipeline: chunks are the internal groupings of modules during compilation, whereas bundles are the final physical files emitted to disk for the browser to consume. This article breaks down how Webpack processes code, the exact roles of chunks and bundles, and how they interact during code splitting.

The Core Definitions

To understand the difference, it helps to look at the progression from source code to output:

  • Module: The discrete files you write in your source code (.js, .ts, .css, .png, etc.). Webpack starts by parsing these modules and mapping their dependencies into a dependency graph.
  • Chunk: An intermediate Webpack concept. During the compilation phase, Webpack connects individual modules into groups called chunks. Chunks exist primarily in memory to manage how code is organized, shared, and split.
  • Bundle: The concrete, output file generated at the end of the build process. A bundle is what gets written to your output directory (typically dist/) and loaded by the browser via <script> or <link> tags.

How Chunks Work

Chunks represent the architecture of your build before it is saved as output files. Webpack primarily creates chunks in two ways:

  1. Entry Chunks: Created based on the entry configuration in your webpack.config.js. Each entry point initializes an entry chunk containing that module and all its statically imported dependencies.
  2. Async (Child) Chunks: Created through code splitting techniques, such as dynamic import() statements. When Webpack encounters a dynamic import, it isolates that module tree into a separate chunk so it can be loaded on demand.

Webpack also creates chunks internally when using the SplitChunksPlugin to extract shared vendor libraries or common code out of entry chunks to prevent duplication.

How Chunks Become Bundles

Once Webpack finishes optimizing the chunk graph, it renders each chunk into one or more output assets—the bundles.

While there is frequently a 1:1 relationship between a chunk and a bundle (for example, the main chunk generating a main.bundle.js file), this is not always the case. A single chunk can produce multiple output files:

  • A JavaScript chunk containing extracted CSS (using tools like MiniCssExtractPlugin) will yield both a .js bundle and a .css bundle.
  • If source maps are enabled, a single chunk produces both the .js bundle and a corresponding .js.map file.
