Modify Webpack Module Source Before Loaders Run

Intercepting and modifying module source code before loaders execute allows developers to rewrite raw assets, inject polyfills, or implement dynamic code transformations directly at the build pipeline's root. In Webpack 5, the standard way to achieve this is by tapping into the compilation lifecycle and overriding the readResource method exposed on the loader context via NormalModule.getCompilationHooks. This article details how Webpack's module compilation pipeline works and how to implement a custom plugin to alter file contents before any loader processes them.

Understanding the Webpack Build Lifecycle

During a build, Webpack resolves imported file paths using NormalModuleFactory. Once resolved, Webpack instantiates a NormalModule and initiates the loader runner to transform the module's content into valid JavaScript.

Before the loader runner executes the configured loader chain, it must read the target file's raw content from disk. This operation is handled by loaderContext.readResource, which defaults to the compiler's underlying input file system. By intercepting this specific step, a plugin can replace or transform the raw file buffer before the first loader in the pipeline ever touches it.

Implementing the Plugin

To intercept the raw file read, tap into the compilation hook from the compiler instance, access the readResource hook via NormalModule.getCompilationHooks, and replace the readResource function on the loaderContext.

const { NormalModule } = require('webpack');

class PreLoaderSourceInterceptorPlugin {
  constructor(options = {}) {
    this.options = options;
  }

  apply(compiler) {
    compiler.hooks.compilation.tap(
      'PreLoaderSourceInterceptorPlugin',
      (compilation) => {
        // Access NormalModule hooks for this compilation
        const hooks = NormalModule.getCompilationHooks(compilation);

        // Tap into readResource hook
        hooks.readResource.tap(
          'PreLoaderSourceInterceptorPlugin',
          (loaderContext) => {
            const originalReadResource = loaderContext.readResource;

            // Override the reader used to populate the initial loader input
            loaderContext.readResource = (targetPath, callback) => {
              originalReadResource(targetPath, (err, result) => {
                if (err) {
                  return callback(err);
                }

                try {
                  // Only transform matching target files
                  if (targetPath.endsWith('.js')) {
                    const originalContent = result.toString('utf-8');
                    const transformedContent = originalContent.replace(
                      /__INTERCEPT_TARGET__/g,
                      'transformedValue'
                    );

                    // Return transformed content as a Buffer or string
                    return callback(null, Buffer.from(transformedContent));
                  }

                  // Fall back to original content
                  callback(null, result);
                } catch (transformationError) {
                  callback(transformationError);
                }
              });
            };
          }
        );
      }
    );
  }
}

module.exports = PreLoaderSourceInterceptorPlugin;

Alternative Approach: Hooking the Input File System

Another method is wrapping the compiler's inputFileSystem directly during plugin initialization. This approach takes effect earlier in the execution cycle and applies globally across all file read requests, including those made by custom resolvers.

class FileSystemInterceptorPlugin {
  apply(compiler) {
    compiler.hooks.afterEnvironment.tap('FileSystemInterceptorPlugin', () => {
      const originalReadFile = compiler.inputFileSystem.readFile.bind(
        compiler.inputFileSystem
      );

      compiler.inputFileSystem.readFile = (filePath, callback) => {
        originalReadFile(filePath, (err, data) => {
          if (err) {
            return callback(err);
          }

          if (typeof filePath === 'string' && filePath.endsWith('.js')) {
            const content = data.toString('utf-8');
            const modified = `/* Injected Header */\n` + content;
            return callback(null, Buffer.from(modified));
          }

          callback(null, data);
        });
      };
    });
  }
}

module.exports = FileSystemInterceptorPlugin;

Best Practices

When altering source code before the loader pipeline:

  1. Target Specifically: Filter strictly by file extension or directory path within the wrapper function to avoid adding parsing overhead to non-relevant files and binary assets.
  2. Preserve Buffers: Return Buffer instances when interacting with the file system hooks unless you specifically need string operations, ensuring binary assets are not corrupted.
  3. Handle Errors Gracefully: Always forward file read errors directly to the provided callback so Webpack can populate module build errors properly.
