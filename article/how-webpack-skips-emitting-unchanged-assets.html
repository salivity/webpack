How Webpack Skips Emitting Unchanged Assets

Webpack minimizes build times and unnecessary disk I/O by evaluating source file changes, build cache states, and existing output contents before writing files to the disk. Through an internal pipeline consisting of filesystem snapshotting, chunk hashing, and output target comparison, Webpack determines whether a generated asset is identical to an already emitted file and skips the write operation when no changes are detected.

Input Snapshotting and Cache Invalidation

The process begins during module resolution. Webpack tracks dependencies using the FileSystemInfo API, which creates snapshots of source files. These snapshots record file modification timestamps (mtime) and content hashes.

During incremental builds (such as in watch mode) or when persistent filesystem caching is enabled:

  • Webpack checks whether the current file system state matches the stored snapshot.
  • If the file’s timestamp and hash are unchanged, Webpack reuses the cached module result, skipping parsing and code transformation.
  • If dependencies or configuration options change, the snapshot is invalidated, triggering a recompilation of the affected modules.

Chunk Graph and Asset Generation

Once module processing completes, Webpack organizes modules into chunks and computes content hashes for the chunk components. For assets configured with content-based placeholders (such as [contenthash].js), Webpack generates an internal hash based on the transformed source code:

  • If module contents do not change, the resulting chunk hash remains identical across builds.
  • Webpack populates the compilation.assets object with the final source buffers and target filenames.

The Asset Emission Phase

The final decision to write or skip an asset occurs in the emitAssets method of the Compiler instance. When Webpack iterates through compilation.assets to write the files via the outputFileSystem, it applies the following logic:

  1. Existence Verification: Webpack checks if the target file already exists in the designated output directory.
  2. Buffer and Content Comparison: If the file exists, Webpack compares the target file’s contents on disk against the newly generated asset source buffer.
  3. Write Execution or Bypass: If the buffer matches the file already present on disk, Webpack bypasses the write operation entirely. The file's modification timestamp on the filesystem remains unchanged, and the asset is marked as skipped internally. If the file does not exist or the contents differ, Webpack executes the write operation to overwrite the output.

Webpack 5 Persistent Caching Impact

With the persistent caching introduced in Webpack 5 (cache: { type: 'filesystem' }), emission skipping extends across separate process runs. Webpack stores compilation metadata, chunk structures, and emitted file signatures in the cache directory. Upon a new build invocation, if the global build dependencies, configurations, and input snapshots evaluate as fresh, Webpack retains the existing output files directly without regenerating the internal asset buffers, accelerating the build lifecycle.
