Webpack UMD Default Export with libraryExport

When authoring a JavaScript library using ES modules, bundling it as a Universal Module Definition (UMD) often causes Webpack to bundle the default export under a .default property. This article explains how to configure Webpack using the output.libraryExport option to cleanly extract the default export, allowing consumers to access your library directly across CommonJS, AMD, and browser global environments without referencing .default.

The Issue with Default Exports in UMD

When your entry file uses ES module syntax:

// src/index.js
const MyLibrary = {
  version: "1.0.0",
  greet: () => "Hello, world!"
};

export default MyLibrary;

By default, Webpack wraps this into an object containing a default property. As a result, consumers are forced to write:

// Node.js (CommonJS)
const MyLibrary = require('my-library').default;

// Browser Global
const MyLibrary = window.MyLibrary.default;

To provide an intuitive API, you can configure Webpack to assign the default export directly to the library target.

Configuring Webpack 4

In Webpack 4, use the output.libraryExport property set to 'default'.

// webpack.config.js
const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'my-library.js',
    library: 'MyLibrary',
    libraryTarget: 'umd',
    libraryExport: 'default',
    globalObject: 'this'
  }
};

Configuring Webpack 5

Webpack 5 consolidated library-related options under the output.library object. While Webpack 5 retains backward compatibility for output.libraryExport, the modern approach is using output.library.export:

// webpack.config.js
const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'my-library.js',
    library: {
      name: 'MyLibrary',
      type: 'umd',
      export: 'default'
    },
    globalObject: 'this'
  }
};

Setting globalObject

When targeting UMD, the default global object in Webpack is window. If your library is run in a Node.js or Web Worker environment, referencing window will throw an error. Setting globalObject: 'this' ensures that the library binds safely to global in Node.js, self in Web Workers, or window in standard browser runtimes.

The Result for Consumers

With the export property configured, the extra .default namespace is eliminated:

Node.js (CommonJS):

const MyLibrary = require('my-library');
MyLibrary.greet();

Browser Global (Script tag):

<script src="dist/my-library.js"></script>
<script>
  MyLibrary.greet();
</script>

ES Modules:

import MyLibrary from 'my-library';
MyLibrary.greet();
