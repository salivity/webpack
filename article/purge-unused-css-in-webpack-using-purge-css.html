Purge Unused CSS in Webpack Using PurgeCSS

Optimizing web performance requires minimizing bundle sizes, and large CSS frameworks often ship with thousands of rules that your project never uses. This guide demonstrates how to configure Webpack to automatically scan your templates and source code, detect unused CSS classes, and strip them out using the purgecss-webpack-plugin. By integrating this workflow into your build process, you can dramatically reduce your final CSS payload for production environments.

Step 1: Install Required Dependencies

PurgeCSS works best in Webpack when combined with mini-css-extract-plugin, which extracts CSS into separate files rather than injecting it inline via JavaScript. You also need glob to define file paths for PurgeCSS to analyze.

Run the following command in your terminal:

npm install --save-dev purgecss-webpack-plugin mini-css-extract-plugin glob

Step 2: Configure Webpack

Update your webpack.config.js to extract CSS and apply the PurgeCSSPlugin. The plugin requires a paths array indicating every file (HTML, JS, JSX, Vue, etc.) that might reference CSS classes.

const path = require('path');
const glob = require('glob');
const MiniCssExtractPlugin = require('mini-css-extract-plugin');
const { PurgeCSSPlugin } = require('purgecss-webpack-plugin');

const PATHS = {
  src: path.join(__dirname, 'src')
};

module.exports = {
  mode: 'production',
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
  module: {
    rules: [
      {
        test: /\.css$/,
        use: [
          MiniCssExtractPlugin.loader,
          'css-loader'
        ],
      },
    ],
  },
  plugins: [
    new MiniCssExtractPlugin({
      filename: '[name].[contenthash].css',
    }),
    new PurgeCSSPlugin({
      paths: glob.sync(`${PATHS.src}/**/*`, { nodir: true }),
    }),
  ],
};

Step 3: Prevent Over-Purging with a Safelist

PurgeCSS cannot always detect dynamically constructed class names (such as classes generated conditionally in JavaScript like btn-${variant}). To prevent crucial styles from being removed, pass a safelist option to the plugin configuration:

new PurgeCSSPlugin({
  paths: glob.sync(`${PATHS.src}/**/*`, { nodir: true }),
  safelist: {
    standard: [/^btn-/, 'active', 'is-open'],
    deep: [/modal$/],
    greedy: [/tooltip/],
  },
})
  • standard: Matches exact strings or regex against class names.
  • deep: Keeps child selectors based on a regex match.
  • greedy: Keeps any selector containing the pattern.

Step 4: Run Conditionally for Production

Purging CSS adds computational overhead and can complicate debugging during development. It is best practice to enable PurgeCSS only for production builds:

const isProduction = process.env.NODE_ENV === 'production';

module.exports = {
  // ... other configuration options
  plugins: [
    new MiniCssExtractPlugin({
      filename: isProduction ? '[name].[contenthash].css' : '[name].css',
    }),
    ...(isProduction
      ? [
          new PurgeCSSPlugin({
            paths: glob.sync(`${PATHS.src}/**/*`, { nodir: true }),
          }),
        ]
      : []),
  ],
};
