How module.hot.accept Works in Webpack HMR

In Webpack’s Hot Module Replacement (HMR) system, module.hot.accept() is the essential API method used to declare update boundaries for modified code. This article provides a focused look at how module.hot.accept() operates, detailing its role in intercepting module updates, executing custom replacement logic, and preventing unnecessary full-page browser reloads while maintaining application state.

The Core Purpose of module.hot.accept()

Hot Module Replacement exchanges, adds, or removes modules while an application is running without reloading the entire page. By default, when a file changes, Webpack does not know how to handle the update on its own.

The module.hot.accept() function serves as an explicit instruction telling Webpack's HMR runtime: "This module (or its specified dependencies) knows how to update itself. Do not bubble the update up to the root or trigger a full page refresh."

How Module Update Bubbling Works

When a file is modified during development, the HMR runtime sends an update to the browser. The runtime traverses the dependency tree from the modified module upward toward the entry point:

  1. Webpack checks if the modified file contains a module.hot.accept() call.
  2. If it does not, the update "bubbles" up to the parent modules that imported it.
  3. The runtime checks those parents for an accept handler that covers the modified dependency.
  4. If the update bubbles all the way to the root entry point without encountering an accept handler, the HMR process fails, and Webpack falls back to a full browser reload.

Syntax and Implementation Patterns

module.hot.accept() is typically used in two distinct ways:

1. Self-Accepting Modules

A module can accept its own updates. This is common in leaf modules such as UI components or CSS/style loaders where re-executing the file is sufficient to reflect the change.

// Inside a module (e.g., component.js)
export function render() {
  document.getElementById('root').innerHTML = 'Updated content';
}

render();

if (module.hot) {
  module.hot.accept();
}

When module.hot.accept() is called with no arguments, Webpack re-executes this specific module when it changes, without notifying parent modules.

2. Accepting Dependencies

A parent module can explicitly declare that it handles updates for one or more of its child dependencies by passing the path and an update callback.

import { renderHeader } from './header.js';

renderHeader();

if (module.hot) {
  module.hot.accept('./header.js', () => {
    // Logic to re-render or patch the component with the new code
    renderHeader();
  });
}

In this pattern:

  • First parameter: A string (or array of strings) representing the module request paths to monitor.
  • Second parameter: A callback function triggered immediately after the updated dependency has been fetched and evaluated by the runtime.
  • Third parameter (optional): An error-handling callback that manages exceptions thrown during the update process.

State Preservation

By controlling updates via module.hot.accept(), developers can write cleanup and re-initialization logic to swap functionality in memory. This preserves runtime state—such as user inputs, scroll positions, or state store data—drastically speeding up the development feedback loop.
