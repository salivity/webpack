Test Webpack Output In-Memory Using memfs

Testing custom Webpack loaders, plugins, and complex build configurations often requires validating the generated output files, but writing these files to disk slows down automated test suites and introduces cleanup overhead. By configuring Webpack to use an in-memory file system via memfs (the modern successor to the deprecated memory-fs), you can compile bundles and assert asset contents entirely in RAM. This approach yields faster test execution, prevents filesystem race conditions, and eliminates the need for temporary output directories.

Why Choose memfs Over memory-fs

While older versions of Webpack relied on memory-fs, Webpack 5 officially deprecated it in favor of memfs. The memfs library provides a full, Node.js-compatible file system implementation in memory and integrates cleanly with Webpack's internal input and output interfaces.

Setting Up memfs with Webpack

To route Webpack's output to memory, assign an instance of memfs to the outputFileSystem property of the Webpack compiler before running the compilation.

First, install the necessary dependencies:

npm install --save-dev webpack memfs

Implementation Example

The following pattern demonstrates how to configure, run, and assert Webpack output using Node.js and standard testing frameworks like Jest or Vitest:

const webpack = require('webpack');
const { createFsFromVolume, Volume } = require('memfs');
const path = require('path');

function compile(webpackConfig) {
  const compiler = webpack(webpackConfig);
  const memFs = createFsFromVolume(new Volume());

  // Assign memfs to Webpack's output file system
  compiler.outputFileSystem = memFs;

  return new Promise((resolve, reject) => {
    compiler.run((err, stats) => {
      if (err) {
        return reject(err);
      }

      const info = stats.toJson();

      if (stats.hasErrors()) {
        return reject(new Error(info.errors.map(e => e.message).join('\n')));
      }

      resolve({ stats, memFs });
    });
  });
}

Inspecting and Asserting In-Memory Assets

Once the compilation succeeds, read the generated assets directly from the memFs instance using absolute paths matching your output.path configuration.

async function runTest() {
  const outputPath = path.resolve(__dirname, 'dist');

  const config = {
    mode: 'production',
    entry: path.resolve(__dirname, 'src/index.js'),
    output: {
      path: outputPath,
      filename: 'bundle.js',
    },
  };

  const { memFs } = await compile(config);

  // Read the bundle directly from the in-memory filesystem
  const bundlePath = path.join(outputPath, 'bundle.js');
  const bundleContent = memFs.readFileSync(bundlePath, 'utf-8');

  // Perform assertions
  console.assert(bundleContent.includes('expected output string'), 'Asset content mismatch');
  console.assert(memFs.existsSync(bundlePath), 'Bundle was not created in memory');
}

Cleaning Up Compiler Resources

When testing with Webpack 5, always close the compiler instance to ensure persistent caching mechanisms, watch dogs, and file watchers release their handles:

compiler.close((closeErr) => {
  if (closeErr) {
    console.error('Failed to close compiler:', closeErr);
  }
});

Using memfs via compiler.outputFileSystem provides an isolated, reliable, and fast environment to test build artifacts without touching the physical disk.
