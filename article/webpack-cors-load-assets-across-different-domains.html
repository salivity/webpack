Webpack CORS: Load Assets Across Different Domains

Loading assets from external domains or CDNs requires proper Cross-Origin Resource Sharing (CORS) configurations to ensure browsers do not block scripts, stylesheets, web fonts, or worker files. In Webpack, enabling cross-domain asset loading involves configuring the output path, applying the proper cross-origin loading attributes to generated chunks, and ensuring the remote server responds with appropriate HTTP headers.

1. Configure output.crossOriginLoading

Webpack provides a built-in configuration option called output.crossOriginLoading. This setting instructs Webpack to inject the crossorigin attribute into dynamically loaded <script> and <link> tags (such as on-demand chunks loaded via import()).

In your webpack.config.js:

module.exports = {
  output: {
    // Set to 'anonymous' or 'use-credentials'
    crossOriginLoading: 'anonymous',
  },
};
  • anonymous: Sends cross-origin requests without user credentials (cookies, HTTP basic authentication, or client-side SSL certificates). This is the standard setting for public CDNs.
  • use-credentials: Sends cookies and authentication headers alongside the request.

2. Set the output.publicPath

When loading assets from a different domain, Webpack needs to know the absolute URL where those assets reside. Define your external domain using output.publicPath.

module.exports = {
  output: {
    publicPath: 'https://cdn.example.com/assets/',
    crossOriginLoading: 'anonymous',
  },
};

If the domain is not known at build time, you can set the public path dynamically at runtime inside your entry file before any dynamic imports are triggered:

__webpack_public_path__ = window.ASSET_CDN_URL;

3. Handle Initial HTML Assets

The output.crossOriginLoading property only applies to dynamic, Webpack-injected chunks. If you use html-webpack-plugin to generate your initial index.html file, you must explicitly configure it to include crossorigin attributes on the initial bundle tags.

Install and configure html-webpack-plugin:

const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  // ...
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/index.html',
      attributes: {
        crossorigin: 'anonymous',
      },
    }),
  ],
};

Alternatively, use plugins like html-webpack-inject-attributes-plugin to assign crossorigin="anonymous" directly to all emitted <script> and <link> elements.

4. Ensure Proper Server-Side CORS Headers

Webpack configurations only handle the client-side request attributes. The remote server hosting the assets (such as an S3 bucket, Cloudflare, or Nginx server) must allow cross-origin requests.

The remote server must return:

Access-Control-Allow-Origin: *

Or, if using crossOriginLoading: 'use-credentials':

Access-Control-Allow-Origin: https://your-app-domain.com
Access-Control-Allow-Credentials: true

Without these response headers, the browser will block the execution of cross-origin scripts and reject CSS or font files regardless of Webpack's client-side configuration.
