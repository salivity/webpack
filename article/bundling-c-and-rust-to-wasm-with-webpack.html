Bundling C and Rust to Wasm with Webpack

Webpack can directly bundle C and Rust source code into WebAssembly (Wasm) using specialized loaders and plugins. Instead of requiring developers to manually precompile their native code via external command-line tools, Webpack’s ecosystem provides integrations that invoke compilers like rustc/cargo and Emscripten (emcc) during the build process. This article explains how Webpack handles native source compilation, the key loaders and plugins available, and how Webpack 5’s native WebAssembly architecture integrates with them.

How Webpack Handles C and Rust

Webpack natively understands JavaScript and, with Webpack 5, precompiled WebAssembly files (.wasm) via the experiments.asyncWebAssembly flag. However, it cannot parse raw .rs, .c, or .cpp files on its own.

To bridge this gap, specialized loaders and plugins intercept these source files, trigger the appropriate native compiler under the hood, output a .wasm binary along with JavaScript binding glue, and feed the resulting artifacts directly into the Webpack dependency graph.

Compiling Rust Directly with Webpack

The most mature ecosystem for native code bundling in Webpack exists for Rust. Developers have two primary approaches:

  1. @wasm-tool/wasm-pack-plugin: This is the recommended approach for Rust projects. Rather than acting as a standard loader, it is a Webpack plugin that watches your Cargo project directory, runs wasm-pack build automatically whenever native files change, and exposes the generated package directly to your JavaScript imports.
  2. rust-wasm-loader: A traditional loader that hooks directly into Webpack's module resolution pipeline. It takes .rs entry files, compiles them using the Rust toolchain, and outputs the binary and bindings.

When configured alongside experiments: { asyncWebAssembly: true }, you can import functions directly from Rust files inside JavaScript modules using standard ES module syntax:

import { add } from './src/lib.rs';

Compiling C and C++ with Webpack

Compiling C and C++ within Webpack relies on the Emscripten toolchain. While less common than precompiling to static Wasm binaries, several loaders automate this workflow:

  • cpp-wasm-loader / emscripten-wasm-loader: These loaders take C or C++ source files, invoke emcc in a child process, and emit both the WebAssembly module and the runtime glue code needed to initialize Emscripten's virtual file system and memory heap.
  • Custom Shell / Execution Loaders: Because modern Emscripten toolchains update frequently, many teams configure custom Webpack build steps or loaders (such as running emcc through a file-watching pipeline) to maintain full control over compiler flags, optimization levels, and memory configurations.

Configuration Requirements and Considerations

To bundle native code compiled directly to Wasm in Webpack 5, your configuration must support asynchronous WebAssembly:

module.exports = {
  experiments: {
    asyncWebAssembly: true,
  },
  module: {
    rules: [
      {
        test: /\.rs$/,
        use: [{ loader: 'rust-wasm-loader' }]
      }
    ]
  }
};

While bundling native source files directly speeds up rapid prototyping, it introduces important architectural trade-offs:

  • Toolchain Dependency: The host machine running the Webpack build must have native toolchains (Rust/Cargo or Emscripten/LLVM) installed and accessible in the system path.
  • Build Performance: Compiling native languages—especially C++ templates or large Rust dependency trees—takes significantly longer than compiling JavaScript. In production CI/CD pipelines, precompiling code into .wasm modules prior to running Webpack is often preferred to keep bundling times fast.
