Share Redux or Zustand Across Webpack Micro-Frontends

Sharing an active state management store like Redux or Zustand across micro-frontends requires maintaining a single, shared runtime instance across independently bundled applications. Using Webpack 5 Module Federation, you can configure both the state libraries and the actual store instance as shared singletons. This article explains how to configure Webpack Module Federation and architect your code to share an active, reactive Redux or Zustand store seamlessly between a host application and remote micro-frontends.

The Core Problem: Module Isolation

By default, Webpack isolates bundles. If the host container and a remote micro-frontend both import zustand or react-redux, Webpack may bundle separate instances of those libraries. Even if they load the same code, their in-memory execution contexts remain split, causing state updates in one micro-frontend to be invisible to another.

To share an active store, you must satisfy two requirements:

  1. Shared Dependency Singleton: The state library (zustand, redux, react-redux) must resolve to a single runtime instance.
  2. Shared Store Reference: The instantiated store must be accessible across bundle boundaries either through Module Federation exports, React Context at the root, or window-level registry.

1. Webpack Configuration for Singletons

In both your host and remote webpack.config.js files, use ModuleFederationPlugin to declare your state libraries as singletons under the shared key.

// webpack.config.js (Host and Remotes)
const { ModuleFederationPlugin } = require("webpack").container;
const deps = require("./package.json").dependencies;

module.exports = {
  plugins: [
    new ModuleFederationPlugin({
      name: "host", // or "remote"
      shared: {
        ...deps,
        react: { singleton: true, requiredVersion: deps.react },
        "react-dom": { singleton: true, requiredVersion: deps["react-dom"] },
        zustand: { singleton: true, requiredVersion: deps.zustand },
        // If using Redux:
        // "@reduxjs/toolkit": { singleton: true, requiredVersion: deps["@reduxjs/toolkit"] },
        // "react-redux": { singleton: true, requiredVersion: deps["react-redux"] },
      },
    }),
  ],
};

Setting singleton: true forces Webpack to load only one copy of the library, preventing conflicting internal React contexts or distinct memory registries.

2. Sharing a Zustand Store

Zustand is particularly well-suited for micro-frontends because its store is a simple JavaScript closure that can exist independently of the React tree.

Step A: Create and Expose the Store (Host or Shared Library)

Define the store in the host (or a dedicated "shared" micro-frontend) and expose it via Module Federation:

// host/src/store.js
import { create } from "zustand";

export const useSharedStore = create((set) => ({
  user: null,
  theme: "light",
  setUser: (user) => set({ user }),
  setTheme: (theme) => set({ theme }),
}));

Expose the file in the host’s webpack.config.js:

// host/webpack.config.js
new ModuleFederationPlugin({
  name: "host",
  filename: "remoteEntry.js",
  exposes: {
    "./store": "./src/store",
  },
  shared: {
    zustand: { singleton: true },
    react: { singleton: true },
    "react-dom": { singleton: true },
  },
});

Step B: Consume the Store in the Remote

Declare the host remote in the remote’s Webpack configuration:

// remote/webpack.config.js
new ModuleFederationPlugin({
  name: "remoteApp",
  remotes: {
    host: "host@http://localhost:3000/remoteEntry.js",
  },
  shared: {
    zustand: { singleton: true },
    react: { singleton: true },
    "react-dom": { singleton: true },
  },
});

Import and use the store hook directly inside remote components:

// remote/src/UserProfile.jsx
import React from "react";
import { useSharedStore } from "host/store";

export default function UserProfile() {
  const { user, setUser } = useSharedStore();

  return (
    <div>
      <p>Current User: {user ? user.name : "Guest"}</p>
      <button onClick={() => setUser({ name: "Jane Doe" })}>
        Log In as Jane
      </button>
    </div>
  );
}

Because zustand is a singleton and the hook instance comes directly from the host bundle, any changes update all subscribers across micro-frontend boundaries immediately.

3. Sharing an Active Redux Store

Redux relies on React Context via <Provider store={store}>. Sharing an active Redux store requires both a shared react-redux runtime and passing the active store instance down to the remote.

Approach: Pass the Store Instance via Props

Passing the store instance directly from the host to the remote entry component avoids circular dependencies and ensures strict control over lifecycle management.

Host Implementation:

// host/src/App.jsx
import React from "react";
import { Provider } from "react-redux";
import { store } from "./store";

// Dynamically or statically import Remote component
const RemoteWidget = React.lazy(() => import("remoteApp/Widget"));

export default function App() {
  return (
    <Provider store={store}>
      <div>
        <h1>Host Application</h1>
        <React.Suspense fallback="Loading...">
          {/* Pass the store directly to the remote component */}
          <RemoteWidget store={store} />
        </React.Suspense>
      </div>
    </Provider>
  );
}

Remote Implementation:

In the remote component, wrap the internal tree with a Provider using the injected store instance:

// remote/src/Widget.jsx
import React from "react";
import { Provider, useSelector, useDispatch } from "react-redux";

function WidgetContent() {
  const count = useSelector((state) => state.counter.value);
  const dispatch = useDispatch();

  return (
    <div>
      <p>Count from Host Store: {count}</p>
      <button onClick={() => dispatch({ type: "counter/increment" })}>
        Increment
      </button>
    </div>
  );
}

export default function Widget({ store }) {
  // If the host provides the store, wrap with Provider; otherwise use a fallback
  if (!store) {
    return <div>Error: Redux store not provided.</div>;
  }

  return (
    <Provider store={store}>
      <WidgetContent />
    </Provider>
  );
}

Since react-redux is configured with singleton: true, the remote's useSelector and useDispatch interact directly with the host's active dispatcher and state tree.

Key Considerations

  1. Semantic Versioning (requiredVersion): Ensure that the major versions of the shared libraries match between the host and remotes to prevent Webpack from falling back to local copies.
  2. State Decoupling: When using Redux across teams, implement dynamic reducer injection (store.replaceReducer) so micro-frontends can attach their own state slices at runtime without modifying the host's core reducer configuration.
  3. Standalone Mode: For local development, configure remotes to instantiate a mock or local store if the shared store is not passed or available.
