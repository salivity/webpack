Webpack CSS Chunk Naming with Dynamic Imports

Webpack handles CSS chunk naming for dynamic imports by coordinating dynamic code-splitting points with extraction plugins like mini-css-extract-plugin. When an asynchronous JavaScript module is imported using import(), Webpack splits both the JavaScript and its associated CSS into separate asynchronous chunks. This article explains how Webpack determines these CSS chunk names, how to configure them via build settings, and how to control them using inline magic comments.

The Role of mini-css-extract-plugin

By default, Webpack treats CSS as imported JavaScript modules, often injecting styles into the DOM at runtime via style-loader. To generate standalone CSS files for split chunks, projects rely on mini-css-extract-plugin.

When this plugin is active, Webpack creates a corresponding .css chunk for any dynamic chunk that imports stylesheets. The plugin hooks into Webpack’s compilation lifecycle to replicate the dependency graph split, ensuring that loading an asynchronous JavaScript file also fetches its dedicated CSS asset.

Webpack Configuration for CSS Chunks

CSS chunk names are primarily managed through the chunkFilename configuration property inside the MiniCssExtractPlugin options. While filename controls the names of initial chunks, chunkFilename dictates the pattern for non-initial, dynamically loaded CSS assets.

const MiniCssExtractPlugin = require('mini-css-extract-plugin');

module.exports = {
  plugins: [
    new MiniCssExtractPlugin({
      filename: '[name].[contenthash].css',
      chunkFilename: '[name].[contenthash].chunk.css',
    }),
  ],
};

Commonly used substitution templates include:

  • [id]: The internal ID assigned to the chunk by Webpack.
  • [name]: The derived or explicitly assigned name of the chunk.
  • [contenthash]: A hash generated from the contents of the CSS file, essential for long-term browser caching.

If chunkFilename is omitted from the plugin configuration, Webpack typically falls back to the plugin's filename setting or Webpack’s global output.chunkFilename.

Controlling Names with Magic Comments

Without explicit naming, Webpack automatically assigns dynamic chunks an auto-generated identifier (such as an incremental number like 1.css or a path-derived identifier like vendors-node_modules_...css).

To assign deterministic, human-readable names to dynamic chunks and their corresponding CSS assets, Webpack provides the /* webpackChunkName: "name" */ magic comment within the import() statement:

// The extracted stylesheet will resolve using the specified chunk name
import(/* webpackChunkName: "dashboard" */ './Dashboard.js');

When Webpack builds this import, it assigns the string "dashboard" to the [name] placeholder. According to the chunkFilename rule defined in MiniCssExtractPlugin, the resulting CSS file will be emitted as dashboard.[contenthash].chunk.css.

Grouping Multiple Dynamic Imports

Using the same webpackChunkName across multiple dynamic imports merges their code and CSS into a single shared chunk:

import(/* webpackChunkName: "analytics-view" */ './Chart.js');
import(/* webpackChunkName: "analytics-view" */ './Table.js');

If both Chart.js and Table.js import CSS files, Webpack aggregates their styles into one CSS chunk named analytics-view.[contenthash].chunk.css. The client loads this combined stylesheet simultaneously when either module is fetched.
