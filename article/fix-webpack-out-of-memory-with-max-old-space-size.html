Fix Webpack Out of Memory with max-old-space-size

Large Webpack builds often crash with a "JavaScript heap out of memory" error when project assets exceed Node.js's default heap allocation. This article demonstrates how to configure the max-old-space-size flag in Node.js to expand available memory for Webpack, detailing solutions via package.json scripts, the NODE_OPTIONS environment variable, and cross-platform build commands.

Understanding the Problem

By default, the V8 JavaScript engine caps memory consumption to around 2 GB on 64-bit systems (or up to 4 GB in newer Node.js releases). Webpack processes, such as abstract syntax tree (AST) generation, minification, tree-shaking, and source-map creation, can easily exceed these limits on large codebases.

The max-old-space-size flag instructs Node.js to raise the V8 memory threshold. The value is specified in megabytes:

  • 4096: Allocates 4 GB of memory
  • 8192: Allocates 8 GB of memory

Method 1: Using NODE_OPTIONS in package.json (Recommended)

The most portable way to supply this flag to Webpack is by defining the NODE_OPTIONS environment variable directly in your build scripts.

{
  "scripts": {
    "build": "NODE_OPTIONS=--max-old-space-size=4096 webpack --config webpack.config.js"
  }
}

Windows Compatibility with cross-env

Because environment variables are declared differently across operating systems, install cross-env to ensure commands run consistently on Linux, macOS, and Windows:

npm install --save-dev cross-env

Update your script:

{
  "scripts": {
    "build": "cross-env NODE_OPTIONS=--max-old-space-size=4096 webpack --config webpack.config.js"
  }
}

Method 2: Invoking the Webpack CLI Directly via Node

If you run Webpack without wrapper tools, you can pass the flag directly to the Node binary before the Webpack executable path:

{
  "scripts": {
    "build": "node --max-old-space-size=4096 ./node_modules/webpack/bin/webpack.js --config webpack.config.js"
  }
}

Method 3: Setting the Environment Variable Globally

For CI/CD pipelines (such as GitHub Actions, GitLab CI, or Jenkins), you can export the memory setting for the entire runner environment before executing any build steps.

Linux / macOS / Bash:

export NODE_OPTIONS="--max-old-space-size=4096"
npm run build

Windows (Command Prompt):

set NODE_OPTIONS=--max-old-space-size=4096
npm run build

Windows (PowerShell):

$env:NODE_OPTIONS="--max-old-space-size=4096"
npm run build

Additional Strategies to Reduce Memory Usage

If increasing max-old-space-size only delays crashes, inspect the Webpack configuration to reduce overall memory overhead:

  1. Lighten Source Maps: Replace source-map with cheap-module-source-map or eval-cheap-module-source-map during development.
  2. Limit Parallelism: Tools like TerserPlugin or thread-loader spawn worker pools that consume separate memory instances. Set parallel: 2 or parallel: os.cpus().length - 1 to reduce memory spikes.
  3. Exclude Unnecessary Files: Ensure loaders like babel-loader or ts-loader explicitly exclude /node_modules/ via the exclude option.
