Bypass SSL Errors in Webpack Dev Server Proxy

When developing locally against backend services that use self-signed or invalid HTTPS certificates, Webpack Dev Server will block proxy requests by default due to strict SSL validation. This article explains the exact configuration options needed within your webpack.config.js file to bypass these certificate errors safely during development.

The secure Setting

The primary setting to ignore SSL certificate validation errors is secure: false.

Webpack Dev Server relies on http-proxy-middleware under the hood. By default, its secure flag is set to true, which enforces valid SSL certificates. Setting this value to false instructs the proxy to accept backend servers with self-signed, expired, or untrusted certificates.

Configuration Example

Add secure: false directly to the proxy target configuration inside your webpack.config.js:

module.exports = {
  // ... other webpack settings
  devServer: {
    proxy: {
      '/api': {
        target: 'https://localhost:5001',
        secure: false,
        changeOrigin: true,
      },
    },
  },
};

For Webpack Dev Server version 5 (and version 4 arrays syntax), the structure looks like this:

module.exports = {
  // ... other webpack settings
  devServer: {
    proxy: [
      {
        context: ['/api'],
        target: 'https://localhost:5001',
        secure: false,
        changeOrigin: true,
      },
    ],
  },
};

Key Options Explained

  • secure: false: Disables the verification of the target server's SSL certificate. This prevents UNABLE_TO_VERIFY_LEAF_SIGNATURE, DEPTH_ZERO_SELF_SIGNED_CERT, and other standard Node.js TLS rejection errors.
  • changeOrigin: true: While not strictly required for SSL bypassing, this option changes the host header of the request to match the target URL. This is frequently required by backends operating over HTTPS to prevent virtual host routing issues.

Environment-Level Alternative

If you encounter issues before the proxy middleware handles the connection, you can configure Node.js directly to ignore all TLS certificate errors by setting an environment variable before starting Webpack:

NODE_TLS_REJECT_UNAUTHORIZED=0 webpack serve

While effective, using secure: false inside devServer.proxy is the recommended approach, as it confines the insecure behavior exclusively to the proxied requests rather than the entire Node.js runtime.
