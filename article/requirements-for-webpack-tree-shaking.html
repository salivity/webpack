Requirements for Webpack Tree Shaking

Tree shaking is Webpack's mechanism for dead-code elimination, allowing developers to remove unused exports from the final bundle to significantly reduce file size and improve loading performance. To enable Webpack to analyze and prune unreferenced code effectively, your project must fulfill specific structural and configuration criteria. Below are the essential requirements your JavaScript code and build setup must satisfy for Webpack to successfully perform tree shaking.

1. Use Static ES2015 Module Syntax

Webpack's tree shaking algorithm relies on static analysis. Your code must strictly use standard ES6 module syntax (import and export) rather than CommonJS (require() and module.exports). Because CommonJS modules are dynamic and can be imported conditionally or modified at runtime, Webpack cannot reliably determine which exports are unused during the build phase.

2. Prevent Compilers from Transpiling Modules to CommonJS

If you use transpilers like Babel or TypeScript, you must configure them to preserve ES module syntax. By default, older configurations often convert ES modules into CommonJS, breaking Webpack's ability to analyze exports.

  • Babel: In @babel/preset-env, explicitly set { "modules": false }.
  • TypeScript: In tsconfig.json, set "module": "ES2015", "ES2020", or "ESNext".

3. Configure the sideEffects Flag

Even if an exported function is not used, Webpack will retain it if it believes importing the file executes side effects (such as modifying global variables, setting up polyfills, or injecting CSS). You must signal to Webpack that your files are pure:

  • In your package.json, set "sideEffects": false if all unused exports can safely be dropped.

  • If specific files contain side effects (like CSS files or polyfills), specify them in an array:

    "sideEffects": [
  "*.css",
  "./src/polyfills.js"
]

4. Enable Production Mode

Tree shaking is a two-step process: Webpack first marks unused exports during bundling, and then a minifier (such as Terser) removes them. Setting your Webpack configuration to mode: 'production' automatically enables the necessary optimization settings:

  • optimization.usedExports: true (identifies and marks unused code)
  • optimization.minimize: true (strips out the dead code)

If configuring manually, both flags must be enabled for unused code to be physically deleted from the output bundle.

5. Avoid Side-Effect-Prone Code Patterns

Ensure individual functions and modules avoid top-level side effects. Creating functions that modify global state, running computations immediately upon module execution, or assigning methods dynamically to objects can prevent Terser and Webpack from recognizing the code as safe to eliminate. Keeping modules pure and composed of isolated exports ensures reliable tree shaking.
