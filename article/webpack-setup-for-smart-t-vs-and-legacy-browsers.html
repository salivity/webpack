Webpack Setup for Smart TVs and Legacy Browsers

Configuring Webpack for Smart TVs and embedded devices requires downleveling modern JavaScript to older ECMAScript standards and ensuring runtime wrappers are compatible with outdated browser engines. Devices running older versions of Samsung Tizen, LG webOS, or legacy Android TV often rely on Chromium or WebKit builds that lack modern APIs and ES6+ syntax. This guide outlines the essential Webpack settings, Babel configurations, polyfill strategies, and minification options required to output reliable, browser-ready code for legacy embedded environments.

Configure Webpack Output Targets

Webpack 5 defaults to modern ECMAScript runtimes for its internal helper functions (such as arrow functions and const/let bindings). When building for older embedded engines, you must explicitly instruct Webpack to generate ES5-compliant runtime wrapper code using the target configuration:

// webpack.config.js
module.exports = {
  target: ['web', 'es5'],
  output: {
    // Prevent Webpack from using arrow functions in runtime code
    environment: {
      arrowFunction: false,
      bigIntLiteral: false,
      const: false,
      destructuring: false,
      dynamicImport: false,
      forOf: false,
      module: false,
    },
    // Useful for legacy engines handling relative bundle paths
    publicPath: './',
  },
};

Setting target: ['web', 'es5'] guarantees that Webpack’s generated boilerplate (chunk loading logic, module caches, and exports) uses only ES5 syntax.

Transpile Modern Syntax with Babel

While Webpack handles the bundling runtime, babel-loader is required to transpile application code and third-party dependencies down to legacy-compatible JavaScript.

Install the necessary dependencies:

npm install --save-dev babel-loader @babel/core @babel/preset-env core-js

Configure babel-loader in webpack.config.js:

module.exports = {
  module: {
    rules: [
      {
        test: /\.m?js$/,
        // Do not exclude all node_modules; modern packages often distribute ES6+
        exclude: /node_modules\/(?!(modern-package-1|modern-package-2)\/).*/,
        use: {
          loader: 'babel-loader',
          options: {
            presets: [
              [
                '@babel/preset-env',
                {
                  targets: {
                    // Adjust to match the browser version of target TV platforms
                    chrome: '38', // Example: Tizen 2.4/3.0
                  },
                  useBuiltIns: 'usage',
                  corejs: 3,
                  forceAllTransforms: true,
                },
              ],
            ],
          },
        },
      },
    ],
  },
};

Many npm packages ship untranspiled ES6+ syntax. If an embedded engine crashes on unexpected tokens, identify the offending dependency and whitelist it from the exclude rule so Babel processes it.

Manage Runtime Polyfills

Legacy engines lack modern JavaScript global APIs such as Promise, fetch, Object.assign, or Array.prototype.includes. Setting useBuiltIns: 'usage' in @babel/preset-env automatically injects required core-js polyfills based on your code and target engine.

If you encounter issues with global APIs outside the module scope or need polyfills for DOM APIs (such as CustomEvent or whatwg-fetch), import them explicitly at the very top of your entry file:

// src/index.js
import 'core-js/stable';
import 'regenerator-runtime/runtime';
import 'whatwg-fetch';

// Application code follows

Configure Terser for ES5 Minification

Modern minification can reintroduce modern syntax or optimize code in ways that crash older JavaScript interpreters. Configure terser-webpack-plugin to restrict the output strictly to ES5 and work around legacy browser engine bugs:

const TerserPlugin = require('terser-webpack-plugin');

module.exports = {
  optimization: {
    minimize: true,
    minimizer: [
      new TerserPlugin({
        terserOptions: {
          ecma: 5,
          safari10: true, // Fixes loop variable scoping bugs in legacy WebKit
          compress: {
            arrows: false,
            comparisons: false, // Prevents aggressive comparisons that break old V8 builds
          },
          output: {
            ecma: 5,
            comments: false,
            ascii_only: true, // Prevents encoding issues with non-ASCII characters
          },
        },
      }),
    ],
  },
};

The ascii_only: true flag prevents execution errors in embedded engines that fail to parse UTF-8 characters properly in minified bundles.

Complete Configuration Example

Below is a consolidated webpack.config.js tailored for legacy Smart TV web engines:

const path = require('path');
const TerserPlugin = require('terser-webpack-plugin');

module.exports = {
  mode: 'production',
  entry: './src/index.js',
  target: ['web', 'es5'],
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'bundle.js',
    publicPath: './',
    environment: {
      arrowFunction: false,
      const: false,
      destructuring: false,
      forOf: false,
      module: false,
    },
  },
  module: {
    rules: [
      {
        test: /\.js$/,
        exclude: /node_modules/,
        use: {
          loader: 'babel-loader',
          options: {
            presets: [
              [
                '@babel/preset-env',
                {
                  targets: { chrome: '38' },
                  useBuiltIns: 'usage',
                  corejs: 3,
                  forceAllTransforms: true,
                },
              ],
            ],
          },
        },
      },
    ],
  },
  optimization: {
    minimize: true,
    minimizer: [
      new TerserPlugin({
        terserOptions: {
          ecma: 5,
          safari10: true,
          output: {
            ecma: 5,
            ascii_only: true,
          },
        },
      }),
    ],
  },
};
