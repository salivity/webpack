How to Use Webpack resourceQuery for File Imports

In Webpack, the resourceQuery property allows developers to apply different loader configurations to files sharing the same extension based on query strings appended to import statements. This article explains how resourceQuery works, demonstrates how to configure conditional rules in webpack.config.js, and provides practical examples for managing assets such as SVGs or raw data imports without altering file paths or extensions.

Understanding resourceQuery

By default, Webpack matches files using the test property, which typically inspects the file path and extension via regular expressions. However, modern applications often require the same asset type to be processed in multiple ways. For instance, an SVG file might need to be imported as a React component in one place and as an external URL or raw text in another.

The resourceQuery condition tests the query portion of the resource path (the string starting with ?). When combined with Webpack rules, it selectively applies specific loaders, parser settings, or asset modules whenever a defined query string matches.

Configuring Webpack Rules with resourceQuery

To implement conditional handling, define rules inside module.rules using the resourceQuery option. The option accepts a regular expression, a string, a function, or an array of conditions.

Here is an example configuring SVG files to behave differently based on query parameters:

module.exports = {
  module: {
    rules: [
      {
        test: /\.svg$/i,
        oneOf: [
          // Match imports ending in ?raw
          {
            resourceQuery: /raw/,
            type: 'asset/source',
          },
          // Match imports ending in ?react
          {
            resourceQuery: /react/,
            use: ['@svgr/webpack'],
          },
          // Match imports ending in ?url
          {
            resourceQuery: /url/,
            type: 'asset/resource',
          },
          // Default behavior if no query is provided
          {
            type: 'asset/inline',
          },
        ],
      },
    ],
  },
};

Using oneOf ensures that only the first matching rule inside the array is executed, avoiding conflicts between multiple loaders.

Importing Assets with Query Strings

Once the configuration is in place, developers can pass queries directly in JavaScript or TypeScript import or require statements:

// Imported as raw SVG markup string
import rawSvg from './icon.svg?raw';

// Imported as a React component using @svgr/webpack
import IconComponent from './icon.svg?react';

// Imported as an external static asset URL
import iconUrl from './icon.svg?url';

// Default fallback: imported as a Base64 data URI
import defaultIcon from './icon.svg';

Advanced Matching and Exclusions

Webpack also supports negative matching using not within resourceQuery. This allows default rules to explicitly exclude certain queries:

{
  test: /\.css$/i,
  oneOf: [
    {
      resourceQuery: /module/,
      use: [
        'style-loader',
        {
          loader: 'css-loader',
          options: { modules: true },
        },
      ],
    },
    {
      resourceQuery: { not: [/module/] },
      use: ['style-loader', 'css-loader'],
    },
  ],
}

This configuration applies CSS Modules only when ?module is appended, while routing all other CSS imports to the standard CSS loader pipeline.

TypeScript Integration

When using TypeScript, imports with query parameters will cause type-checking errors unless custom ambient module declarations are provided. To resolve this, declare module types in an env.d.ts or globals.d.ts file:

declare module '*.svg?raw' {
  const content: string;
  export default content;
}

declare module '*.svg?react' {
  import React from 'react';
  const Component: React.FC<React.SVGProps<SVGSVGElement>>;
  export default Component;
}

declare module '*.svg?url' {
  const url: string;
  export default url;
}

By leveraging resourceQuery, development teams can handle diverse asset loading strategies cleanly without introducing bespoke file naming conventions or duplicating assets.
