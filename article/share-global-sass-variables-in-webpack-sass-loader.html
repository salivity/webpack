Share Global Sass Variables in Webpack sass-loader

Sharing global Sass variables across an entire project eliminates the need to manually @import or @use shared design tokens, mixins, and theme files inside every component stylesheet. This article demonstrates how to configure Webpack's sass-loader to automatically inject global Sass variables into all stylesheets using the additionalData option, ensuring consistent styling while reducing repetitive boilerplate code.

Step 1: Create the Global Sass File

Create a centralized Sass file containing only variables, functions, or mixins. Avoid writing actual CSS selectors in this file, as they will be duplicated in every compiled stylesheet.

src/styles/_variables.scss:

$primary-color: #3b82f6;
$secondary-color: #10b981;
$font-stack: 'Helvetica Neue', sans-serif;
$breakpoint-mobile: 768px;

Step 2: Configure Webpack

In your webpack.config.js file, locate the rule that handles .scss or .sass files. Add the additionalData property inside the options object of sass-loader.

const path = require('path');

module.exports = {
  module: {
    rules: [
      {
        test: /\.s[ac]ss$/i,
        use: [
          'style-loader',
          'css-loader',
          {
            loader: 'sass-loader',
            options: {
              additionalData: `@use "@/styles/_variables.scss" as *;`,
              sassOptions: {
                // Optional: ensure relative paths resolve cleanly
                includePaths: [path.resolve(__dirname, 'src')],
              },
            },
          },
        ],
      },
    ],
  },
  resolve: {
    alias: {
      '@': path.resolve(__dirname, 'src'),
    },
  },
};

Understanding additionalData Syntax

Depending on which Sass module system you use, you can inject the file in two ways:

  1. Modern Sass (@use):

    additionalData: `@use "@/styles/_variables.scss" as *;`

    Using as * makes variables directly accessible without namespace prefixes (e.g., $primary-color instead of variables.$primary-color).

  2. Legacy Sass (@import):

    additionalData: `@import "@/styles/_variables.scss";`

    While this method works, @import is deprecated in modern Dart Sass.

Handling Dynamic Content with Functions

If you need conditional injection based on file paths, additionalData also accepts a function:

additionalData: (content, loaderContext) => {
  const { resourcePath, rootContext } = loaderContext;
  const relativePath = path.relative(rootContext, resourcePath);

  // Avoid injecting into the variables file itself to prevent recursion
  if (relativePath.endsWith('_variables.scss')) {
    return content;
  }

  return `@use "@/styles/_variables.scss" as *;\n${content}`;
},

Step 3: Use Variables Directly in Stylesheets

Once configured, any component stylesheet can reference the global variables directly without any explicit imports:

src/components/Button.scss:

.button {
  background-color: $primary-color;
  font-family: $font-stack;

  @media (max-width: $breakpoint-mobile) {
    width: 100%;
  }
}
