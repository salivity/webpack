How to Modify Webpack Chunks and Assets with a Plugin

This article explains how to create a custom Webpack plugin that intercepts, alters, and updates existing chunks and emitted asset sources before they are written to disk. By leveraging the Webpack 5 compilation lifecycle—specifically the processAssets hook and the webpack-sources library—developers can safely transform generated code, inject custom logic, or prepend banners across specific chunks.

Understanding the Compilation Lifecycle

In Webpack, files generated from the dependency graph are organized into chunks and emitted as assets. In Webpack 5, the standard way to inspect and mutate these generated assets is through the processAssets hook provided by the Compilation instance. This hook replaces older, deprecated hooks such as optimizeChunkAssets.

The processAssets hook uses stages to determine the priority and timing of operations:

  • Compilation.PROCESS_ASSETS_STAGE_ADDITIONAL: Add new assets to the compilation.
  • Compilation.PROCESS_ASSETS_STAGE_TRANSFORM: Modify existing assets directly.
  • Compilation.PROCESS_ASSETS_STAGE_OPTIMIZE: Optimize existing assets (e.g., minification).

To modify code cleanly before final output, targeting PROCESS_ASSETS_STAGE_TRANSFORM or PROCESS_ASSETS_STAGE_OPTIMIZE is ideal.

Accessing Chunks and Asset Sources

Modifying an asset requires referencing the asset name within compilation.assets and providing a new source object compatible with webpack-sources.

You can modify files in two ways:

  1. Iterating over chunks: Traverse compilation.chunks to target only the files generated from specific entry points or split chunks.
  2. Iterating over assets: Use compilation.getAssets() or compilation.updateAsset() to modify files matching specific naming patterns (e.g., all .js files).

Implementation Example

The following custom plugin demonstrates how to target JavaScript files belonging to specific chunks and append custom comments or wrapper code to their source:

const { sources, Compilation } = require('webpack');

class ModifyChunksPlugin {
  constructor(options = {}) {
    this.options = options;
  }

  apply(compiler) {
    const pluginName = ModifyChunksPlugin.name;

    compiler.hooks.thisCompilation.tap(pluginName, (compilation) => {
      compilation.hooks.processAssets.tap(
        {
          name: pluginName,
          stage: Compilation.PROCESS_ASSETS_STAGE_TRANSFORM,
        },
        (assets) => {
          // Iterate over all compiled chunks
          for (const chunk of compilation.chunks) {
            // Optional: Filter by specific chunk names
            if (this.options.chunkName && chunk.name !== this.options.chunkName) {
              continue;
            }

            // A chunk may emit multiple files (e.g., .js and .js.map)
            for (const fileName of chunk.files) {
              // Target only JavaScript assets
              if (!fileName.endsWith('.js')) {
                continue;
              }

              // Use compilation.updateAsset to mutate the asset safely
              compilation.updateAsset(fileName, (oldSource) => {
                const originalCode = oldSource.source();
                
                // Perform your modification
                const modifiedCode = `/* Injected by Custom Plugin */\n${originalCode}`;

                // Return a new source object (e.g., RawSource, ConcatSource, or ReplaceSource)
                return new sources.RawSource(modifiedCode);
              });
            }
          }
        }
      );
    });
  }
}

module.exports = ModifyChunksPlugin;

Key Considerations

  • Source Maps: If your build relies on source maps, use sources.ReplaceSource or sources.ConcatSource instead of sources.RawSource to preserve accurate line and column mapping.
  • Asset Mutation Safety: Always use compilation.updateAsset() instead of directly overwriting compilation.assets[fileName]. Webpack internally validates operations performed through updateAsset.
  • Execution Order: If other plugins (such as Terser or minifiers) overwrite your changes, adjust the stage option to a later point, such as Compilation.PROCESS_ASSETS_STAGE_SUMMARIZE or Compilation.PROCESS_ASSETS_STAGE_REPORT.
