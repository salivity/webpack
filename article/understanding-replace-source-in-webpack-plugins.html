Understanding ReplaceSource in Webpack Plugins

ReplaceSource is a specialized utility class provided by the webpack-sources package that enables developers to mutate source code within Webpack bundles while automatically tracking and preserving source maps. Webpack plugins commonly utilize ReplaceSource during asset processing hooks to inject, remove, or substitute specific tokens and code patterns inside generated chunks. By operating on character indices rather than performing raw string manipulations, it guarantees that debugging information remains synchronized throughout transformations.

What is ReplaceSource?

In Webpack's compilation pipeline, assets are represented as Source objects rather than plain strings. These objects encapsulate both the raw source code and its corresponding source map representation.

ReplaceSource acts as a decorator for another Source instance (such as RawSource or ConcatSource). Instead of altering code via destructive string replacement methods like String.prototype.replace(), which breaks source mapping lines and columns, ReplaceSource maintains a list of targeted replacements mapped to the original positions. When the source is ultimately serialized, it produces the modified output alongside a properly shifted source map.

Key Methods of ReplaceSource

ReplaceSource operates using 0-based character offsets relative to the original source text. The most common methods include:

  • replace(start, end, newValue, [name]): Replaces the character range from start (inclusive) to end (exclusive) with newValue. The optional name parameter can annotate the mapping in the source map.
  • insert(position, newValue, [name]): Inserts newValue at the specified character offset without replacing existing characters.

A critical advantage of ReplaceSource is that all index references correspond to the original text. You do not need to calculate running offset deltas when performing multiple replacements on the same asset.

How a Plugin Uses ReplaceSource

A Webpack plugin typically interacts with ReplaceSource inside the compilation.hooks.processAssets hook, usually during optimization or code generation stages.

Here is an end-to-end example demonstrating how a plugin wraps an asset in ReplaceSource, finds target text, and commits the transformation:

const { ReplaceSource } = require("webpack-sources");
const { Compilation } = require("webpack");

class BannerReplacementPlugin {
  apply(compiler) {
    compiler.hooks.compilation.tap("BannerReplacementPlugin", (compilation) => {
      compilation.hooks.processAssets.tap(
        {
          name: "BannerReplacementPlugin",
          stage: Compilation.PROCESS_ASSETS_STAGE_OPTIMIZE,
        },
        (assets) => {
          for (const [filename, asset] of Object.entries(assets)) {
            // Target only JavaScript bundles
            if (!filename.endsWith(".js")) continue;

            const originalCode = asset.source();
            const targetPattern = /__BUILD_DATE__/g;
            let match;

            // 1. Wrap the existing asset with ReplaceSource
            const replaceSource = new ReplaceSource(asset);

            // 2. Identify the character indices of all targets
            while ((match = targetPattern.exec(originalCode)) !== null) {
              const start = match.index;
              const end = start + match[0].length;
              const replacementText = JSON.stringify(new Date().toISOString());

              // 3. Queue the replacement at the exact original coordinates
              replaceSource.replace(start, end, replacementText);
            }

            // 4. Update the compilation asset with the ReplaceSource instance
            compilation.updateAsset(filename, replaceSource);
          }
        }
      );
    });
  }
}

module.exports = BannerReplacementPlugin;

Why Use ReplaceSource Over Raw Strings

  1. Source Map Integrity: Direct string replacement invalidates downstream source maps because offsets shift. ReplaceSource recalculates line and column mappings dynamically based on applied mutations.
  2. Deterministic Indexing: Because all mutation coordinates refer to the original source coordinates, developers can iterate over regular expression matches without manually offsetting indices for prior modifications.
  3. Pipeline Compatibility: Returning a ReplaceSource instance satisfies Webpack’s internal asset interfaces, allowing subsequent plugins and stages (such as minification) to consume the asset without disruption.
