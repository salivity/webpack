Dynamic Public Paths with __webpack_public_path__

Webpack allows developers to determine the base path for loading assets and asynchronous chunks at runtime rather than build time. By leveraging the internal free variable __webpack_public_path__, applications can adapt their asset resolution dynamically based on host environments, dynamic Content Delivery Networks (CDNs), or server-injected variables. This article covers how Webpack manages runtime paths, how to implement __webpack_public_path__ properly, and the critical rules regarding module evaluation order.

The Static Public Path Limitation

In standard Webpack configurations, the output.publicPath option determines the target directory path where output files (such as dynamic imports, images, and split chunks) are hosted:

// webpack.config.js
module.exports = {
  output: {
    publicPath: 'https://cdn.example.com/assets/',
  },
};

This approach compiles a hardcoded URL directly into the generated bundles. If the same build artifacts must be deployed across varying domains, multi-tenant subpaths, or regional CDNs, rebuilding the application for each target environment becomes inefficient.

How __webpack_public_path__ Works

Webpack includes an internal runtime variable—historically referred to as __webpack_require__.p—that prepends the base path to any dynamically requested resource.

The __webpack_public_path__ variable is a Webpack-specific global variable exposed to the application code. When Webpack parses this token, it rewrites the assignment directly to the internal runtime property __webpack_require__.p. Changing this variable at runtime immediately updates the URL prefix used for subsequent on-demand chunk loading (e.g., via import()) and asset module resolutions.

Implementation Guide

To use __webpack_public_path__, assign a string representing the desired base path before any asynchronous code or assets are resolved.

1. Create a Dedicated Path Module

Create a file responsible for resolving and assigning the dynamic path. This file should execute before anything else in the application lifecycle.

// src/public-path.js
__webpack_public_path__ = window.ASSET_HOST || '/default-assets/';

In this pattern, the server can render a global window.ASSET_HOST configuration variable directly into the HTML template, allowing the frontend bundle to adapt instantly.

2. Import the Module at the Root Entry

Import the public path definition at the very top of your application's entry point:

// src/index.js
import './public-path';
import './app';

Handling ES Module Import Hoisting

A common pitfall with __webpack_public_path__ involves ES Module (ESM) import hoisting. In standard JavaScript, all static import declarations are hoisted to the top of the file, evaluating imported modules before inline code runs.

If __webpack_public_path__ is assigned inside the main file alongside static imports that immediately trigger chunk loads, the assignment may execute too late:

// Problematic implementation
import { dynamicFeature } from './feature'; // May evaluate before path is set
__webpack_public_path__ = window.DYNAMIC_CDN;

The Solution: Separate Entry Points or Pure Side-Effect Imports

To guarantee that the path assignment happens before any chunk requests:

  1. Top-Level Side-Effect Import: Place the assignment in an isolated file (e.g., public-path.js) and import it as the first line of your main entry file, as shown in the implementation guide.
  2. Webpack Entry Configuration: Define the path module as an entry array item in webpack.config.js, ensuring it runs first:
// webpack.config.js
module.exports = {
  entry: ['./src/public-path.js', './src/index.js'],
};

Combining with output.publicPath: 'auto'

In modern versions of Webpack (v5+), you can also set output.publicPath: 'auto'. This instructs Webpack to infer the public path automatically from the currentScript, document.baseURI, or the relative path of the executing bundle.

However, setting __webpack_public_path__ explicitly overrides the automated resolution, giving complete programmatic control when automatic detection is insufficient, such as in environments without a DOM or when delegating asset delivery to external CDNs.
