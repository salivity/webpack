Configure Webpack Asset Loading with resourceFragment

Webpack’s resourceFragment property allows developers to match and route assets based on the URL fragment (the #hash identifier) provided in an import or require statement. By filtering through resourceFragment, Webpack can apply distinct loader pipelines or asset/* module types to the exact same file depending on how it is requested. This overview explains how resourceFragment works, how to configure it in webpack.config.js, and the common scenarios where fragment-based asset routing is most effective.

Understanding resourceFragment

In JavaScript module systems, an import path can include URL fragments:

import iconInline from './icon.svg#inline';
import iconUrl from './icon.svg#url';

While Webpack matches the file path (./icon.svg) against the standard test or resource regex, it strips the # fragment from the resolved file system path. Instead, Webpack assigns the fragment (including or excluding the #, matching via regex or string) to resourceFragment.

This mechanism is distinct from resourceQuery, which targets query parameters (?param=value). Using fragments is particularly natural for media and SVGs, where hashes often align with browser-native SVG fragment identifiers or styling contexts.

Basic Configuration

You configure resourceFragment inside the module.rules array of your Webpack configuration. It accepts a RegExp, a string, or an array/logical condition object.

module.exports = {
  module: {
    rules: [
      {
        test: /\.svg$/,
        resourceFragment: /inline/,
        type: 'asset/inline',
      },
      {
        test: /\.svg$/,
        resourceFragment: /external/,
        type: 'asset/resource',
      },
      {
        test: /\.svg$/,
        resourceFragment: { not: [/inline/, /external/] },
        type: 'asset', // Default fallback behavior
      },
    ],
  },
};

In this setup:

  • Importing ./icon.svg#inline converts the SVG to a base64-encoded data URI.
  • Importing ./icon.svg#external emits the SVG as a separate static file and returns its public URL.
  • Importing ./icon.svg without a fragment falls back to Webpack's automatic asset size threshold.

Common Use Cases

1. Dual-Mode SVG Handling

A standard application often requires SVGs to act both as React components (for dynamic styling) and as standard image URLs (for <img> tags or CSS backgrounds). resourceFragment enables this cleanly:

module.exports = {
  module: {
    rules: [
      {
        test: /\.svg$/,
        resourceFragment: /react/,
        use: ['@svgr/webpack'],
      },
      {
        test: /\.svg$/,
        resourceFragment: { not: [/react/] },
        type: 'asset/resource',
      },
    ],
  },
};

Usage:

import LogoComponent from './logo.svg#react';
import logoUrl from './logo.svg';

2. SVG Sprite Stacks

Native SVG specifications allow referencing specific sub-elements using fragment identifiers, such as icon.svg#search-view. Using resourceFragment, you can intercept specific sprite identifiers with custom loaders while letting native fragment references pass through unmodified to the output URL.

3. Granular CSS Module Control

You can toggle between raw CSS, CSS Modules, or Shadow DOM inject methods for the same stylesheet:

{
  test: /\.css$/,
  resourceFragment: /raw/,
  type: 'asset/source',
}

resourceFragment vs. resourceQuery

  • resourceQuery checks values after a question mark (./image.png?as=webp).
  • resourceFragment checks values after a hash (./image.png#inline).

Both offer conditional loader mapping without altering the underlying file on disk. However, resourceFragment is ideal when adhering to standard URL semantics where the hash represents a specific state, view, or fragment of an asset rather than a parameterized build query.
