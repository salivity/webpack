Understanding resolve.extensions in Webpack

In a Webpack configuration, the resolve.extensions option specifies which file extensions Webpack should automatically append when resolving module import statements that omit explicit file extensions. By defining an array of extensions such as .js, .ts, or .jsx, this configuration streamlines source code readability and enables seamless integration with various languages and preprocessors across a project.

How resolve.extensions Works

When you import a file without specifying its extension—such as import App from './App'—Webpack uses the resolve.extensions list to determine which file to look for on the filesystem.

Webpack iterates through the array in order from left to right. For example, given the configuration:

module.exports = {
  // ...
  resolve: {
    extensions: ['.ts', '.tsx', '.js', '.jsx'],
  },
};

Webpack resolves ./App by checking the file system in the following order:

  1. ./App.ts
  2. ./App.tsx
  3. ./App.js
  4. ./App.jsx

As soon as Webpack finds a matching file, it stops searching and bundles that file. If no matching file is found after testing every extension in the array, Webpack throws a "Module not found" error.

Default Values

In Webpack 5, the default setting for resolve.extensions is:

['.js', '.json', '.wasm']

If you override this property without including the default extensions, Webpack will no longer resolve .js or .json files without explicit extensions. In Webpack 5, you can retain the defaults while adding custom extensions by using the spread operator syntax:

module.exports = {
  resolve: {
    extensions: ['.ts', '.tsx', '...'],
  },
};

The '...' token instructs Webpack to append its default extensions list at that position.

Why resolve.extensions Is Important

  • Cleaner Import Statements: Developers can write cleaner, more maintainable code without hardcoding extensions in every import or require statement.
  • Framework and Language Support: Compilers for TypeScript (.ts, .tsx) or React (.jsx) depend on this option to allow standard module syntax across mixed-language codebases.
  • File Precedence Control: Because resolution occurs sequentially, developers can intentionally prioritize one file type over another (e.g., loading .ts files before .js files if both exist in the same directory).

Best Practices and Considerations

Order matters significantly. Place the most frequently imported extensions at the beginning of the array to minimize disk access operations during the build. Keeping the list as short as possible ensures optimal build performance, as each added extension increases the number of filesystem lookups Webpack must perform for every extensionless import.
