Webpack Module vs Nomodule Build Setup

Differential serving through the module and nomodule pattern enables developers to deliver lightweight, modern ES2015+ code to modern browsers while maintaining backwards compatibility for legacy browsers using polyfilled, transpiled bundles. By implementing this pattern, modern browsers skip polyfills and heavy syntax transformations, significantly reducing bundle size and execution time. This guide covers how to implement a dual-bundle pipeline in Webpack using multi-compiler configurations, targeted Babel transpilation, and HTML script injection.

The Module / Nomodule Pattern Explained

Modern browsers natively support ES modules using <script type="module" src="modern.js"></script>. Browsers that recognize the type="module" attribute execute the file and automatically ignore any script containing the nomodule attribute: <script nomodule src="legacy.js"></script>.

Conversely, older browsers that do not understand ES modules ignore the type="module" script entirely and execute the nomodule fallback. This provides a native mechanism to conditionally load different JavaScript bundles without user-agent sniffing.

Configuring Webpack Multi-Compiler

Webpack natively supports exporting an array of configurations. This multi-compiler mode runs both builds simultaneously, creating isolated modern and legacy bundles.

// webpack.config.js
const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

const commonConfig = {
  entry: './src/index.js',
  resolve: {
    extensions: ['.js'],
  },
};

// 1. Legacy Configuration
const legacyConfig = {
  ...commonConfig,
  name: 'legacy',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].legacy.[contenthash].js',
  },
  module: {
    rules: [
      {
        test: /\.js$/,
        exclude: /node_modules/,
        use: {
          loader: 'babel-loader',
          options: {
            presets: [
              [
                '@babel/preset-env',
                {
                  targets: '> 0.5%, last 2 versions, Firefox ESR, not dead',
                  useBuiltIns: 'usage',
                  corejs: 3,
                },
              ],
            ],
          },
        },
      },
    ],
  },
};

// 2. Modern Configuration
const modernConfig = {
  ...commonConfig,
  name: 'modern',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].modern.[contenthash].js',
  },
  module: {
    rules: [
      {
        test: /\.js$/,
        exclude: /node_modules/,
        use: {
          loader: 'babel-loader',
          options: {
            presets: [
              [
                '@babel/preset-env',
                {
                  targets: { esmodules: true },
                  bugfixes: true,
                },
              ],
            ],
          },
        },
      },
    ],
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/index.html',
      inject: false, // Script injection is handled customly
    }),
  ],
};

module.exports = [legacyConfig, modernConfig];

Key Babel Configuration Differences

  1. Legacy Targets: The legacy configuration uses a standard Browserlist query (e.g., > 0.5%, not dead) paired with @babel/preset-env and core-js to aggressively polyfill and transpile syntax back to ES5.
  2. Modern Targets: The modern configuration utilizes targets: { esmodules: true }. When set, Babel targets browsers that natively support ES modules (such as Safari 10.1+, Chrome 61+, Firefox 60+, and Edge 16+). Modern syntax features like async/await, classes, and arrow functions remain untranspiled, resulting in smaller payloads and faster parsing. Setting bugfixes: true further optimizes output by compiling only broken syntax implementations rather than entire feature sets.

Injecting Assets into HTML Templates

To link the generated files in the final HTML document, you must coordinate asset injection between both builds. A reliable approach involves writing a manifest file during the builds or configuring custom templates via HtmlWebpackPlugin.

Using template parameters with Webpack compilation hooks allows you to inject attributes directly into the generated markup:

<!-- src/index.html -->
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>App</title>
</head>
<body>
  <div id="root"></div>

  <!-- Legacy Fallback Script -->
  <script nomodule src="main.legacy.<hash>.js" defer></script>

  <!-- Modern Script -->
  <script type="module" src="main.modern.<hash>.js"></script>
</body>
</html>

For fully automated injection without hardcoded asset names, use a post-processing plugin such as webpack-manifest-plugin to generate an asset map, or utilize custom HtmlWebpackPlugin hooks to dynamically append type="module" to the modern assets and nomodule to the legacy assets before writing the HTML to disk.
