How Webpack Loads Dynamic Externals on Demand

Dynamic externals in Webpack allow applications to decouple dependencies from the main bundle and fetch them from external locations, such as a Content Delivery Network (CDN), only when requested at runtime. Rather than hardcoding third-party libraries into static HTML <script> tags or bundling them directly, Webpack resolves dynamic imports into runtime instructions that dynamically inject script tags into the Document Object Model (DOM). This article explains the internal mechanics behind how Webpack handles dynamic externals, how the runtime orchestrates on-demand script loading, and how the external library binds back into the module system.

Static vs. Dynamic Externals

Standard Webpack externals require dependencies to exist globally (for example, on the window object) before the bundle executes. If the application bundles an external without loading it first, runtime errors occur immediately.

Dynamic externals resolve this limitation. By pairing Webpack's externalsType: 'script' with dynamic import() statements, Webpack postpones fetching the dependency until the code branch executing the import() is reached.

Configuration Setup

To enable on-demand loading of external scripts, Webpack relies on the script external type. This can be configured in webpack.config.js:

module.exports = {
  externalsType: 'script',
  externals: {
    lodash: ['https://cdn.jsdelivr.net/npm/lodash@4.17.21/lodash.min.js', '_'],
  },
};

In this configuration, the key (lodash) represents the imported module specifier, the first array element defines the remote URL, and the second element defines the global variable exposed by the external script on window.

The Under-the-Hood Loading Mechanism

When your application code triggers a dynamic import such as const _ = await import('lodash'), Webpack executes a distinct multi-step process at runtime:

1. Runtime Detection and Promise Creation

Webpack compiles the dynamic import() call into an internal runtime call, typically __webpack_require__.e. This runtime function is responsible for ensuring the specified chunk or external script is fetched and ready. It initializes a JavaScript Promise to track the loading state.

2. DOM Injection via __webpack_require__.l

Webpack contains an internal runtime utility (historically represented as __webpack_require__.l) specifically designed for DOM script injection. When the external is requested:

  • Webpack checks if a <script> tag with the target URL already exists to prevent duplicate downloads.
  • If it does not exist, Webpack creates a standard HTML element: document.createElement('script').
  • It configures attributes such as script.src = url, script.async = true, and attaches tracking handlers for onload and onerror.
  • The element is appended to document.head.

3. Execution and Global Namespace Binding

The browser downloads the script asynchronously and executes it. Standard UMD or IIFE-based external scripts automatically attach their exports to the global object (window).

4. Promise Resolution and Module Synthesis

Once the browser fires the onload event:

  • Webpack’s script loader handler fires, marking the network request as complete.
  • Webpack accesses the global variable configured in the externals definition (for example, window._).
  • The runtime packages this global variable into a synthetic ES module structure, complete with default and named exports.
  • The initial Promise returned by import() resolves, allowing execution to proceed with the fetched library.

Error Handling and Fallbacks

If the network request fails or the script times out, the onerror event triggers. Webpack rejects the internal promise, converting the failure into a catchable JavaScript error:

try {
  const { default: remoteModule } = await import('remote-lib');
} catch (error) {
  console.error('Failed to load the external script:', error);
}

This dynamic approach eliminates the need to load large dependencies during the initial page paint, ensuring third-party vendor code is downloaded strictly when the user needs it.
