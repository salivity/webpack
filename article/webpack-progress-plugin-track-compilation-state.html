Webpack ProgressPlugin: Track Compilation State

webpack.ProgressPlugin is a built-in Webpack utility designed to report the status and progress of the compilation process in real time. This article covers what webpack.ProgressPlugin is, how it hooks into the internal build lifecycle to determine compilation stages, and how developers can configure it to display custom build metrics and progress indicators in their terminal or build tooling.

What Is webpack.ProgressPlugin?

webpack.ProgressPlugin provides feedback during Webpack's build execution. By default, large builds can appear stalled as Webpack resolves dependencies, parses Abstract Syntax Trees (ASTs), runs loaders, and applies optimizations. ProgressPlugin bridges this visibility gap by tapping directly into Webpack's internal hooks to calculate an estimated completion percentage and identify the current active compilation task.

How ProgressPlugin Tracks Compilation State

Webpack compiles assets through a sequence of internal hooks managed by its Tapable engine. ProgressPlugin intercepts these lifecycle stages to infer progress.

  1. Lifecycle Hook Attachment: When initialized, the plugin attaches listeners to key compiler and compilation hooks such as beforeRun, run, normalModuleFactory, compilation, make, optimize, and emit.
  2. State Estimation: Webpack cannot know the exact number of modules in advance because dynamic imports and nested dependencies are discovered recursively. To overcome this, ProgressPlugin calculates an estimated completion ratio (from 0 to 1) based on the current stage of the build pipeline (e.g., module resolution, compilation, tree shaking, asset emission).
  3. Module Counter Tracking: As modules are resolved and transformed by loaders, the plugin tracks how many modules have finished versus how many are currently enqueued, updating the overall percentage continuously.

Displaying Compilation State

By default, when enabled through the Webpack configuration or the CLI flag (--progress), the plugin writes directly to the standard output (stdout), printing a percentage along with the current compilation step:

// webpack.config.js
const webpack = require('webpack');

module.exports = {
  // ... other configuration settings
  plugins: [
    new webpack.ProgressPlugin()
  ]
};

This renders inline updates in the terminal, such as:

10% building 2/2 modules 0 active
70% building 142/150 modules 8 active .../src/components/App.js
98% emit

Customizing the Display Handler

ProgressPlugin accepts a custom handler function that receives the raw progress metrics. This allows developers to route compilation data to custom loggers, graphical interfaces, or remote monitoring systems.

new webpack.ProgressPlugin({
  activeModules: true,
  entries: true,
  modules: true,
  modulesCount: 5000,
  profile: false,
  handler(percentage, message, ...args) {
    const percent = Math.floor(percentage * 100);
    console.log(`${percent}% - ${message}`, ...args);
  }
})

The parameters provided to the custom handler are:

  • percentage: A floating-point number between 0 and 1 representing the overall build progress.
  • message: A short description of the current task (e.g., building, optimizing, emitting).
  • ...args: Contextual details, such as the current module path, module count, or optimization step.

Configuration Options

The plugin supports several configuration flags to control the granularity of the displayed state:

  • activeModules (boolean): Displays the file currently being processed.
  • entries (boolean): Displays progress regarding the entry point resolution.
  • modules (boolean): Displays the count of built modules versus total detected modules.
  • modulesCount (number): Sets an initial minimum module count to improve percentage accuracy early in the build.
  • profile (boolean): Collects execution timings for individual build steps to help identify performance bottlenecks.
