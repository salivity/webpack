How to Fix Invalid Host Header in Webpack Dev Server

The "Invalid Host Header" error in Webpack Dev Server occurs as a security measure designed to protect local development environments from DNS rebinding attacks. This issue typically arises when you access your development server through a proxy, a tunneling service like ngrok, a local IP address, or a custom domain name instead of standard localhost. Resolving it requires configuring Webpack Dev Server to recognize and whitelist the incoming host header, or bypassing the check entirely in controlled development environments.

What Causes the Error?

By default, Webpack Dev Server validates the incoming HTTP Host header sent by the browser. It checks whether the request originates from localhost or 127.0.0.1.

If an attacker tricks a user into visiting a malicious site, that site could execute JavaScript to send requests to local services via DNS rebinding. To prevent unauthorized external sites from interacting with your local server, Webpack blocks any request where the Host header does not match expected local addresses. When you use tools like ngrok, port-forwarding, Docker containers, or custom domains mapped via your hosts file, the Host header differs from what Webpack expects, triggering the "Invalid Host Header" screen.

How to Resolve the Error

Depending on your Webpack Dev Server version and project setup, you can resolve this issue using the following methods.

Method 1: Use allowedHosts (Webpack Dev Server v4+)

For modern setups using Webpack Dev Server version 4 or newer, configure the allowedHosts option in your webpack.config.js. This is the safest approach because it restricts access only to designated domains.

To allow specific domains, pass an array of hostnames:

// webpack.config.js
module.exports = {
  // ...
  devServer: {
    allowedHosts: [
      'my-custom-domain.local',
      '.ngrok-free.app', // Leading dot acts as a wildcard for subdomains
    ],
  },
};

If you are working in a secure local environment and need to allow any incoming host (such as when testing across multiple devices on a local network), you can set allowedHosts to 'all':

// webpack.config.js
module.exports = {
  // ...
  devServer: {
    allowedHosts: 'all',
  },
};

Method 2: Use disableHostCheck (Webpack Dev Server v3 and Older)

If your project relies on Webpack Dev Server v3 or earlier, the allowedHosts configuration may not support string values like 'all'. Instead, use the disableHostCheck flag:

// webpack.config.js (Webpack Dev Server v3)
module.exports = {
  // ...
  devServer: {
    disableHostCheck: true,
  },
};

Note: disableHostCheck is deprecated and removed in Webpack Dev Server v4. If you are on version 4 or higher, use allowedHosts: 'all' instead.

Method 3: Fix for Create React App (CRA)

If you are using Create React App and have not ejected your configuration, you cannot modify webpack.config.js directly.

You can bypass the check by creating or updating a .env.development file in the root of your project:

DANGEROUSLY_DISABLE_HOST_CHECK=true

Alternatively, add it directly to your startup script inside package.json:

"scripts": {
  "start": "DANGEROUSLY_DISABLE_HOST_CHECK=true react-scripts start"
}

On Windows environments without bash support, use cross-env:

"scripts": {
  "start": "cross-env DANGEROUSLY_DISABLE_HOST_CHECK=true react-scripts start"
}

After modifying your configuration or environment variables, restart the development server for the changes to take effect.
