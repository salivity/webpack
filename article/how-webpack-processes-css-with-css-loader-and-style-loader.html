How Webpack Processes CSS with css-loader and style-loader

Webpack treats all files as modules, but natively it only understands JavaScript and JSON. This article explains how Webpack processes stylesheets by chaining two essential loaders: css-loader and style-loader. You will learn the exact order of execution, the specific responsibility of each loader, and how they convert raw CSS files into active styles rendered inside the browser's Document Object Model (DOM).

The Loader Execution Order

In a Webpack configuration, loaders are defined inside the module.rules array. When chaining multiple loaders for a single file type, Webpack executes them in reverse order: from right to left, or bottom to top.

A standard CSS configuration looks like this:

module.exports = {
  module: {
    rules: [
      {
        test: /\.css$/i,
        use: ['style-loader', 'css-loader'],
      },
    ],
  },
};

Because of the reverse execution order, Webpack passes the .css file to css-loader first. Once css-loader finishes its transformations, the resulting output is passed directly into style-loader.

Step 1: Parsing Styles with css-loader

The primary responsibility of css-loader is to interpret CSS syntax and convert it into a JavaScript module.

When your JavaScript imports a stylesheet (e.g., import './main.css'), css-loader performs the following tasks:

  • Resolves Dependencies: It interprets @import statements and internal asset paths like url('./image.png'), translating them into standard ES modules or require() statements that Webpack can bundle.
  • Converts to JavaScript: It reads the CSS file contents and outputs a JavaScript module that exports the CSS rules as a string, along with metadata needed to track source maps or CSS Modules.

At this stage, the CSS has been translated into valid JavaScript, but it has not yet been applied to the webpage. If you use css-loader alone, the styling will exist inside your bundle as a JavaScript string, but the browser will not render it.

Step 2: Injecting Styles with style-loader

Once css-loader converts the CSS into a JavaScript module, style-loader takes over to make those styles active in the browser.

style-loader does not parse CSS rules itself. Instead, it adds runtime code to the final JavaScript bundle that:

  1. Creates an HTML <style> element during runtime.
  2. Injects the CSS string generated by css-loader into that element.
  3. Appends the <style> tag directly to the <head> of the DOM when the bundle loads in the browser.

By deferring the style injection to JavaScript runtime, style-loader enables features like Hot Module Replacement (HMR), allowing styles to update instantly during development without requiring a full page reload.

Summary of the Processing Pipeline

  1. Trigger: Webpack encounters an import such as import './styles.css' in the dependency graph.
  2. css-loader: Reads the raw CSS, resolves all @import and url() references, and exports the CSS as a JavaScript module string.
  3. style-loader: Takes the JavaScript string and wraps it with runtime instructions to dynamically inject a <style> tag into the DOM <head>.
  4. Result: The browser executes the bundle, mounts the styles, and renders the styled page.
