How to Ignore node_modules in Webpack Watch Mode

When developing with Webpack in watch mode, monitoring file changes can quickly become resource-intensive and degrade system performance. This guide demonstrates how to use Webpack’s watchOptions.ignored setting to exclude large, static directories like node_modules from the watcher, significantly reducing CPU and memory overhead while speeding up rebuild times.

The Problem with Default Watching

By default, Webpack watches all files resolved within your dependency tree. Because the node_modules directory often contains tens of thousands of files, allowing Webpack to watch this folder wastes system resources and can lead to high CPU spikes, battery drain, and system-level file-descriptor errors (such as EMFILE: too many open files). Since third-party packages rarely change during active local development, watching them is generally unnecessary.

Configuring watchOptions.ignored

You can exclude directories by configuring the watchOptions object inside your webpack.config.js file. The ignored property accepts a regular expression, an absolute path string, a glob pattern, or an array containing a combination of these types.

Here is the standard setup to ignore node_modules:

// webpack.config.js
const path = require('path');

module.exports = {
  // ... other configuration settings (entry, output, module, etc.)
  watch: true,
  watchOptions: {
    // Ignore node_modules using a RegExp
    ignored: /node_modules/,
  },
};

Advanced Patterns and Multiple Directories

For more complex projects, you may want to ignore multiple directories, such as build outputs, test coverage folders, or version control directories. You can pass an array or use glob syntax.

// webpack.config.js
module.exports = {
  watchOptions: {
    // Array syntax matching multiple patterns
    ignored: [
      '**/node_modules/**',
      '**/dist/**',
      '**/.git/**',
    ],
  },
};

Webpack uses the anymatch library under the hood to process the ignored property. While glob strings are flexible, using a standard JavaScript regular expression like /node_modules/ is generally faster and avoids cross-platform path-separator issues between Windows and Unix environments.

Fine-Tuning Performance with Other Watch Options

To optimize rebuild performance further alongside ignored, you can combine it with aggregateTimeout:

// webpack.config.js
module.exports = {
  watchOptions: {
    ignored: /node_modules/,
    // Delay the rebuild after the first change (in milliseconds)
    aggregateTimeout: 300,
  },
};

The aggregateTimeout setting adds a small buffer before triggering a rebuild, aggregating multiple simultaneous changes into a single compilation cycle.

Excluding node_modules via watchOptions.ignored ensures Webpack only monitors the code you are actively modifying, resulting in faster development rebuilds and lower system resource usage.
