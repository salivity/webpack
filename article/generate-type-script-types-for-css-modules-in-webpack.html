Generate TypeScript Types for CSS Modules in Webpack

Integrating CSS Modules into a TypeScript project often results in type errors because the TypeScript compiler does not natively understand CSS imports. This guide demonstrates how to automatically generate .d.ts declaration files for CSS Modules using Webpack, enabling full autocompletion, type safety for class names, and error prevention during builds.

The Problem

When importing a CSS module into a TypeScript file:

import styles from './Button.module.css';

// TypeScript throws: Cannot find module './Button.module.css'
const Button = () => <button className={styles.btnPrimary}>Click</button>;

Without declaration files, TypeScript does not recognize the CSS file path or the class names defined within it. While creating a generic globals.d.ts file with declare module '*.module.css' stops the compiler error, it treats all classes as any, forfeiting autocomplete and type-checking.

Solution: Use css-modules-typescript-loader

The most common and seamless way to generate .d.ts files automatically during development and build steps is by inserting css-modules-typescript-loader into your Webpack configuration.

1. Install Dependencies

Install the required loaders:

npm install --save-dev css-modules-typescript-loader css-loader style-loader

2. Configure Webpack

Update your webpack.config.js to include css-modules-typescript-loader.

Loaders execute from right to left (or bottom to top). The css-modules-typescript-loader must run immediately after css-loader parses the class names, but before style-loader or MiniCssExtractPlugin.loader.

module.exports = {
  module: {
    rules: [
      {
        test: /\.module\.css$/,
        use: [
          'style-loader',
          {
            loader: 'css-modules-typescript-loader',
            options: {
              mode: process.env.NODE_ENV === 'production' ? 'verify' : 'emit'
            }
          },
          {
            loader: 'css-loader',
            options: {
              modules: {
                namedExport: true,
                localIdentName: '[name]__[local]--[hash:base64:5]'
              }
            }
          }
        ]
      }
    ]
  }
};

Options Explained:

  • mode: 'emit': Creates or updates the .d.ts files alongside each .module.css file during development.
  • mode: 'verify': Validates that existing .d.ts files are up-to-date without writing to disk. This is ideal for Continuous Integration (CI) environments to catch missing or outdated type definitions.

Working with SASS / SCSS Modules

If you are using SCSS, include sass-loader at the end of the chain:

{
  test: /\.module\.scss$/,
  use: [
    'style-loader',
    'css-modules-typescript-loader',
    {
      loader: 'css-loader',
      options: {
        modules: true
      }
    },
    'sass-loader'
  ]
}

Git Management and Housekeeping

Because css-modules-typescript-loader writes .d.ts files directly to your source directory next to the corresponding CSS file (e.g., Button.module.css.d.ts), you must decide whether to commit these generated files.

To avoid bloating Git diffs with automatically generated code, add the generated declaration files to your .gitignore:

*.module.css.d.ts
*.module.scss.d.ts

If you ignore these files in Git, ensure your build command runs Webpack or an explicit type-generation script prior to running tsc in your CI/CD pipelines.
