Webpack Rule: Test vs Include vs Exclude

In Webpack, module rules define how different types of files are processed by loaders during the bundling process. The test, include, and exclude properties act as filtering conditions that determine whether a specific file should be transformed by a given loader. While they all evaluate file paths, they serve different functional roles, operate with specific priority rules, and directly impact your build performance.

The test Property

The test property specifies a condition that a file path must match to be considered by the loader. It is typically defined using a regular expression that targets file extensions.

  • Purpose: Identifies the file type.
  • Common Use: Setting test: /\.jsx?$/ to target .js and .jsx files, or test: /\.css$/ for stylesheets.
  • Behavior: It checks the absolute path of the resource. Without include or exclude, test will apply the loader to every matching file across the entire project, including dependencies.

The include Property

The include property restricts the loader to only match files within a specific directory or set of paths.

  • Purpose: Whitelists directories that should be processed.
  • Common Use: Setting include: path.resolve(__dirname, 'src') to ensure only your application's source code is transformed.
  • Behavior: If a file matches test but is located outside the include path, Webpack will not pass it to the loader. Using include is considered a performance best practice because it prevents loaders from needlessly analyzing external files.

The exclude Property

The exclude property specifies files or directories that must be skipped, even if they match the test condition.

  • Purpose: Blacklists specific directories from processing.
  • Common Use: Setting exclude: /node_modules/ to prevent third-party packages from being re-compiled by heavy loaders like Babel.
  • Behavior: Any file located inside an excluded path is immediately bypassed by the loader.

Key Differences and Precedence

The main difference lies in how Webpack evaluates these properties together:

  1. Filtering Mechanism: test checks the file extension, include specifies the allowed file locations (whitelist), and exclude specifies forbidden file locations (blacklist).
  2. Priority: exclude takes precedence over include. If a file path matches both an include rule and an exclude rule, the file will be excluded.
  3. Execution Condition: For a loader to execute on a file, the file must match the test condition, match the include condition (if one is provided), and not match the exclude condition.
const path = require('path');

module.exports = {
  module: {
    rules: [
      {
        test: /\.js$/,
        include: path.resolve(__dirname, 'src'),
        exclude: /node_modules/,
        use: {
          loader: 'babel-loader',
        },
      },
    ],
  },
};

In this configuration, Babel will only process files that end in .js, reside within the src directory, and are not located inside node_modules. While specifying both include and exclude works, using an explicit include pointing to your source directory often makes exclude: /node_modules/ redundant, as node_modules is already outside the src folder.
