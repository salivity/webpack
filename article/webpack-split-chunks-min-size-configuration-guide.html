Webpack SplitChunks minSize Configuration Guide

The minSize option in Webpack's SplitChunksPlugin dictates the minimum file size, in bytes, required for a module or group of modules to be split into a separate chunk. This article explains how the minSize threshold works, why it is critical for balancing network overhead against asset caching, and how to configure it effectively within your Webpack setup.

Understanding minSize

In modern web development, code splitting creates smaller bundles so browsers only download what they need. However, creating too many tiny chunks can degrade performance due to the overhead of extra HTTP requests. The minSize setting acts as a safeguard against excessive fragmentation by preventing Webpack from generating chunks that are smaller than a specified byte limit.

If a potential chunk does not meet this threshold, Webpack leaves the code in its parent bundle or merges it with other chunks rather than isolating it into its own file.

In Webpack 5, the default value for minSize is 20000 bytes (approximately 20 KiB) in production mode.

How to Configure minSize

You can configure minSize globally within the optimization.splitChunks object, or target specific module groups inside the cacheGroups configuration.

// webpack.config.js
module.exports = {
  // ...
  optimization: {
    splitChunks: {
      // Global threshold applied to all chunks
      minSize: 20000,
      cacheGroups: {
        vendor: {
          test: /[\\/]node_modules[\\/]/,
          name: 'vendors',
          // Override global minSize for vendor libraries
          minSize: 30000,
          chunks: 'all',
        },
      },
    },
  },
};

When defined within a specific cache group, that value overrides the global setting.

Key Considerations

1. HTTP/1.1 vs. HTTP/2 and HTTP/3

Under HTTP/1.1, browsers are limited to a small number of simultaneous TCP connections per domain. Setting a higher minSize (e.g., 30–50 KiB) reduces the total number of requests, preventing connection bottlenecks. Under HTTP/2 and HTTP/3 with multiplexing, smaller chunks are less penalized, allowing you to lower minSize if fine-grained cache invalidation is a priority.

2. Interaction with maxSize

Webpack provides a companion setting called maxSize. While minSize enforces the lower bound, maxSize tells Webpack to try splitting chunks larger than that limit into smaller parts. The minSize property always takes precedence: Webpack will not split a chunk to satisfy maxSize if doing so creates a piece smaller than minSize.

3. Development vs. Production

In development mode, minSize defaults to 10000 bytes to speed up build times. For production builds, you should monitor your real-world bundle analysis using tools like webpack-bundle-analyzer to ensure minSize is neither producing thousands of negligible micro-chunks nor bundling distinct third-party libraries into massive monolithic files.
