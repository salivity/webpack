How Webpack Handles CSS-in-JS Compilation

This article provides an overview of how Webpack processes CSS-in-JS libraries during bundle compilation. It examines the fundamental divergence between runtime and build-time (zero-runtime) libraries, detailing how Webpack leverages custom loaders, Abstract Syntax Tree (AST) transformations, and standard CSS extraction pipelines to convert component-level styles into production-ready browser assets.

The Two Approaches to CSS-in-JS

Webpack's handling of CSS-in-JS depends entirely on whether a library relies on runtime style injection or build-time static extraction. Because Webpack is fundamentally a module bundler that treats all imported files as dependencies in a dependency graph, it interacts with these two paradigms in distinctly different ways.

1. Runtime CSS-in-JS Libraries

Libraries such as Styled Components and Emotion (in their default configurations) execute their styling logic directly in the browser's JavaScript runtime.

When compiling runtime CSS-in-JS, Webpack does not process any actual CSS files. Instead:

  • JavaScript Transpilation: Webpack treats the styled components purely as JavaScript or TypeScript modules. Loaders like babel-loader, swc-loader, or ts-loader parse the code.
  • Babel/SWC Plugins: Specialized plugins (e.g., babel-plugin-styled-components) run during compilation to optimize the code. These plugins rewrite tagged template literals to attach human-readable class names, generate stable component identifiers for Server-Side Rendering (SSR), and strip dead styles via minification.
  • Bundle Output: The styles remain as string literals embedded inside the compiled JavaScript bundle.
  • Browser Injection: At runtime, the client-side JavaScript executes, evaluates the style strings, hashes them into class names, and injects them into the document's <head> using <style> tags or the CSSOM insertRule API.

In this model, Webpack does not invoke css-loader or MiniCssExtractPlugin because CSS assets are never generated at compile time.

2. Zero-Runtime (Build-Time) CSS-in-JS Libraries

Zero-runtime libraries, such as Linaria, Vanilla Extract, and Astroturf, extract styles into static CSS files during the Webpack compilation phase. This process involves a more complex pipeline within Webpack:

Step 1: AST Parsing and Static Evaluation

When Webpack encounters a file containing styled elements, dedicated loaders (such as @linaria/webpack5-loader or @vanilla-extract/webpack-plugin) intercept the module. The loader parses the source code into an Abstract Syntax Tree (AST) and evaluates the style expressions at build time.

Step 2: Virtual CSS Module Generation

Once the styles are evaluated, the loader strips the CSS definitions from the JavaScript file, leaving behind only the generated, static class names mapped to the component elements. The extracted style rules are then emitted as a "virtual" CSS file (e.g., Button.linaria.css) and re-injected into Webpack’s internal module dependency graph.

Step 3: Standard CSS Pipeline Hand-Off

Webpack treats the generated virtual file as a native CSS asset, passing it to standard Webpack style-processing loaders:

  1. css-loader: Resolves @import and url() paths within the extracted CSS and translates it into a JavaScript-compatible string export.
  2. postcss-loader (optional): Applies plugins such as Autoprefixer to the extracted CSS.
  3. MiniCssExtractPlugin.loader or style-loader: In production, MiniCssExtractPlugin.loader extracts the CSS out of the JavaScript runtime and into separate .css files. In development, style-loader may be used to inject the styles dynamically for Hot Module Replacement (HMR).

Asset Optimization and Emission

For zero-runtime workflows, once the CSS modules reach the compilation asset phase, Webpack processes them through its optimization hooks. Plugins such as CssMinimizerWebpackPlugin compress and deduplicate rules across the extracted style files. Finally, Webpack outputs the compiled JavaScript chunks alongside standard, standalone .css files and automatically injects corresponding <link rel="stylesheet"> tags into the output HTML via HtmlWebpackPlugin.
