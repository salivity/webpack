How to Configure Webpack Console Output Verbosity

Controlling console verbosity in Webpack allows developers to reduce terminal clutter during routine builds or surface deep diagnostics during debugging. Webpack provides two primary configuration properties to govern console output—stats for compilation-related data and infrastructureLogging for internal operational messages—alongside secondary options like performance.hints and devServer.client.logging. This guide details these configuration options and demonstrates how to adjust terminal output levels to suit your development and production workflows.

The stats Option

The stats configuration option controls how Webpack outputs bundle compilation statistics, including assets, modules, chunks, timings, and build warnings or errors.

Preset Strings

Webpack includes built-in presets that provide immediate control over terminal detail:

module.exports = {
  // Options: 'none', 'errors-only', 'errors-warnings', 'minimal', 'normal', 'detailed', 'verbose'
  stats: 'minimal',
};
  • none: Suppresses all output.
  • errors-only: Outputs only when fatal compilation errors occur.
  • errors-warnings: Outputs only compilation errors and warnings.
  • minimal: Displays errors, warnings, and minimal build status.
  • normal: The default output showing bundle details, assets, and time.
  • detailed: Outputs extra details regarding chunks and loaders.
  • verbose: Outputs all available build data, including skipped modules and child compilations.

Granular Object Configuration

For fine-grained control, stats can be configured as an object to toggle specific output items:

module.exports = {
  stats: {
    all: false, // Disables all stats by default
    assets: true, // Shows emitted assets
    errors: true, // Displays compilation errors
    errorDetails: true, // Explains error causes
    warnings: true, // Displays warnings
    timings: true, // Shows build duration
    colors: true, // Highlights output with colors
  },
};

The infrastructureLogging Option

While stats manages compilation and asset details, infrastructureLogging handles messages originating from Webpack's internal processes, file watchers, caches, and third-party plugins.

module.exports = {
  infrastructureLogging: {
    level: 'warn', // Options: 'none', 'error', 'warn', 'info', 'log', 'verbose'
    debug: ['MyPlugin'], // Enables verbose logs for specific plugins or modules
  },
};
  • level: Determines the threshold for internal messages. Setting this to 'error' or 'warn' eliminates general informational output (such as cache status) while retaining critical operational problems.
  • debug: Accepts an array of strings or RegExp patterns to selectively enable debug logs for specific packages or core modules without enabling full verbosity globally.

The performance.hints Option

Webpack displays warnings in the console when generated bundles exceed size thresholds. The performance.hints setting controls whether these warnings appear:

module.exports = {
  performance: {
    hints: false, // Options: false, 'warning', 'error'
  },
};
  • Setting hints: false stops Webpack from alerting you about oversized entry points and assets.
  • Setting hints: 'error' causes builds to fail when limits are breached.

The devServer.client.logging Option

If you use webpack-dev-server, console noise in the browser's developer console can be managed separately through the devServer configuration:

module.exports = {
  devServer: {
    client: {
      logging: 'warn', // Options: 'none', 'error', 'warn', 'info', 'log', 'verbose'
    },
  },
};

This controls the log level emitted to the browser console before reload or hot module replacement (HMR) events occur.
