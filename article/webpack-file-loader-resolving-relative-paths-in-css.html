Webpack file-loader: Resolving Relative Paths in CSS

When Webpack processes CSS files containing relative image paths, it relies on a coordinated pipeline between css-loader and file-loader to locate, emit, and rewrite those asset references. Understanding this process requires looking at how Webpack treats CSS url() declarations as module dependencies, how paths are resolved relative to the stylesheet, and how file-loader outputs the final assets and rewrites the generated URLs.

1. Parsing CSS URLs via css-loader

The resolution process begins not in file-loader, but in css-loader. When Webpack encounters a stylesheet, css-loader parses the CSS abstract syntax tree (AST) and searches for declarations using url(...).

When it encounters a relative path—such as background-image: url('./assets/icon.png')—css-loader treats that path as a CommonJS or ES module dependency. Crucially, css-loader resolves this path relative to the specific CSS file in which the url() is declared, not relative to the entry point or root directory of your project. It translates the CSS statement into an internal import statement:

require('./assets/icon.png');

2. Module Resolution and file-loader Invocation

Webpack's enhanced module resolver then attempts to locate ./assets/icon.png on the filesystem. Once the file is found, Webpack checks its configured module rules to determine which loader should handle that file extension.

When configured to match image extensions, file-loader intercepts the required file. At this stage, file-loader performs two main actions:

  1. Emits the File: It copies the original binary file from its source directory to the configured Webpack output directory (such as dist/). During this step, it renames the file according to its name configuration, which commonly includes content hashes (e.g., [name].[contenthash].[ext]).
  2. Returns the Public URL: Instead of returning raw image data to the JavaScript bundle, file-loader returns a JavaScript module that exports a string representing the final public URL of the asset:
module.exports = __webpack_public_path__ + "icon.5d41402abc4b2a76b9719d911017c592.png";

3. Rewriting the URL in the Final CSS

After file-loader processes the image, the generated string URL is passed back to css-loader. Webpack substitutes the original relative path inside the CSS declaration with this returned value.

The output URL depends directly on your Webpack configuration:

  • Default Behavior: If no publicPath is set, file-loader generates a path relative to the output directory or the runtime public path.
  • Custom publicPath: If publicPath is defined (either globally in output.publicPath or locally inside file-loader options), it prefixes the emitted filename. For example, a publicPath of /static/ results in url('/static/icon.hash.png').

4. Handling Extracted CSS vs. Injected CSS

The way the final path behaves in the browser depends on how the CSS is delivered:

  • With style-loader: The CSS is injected directly into <style> tags in the HTML document at runtime. The resolved image path will be requested relative to the HTML document's base URL unless an absolute publicPath was provided.
  • With MiniCssExtractPlugin: The CSS is extracted into a standalone .css file in the build directory. If the generated path is relative rather than absolute, it must be correct relative to the output .css file's location, which often requires configuring the publicPath option specifically within MiniCssExtractPlugin.loader.
