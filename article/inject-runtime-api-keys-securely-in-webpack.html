Inject Runtime API Keys Securely in Webpack

Embedding API keys directly into Webpack builds exposes sensitive credentials inside client-side JavaScript bundles, creating significant security vulnerabilities. This article outlines why build-time injection fails to protect secrets, and provides practical, production-ready architectures to inject configuration at runtime—including Backend-for-Frontend (BFF) proxies, dynamic HTML hydration, and runtime configuration endpoints.

The Problem with Webpack Build-Time Injection

Developers frequently use tools like webpack.DefinePlugin or dotenv-webpack to introduce environment variables into their applications:

// webpack.config.js
new webpack.DefinePlugin({
  'process.env.API_KEY': JSON.stringify(process.env.API_KEY),
});

During compilation, Webpack replaces every instance of process.env.API_KEY with the plain-text string value. Because JavaScript runs in the user's browser, any user can inspect network traffic, search the bundled .js files, or access the key through the browser console.

Rule of thumb: If an API key grants write permissions, bills your account, or accesses sensitive backend data, it must never touch the client bundle.

Method 1: The Backend-for-Frontend (BFF) Proxy Pattern

The most secure way to handle sensitive API keys is to ensure the frontend never handles them at all. Instead of having the browser call a third-party API directly with a private key, route requests through your own lightweight server.

  1. The frontend client sends an authenticated request to your backend:

    // Browser request
fetch('/api/v1/weather?city=London');

  2. Your server intercepts the request, appends the secret API key internally, and queries the external service:

    // Express.js / Node server
app.get('/api/v1/weather', async (req, res) => {
  const city = req.query.city;
  const response = await fetch(`https://api.external.com/data?city=${city}`, {
    headers: { Authorization: `Bearer ${process.env.PRIVATE_API_KEY}` }
  });
  const data = await response.json();
  res.json(data);
});

  3. The response is forwarded back to the client. The key never leaves the server environment.

Method 2: Dynamic HTML Injection (window.__ENV__)

For public-facing keys that must reside in the browser (such as Google Maps, Stripe Publishable Keys, or Sentry DSNs) across varying environments (staging, production) without rebuilding the static Webpack bundle, use runtime HTML templating.

Instead of building separate bundles per environment, inject a global configuration object inside your index.html at the time the file is requested.

1. Configure the HTML Template

Add an unpopulated script tag to your root index.html:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <script src="/config.js"></script>
  <!-- Or inline via server-side rendering -->
  <script>
    window.__RUNTIME_CONFIG__ = {
      PUBLIC_KEY: "$PUBLIC_KEY_PLACEHOLDER"
    };
  </script>
</head>
<body>
  <div id="root"></div>
</body>
</html>

2. Replace Placeholders at Startup

In Docker/containerized environments running NGINX, replace the placeholder inside the container entrypoint using envsubst:

# entrypoint.sh
envsubst '$PUBLIC_KEY' < /usr/share/nginx/html/index.html.template > /usr/share/nginx/html/index.html
nginx -g 'daemon off;'

3. Access the Configuration in Code

Reference the key directly from the browser context rather than process.env:

// src/services/api.js
const apiKey = window.__RUNTIME_CONFIG__?.PUBLIC_KEY;

export const client = new ExternalClient({ apiKey });

Method 3: Fetching Runtime Config via an Endpoint

Another decoupled approach is to fetch public configurations on client initialization before mounting the application root.

1. Provide an Unauthenticated Config Endpoint

Your server or edge function serves environment-specific, non-sensitive variables:

// Server route: GET /config.json
app.get('/config.json', (req, res) => {
  res.json({
    analyticsKey: process.env.PUBLIC_ANALYTICS_KEY,
    apiBaseUrl: process.env.API_BASE_URL
  });
});

2. Initialize Application State

Block application rendering until the configuration is resolved:

// src/index.js
async function init() {
  const response = await fetch('/config.json');
  const config = await response.json();

  window.__APP_CONFIG__ = config;

  // Mount React / Vue / Angular application
  ReactDOM.render(<App />, document.getElementById('root'));
}

init();

Summary of Best Practices

  • Private Secrets: Always manage via Backend-for-Frontend (BFF) proxies. Never pass secrets to Webpack through DefinePlugin or dotenv-webpack.
  • Public Client Keys: Inject them dynamically via server-rendered HTML or container startup scripts to preserve the "Build Once, Deploy Anywhere" principle.
  • Bundle Inspection: Audit your production bundles using tools like source-map-explorer or webpack-bundle-analyzer to verify no accidental string literals contain credentials.
