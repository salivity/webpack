TerserPlugin extractComments in Webpack Builds

This article explains the extractComments option in Webpack's TerserPlugin, covering its purpose, default behavior, and practical configuration. You will learn why Webpack generates separate .LICENSE.txt files during production builds, how this setting aids legal compliance without sacrificing code minification, and how to customize or disable the feature depending on your deployment requirements.

What is extractComments?

TerserPlugin is the default JavaScript minifier used by Webpack in production mode. The extractComments option controls whether legal, copyright, and licensing comments found in your source code and node_modules dependencies are preserved and extracted into a separate text file.

By default, minification removes white space, shortens variable names, and strips out unnecessary code and comments to minimize bundle size. However, open-source licenses (such as MIT, Apache 2.0, and BSD) typically require that their copyright notices and license terms remain intact when distributed.

Instead of leaving these large blocks of text inside your active JavaScript files—which would increase parse times and payload sizes—TerserPlugin extracts them into a companion file, typically named <output-filename>.LICENSE.txt, and leaves a small comment referencing this file at the top of the bundle.

Default Behavior in Webpack

In Webpack 5, extractComments is enabled by default in production mode (true).

By default, TerserPlugin identifies license comments using a built-in regular expression that looks for terms like @license, @preserve, /*!, or @cc_on. When one of these matches is detected:

  1. The comment is removed from the main JavaScript chunk.
  2. The comment is written to a <bundle-name>.js.LICENSE.txt file in the output directory.
  3. A single-line reference comment pointing to the license file is added to the top of the minified bundle.

How to Configure extractComments

You configure extractComments within the optimization.minimizer section of your webpack.config.js.

1. Disabling Comment Extraction

If you do not want Webpack to generate .LICENSE.txt files, you can set the option to false. When disabled, all comments (including licenses) are completely removed from the build output unless preserved via Terser's general comment settings.

const TerserPlugin = require('terser-webpack-plugin');

module.exports = {
  mode: 'production',
  optimization: {
    minimize: true,
    minimizer: [
      new TerserPlugin({
        extractComments: false,
      }),
    ],
  },
};

2. Customizing with a Regular Expression or Function

You can pass a regular expression or a custom function to match specific comments:

new TerserPlugin({
  // Only extract comments that contain the word "LICENSE"
  extractComments: /LICENSE/i,
});

Using a function provides granular control over which comments are preserved based on the AST node or comment text:

new TerserPlugin({
  extractComments: (astNode, comment) => {
    return comment.value.includes('@custom-license');
  },
});

3. Advanced Configuration Using an Object

To control the output filename, condition, or the banner text referencing the extracted file, pass an object:

new TerserPlugin({
  extractComments: {
    condition: /^\**!|@preserve|@license|@cc_on/i,
    filename: (fileData) => {
      // Custom naming format for license files
      return `${fileData.filename}.legal.txt`;
    },
    banner: (licenseFile) => {
      // Custom banner left in the minified JS bundle
      return `License information can be found in ${licenseFile}`;
    },
  },
});

Summary

The extractComments option in TerserPlugin provides an automated way to satisfy open-source licensing requirements while maintaining optimized, lightweight JavaScript bundles. While it is active by default in Webpack production builds, you can easily disable it to prevent the creation of .LICENSE.txt files or customize it to fit specific project and licensing workflows.
