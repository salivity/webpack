Webpack CLI Arguments and Configuration Merging

This article explains how command-line arguments passed to webpack-cli are parsed, passed, and merged into a Webpack configuration. You will learn how CLI flags interact with static and functional configuration files, the role of the env and argv parameters, and the priority rules governing which settings take precedence when building your bundle.

Static Configurations vs. Function Configurations

The way command-line arguments interact with your Webpack configuration depends primarily on how your configuration is exported in webpack.config.js: as a static object or as a function.

1. Configuration Exported as a Function

To dynamically access command-line arguments before the configuration is resolved, Webpack supports exporting a function rather than an object:

module.exports = (env, argv) => {
  return {
    mode: argv.mode || 'development',
    // ... other configurations
  };
};

When webpack-cli detects that the exported configuration is a function, it invokes that function and passes two primary arguments:

  • env: An object containing variables set using the --env flag (for example, --env production --env platform=web resolves to { production: true, platform: 'web' }).
  • argv: An object containing all parsed command-line arguments passed to webpack-cli, including flags like --mode, --entry, --output-path, and custom flags.

This mechanism allows you to manually inspect arguments and programmatically merge them, generate conditional plugins, or switch entry points before returning the final configuration object.

2. Configuration Exported as an Object

If your configuration exports a static object, you do not receive direct access to argv inside the configuration file. Instead, webpack-cli handles the merging process automatically after importing the file.

The Internal Merging Process

When command-line flags are executed, webpack-cli follows a defined lifecycle to resolve the final configuration passed to the core Webpack compiler:

  1. Argument Parsing: webpack-cli parses the raw terminal input using internal argument mapping definitions. Known Webpack options (such as --entry, --output-path, --target, or --mode) are validated against Webpack's schema.
  2. Loading the Configuration File: The CLI identifies and imports the configuration file specified by default or via the --config flag.
  3. Executing Functional Configs: If the imported module is a function or returns a Promise, webpack-cli executes it with (env, argv) and awaits the resolved configuration object.
  4. Applying CLI Overrides: Once the base configuration object is acquired, webpack-cli applies command-line arguments on top of it. CLI arguments strictly take precedence over values defined in the configuration file.

Precedence Rules and Conflict Resolution

Command-line arguments are designed to override static configurations to facilitate on-the-fly environment changes (such as overriding target modes in CI/CD pipelines).

  • Direct Overwrites (Primitives): Options that take single values, such as --mode production or --target node, will unconditionally overwrite any mode or target properties defined inside the returned configuration object.
  • Complex Properties: Flags like --entry or --output-path override their respective paths in the configuration. If an argument specifies a collection or complex type, webpack-cli maps the argument directly to the corresponding schema location within the Webpack configuration tree rather than shallowly merging it.
  • Multi-Configuration Builds: If your configuration exports an array of configurations, CLI flags are applied across all individual configurations in the array unless conditionally scoped inside a configuration function.
