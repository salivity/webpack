Webpack raw-loader: Loading Text and Shader Files

This article provides an overview of the role and mechanics of raw-loader in Webpack. It explains how this loader transforms non-JavaScript assets, such as plain text documents and GLSL shader files, into readable JavaScript strings during the build process, along with its primary use cases and modern alternatives.

What Is raw-loader?

By default, Webpack treats imported files as JavaScript or JSON modules. When an application attempts to import unstructured files—such as .txt, .html, or 3D shader files like .vert and .frag—Webpack cannot parse them without explicit instructions.

The raw-loader package acts as a pre-processor that reads the target file's raw content and exports it directly as a JavaScript string. When imported into an application, the module resolves to a UTF-8 string containing the exact contents of the source file.

Loading Plain Text Files

In frontend development, developers frequently need access to raw text files without hardcoding large text blocks into JavaScript files. Common scenarios include:

  • Markdown Files: Importing .md files for dynamic rendering via markdown parsers.
  • HTML Templates: Importing static markup templates for custom components or rendering engines.
  • Configuration and Data: Reading unstructured plain text, licenses, or CSV data directly into the application state.

By routing these extensions through raw-loader, Webpack bundles the file contents into the output bundle, eliminating runtime network requests that would otherwise be required using fetch or XMLHttpRequest.

Loading Shader Files (GLSL)

In WebGL, Three.js, and Babylon.js applications, graphical computations rely on vertex and fragment shaders written in OpenGL Shading Language (GLSL). WebGL APIs require these shaders to be passed to the GPU compiler as plain JavaScript strings via functions like gl.shaderSource().

Storing shaders inside JavaScript template literals causes several issues, including lack of syntax highlighting, missing IDE autocompletion, and poor code organization. raw-loader solves this problem by allowing developers to write shaders in dedicated .glsl, .vs, or .fs files while compiling them directly into the bundle as strings.

// Webpack rule configuration
module.exports = {
  module: {
    rules: [
      {
        test: /\.(txt|glsl|vert|frag)$/i,
        use: 'raw-loader',
      },
    ],
  },
};

Once configured, importing a shader behaves like importing any standard module:

import vertexShaderSource from './shaders/vertex.vert';

// vertexShaderSource is now a string ready for WebGL
gl.shaderSource(shader, vertexShaderSource);

Transition in Modern Webpack (Webpack 5)

In Webpack 5, raw-loader has been officially deprecated in favor of built-in Asset Modules. The identical functionality is now natively available without installing external packages by using the asset/source rule type:

module.exports = {
  module: {
    rules: [
      {
        test: /\.(txt|glsl|vert|frag)$/i,
        type: 'asset/source',
      },
    ],
  },
};

Regardless of whether you use the legacy raw-loader or Webpack 5's native asset/source, the fundamental role remains the same: treating text and shader assets as raw strings during compilation to maintain cleaner source code and reduce runtime I/O overhead.
