Raw, URL, and File Loader in Webpack Explained

Prior to Webpack 5, Webpack natively understood only JavaScript and JSON files, requiring specialized loaders to process and bundle external assets like images, fonts, and raw text. To manage these static resources, developers relied on a trio of community packages: file-loader, url-loader, and raw-loader. Each loader served a distinct role in resolving file paths, inlining content, or reading assets as strings. With the release of Webpack 5, these loaders were formally deprecated and replaced by native Asset Modules.

file-loader

The primary purpose of file-loader was to instruct Webpack how to emit a file into the output directory and return its public URL. When an asset like an image or a font was imported into a JavaScript file (e.g., import logo from './logo.png'), Webpack did not know how to handle the binary data natively.

file-loader resolved this by:

  • Copying the target file from the source directory to the build output directory (such as dist/).
  • Renaming the file, typically using a content hash (e.g., logo.d3b07384.png), to support long-term browser caching.
  • Returning the final public path or filename as a string export, allowing code like <img src={logo} /> to reference the correct location in the production environment.

It was predominantly used for large images (PNG, JPEG, GIF), font files (WOFF, TTF, EOT), and other binary assets (PDFs, media files).

url-loader

While file-loader moved files to the output directory, making separate HTTP requests necessary to fetch them, url-loader solved the performance cost of multiple round-trips for small assets.

The purpose of url-loader was to transform files into Base64-encoded Data URLs, inlining the asset directly into the generated JavaScript bundle. Its key feature was a configurable byte threshold (limit option):

  • Below the threshold: If the asset size was smaller than the defined limit (e.g., 8 KB), url-loader converted the file into a data:image/png;base64,... string. This eliminated an HTTP request at the expense of slightly increasing bundle size.
  • Above the threshold: If the asset exceeded the limit, url-loader automatically delegated the file to file-loader as a fallback, emitting it as a standalone file.

This made url-loader ideal for small icons, SVGs, and tiny background graphics.

raw-loader

The purpose of raw-loader was straightforward: it read the contents of a file and exported them directly as a plain JavaScript string.

Unlike url-loader, which encoded binary files into Base64 format, raw-loader did not encode or move files to the output folder. Instead, it read the source content using UTF-8 encoding and wrapped it inside a standard module export.

Common use cases for raw-loader included:

  • Importing raw text files (.txt).
  • Reading Markdown files (.md) to be parsed by an in-browser renderer.
  • Injecting raw SVG markup directly into the DOM as inline HTML.
  • Importing plain CSS, GLSL shader code, or HTML template strings.

Summary of Webpack 5 Replacements

In Webpack 5, the functionality of these three loaders was integrated directly into the core runtime via Asset Modules:

  • raw-loader was replaced by asset/source.
  • file-loader was replaced by asset/resource.
  • url-loader was replaced by asset/inline (for direct inlining) or asset (for conditional inlining based on file size).
