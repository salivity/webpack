Set Webpack Hash to SHA-256 for FIPS Compliance

Federal Information Processing Standards (FIPS) environments enforce strict cryptographic standards, causing Webpack builds to fail with ERR_OSSL_EVP_UNSUPPORTED because Webpack historically relied on the deprecated MD4 algorithm for cache and asset hashing. This guide provides the exact configuration updates needed to switch your Webpack build to a FIPS-compliant SHA-256 hashing algorithm, resolving OpenSSL compatibility errors while preserving asset caching behavior.

Why Webpack Fails in FIPS Mode

When Node.js runs in an OS with FIPS mode enabled (or using Node.js 17+ with strict OpenSSL 3.0 policies), non-approved cryptographic algorithms are blocked at the engine level. Webpack uses hashes to generate unique filenames for bundle busting and internal module identification. By default, older configurations use md4, which immediately triggers an OpenSSL fatal error upon execution:

Error: error:0308010C:digital envelope routines::unsupported
    at new Hash (node:internal/crypto/hash:67:19)
    at Object.createHash (node:crypto:130:10)

Configuring SHA-256 in Webpack 5

Webpack 5 provides a native configuration property to alter the algorithm used for compilation and file generation. You can override the default algorithm globally by defining output.hashFunction in your webpack.config.js.

Update your configuration as follows:

// webpack.config.js
module.exports = {
  // ... other configuration options
  output: {
    // Set the hashing algorithm to SHA-256 for FIPS compliance
    hashFunction: 'sha256',
    // Optional: Specify hash digest encoding (hex is standard)
    hashDigest: 'hex',
    // Optional: Shorten output filename hashes if desired
    hashDigestLength: 20,
    filename: '[name].[contenthash].js',
    chunkFilename: '[name].[contenthash].chunk.js',
    clean: true,
  },
};

Explaining the Parameters

  • hashFunction: Sets the cryptographic algorithm passed directly to Node.js's crypto.createHash(). Changing this to 'sha256' satisfies FIPS requirements.
  • hashDigest: Defines the encoding format for the output string (default is 'hex').
  • hashDigestLength: Controls the maximum length of generated hashes in file templates (such as [contenthash]). Because SHA-256 produces longer strings than MD4, setting this between 16 and 32 keeps output filenames manageable.

Overriding Webpack 4 or Third-Party Plugin Invocations

Webpack 4 hardcodes md4 internally and does not expose a single property to override all hashing. Additionally, some Webpack 5 plugins instantiate custom instances of crypto.createHash('md4').

If upgrading to Webpack 5 is not immediately viable, or if an unmaintained plugin bypasses your configuration, you can patch Node's crypto module at runtime. Create a script to intercept crypto.createHash before invoking Webpack:

// patch-fips.js
const crypto = require('crypto');
const originalCreateHash = crypto.createHash;

crypto.createHash = function (algorithm, options) {
  if (algorithm === 'md4') {
    return originalCreateHash.call(crypto, 'sha256', options);
  }
  return originalCreateHash.call(crypto, algorithm, options);
};

// Require and run your standard webpack CLI or build process
require('webpack/bin/webpack.js');

You can execute this monkey-patch in your package.json:

{
  "scripts": {
    "build": "node patch-fips.js --mode production"
  }
}

Verification

To confirm the update is working:

  1. Run your build process inside your target FIPS-enabled environment:

    npm run build

  2. Verify that output filenames contain valid SHA-256 based hex strings without throwing ERR_OSSL_EVP_UNSUPPORTED.

  3. Ensure continuous integration runners validate builds with the Node flag --enable-fips to catch any new dependencies attempting to use non-compliant algorithms.
