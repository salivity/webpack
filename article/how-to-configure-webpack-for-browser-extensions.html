How to Configure Webpack for Browser Extensions

This guide demonstrates how to configure Webpack to build and package browser extensions for Google Chrome (Manifest V3) and Mozilla Firefox. You will learn how to set up multi-entry compilation for background service workers, content scripts, and popup interfaces, as well as how to copy static assets like the extension manifest and HTML files into a production-ready distribution folder.

Core Concepts of Extension Bundling

Browser extensions rely on multiple isolated contexts running simultaneously:

  • Background Scripts / Service Workers: Handle events and lifecycle logic.
  • Content Scripts: Execute within the context of loaded web pages.
  • Popup / Options Pages: Standard HTML and JavaScript interfaces for user interaction.

Because these components execute independently, Webpack must be configured with multiple entry points rather than a single single-page application (SPA) root.

Project Structure

A typical directory structure for a Webpack-based extension looks like this:

my-extension/
├── dist/
├── src/
│   ├── background/
│   │   └── index.js
│   ├── content/
│   │   └── index.js
│   ├── popup/
│   │   ├── popup.html
│   │   └── popup.js
│   ├── icons/
│   │   └── icon48.png
│   └── manifest.json
├── package.json
└── webpack.config.js

Prerequisites and Dependencies

Install Webpack, its CLI, and the necessary plugins to handle assets and HTML templates:

npm install --save-dev webpack webpack-cli copy-webpack-plugin html-webpack-plugin clean-webpack-plugin

Webpack Configuration

Create a webpack.config.js file at the root of your project:

const path = require('path');
const CopyWebpackPlugin = require('copy-webpack-plugin');
const HtmlWebpackPlugin = require('html-webpack-plugin');
const { CleanWebpackPlugin } = require('clean-webpack-plugin');

module.exports = (env, argv) => {
  const isProduction = argv.mode === 'production';

  return {
    mode: isProduction ? 'production' : 'development',
    devtool: isProduction ? false : 'cheap-module-source-map',
    entry: {
      background: path.resolve(__dirname, 'src/background/index.js'),
      content: path.resolve(__dirname, 'src/content/index.js'),
      popup: path.resolve(__dirname, 'src/popup/popup.js'),
    },
    output: {
      path: path.resolve(__dirname, 'dist'),
      filename: '[name].bundle.js',
      clean: true,
    },
    module: {
      rules: [
        {
          test: /\.js$/,
          exclude: /node_modules/,
          use: {
            loader: 'babel-loader',
            options: {
              presets: ['@babel/preset-env'],
            },
          },
        },
        {
          test: /\.css$/,
          use: ['style-loader', 'css-loader'],
        },
      ],
    },
    plugins: [
      new CleanWebpackPlugin(),
      new HtmlWebpackPlugin({
        template: path.resolve(__dirname, 'src/popup/popup.html'),
        filename: 'popup.html',
        chunks: ['popup'],
      }),
      new CopyWebpackPlugin({
        patterns: [
          {
            from: path.resolve(__dirname, 'src/manifest.json'),
            to: path.resolve(__dirname, 'dist'),
          },
          {
            from: path.resolve(__dirname, 'src/icons'),
            to: path.resolve(__dirname, 'dist/icons'),
            noErrorOnMissing: true,
          },
        ],
      }),
    ],
  };
};

Handling the Manifest File

Ensure your src/manifest.json matches the output file names generated by Webpack:

{
  "manifest_version": 3,
  "name": "My Webpack Extension",
  "version": "1.0.0",
  "action": {
    "default_popup": "popup.html",
    "default_icon": "icons/icon48.png"
  },
  "background": {
    "service_worker": "background.bundle.js"
  },
  "content_scripts": [
    {
      "matches": ["<all_urls>"],
      "js": ["content.bundle.js"]
    }
  ]
}

Note for Firefox: Firefox supports Manifest V3, but background tasks are typically defined via background.scripts instead of background.service_worker. If you are targeting Firefox specifically or writing a cross-browser extension, you can use environment variables in Webpack to dynamically transform the manifest.json using the transform hook inside CopyWebpackPlugin.

Cross-Browser Manifest Transformation

To manage browser-specific differences during compilation, configure CopyWebpackPlugin to modify the manifest dynamically:

new CopyWebpackPlugin({
  patterns: [
    {
      from: path.resolve(__dirname, 'src/manifest.json'),
      to: path.resolve(__dirname, 'dist'),
      transform(content) {
        const manifest = JSON.parse(content.toString());

        if (env.browser === 'firefox') {
          manifest.background = {
            scripts: ['background.bundle.js'],
          };
        }

        return JSON.stringify(manifest, null, 2);
      },
    },
  ],
})

Build and Load the Extension

Add execution scripts to your package.json:

"scripts": {
  "build": "webpack --mode=production",
  "build:firefox": "webpack --mode=production --env browser=firefox",
  "watch": "webpack --watch --mode=development"
}
  1. Run npm run build to generate the dist/ directory.
  2. In Google Chrome, navigate to chrome://extensions/, enable Developer mode, click Load unpacked, and select the dist folder.
  3. In Mozilla Firefox, navigate to about:debugging#/runtime/this-firefox, click Load Temporary Add-on..., and select any file inside the dist directory.
