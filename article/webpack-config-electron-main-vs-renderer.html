Webpack Config: Electron Main vs Renderer

Building Electron applications with Webpack requires distinct configurations for the main and renderer processes due to their differing execution environments and security contexts. While the main process runs in a pure Node.js environment responsible for application lifecycle and native OS interactions, the renderer process typically behaves like a traditional browser window displaying web UI. This guide breaks down the essential Webpack configuration settings—including the target property, entry and output points, Node.js polyfill behaviors, and native module handling—needed to compile both processes efficiently.

The Core Difference: The target Property

The primary configuration difference lies in Webpack's target field. This property tells Webpack which built-in modules to externalize and how to handle module loading mechanisms.

  • target: 'electron-main': Instructs Webpack to treat the bundle as a Node.js process with access to Electron's main-process APIs (app, BrowserWindow, ipcMain). Native Node.js modules (fs, path, crypto) are treated as external and not bundled into the output file.
  • target: 'electron-renderer': Configures the bundle for the UI layer, assuming access to both the DOM and Node.js primitives. Note: With modern Electron security defaults (contextIsolation: true and nodeIntegration: false), using target: 'web' for the renderer alongside a dedicated preload script using target: 'electron-preload' is recommended over direct electron-renderer usage.

Webpack Configuration for electron-main

The main process bundle requires settings optimized for a Node.js runtime and often needs special handling for paths and native C/C++ dependencies.

Key Settings:

  1. Target: Set to 'electron-main'.
  2. __dirname and __filename: Webpack replaces __dirname with / by default. To preserve the actual runtime path on the user's filesystem, configure node: { __dirname: false, __filename: false }.
  3. Externals: Native C++ Node addons (like sqlite3, better-sqlite3, or serialport) cannot be bundled into JavaScript. They must be listed in externals or handled via node-loader.
// webpack.main.config.js
const path = require('path');

module.exports = {
  mode: 'production',
  target: 'electron-main',
  entry: './src/main/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'main.js'
  },
  node: {
    __dirname: false,
    __filename: false
  },
  externals: {
    // List native dependencies that should remain external
    sqlite3: 'commonjs sqlite3'
  }
};

Webpack Configuration for electron-renderer

The renderer configuration behaves similarly to a standard Single Page Application (SPA) Webpack setup, managing UI code, stylesheets, assets, and frontend frameworks (such as React, Vue, or Svelte).

Key Settings:

  1. Target: Set to 'electron-renderer' (if nodeIntegration: true) or 'web' (standard secure setup).
  2. Plugins: Commonly includes HtmlWebpackPlugin to generate the HTML entry file loaded by BrowserWindow.loadFile() or loadURL().
  3. Loaders: Standard loaders for CSS, Sass, images, fonts, and transpilers like Babel or SWC.
// webpack.renderer.config.js
const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  mode: 'production',
  target: 'electron-renderer', // Use 'web' if contextIsolation is enabled
  entry: './src/renderer/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'renderer.js'
  },
  module: {
    rules: [
      {
        test: /\.css$/,
        use: ['style-loader', 'css-loader']
      },
      {
        test: /\.(png|svg|jpg|jpeg|gif)$/i,
        type: 'asset/resource'
      }
    ]
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/renderer/index.html'
    })
  ]
};

Combined Multi-Compiler Setup

Webpack allows exporting an array of configurations. This enables bundling both processes simultaneously using a single command (webpack).

// webpack.config.js
const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

const mainConfig = {
  target: 'electron-main',
  entry: './src/main/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'main.js'
  },
  node: {
    __dirname: false,
    __filename: false
  }
};

const rendererConfig = {
  target: 'electron-renderer',
  entry: './src/renderer/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'renderer.js'
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/renderer/index.html'
    })
  ]
};

module.exports = [mainConfig, rendererConfig];

Preload Scripts

If your application utilizes a preload script to expose secure IPC channels via contextBridge, configure a third configuration entry using target: 'electron-preload'. This ensures standard Node.js APIs can be used inside the preload script while keeping the main renderer bundle isolated and secure.
