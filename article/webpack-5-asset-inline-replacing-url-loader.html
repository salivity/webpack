Webpack 5 asset/inline: Replacing url-loader

Webpack 5 introduced Asset Modules to handle static files natively without relying on external loaders like file-loader and url-loader. Specifically, the asset/inline module type serves as the modern replacement for url-loader, automatically converting assets such as images, fonts, and SVGs into Base64-encoded Data URIs embedded directly within the output JavaScript bundle. This article explains what asset/inline does, how it improves upon url-loader, and how to configure it in your build configuration.

What is asset/inline?

In Webpack 5, asset/inline is one of four built-in Asset Module types. When a file is processed using asset/inline, Webpack bypasses emitting a separate physical file into the output directory. Instead, it reads the content of the file and encodes it as a Base64 Data URI string directly inside the emitted bundle.

This is ideal for tiny assets, such as small icons or SVG glyphs, where reducing the number of external HTTP requests provides a tangible performance benefit over caching individual asset files.

The Role of url-loader in Webpack 4

Prior to Webpack 5, processing inline assets required installing and configuring community packages—most notably url-loader.

A standard Webpack 4 configuration for inlining images looked like this:

module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|gif|svg)$/i,
        use: [
          {
            loader: 'url-loader',
            options: {
              // Without a limit, it inlined everything
            },
          },
        ],
      },
    ],
  },
};

While functional, this approach required maintaining extra dependencies, increased node_modules overhead, and added complexity when coordinating fallback behaviors with file-loader.

How asset/inline Replaces url-loader

Webpack 5 completely deprecates the need for url-loader by integrating the encoding mechanism directly into Webpack core. To replicate the core functionality of url-loader without any dependencies, you simply assign the rule's type property to 'asset/inline'.

Here is the equivalent configuration in Webpack 5:

module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|gif|svg)$/i,
        type: 'asset/inline',
      },
    ],
  },
};

When importing an image in your application:

import smallIcon from './icon.svg';

const img = document.createElement('img');
img.src = smallIcon; // Resolves to "data:image/svg+xml;base64,..."
document.body.appendChild(img);

Webpack automatically serializes the file content into an inline Data URI string.

Handling Conditional Inlining: asset/inline vs. asset

A common feature of url-loader was the limit option, which inlined files below a specific byte threshold while falling back to emitting a file (via file-loader) for larger assets.

If you want strict inlining regardless of size, use type: 'asset/inline'.

However, if you need the conditional behavior previously handled by url-loader's limit, Webpack 5 provides the general type: 'asset' module instead, configured as follows:

module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|gif|svg)$/i,
        type: 'asset',
        parser: {
          dataUrlCondition: {
            maxSize: 8 * 1024, // 8 KB: inlines if <= 8kb, emits file if > 8kb
          },
        },
      },
    ],
  },
};

In this setup, files smaller than 8 KB are automatically handled as asset/inline, while files exceeding the limit are handled as asset/resource.

Key Benefits of Upgrading

Migrating to asset/inline eliminates url-loader and file-loader dependencies from package.json, simplifies configuration syntax, and ensures better compatibility with Webpack 5's internal caching and performance optimizations.
