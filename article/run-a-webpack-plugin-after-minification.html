Run a Webpack Plugin After Minification

Ensuring a custom Webpack plugin executes only after minification requires tapping into the appropriate stage of Webpack's asset processing lifecycle. Because Webpack 5 delegates minification tools like Terser and CssMinimizer to specific optimization stages within the compilation phase, you must schedule your plugin's logic in a subsequent compilation stage or hook into later compiler events such as emit.

Understanding the Asset Processing Lifecycle

In Webpack 5, asset transformations occur inside the compilation.hooks.processAssets hook. Minification plugins register their tasks under the PROCESS_ASSETS_STAGE_OPTIMIZE_SIZE stage.

Webpack processes assets in a strictly ordered sequence of stages:

  1. PROCESS_ASSETS_STAGE_ADDITIONAL
  2. PROCESS_ASSETS_STAGE_PRE_PROCESS
  3. PROCESS_ASSETS_STAGE_DERIVED
  4. PROCESS_ASSETS_STAGE_ADDITIONS
  5. PROCESS_ASSETS_STAGE_OPTIMIZE
  6. PROCESS_ASSETS_STAGE_OPTIMIZE_COUNT
  7. PROCESS_ASSETS_STAGE_OPTIMIZE_COMPATIBILITY
  8. PROCESS_ASSETS_STAGE_OPTIMIZE_SIZE (Minification takes place here)
  9. PROCESS_ASSETS_STAGE_DEV_TOOLING
  10. PROCESS_ASSETS_STAGE_OPTIMIZE_TRANSFER
  11. PROCESS_ASSETS_STAGE_ANALYSE
  12. PROCESS_ASSETS_STAGE_REPORT

To read or modify assets after minification finishes, your plugin must register at a stage following PROCESS_ASSETS_STAGE_OPTIMIZE_SIZE.

Method 1: Using a Late processAssets Stage

The recommended approach in Webpack 5 is to tap into processAssets using a later stage, such as PROCESS_ASSETS_STAGE_SUMMARIZE or PROCESS_ASSETS_STAGE_REPORT.

const { Compilation } = require('webpack');

class PostMinifyPlugin {
  apply(compiler) {
    compiler.hooks.compilation.tap('PostMinifyPlugin', (compilation) => {
      compilation.hooks.processAssets.tap(
        {
          name: 'PostMinifyPlugin',
          // Run in a stage guaranteed to execute after minification
          stage: Compilation.PROCESS_ASSETS_STAGE_SUMMARIZE,
        },
        (assets) => {
          Object.entries(assets).forEach(([pathname, source]) => {
            console.log(`Processing minified asset: ${pathname}`);
            // Access minified content via source.source()
          });
        }
      );
    });
  }
}

module.exports = PostMinifyPlugin;

Method 2: Using the afterProcessAssets Hook

If your plugin does not need to declare a specific stage and simply needs to run once all asset manipulation has settled, use the afterProcessAssets hook on the compilation object.

class PostMinifyPlugin {
  apply(compiler) {
    compiler.hooks.compilation.tap('PostMinifyPlugin', (compilation) => {
      compilation.hooks.afterProcessAssets.tap(
        'PostMinifyPlugin',
        (assets) => {
          // All processAssets stages, including minification, are complete
        }
      );
    });
  }
}

module.exports = PostMinifyPlugin;

Method 3: Using the Compiler emit Hook

If your plugin performs non-transformative tasks—such as uploading assets to a CDN, writing checksum files, or generating deployment manifests—you can hook into compiler.hooks.emit.

The emit hook runs right before Webpack writes compiled assets to the output directory, long after minification has finished.

class PostMinifyPlugin {
  apply(compiler) {
    compiler.hooks.emit.tapAsync('PostMinifyPlugin', (compilation, callback) => {
      // compilation.assets contains fully minified assets
      const assetKeys = Object.keys(compilation.assets);
      
      // Perform async work if necessary
      callback();
    });
  }
}

module.exports = PostMinifyPlugin;

Summary

For modifying minified assets directly in the Webpack pipeline, target compilation.hooks.processAssets using Compilation.PROCESS_ASSETS_STAGE_SUMMARIZE or later. For read-only actions, external transfers, or post-compilation metadata generation, tap into compiler.hooks.emit.
