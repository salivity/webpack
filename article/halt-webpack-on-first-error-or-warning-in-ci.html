Halt Webpack on First Error or Warning in CI

Configuring Webpack to fail immediately upon encountering an issue ensures that Continuous Integration (CI) pipelines do not waste compute time or publish broken builds. This guide explains how to enable Webpack's native fail-fast behavior for errors using the bail property and how to treat warnings as fatal errors using a lightweight custom plugin.

Halting on the First Error Using bail

By default, Webpack continues compiling even after encountering errors to report all detected issues at the end. In a CI environment, you typically want execution to stop as soon as an error occurs.

Webpack provides the bail configuration option to handle this behavior. When set to true, Webpack aborts the compilation process immediately on the first error.

You can set this in your webpack.config.js:

module.exports = {
  // Halt compilation on the first error
  bail: true,
  // Other configurations...
};

Alternatively, you can pass the flag directly through the Webpack CLI in your CI build script:

webpack --bail

Halting on Warnings

The bail option applies only to errors, not warnings. Because Webpack does not have a native bailOnWarnings configuration, you must intercept the build lifecycle to treat warnings as fatal failures.

The most efficient approach is to add a small inline plugin using the shouldEmit or done compiler hooks. Using the shouldEmit hook prevents Webpack from outputting assets to the filesystem if any warnings are present:

class FailOnWarningPlugin {
  apply(compiler) {
    compiler.hooks.shouldEmit.tap('FailOnWarningPlugin', (compilation) => {
      if (compilation.warnings.length > 0) {
        compilation.errors.push(
          new Error(
            `Failing build due to ${compilation.warnings.length} warning(s).`
          )
        );
        return false;
      }
      return true;
    });
  }
}

module.exports = FailOnWarningPlugin;

If you need the CI runner to exit immediately with a non-zero exit code upon completion when warnings exist, use the done hook:

class FailOnWarningPlugin {
  apply(compiler) {
    compiler.hooks.done.tap('FailOnWarningPlugin', (stats) => {
      if (stats.hasWarnings()) {
        const warnings = stats.toJson().warnings;
        console.error('CI Failure: Warnings detected during compilation:');
        warnings.forEach((warning) => console.error(warning.message));
        process.exit(1);
      }
    });
  }
}

Complete CI Configuration Example

Most projects should only enforce strict halting in CI environments while keeping standard, more lenient compilation reporting in local development. You can conditionally enable bail and the warning interceptor by checking the environment variables commonly provided by CI providers:

const isCI = process.env.CI === 'true' || Boolean(process.env.CI);

module.exports = {
  mode: isCI ? 'production' : 'development',
  bail: isCI,
  plugins: [
    ...(isCI
      ? [
          {
            apply(compiler) {
              compiler.hooks.done.tap('StrictCIPlugin', (stats) => {
                if (stats.hasWarnings()) {
                  console.error('Build aborted: warnings found in CI run.');
                  process.exit(1);
                }
              });
            },
          },
        ]
      : []),
  ],
};

This configuration ensures that local development benefits from aggregated error reporting, while the CI pipeline aborts immediately on the first error and strictly terminates if any warnings remain unresolved.
