Understanding optimization.usedExports in Webpack

In Webpack, optimization.usedExports is a core configuration setting responsible for tracking which module exports are actively referenced across your application. This article covers the purpose of optimization.usedExports, how it powers Webpack's tree shaking mechanism, how it works in tandem with code minifiers like Terser, and its default configuration behavior across different build environments.

What is optimization.usedExports?

The optimization.usedExports option instructs Webpack to perform static analysis on your code to determine which exports from ES modules (ESM) are actually used and which are unused.

Instead of stripping code on its own, usedExports marks the exports within the generated bundle with internal Webpack comments. For example:

  • Active exports are marked with annotations like /* harmony export (binding) */.
  • Unused exports are annotated with comments such as /* unused harmony export [exportName] */.

The Role of usedExports in Tree Shaking

Tree shaking—the process of eliminating dead or unreachable code from your final production bundle—requires two distinct phases:

  1. Identification (Webpack): Webpack analyzes ES module import and export statements. When optimization.usedExports is enabled, Webpack identifies exports that have no corresponding imports and flags them in the intermediate code graph.
  2. Elimination (Minifier): Webpack delegates the actual removal of dead code to a minifier, typically Terser or SWC (configured through optimization.minimizer). When the minifier processes the bundle, it recognizes the unused export signatures and safely strips them, reducing the final bundle size.

Without usedExports, the minifier cannot safely determine whether an export might be dynamically required elsewhere in the module, resulting in unused code being retained in the production bundle.

Default Behavior and Modes

Webpack sets defaults for optimization.usedExports based on the active mode:

  • Production Mode (mode: 'production'): Automatically set to true. Webpack performs full export analysis to maximize tree shaking potential and minimize the bundle size.
  • Development Mode (mode: 'development'): Automatically disabled or set to false. Performing static analysis adds compile-time overhead, so disabling it speeds up incremental rebuilds during active development.

How to Configure optimization.usedExports

You can manually control this setting inside your webpack.config.js file:

module.exports = {
  mode: 'production',
  optimization: {
    usedExports: true,
    minimize: true,
  },
};

When setting usedExports: true, ensure that minimize: true is also active if you want unused code physically removed, rather than just labeled in the bundle output.

Relationship with the sideEffects Flag

While usedExports analyzes individual export statements, the sideEffects property (usually set in package.json) evaluates whether entire files can be dropped if none of their exports are used. The two work together:

  • sideEffects: false allows Webpack to skip analyzing and compiling entire files that have no imported members used.
  • usedExports: true handles granular, export-by-export analysis when parts of a file are imported, but other exported functions or variables within that same file are unused.
