Webpack hashFunction and hashDigestLength Explained

This article provides an overview of Webpack's output.hashFunction and output.hashDigestLength configuration options, explaining how they control asset fingerprinting for cache management. You will learn the purpose of each setting, their default values, common use cases, and how to configure them in your Webpack build to optimize build performance and prevent filename collisions.

What is output.hashFunction?

In Webpack, output.hashFunction specifies the cryptographic hashing algorithm used to generate unique hashes for emitted assets, chunks, and modules. These hashes are typically used in filenames (such as [contenthash] or [chunkhash]) to facilitate long-term browser caching and cache busting.

Supported Algorithms and Defaults

  • Webpack 5: The default algorithm is 'xxhash64', a non-cryptographic hash function designed for high performance and speed during compilation.
  • Webpack 4: The default algorithm was 'md4'.

Webpack supports any algorithm provided by Node.js's built-in crypto.createHash module (such as 'sha256', 'sha512', or 'md5'), as well as custom hash functions.

When to Change hashFunction

  1. Node.js Compatibility: Older configurations using 'md4' often encounter errors like error:0308010C:digital envelope routines::unsupported on Node.js 17 and above due to OpenSSL 3.0 restrictions. Explicitly setting hashFunction: 'xxhash64' or 'sha256' resolves this issue.
  2. Security and Compliance: If your deployment environment enforces Federal Information Processing Standards (FIPS), algorithms like md4 and md5 are disallowed. Switching to 'sha256' ensures compliance.
  3. Build Speed: Keeping or switching to 'xxhash64' provides significantly faster compilation times compared to cryptographically secure algorithms like SHA-256.

What is output.hashDigestLength?

output.hashDigestLength defines the maximum character length of the generated hash prefix when injected into asset filenames.

Instead of printing a full-length 64-character hash into your output files, Webpack truncates the hash to the length specified by this option.

Defaults and Collision Trade-offs

  • Default Value: Webpack defaults to 20 characters.
  • Customizing Length: You can specify any integer value. For instance, setting hashDigestLength: 8 produces concise filenames like main.a1b2c3d4.js.

Why Adjust hashDigestLength?

  • Shorter URLs and Filenames: Lowering the digest length (e.g., between 8 and 16 characters) produces cleaner URLs and reduces file path lengths while maintaining enough entropy to avoid hash collisions across builds.
  • Collision Avoidance: For massive enterprise projects with tens of thousands of split chunks, increasing the length reduces the mathematical probability of two distinct files generating identical hash prefixes.

Configuration Example

Both properties are set under the output object in webpack.config.js:

const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].[contenthash].js',
    
    // Algorithm used to generate the hash
    hashFunction: 'xxhash64',
    
    // Number of characters to retain in the hash
    hashDigestLength: 10,
  },
};

In this setup, Webpack hashes file contents using xxhash64 and truncates the resulting [contenthash] to 10 characters (for example, main.4f8a2b9c1d.js).
