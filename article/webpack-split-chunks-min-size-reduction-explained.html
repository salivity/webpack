Webpack splitChunks minSizeReduction Explained

This article provides an overview of the optimization.splitChunks.minSizeReduction configuration introduced in Webpack 5, detailing its role in bundle optimization, how it works alongside existing split rules, and practical examples for implementing it to avoid counterproductive chunk generation.

What is minSizeReduction?

optimization.splitChunks.minSizeReduction is a configuration option in Webpack that defines the minimum size reduction required for the source chunk to justify creating a new, separate chunk.

Before this option was introduced, chunk splitting decisions were primarily driven by thresholds like minSize (the minimum size of the generated chunk). However, extracting a module into a standalone chunk incurs browser overhead due to additional HTTP requests and runtime wrapper code. The minSizeReduction setting ensures that Webpack only splits a chunk if doing so significantly reduces the size of the original bundle, preventing micro-optimizations that degrade overall page load performance.

The Problem It Solves

When Webpack evaluates modules for code splitting, extracting small or shared modules can occasionally produce diminishing returns:

  1. Request Overhead: Modern browsers can handle concurrent requests via HTTP/2 and HTTP/3, but excessive chunk fragmentation still introduces parsing, connection, and scheduling overhead.
  2. Boilerplate Inflation: Adding a new chunk introduces Webpack runtime boilerplate. If a module is extracted, but the parent bundle barely decreases in size, the total byte count across the application increases.

By setting a threshold with minSizeReduction, Webpack verifies that the extraction provides a tangible reduction in the source bundle's footprint before approving the split.

Configuration and Syntax

The property accepts a number (representing bytes) or an object specifying sizes per asset type. It can be applied globally under optimization.splitChunks or scoped to specific cache groups.

// webpack.config.js
module.exports = {
  // ...
  optimization: {
    splitChunks: {
      // Global threshold: source chunk must shrink by at least 10 KB
      minSizeReduction: 10000,
      cacheGroups: {
        vendor: {
          test: /[\\/]node_modules[\\/]/,
          name: 'vendors',
          chunks: 'all',
          // Cache-group-specific threshold
          minSizeReduction: 20000,
        },
      },
    },
  },
};

You can also target specific asset types if your setup extracts CSS alongside JavaScript:

minSizeReduction: {
  javascript: 10000,
  css: 5000,
}

minSize vs. minSizeReduction

Understanding the distinction between these two configurations is essential for effective bundle optimization:

  • minSize: Measures the newly created chunk. If the extracted module(s) do not combine to reach this threshold, the new chunk will not be created.
  • minSizeReduction: Measures the source/parent chunk's reduction. Even if a newly formed chunk satisfies the minSize requirement, Webpack will cancel the split if the original chunk does not shrink by at least the minSizeReduction amount.

When to Adjust This Setting

Tuning minSizeReduction is particularly useful in large-scale applications with aggressive code-splitting strategies. If your build outputs dozens of small chunks that offer marginal caching benefits at the expense of request density, increasing the minSizeReduction value will consolidate those assets back into parent chunks, streamlining browser resource loading.
