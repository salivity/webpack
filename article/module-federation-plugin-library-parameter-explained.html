ModuleFederationPlugin Library Parameter Explained

This article explains the purpose, configuration, and practical use cases of the library parameter within Webpack’s ModuleFederationPlugin. You will learn how this option defines the output format and global assignment of federated containers, ensuring proper integration between host applications and remote micro-frontends.

What Is the library Parameter?

In Webpack 5, the ModuleFederationPlugin allows multiple independent builds to form a single application. When a build exposes modules as a remote container, it produces a container entry file (commonly named remoteEntry.js).

The library parameter determines how this container is assigned, exposed, and accessed in the execution environment. It defines the export target and mechanism that the host uses to reference the remote container's interface.

Syntax and Structure

The library parameter accepts an object specifying the target type and an optional name:

new ModuleFederationPlugin({
  name: 'app_remote',
  filename: 'remoteEntry.js',
  library: { 
    type: 'var', 
    name: 'app_remote' 
  },
  exposes: {
    './Button': './src/Button',
  },
})

If the name within library is omitted, Webpack typically falls back to the top-level name provided in the plugin options.

Common Library Types

The type property defines the environment-specific mechanism used to expose the container:

  • var (Default for script tags): Assigns the container to a variable in the current scope. When loaded via a <script> tag in a browser, it creates a global variable matching the specified name.
  • window: Explicitly assigns the container object to the browser's window object (e.g., window.app_remote).
  • global / globalThis: Attaches the container to globalThis, making it accessible across diverse environments like Node.js, Web Workers, and modern browsers.
  • module: Exposes the container as a native ECMAScript Module (ESM). This removes reliance on global variables and requires setting experiments.outputModule: true in your Webpack configuration.
  • assign-properties / this: Attaches the exposed container properties directly to the current execution context.

Why the library Parameter Matters

  1. Host-Remote Communication: The host application needs a standardized way to find the remote entry once it is loaded. If the host expects a global variable, but the remote outputs an ES module without setting the appropriate library.type, the host will fail to locate the container interface.
  2. Server-Side Rendering (SSR) and Node.js: Browser environments often rely on var or window, but Node.js environments lack a window object. Adjusting the library type to commonjs-module, global, or module enables federated code execution on the server.
  3. Transition to Modern ES Modules: As modern web architecture moves away from polluting the global namespace with window objects, setting library: { type: 'module' } allows federated remotes to be dynamically imported using native browser import() statements.

Summary

The library parameter in ModuleFederationPlugin acts as the bridge between how a remote container is bundled and how a host application consumes it. Configuring it correctly ensures compatibility with your target runtime, prevents global namespace conflicts, and allows seamless adoption of modern module formats.
