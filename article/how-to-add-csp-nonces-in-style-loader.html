How to Add CSP Nonces in Style-Loader

This article explains how to configure Webpack’s style-loader to include a Content Security Policy (CSP) nonce on dynamically injected <style> tags. When a strict CSP rejects 'unsafe-inline' styles, browsers block dynamically inserted CSS unless each injected tag includes a matching cryptographic nonce. Below are the specific options and mechanisms available in style-loader to handle nonce insertion, ranging from static configuration to dynamic runtime evaluation.

1. The Global __webpack_nonce__ Variable

The primary and recommended way to supply a dynamic, per-request nonce to style-loader is through Webpack's built-in __webpack_nonce__ variable. While technically a Webpack runtime feature rather than a loader option key, style-loader is designed to automatically detect and assign this value to the nonce attribute of any generated <style> element.

To use this approach:

  1. Ensure your server injects the unique nonce into the HTML (for example, via a meta tag or a global JavaScript variable).
  2. Set the __webpack_nonce__ variable at the very top of your entry file before any CSS imports are processed:
// entry.js (must execute before importing styles)
__webpack_nonce__ = document.querySelector('meta[name="csp-nonce"]').getAttribute('content');

import './styles.css';

When Webpack bundles the application, style-loader reads __webpack_nonce__ and sets the nonce attribute on the style node upon DOM insertion.

2. The attributes Option

If you require a specific attribute configuration or are dealing with a static nonce, you can use the attributes option in your Webpack configuration. This option allows you to define custom key-value pairs that style-loader applies to the generated <style> elements.

// webpack.config.js
module.exports = {
  module: {
    rules: [
      {
        test: /\.css$/i,
        use: [
          {
            loader: 'style-loader',
            options: {
              attributes: {
                nonce: 'YOUR_STATIC_NONCE_VALUE',
              },
            },
          },
          'css-loader',
        ],
      },
    ],
  },
};

Note: Because nonces must be dynamically generated per HTTP response to maintain strict security, the attributes option is typically only suitable for testing or environments where the bundle is compiled per request.

3. The insert Option (Custom Insertion Function)

When you need granular control over the <style> tag creation and need to attach a dynamic nonce without using __webpack_nonce__, you can supply a custom function to the insert option. This function receives the generated <style> tag before it is appended to the DOM.

// webpack.config.js
module.exports = {
  module: {
    rules: [
      {
        test: /\.css$/i,
        use: [
          {
            loader: 'style-loader',
            options: {
              insert: function (element) {
                const nonceMeta = document.querySelector('meta[name="csp-nonce"]');
                if (nonceMeta) {
                  element.setAttribute('nonce', nonceMeta.getAttribute('content'));
                }
                document.head.appendChild(element);
              },
            },
          },
          'css-loader',
        ],
      },
    ],
  },
};

This method overrides the default insertion behavior and gives you full control over extracting the nonce from the DOM and setting it directly on the node.
