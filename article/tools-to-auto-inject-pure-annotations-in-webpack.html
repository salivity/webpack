Tools to Auto-Inject PURE Annotations in Webpack

In a Webpack build pipeline, the /*#__PURE__*/ comment annotation instructs minifiers like Terser to safely tree-shake unused expressions and top-level function calls that have no side effects. While developers can write these annotations manually, maintaining them across a large codebase is impractical. Several compilers, loaders, and plugins integrated into Webpack can automatically inject /*#__PURE__*/ annotations during the build process to optimize bundle sizes.

1. Babel Plugins

When using babel-loader in Webpack, Babel is the primary tool for injecting pure annotations via AST transformations.

  • babel-plugin-annotate-pure-calls: This dedicated plugin detects function and method calls that can be safely considered pure when their return values are not referenced. It automatically prefixes those calls with /*#__PURE__*/, enabling Terser to strip them out.
  • @babel/preset-env and Core Transforms: Many built-in Babel transformations automatically insert /*#__PURE__*/ annotations. For example, when Babel transpiles ES6 classes or downlevels export statements into ES5 helper functions, it attaches /*#__PURE__*/ to the generated IIFE (Immediately Invoked Function Expression) wrappers.

2. The TypeScript Compiler (tsc via ts-loader)

If your Webpack configuration compiles TypeScript using ts-loader or awesome-typescript-loader, the TypeScript compiler natively injects /*#__PURE__*/ annotations.

When downleveling modern ECMAScript features to ES5 or ES2015, TypeScript automatically flags generated constructs as pure. This includes:

  • Transpiled ES6 classes wrapped in IIFEs.
  • Downleveled TypeScript enum declarations.
  • Transpiled namespace blocks.

To enable this behavior, ensure your tsconfig.json targets a downlevel format (such as "target": "ES5" or "target": "ES2015") and uses an ES module format (such as "module": "ESNext") so Webpack can properly evaluate tree-shaking boundaries.

3. SWC (swc-loader)

SWC is an extensible, Rust-based alternative to Babel. When integrated into Webpack via swc-loader, it performs dead-code optimization and downleveling significantly faster than JavaScript-based tools.

SWC natively handles pure annotations out of the box. During compilation, SWC automatically annotates downleveled class declarations, helper functions, and runtime transformations with /*#__PURE__*/. It also provides an internal tree-shaker that recognizes and respects these annotations before passing the bundle to Webpack's minification stage.

4. esbuild (esbuild-loader)

Using esbuild-loader in Webpack replaces both babel-loader and Terser for transpilation and minification.

When esbuild processes code, it automatically adds pure annotations to downleveled syntax such as class constructors and property initializers. Additionally, esbuild features built-in dead-code elimination that immediately acts on these annotations, purging unused functions before final chunk generation occurs within Webpack.

How Webpack Utilizes Injected Annotations

Webpack itself does not parse function call purity; instead, it relies on its minifier to act on the comments.

When any of the loaders above inject /*#__PURE__*/ into the AST output, Webpack’s default minifier—terser-webpack-plugin—reads the annotation. If the variable assigned to the annotated function call is never imported or used elsewhere, the minifier drops the call entirely, ensuring zero dead code leaks into the final production bundle.
