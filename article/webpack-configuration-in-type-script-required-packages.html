Webpack Configuration in TypeScript: Required Packages

Writing your Webpack configuration in TypeScript allows you to take advantage of type safety, autocompletion, and modern syntax for your build setup. To execute a webpack.config.ts file instead of standard JavaScript, Webpack relies on runtime TypeScript compilation. This article outlines the essential npm packages required to enable TypeScript support in Webpack, along with the basic setup needed to make them work together seamlessly.

Essential Packages

To interpret and execute a TypeScript Webpack configuration, you must install the following development dependencies:

1. typescript

The core TypeScript compiler is necessary for parsing and checking TypeScript syntax.

2. ts-node

Node.js natively executes JavaScript, not TypeScript. ts-node acts as a TypeScript execution engine and JIT (Just-In-Time) compiler for Node.js. When Webpack detects a .ts configuration file, it automatically invokes ts-node under the hood to compile and execute the file on the fly.

3. @types/node

Node.js built-in modules (such as path and fs) are commonly used within Webpack configurations. @types/node provides the type definitions for these standard modules, preventing compiler errors when resolving file paths.

4. @types/webpack

While Webpack includes built-in types in modern versions (Webpack 5+), installing @types/webpack provides explicit interfaces (such as Configuration) to ensure your configuration object matches Webpack's schema with strict type validation.

5. webpack and webpack-cli

The base bundler and command-line interface required to trigger and run the build process.

Installation

Install all the required dependencies using your preferred package manager:

npm install --save-dev webpack webpack-cli typescript ts-node @types/node @types/webpack

Or using Yarn:

yarn add --dev webpack webpack-cli typescript ts-node @types/node @types/webpack

Basic Configuration Setup

After installing the packages, ensure your project contains a tsconfig.json file. Because Node.js utilizes CommonJS modules by default, ts-node requires the module system to be compatible.

Add or update the following compiler options in tsconfig.json:

{
  "compilerOptions": {
    "module": "CommonJS",
    "target": "ES2020",
    "moduleResolution": "node",
    "esModuleInterop": true,
    "allowSyntheticDefaultImports": true
  }
}

If your application source code uses ES modules ("module": "ESNext"), you can configure ts-node specifically in tsconfig.json without affecting the rest of your app:

{
  "ts-node": {
    "compilerOptions": {
      "module": "CommonJS"
    }
  }
}

Example webpack.config.ts

Create your configuration file named webpack.config.ts:

import path from 'path';
import { Configuration } from 'webpack';

const config: Configuration = {
  mode: 'development',
  entry: './src/index.ts',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'bundle.js',
  },
  resolve: {
    extensions: ['.ts', '.js'],
  },
};

export default config;

Running npx webpack will automatically trigger ts-node to compile webpack.config.ts and proceed with the build.
